# 已归档：项目经验存储升级

用于项目经验索引或共享经验库的 schema 发生变化时。正常读取只接受当前 schema；旧格式只能通过明确升级入口进入新格式，完成后不保留双读、旧字段解释或兼容写入。

## 1. 每次升级必须说明

每个 schema 版本变化都先写清：

```text
影响对象：项目索引、项目正文、项目历史、共享索引、共享正文或用户配置
检测方法：怎样只读判断当前版本与受影响数量
修复动作：哪些字段、正文位置、索引和来源关系会改变
需要确认：是否改变内容含义、默认状态、共享范围或用户选择
失败恢复：写入前保留什么，怎样安全重试
完成证据：哪个正式消费者重新读取并验证
```

字段重命名、路径变化、默认状态变化和来源关系变化分别说明，不能用“升级格式”概括。只改变排版且机器合同不变时不提升 schema。

## 2. 升级顺序

1. 运行只读检查：

```powershell
python scripts/project_experience.py upgrade <项目根>
```

2. 根据输出列出所有受影响对象、目标版本和会写入的文件。没有已注册迁移时停止，不临场猜测旧字段含义。
3. 内容含义、共享范围或默认状态会变化时，先取得用户确认。
4. 获准后运行：

```powershell
python scripts/project_experience.py upgrade <项目根> --write
```

5. 运行 `verify`，再用一次真实 `search` 读取升级后的正文；涉及共享库时，从另一个项目检索并确认来源、修订和采用记录仍能解析。

迁移器先在临时内容中完成转换并校验，再原子替换索引。正文路径变化时先写入并验证新位置；旧位置的归档或删除继续服从用户权限，不让正常消费者继续读取旧位置。

## 3. 版本一的当前合同

当前项目索引、共享索引、用户配置和事件均为 schema v1。`upgrade` 对已经使用 v1 的实例返回 `current` 且不写文件。以后新增版本时，必须同时加入：

- 从每个仍受支持旧版本到下一版本的单向迁移；
- 对应的影响、检测、修复、确认和完成说明；
- 从真实旧状态开始、由新消费者读取的测试；
- 旧字段和旧路径的残留检查。

升级完成的标准是所有活动索引只含当前 schema、正式搜索能读取当前正文、来源和采用关系保持成立；不是迁移命令返回成功。
