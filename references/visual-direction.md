# 项目原生视觉方向

用于 README 整页模式、Logo、hero 和表达性视觉素材。它只消费内容方法已经确定的主页主身份或素材沟通任务，以及当前项目的活动代码、文档、测试、接口与数据合同、配置、命令和真实行为，再把这些非图片事实转换为可执行的视觉合同。它不读取任何图片，不选择其它 README 子类型，也不决定发布格式。

## 先锁定图片盲输入边界

设计 Logo、设计图片或写 README 时，项目是唯一真源。现有、旧版、参考、生成、远程和用户附带的图片全部退出输入集合；不得打开、查看、截图、渲染、OCR、取色、临摹、比较或分析，也不得读取画面来提取颜色、字体、形状、构图、主题、语气或品牌性格。当前 README 中的图片引用、仓库图片路径和文件尺寸只能用于结构迁移与消费链核对，不能证明视觉方向。

制作素材前统一记录：

```text
项目活动真源：定义、代码、文档、测试、接口、数据合同、配置、命令和真实行为
项目身份事实：至少两项能够支持识别概念的项目特有事实；不足时准确记录
正式身份源：代码 / 配置 / 资源声明 / 正式素材消费端 / 未发现
图片排除边界：本次存在但不打开、不分析、不复用的图片类别或路径
家族合同：只接受非图片项目真源或用户文字明确声明的共享身份元素
事实等级：项目事实充分 / 项目事实不足
```

没有明确的非图片家族合同，项目就按独立项目处理。旧 Logo、现有 hero、机制图、结果图和同批次素材不能给新素材提供母题；Logo、hero 与章节图的职责分别成立，也不能跨职责借用形状。路径、链接或文件能够加载不改变这项边界。

在同一方法内按事实等级选择一次视觉路径：项目事实充分时先形成语义概念，再形成结构不同的文字候选；项目事实不足时只做准确的中性排版表达，或在整页模式中跳过表达性 hero。完整 README 优化仍需交付首屏 Logo；事实不足时用项目名称或首字母制作中性标志，不借机编造项目对象、流程或品牌性格。选择完成后不重新选择事实等级，也不让任何图片进入后续步骤。

## 先调查项目已有的正式身份源

判断 Logo 缺失、形成新概念或调用任何素材制作方法前，先从真实消费端反查生产者。至少检查应用标题栏与外壳、网站页头、Logo / Icon 组件、绘图或 Canvas 代码、主题与设计令牌、应用清单和打包配置、资源声明以及约束这些对象的测试；搜索组件职责、几何值、颜色角色和调用关系，不能只搜索包含 `logo`、`icon` 或品牌名的文件名。找不到同名图片、README 没有图片引用或素材目录为空，都不是“没有 Logo”的证据。

记录唯一身份源结论：

```text
正式身份消费者及入口：
代码或配置生产者：
几何、颜色角色与语义合同：
正式素材引用及结构状态：
结论：直接复用 / 从代码确定性派生 / 仅保留正式素材引用 / 调查后确认缺失并新建设计
同步验证：生产者、派生素材与 README 消费端怎样防止漂移
```

活动代码或配置已经定义标志的几何、颜色角色或组合关系时，它是首选身份源，优先直接复用或从该生产者确定性派生 README Logo，不再另选一个更“好看”的概念；派生结果必须由测试或等价结构检查与生产者保持同步。应用或构建已经消费一个适合 GitHub 的正式图片素材时，可以在不打开、不分析画面的前提下复用其准确路径；格式不适合作为 README 素材时，只能从非图片代码与配置合同制作适配版本，不能读取原图补全表面值。只有上述生产者、消费者和正式素材引用都经过调查仍不存在时，才能把 Logo 标为缺失，并进入后面的项目事实设计路径。

## 先确定视觉作用与素材动作

视觉先回答“帮助读者理解或相信什么”，再决定怎样表达。整页模式必须明确选择制作新的、排版表达、跳过，或只保留现有引用但不读取内容，并说明怎样服务首页读者变化。在内部写清：

```text
上游沟通重点：主页主身份 / 素材沟通任务
正式身份源结论：直接复用 / 从代码确定性派生 / 仅保留正式素材引用 / 调查后确认缺失并新建设计
事实等级：项目事实充分 / 项目事实不足
视觉作用：结果证据 / 机制解释 / 身份支持
素材动作：制作新的 / 排版表达 / 跳过 / 保留现有引用但不读取内容
活动项目事实与适用状态：
图片排除边界：
允许共享的非图片家族声明：
它能证明什么：
它只能解释什么：
```

- **结果证据**把已经由入口、输出合同、数据结构或端到端行为证明的结果关系转换成视觉；图片本身不反向证明结果。
- **机制解释**使用活动代码、文档、测试、接口或数据合同能够支持的流程、关系、架构、转换或阶段，帮助读者理解项目怎样工作；它不是运行效果或用户结果的证明。
- **身份支持**使用项目名称、准确描述和由本轮项目事实合同生成的标志建立识别，适合结果或机制需要在后文展开、或项目刻意保持简洁的情况。

同一素材可以承担身份支持和另一项主要作用，但要确定一个主作用。解释图与限定它的文字相邻；结果证据能够追溯到当前适用的非图片项目事实。现有素材可以在任务不涉及其重设计时保留原引用，但不得打开内容，也不得向新素材贡献任何表面选择。

## 按项目事实执行

### 非图片身份合同

只有活动项目代码、文档、配置、设计令牌源码、接口合同或用户文字明确声明某项颜色角色、字体角色、形状关系或标志语义时，才能延续该项声明。正式代码或配置生产者已经给出这些身份关系时优先消费，不把它降级为普通灵感。不得打开声明所指向的图片来补全未声明的表面值。

项目有明确家族视觉合同时，只复用合同列出的元素。未被列为家族共享项的构图、容器语言、主题元素和内容密度继续由当前项目事实决定。

### 项目事实充分

先从至少两项项目特有事实写出“项目对象或输入 → 核心动作或关系 → 用户结果”的语义概念合同，再形成至少两个只用文字描述的候选方向。Logo 候选必须保持身份职责；hero 和章节图不得向它捐赠母题。两个候选要在下列维度中至少有三项实质不同：

- 背景明暗或材料感；
- 信息的空间关系与阅读顺序；
- 标题、说明和元数据的字体角色；
- 边界、容器与连接方式；
- 来自项目对象的主题元素；
- 内容密度与留白。

每个候选至少由两项项目特有事实支持。仓库类型、技术栈、流行风格和“看起来专业”只能提供语境，不能单独支持颜色、等宽字体、圆角卡片、网格或左右分栏。选择事实映射更直接、能更清楚完成视觉作用的方向，随后冻结几何合同并退出候选阶段，不把未选方向或旧图特征混入成品。

### 项目事实不足

用户明确要求素材时，使用项目名称、准确描述和必要元数据建立排版层级，颜色、字体和空间保持中性，不补造项目不存在的对象、流程、品牌性格或技术装饰。整页模式可以跳过没有事实支持的表达性 hero，但完整优化不能省略 Logo；用名称或首字母完成中性标志，并把事实不足边界返回整页流程。

## 从内容关系决定形状

先识别内容单位之间是什么关系，再决定是否需要边界：

- 多个独立、可比较或本身有明确表面的对象，可以各自使用卡片、窗口或样本框。
- 连续阶段使用路径、轴线、编号或渐进空间表达依赖。
- 多个对象共同构成一个系统时，先使用共享场、连接和层级，只给真正独立的边界加容器。
- 单一价值或单一产物使用排版、比例、裁切和留白建立重点。
- 活动接口或数据合同确实定义独立容器时，可以保留该结构事实，不把容器语言扩散到其它内容。

因此，卡片是一种内容边界，不是技术项目的默认装饰。圆角、描边、阴影和顶部标签只有承担由项目真源证明的分组、状态或层级时才进入合同。

## 冻结有来源的视觉合同

开始制作前写清每个表面选择的来源：

```text
Visual role: 结果证据 / 机制解释 / 身份支持
Material action: 制作新的 / 排版表达 / 跳过 / 保留现有引用但不读取内容
Project basis: 使用哪些活动代码、文档、测试、接口、数据合同、配置、命令或真实行为；没有时为空
Image exclusion: 哪些图片类别或路径明确未打开、未分析、未复用
Palette: 背景、文字、主色、强调、弱化角色，以及各自来源
Typography: 标题、说明、元数据的字体角色，以及各自来源
Composition: 对象关系、阅读顺序、画面重心，以及项目依据
Shape: 哪些内容需要边界、连接、圆角或直角，以及语义依据
Motif: 来自哪个项目对象；没有可靠对象时为空
Density: 内容量和留白怎样服务当前受众与作用
Family reuse: 明确复用的家族元素；没有合同时为空
Evidence boundary: 能证明什么，只能解释什么
```

协议不变量和 GitHub 画布约束由后续资源负责，不能倒推审美。几何合同至少记录画布、身份对象、路径或形状、相对位置、层级、颜色角色、是否允许文字以及每项与项目事实的对应。任何没有项目来源、非图片家族合同或清晰内容职责的表面值都回到当前项目重新决定，不沿用示范代码、上一项目或任何图片的取值。

## 验收与返回

1. 视觉语义合同是否强化上层主页主身份或完成素材沟通任务。
2. 颜色、字体角色、构图、形状和主题元素是否各有当前项目依据。
3. 输入是否全部来自活动项目真源，且没有打开、分析、复用或比较任何图片；结果证据是否来自当前适用的非图片事实，机制解释是否保持解释身份。
4. 卡片和其它容器是否对应真实的独立内容边界。
5. 项目事实充分时，文字候选是否真正不同，选择是否由至少两项项目特有事实支持并冻结为几何合同。
6. 家族共享是否停在明确合同内，其它视觉决定是否仍来自当前项目。
7. 视觉是否给快速开始和其它独立入口留下清楚位置。

完成后把正式身份源结论、唯一选定的视觉合同、素材动作、实际使用的项目事实、图片排除边界、同步验证和证据边界返回当前 README 子类型。具体 hero、画布、SVG 和发布格式继续由上层已经排定的后续资源负责。
