# 项目原生视觉方向

用于 README 整页模式、hero 和表达性视觉素材。它消费上层已经确定的主页主身份或素材沟通任务、合格材料、视觉证据合同与证据等级，把项目事实转换为一套可执行的视觉合同。它不改变证据等级，不重新核定候选材料，不恢复上层已经判定为过时或未验证的产物，不选择其它 README 子类型，也不决定发布格式。

## 先确定视觉作用与素材动作

视觉先回答“帮助读者理解或相信什么”，再决定怎样表达。在内部写清：

```text
上游沟通重点：主页主身份 / 素材沟通任务
证据等级：已有体系 / 原生材料充分 / 证据不足
视觉作用：结果证据 / 机制解释 / 身份支持
素材动作：复用已有 / 制作新的 / 排版表达 / 跳过
合格项目证据与适用状态：
不采用材料及原因：
允许共享的家族元素：
它能证明什么：
它只能解释什么：
```

- **结果证据**使用真实界面、输出、截图、数据图或端到端产物，让读者看到项目实际产生的结果。
- **机制解释**使用仓库能够支持的流程、关系、架构、转换或阶段，帮助读者理解项目怎样工作；它不是运行效果或用户结果的证明。
- **身份支持**使用项目名称、准确描述和已有项目标志建立识别，适合证据需要在后文放大或项目刻意保持简洁的情况。

同一素材可以承担身份支持和另一项主要作用，但要确定一个主作用。解释图与限定它的文字相邻；结果证据能够追溯到当前适用的真实产物。只有上层已经核定来源、适用项目状态和公开职责的材料才能选择“复用已有”；文件存在、链接有效、画面完整或曾在 README 出现都不构成复用资格。

## 按上层证据等级执行

### 已有体系

从上层已经核定的产品界面、品牌资料、来源独立且一致的资产或用户确认规则中提取颜色角色、字体角色、形状关系和图像处理方式。延续这些已经成立的关系。当前 README 视觉及同批次生成素材没有独立来源时仍是待评估产物，不把其中的偶然配色、圆角、分栏或装饰升级成项目规范。

项目有明确家族视觉合同时，只复用合同列出的元素。未被列为家族共享项的构图、容器语言、主题元素和内容密度继续由当前项目事实决定。

### 原生材料充分

从上层合格的真实界面、输出、处理对象、关系、代码表达或文档语气中形成至少两个候选方向。两个候选要在下列维度中至少有三项实质不同：

- 背景明暗或材料感；
- 信息的空间关系与阅读顺序；
- 标题、说明和元数据的字体角色；
- 边界、容器与连接方式；
- 来自项目对象的主题元素；
- 内容密度与留白。

每个候选至少由两项项目特有证据支持。仓库类型、技术栈、流行风格和“看起来专业”只能提供语境，不能单独支持颜色、等宽字体、圆角卡片、网格或左右分栏。选择证据更直接、能更清楚完成视觉作用的方向，随后退出候选阶段，不把未选方向混入成品。

### 证据不足

用户明确要求素材时，使用项目名称、准确描述和必要元数据建立排版层级，颜色、字体和空间保持服务可读性的中性选择，不补造项目不存在的对象、流程、品牌性格或技术装饰。整页模式未要求必须有素材时，把跳过理由返回整页流程。

## 从内容关系决定形状

先识别内容单位之间是什么关系，再决定是否需要边界：

- 多个独立、可比较或本身有明确表面的对象，可以各自使用卡片、窗口或样本框。
- 连续阶段使用路径、轴线、编号或渐进空间表达依赖。
- 多个对象共同构成一个系统时，先使用共享场、连接和层级，只给真正独立的边界加容器。
- 单一价值或单一产物使用排版、比例、裁切和留白建立重点。
- 真实界面本身采用卡片时，可以保留其产品事实，不把卡片语言扩散到其它内容。

因此，卡片是一种内容边界，不是技术项目的默认装饰。圆角、描边、阴影和顶部标签只有承担分组、状态、层级或真实界面还原时才进入合同。

## 冻结有来源的视觉合同

开始制作前写清每个表面选择的来源：

```text
Visual role: 结果证据 / 机制解释 / 身份支持
Material action: 复用已有 / 制作新的 / 排版表达 / 跳过
Material basis: 使用哪些上层合格材料及其适用状态；没有时为空
Palette: 背景、文字、主色、强调、弱化角色，以及各自来源
Typography: 标题、说明、元数据的字体角色，以及各自来源
Composition: 对象关系、阅读顺序、画面重心，以及项目依据
Shape: 哪些内容需要边界、连接、圆角或直角，以及语义依据
Motif: 来自哪个项目对象；没有可靠对象时为空
Density: 内容量和留白怎样服务当前受众与作用
Family reuse: 明确复用的家族元素；没有合同时为空
Evidence boundary: 能证明什么，只能解释什么
```

协议不变量和 GitHub 画布约束由后续资源负责，不能倒推审美。任何没有项目来源、家族合同或清晰内容职责的表面值都回到当前项目重新决定，不沿用示范代码或上一项目的取值。

## 验收与返回

1. 视觉是否强化上层主页主身份或完成素材沟通任务。
2. 颜色、字体角色、构图、形状和主题元素是否各有当前项目依据。
3. 使用的材料是否都在上层合格集合中；结果证据是否来自当前适用的真实产物，机制解释是否保持解释身份。
4. 卡片和其它容器是否对应真实的独立内容边界。
5. 原生材料充分时，候选是否真正不同，选择是否由至少两项项目特有证据支持。
6. 家族共享是否停在明确合同内，其它视觉决定是否仍来自当前项目。
7. 视觉是否给快速开始和其它独立入口留下清楚位置。

完成后把唯一选定的视觉合同、素材动作、实际使用的合格材料和证据边界返回当前 README 子类型。具体 hero、画布、SVG 和发布格式继续由上层已经排定的后续资源负责。
