# 解压项目重大安全隐患检查

用于源码或项目归档已经解压到独立研究目录之后、开始普通项目研究之前的静默安全门槛。它只回答“继续读取这个副本时，是否已经出现足以阻止后续运行、安装或导入的重大隐患证据”，不把每次归档研究扩张成完整安全审计。

## 1. 固定动作边界

取得解压脚本返回的准确项目根后，先运行：

```text
python scripts/inspect_extracted_project_safety.py <项目根>
```

检查只能读取文件、目录、链接、脚本、清单和二进制字符串，不运行项目入口、不导入模块、不安装依赖、不注册组件、不打开宏、不访问项目声明的远程地址，也不修改、隔离、删除或上传归档内容。扫描器是候选证据生产者，不代替语义判断；它输出的 `high_impact_evidence` 必须继续沿真实入口、触发条件和项目用途核对。

检查范围至少包括：

- 解压后的链接是否逃出研究根；
- 安装、启动、构建和包生命周期入口是否下载并执行未固定的远程载荷；
- 是否形成持久化加远程载荷、进程注入、凭据收集加外传、键盘记录加外传、系统根级破坏或隐藏挖矿控制链；
- 原生二进制、脚本和清单中的高影响能力是否能由项目声明、源码、构建入口和实际消费者解释；
- 工具实际扫描了哪些文件，哪些大文件、格式或目录仍未覆盖。

普通项目研究只消费这次静态门槛。用户明确要求安全审计、恶意软件分析、依赖漏洞审计或动态联网验证时，才把对应结果作为独立请求扩展；本方法不自行运行杀毒软件、上传样本、查询第三方信誉库或启动沙箱。

## 2. 重大隐患必须形成证据链

只有同时满足以下条件，才把候选升级为重大隐患：

1. 存在能够产生高影响结果的具体能力，例如远程任意代码执行、自动下载并运行载荷、持久化控制、进程注入、凭据或输入窃取并外传、隐藏挖矿代理、越出研究根写入，或面向系统与用户数据的破坏性操作；
2. 能从真实入口、自动生命周期、默认配置或用户按正常说明必经的路径到达，而不只是孤立字符串、未调用示例、测试夹具或安全研究样本；
3. 项目公开用途、明确授权和可核对实现不能合理解释这条能力，或者发行物包含公开源码与构建链无法解释的同类高影响行为；
4. 证据足以说明可能影响什么对象以及怎样发生。只能证明“程序联网”“使用了某个系统 API”或“工具没有扫完”时仍是普通事实或未知，不补造成恶意结论。

源码与发行二进制不一致、未披露的设备识别、遥测或授权可以降低信任，但它们只有与上述高影响执行链结合时才构成这道门槛中的重大隐患。不能仅凭作者身份、仓库热度、文件名、域名观感、杀毒软件单次标签或第三方评论完成定性。

## 3. 默认静默的普通发现

以下事实单独出现时不属于重大隐患，不进入用户输出：

- 存在 EXE、DLL、PYD、安装脚本或其它原生文件；
- 二进制没有代码签名、没有可复现构建、缺少 SBOM 或项目维护不完善；
- 程序联网、检查版本、下载业务数据、监听本机端口、包含硬编码地址；
- 使用硬件 ID、设备授权、遥测或日志上报，但尚未形成远程控制、窃密或破坏链；
- 使用进程、注册表、网络、文件或加密 API，但没有构成高影响组合；
- 依赖过旧、存在一般漏洞、配置较弱、接口缺少认证，或者扫描覆盖不完整；
- 扫描器只命中文档、测试、示例、夹具中的危险词语。

这些内容只有在用户当前问题本来就询问项目可信度、安全性、隐私、部署暴露或采用风险，并且会实质改变答案时，才按对应专项正常回答；不能借本门槛给普通项目介绍附加“安全问题”段落。

## 4. 消费扫描结果

扫描结果按三种状态消费：

- `no_high_impact_evidence`：不向用户提到检查、安全或零发现，直接继续原项目研究。它只证明本次静态规则实际覆盖的范围，不等于软件已经被证明安全。
- `incomplete`：保留未覆盖范围，不把未知写成风险，也不在普通结果中提示。若用户随后要求运行、安装或导入，而未覆盖对象正是该入口，则在动作前说明无法建立安全判断，并停在原有运行授权边界。
- `high_impact_evidence`：逐项回读准确文件、入口、调用关系、默认配置和项目用途，排除文档、测试、合法管理工具和声明功能。只有第 2 节全部成立才形成重大隐患；否则按普通发现静默退出。

确认重大隐患后，不运行、安装、导入或连接项目；只读研究仍可在不扩大风险的范围内继续。用户输出先给结论，再给准确文件或二进制身份、从入口到危害的证据链、实际影响、已经证明与仍未知的部分，以及安全的下一步。不能把“可疑”“不透明”改写成“木马”“肉鸡”或“已经中招”；这些定性必须分别有远程控制链、实际执行证据或主机痕迹支持。

没有确认重大隐患时，最终答案不得出现例行安全小节、扫描通过声明、普通风险清单或“未发现病毒”之类背书。

## 5. 完成标准

解压返回的准确项目根已经由确定性扫描器读取；扫描覆盖和限制可在内部复核；每项高影响候选都经过入口、可达性、项目用途和影响核对。确认重大隐患时已经阻止后续运行并提供可复核证据；没有重大隐患时用户只得到原本请求的项目结果，看不到额外安全噪音。
