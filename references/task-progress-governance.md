# 任务进度真值治理

用于设计、审查、诊断或迁移面向用户与公共调用者的任务进度。主路由已经确定改动前预防、只读诊断、已授权修复或产品体验审查，以及本轮写入权限和停止位置；本方法只负责让进度表达真实工作事实，不重新选择任务类型，也不把普通确定性问题升级成昂贵诊断。

## 1. 进入条件与边界

以下任一事实会改变实现或验收时使用本方法：

- 产品显示任务百分比、进度条、当前阶段或聚合进度；
- 公共类型、回调、事件、持久化或 API 传递任务进度；
- 外部工具、下载器、编码器、模型或批处理过程需要映射成任务进度；
- 用户看到进度长期停住、突然跳变、提前完成，或与最终结果明显不符；
- 实现用固定数字表达阶段，或把多个任务的百分比直接平均。

页面滚动、动画时间线和媒体播放位置只有在它们被产品解释为任务完成程度时才进入本方法。仅用于诊断结论的健康、漂移、丢失或同步指标继续由疑难证据诊断负责。两类事实同时出现时由主路由组合使用，不能用诊断指标替代用户任务进度，也不能用进度条证明系统健康。

开始时接收：

```text
用户任务、对象与最终结果：
当前显示的状态、阶段和进度：
正式工作生产者：
进度经过的类型、事件、存储、聚合与消费者：
现有测量来源、未知项与失败证据：
本轮权限和停止位置：
```

## 2. 状态、阶段和进度是三种事实

先为同一次操作建立唯一身份，再分别定义：

| 事实 | 回答的问题 | 所有者 |
| --- | --- | --- |
| 任务状态 | 排队、运行、暂停、取消、失败或完成中的哪一种终态与生命周期事实 | 任务生命周期的唯一所有者 |
| 阶段说明 | 当前正在做什么，用户为什么仍需等待 | 当前正式生产步骤 |
| 进度 | 已完成多少可测量工作，以及总工作量是多少 | 实际执行工作的测量生产者 |

阶段变化不能自动产生百分比，状态进入“运行”也不能把默认零值解释为已经测量。进度使用两种明确模式：

- **可计算**：同时具有已完成量、总量和单位；百分比只由这三个事实派生，不作为新的真源保存或上报。
- **不可计算**：任务正在运行，但当前没有可靠总量或无法连续测量；消费者显示不定进度和阶段说明，不发布一个看似精确的数字。

可计算进度还要满足总量大于零、已完成量不小于零、单位在本次工作内稳定，以及更新来自同一个操作尝试。真实零值表示已经测量且尚未完成任何工作；未知、不可用和未开始不能借零值表达。任务真正完成时，生命周期所有者在正式生产步骤、结果登记和必要持久化成功后提交完成状态；生产步骤不能用接近终点的百分比提前声明任务已经完成。

## 3. 为每个数字建立工作量来源

对每个会显示或传输的可计算进度写出：

```text
操作身份和当前尝试：
正式工作生产者：
已完成量怎样取得：
总量怎样取得：
单位：字节 / 帧 / 媒体时间 / 样本 / 条目 / 批次 / 其它正式单位
采样、更新频率和允许滞后：
进度通道失败或总量失效时怎样回到不可计算：
正式消费者与允许显示的结论：
独立最终结果：
```

字节数、帧数、媒体时间、样本数、条目数和批次数只有在生产者确实按同一单位执行工作时才成立。输入文件大小、输出文件当前大小、第一条日志、相邻事件数、预计耗时、默认常量和界面动画都不能替代正式工作量。

外部工具提供机器可读进度流、正式回调或稳定状态接口时，使用与生产入口相同的版本、参数和流式读取边界取得真实输出，并确认实际字段的单位、结束语义、编码、标准流和取消行为。帮助文本或记忆中的参数只能用于发现候选；正式解析器至少消费一次真实工具输出。只有人类日志、输出不稳定或没有总量时保持不可计算，不能从最后一行、自然语言关键词或进程仍在运行推算百分比。

进度遥测可以有界、合并或丢弃旧更新，但完成、失败、取消和正式结果属于无损状态事实。丢失中间更新可以让显示跳跃，不能让任务终态丢失，也不能让较旧操作的进度覆盖当前尝试。

## 4. 多阶段与聚合不制造第二套数学

多阶段任务先判断各阶段是否共享一个真实总量：

- 全程可以用同一单位和同一总量测量时，由该共同工作量直接产生整体进度。
- 各阶段单位不同、总量只在进入阶段后才知道，或阶段工作量无法预先比较时，显示当前阶段及其局部真实进度；阶段之间不能用人为权重、固定起止数字或“差不多完成”拼成整体百分比。
- 某阶段无法测量时，该阶段保持不可计算。已经完成的前一阶段可以作为历史事实显示，但不能让旧百分比在未知阶段继续冒充当前进展。

聚合任务只合并单位兼容、总量语义一致且属于当前活动尝试的测量值。按总工作量求和，而不是平均各任务百分比。存在未知总量、不同单位或语义不兼容的成员时，整体进度保持不可计算；可以另外显示已完成任务数或每项状态，但这些计数不能改名成整体工作百分比。

## 5. 从唯一模型完成整条迁移

最终进度合同由一个结构化领域模型负责，至少能够表达模式、阶段身份、已完成量、总量和单位。生产者、任务服务、事件或消息、持久化、聚合器、桌面或网页模型、界面和公共 API 全部消费这一合同；不能让某层继续维护裸浮点、独立阶段字段或本地百分比算法。

迁移时建立完整调用点清单：

```text
正式进度生产者
→ 回调、事件或结构化消息
→ 任务状态与持久化
→ 聚合或投影
→ 活动界面、CLI 或公共调用者
→ 完成后的正式结果
```

旧持久状态只有在旧生产者能够证明测量来源时才迁移为可计算进度。无法证明来源的旧运行数字迁移为不可计算；由独立终态已经证明完成的旧任务可以表达完成事实，但不能把历史阶段数字包装成新测量。新消费者接通后移除旧标量字段、旧回调签名、旧 helper、兼容属性、双读、默认补值和页面局部计算。一次性迁移器可以读取旧格式，活动运行时不能长期同时解释两套进度真源。

## 6. 真实验收

根据本次改动选择最小但完整的代表性矩阵，至少覆盖会改变结论的项目：

1. 一个有真实总量的生产者在完成前产生至少一次可计算更新，正式消费者读取同一操作身份、已完成量、总量和单位。
2. 一个无法取得可靠总量的真实阶段保持不可计算，界面或公共输出不显示伪造百分比。
3. 外部工具参与时，正式入口实际启动目标版本和参数，解析器消费真实输出，最终产物由下游消费者读取。
4. 多阶段和聚合路径分别证明兼容单位怎样合并，以及未知或不兼容成员怎样保持不可计算。
5. 进度经过事件与持久化时，保存、关闭、重开和真实旧状态迁移后仍由当前消费者得到同一合同；旧字段与运行分支已经退出。
6. 异步或排队界面从当前活动对象重新读取，等待正式消费者的可观察状态变化；数据库完成、回调发出或固定睡眠不能代替用户已经看到。
7. 任务完成后，正式结果、文件、记录或外部状态确实可用；百分比到达终点不能替代结果消费。

核心链测试必须让正式生产者产生进度与结果，再经过真实事件、存储或公共边界到达消费者。消费端手写一份结构化进度只能验证显示组件，不能证明进度来源、聚合、迁移和完成语义。残留扫描使用进度旧字段、旧回调和固定阶段写法的准确标识，并逐项核对命中；宽泛搜索到的业务数值不能直接当成伪进度。

## 7. 输出与停止

```text
当前任务进度是否真实：
状态、阶段与进度的唯一所有者：
每个可计算进度的已完成量、总量、单位与正式生产者：
保持不可计算的阶段及原因：
多阶段与聚合规则：
类型、事件、持久化、界面与公共调用者的迁移范围：
旧字段、旧回调、兼容路径和固定阶段数字的退出证据：
正式生产、边界、消费与最终结果的验证：
仍未验证或受阻的条件：
```

改动前预防在形成进度合同、迁移范围和验收计划后返回主流程。只读诊断在最早错误边界、影响范围和最终修法已经明确时停止。已授权修复在结构化合同成为唯一活动真源、全部消费者迁移、旧路径退出且真实结果可见可用后返回根因治理或产品实施路径，不自行扩张到其它任务系统问题。
