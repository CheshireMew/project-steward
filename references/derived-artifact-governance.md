# 派生产物治理

用于昂贵结果被切成多个工作单元、通过缓存复用、由资源池调度，或需要 Agent 反复编排工具才能完成的项目。它负责让重算范围跟随最终消费者真正依赖的语义事实，而不是跟随原始输入的偶然表示、文件位置或流程步骤。并发生产和高速回退继续由 `hard-to-reproduce-diagnostics.md` 负责，公共自动化适配器继续由 `external-tool-compatibility.md` 负责，本方法不复制它们的锁、任务状态或协议语义。

## 1. 进入条件与主要失败

以下任一情况会改变成本、正确性或返工范围时使用本方法：

- 一处局部修改触发全部生成、渲染、分析、编译、索引或导出；
- 缓存键包含大量原始输入，但其中只有一部分真正改变产物；
- 为追求固定时长、大小或数量而切断连续语义，导致边界错误或不可消费结果；
- 多个单元重复生产同一连续资源，或者在最终装配前反复转码、压缩或解析；
- 结果机械重复，看似资源不足，但候选池的实际使用情况未知；
- Agent 为同一项目状态反复读取多个接口、逐项提交相邻操作，编排往返显著高于真正生产耗时。

普通一次性、小型且没有复用或分段的派生结果不增加完整治理。没有测量就只说明“可能更快”时，先按 `hard-to-reproduce-diagnostics.md` 建立代表性基线；不能为了设计缓存而提前建立第二套产物、任务或恢复架构。

## 2. 多份产物先选择演化合同

同一用户结果由规格、计划、任务、研究、合同、实现说明或其它多份产物共同表达，并且后续发现可能改变其中事实时，先为每份产物确定职责，再决定变化怎样传播。不能默认所有文件都回写，也不能默认每次变化都新建一套目录，更不能把已经确认的权威产物和方便生成的派生文件同时当成可编辑真源。

先建立：

```text
权威产物及其稳定身份：
其它产物分别属于独立事实、派生结果还是不可变历史：
实施或验证发现是否允许回写权威产物，以及接受边界：
哪些已确认结果保持不可变，后续变化怎样取得新身份：
重新生成派生结果前，重要理由由哪个真源保留：
变化后失效、重算和继续有效的产物与正式消费者：
```

按项目真实需要选择一种活动关系：

- **允许回流**：实施发现可以改变权威事实；由同一接受边界更新所有独立真源，再沿派生图重算消费者，不能只修实现或某一份计划留下冲突。
- **向前留档**：已确认产物保持不可变，新变化建立带新身份的后继记录；活动消费者读取明确选中的当前身份，不能按目录序号、修改时间或最近出现文件猜测。
- **维护活真源**：一份产物拥有当前合同，其它内容由它派生；变化先提交权威产物，再重新生成受影响结果。派生文件中仍有长期价值的实施理由必须先回到权威真源或它正式拥有的理由记录，不能在整体重写时丢失，也不能让理由记录反向成为第二份合同。

三种关系没有全局默认。选择依据是项目现有真源、审计或历史需要、变更能否合法回写、消费者怎样选择当前结果和理由保留责任；不能因为参考项目使用固定文件序列就照搬。只有一份产物，或者权威与派生关系已经由项目合同明确且本次不会改变时，不增加模式字段、状态文件、目录层级、工作流引擎或人工门槛。

### 定性评审只有一份可编辑权威记录

Agent 或人工作出的视觉、语义、质量或其它定性判断需要投影到多个 JSON、报告、任务状态或界面摘要时，先选择一份带成果身份、证据身份、评审者和决定版本的可编辑评审记录。其它状态都是它的派生结果，不能让多个文件分别拥有同一接受、拒绝、修复或完成事实，也不能靠人工双写保持一致。

由一个确定性的收尾边界读取权威评审，核对被评成果与证据身份仍匹配、必需决定已经填写、阶段问题和完成状态不冲突，再一次生成或同步全部机器可读镜像。身份过期、决定矛盾、证据缺失或任一镜像更新失败时，收尾不得报告完成；旧镜像保留为未同步或失效状态，不能反向覆盖权威评审。测试从同一权威记录运行真实收尾入口，证明所有正式消费者读到同一决定，并用人工分别修改两份状态的对抗输入证明双重所有权会被拒绝。

## 3. 先建立语义派生图

从最终消费者需要的结果反向确定工作单元，不从现有循环、文件切片或工具参数直接推导边界：

```text
权威输入与稳定版本
→ 面向生产者的规范投影
→ 语义工作单元
→ 单元产物
→ 相邻边界或共享连续资源
→ 确定性装配
→ 正式消费者
→ 用户可观察结果
```

为每类单元建立合同：

| 项目 | 必须回答 |
| --- | --- |
| 稳定单元身份 | 哪个语义对象或范围使它跨运行仍可识别 |
| 实际消费输入 | 生产者真正读取并会改变结果的规范投影 |
| 输出规格 | 格式、尺寸、精度、目标平台或其它消费者要求 |
| 生产者语义版本 | 哪次实现变化会改变相同输入的输出 |
| 上下游依赖 | 哪些单元、共享资源、边界产物和装配读取它 |
| 不得切分的约束 | 哪些连续语义、事务、状态或资源必须保持完整 |
| 发布边界 | 何时验证完成并原子成为可消费产物 |
| 失效原因 | 哪项实际依赖变化使现有产物不再成立 |

稳定身份不能使用列表位置、临时文件名或本轮调度顺序。生产者输出多个合法对象时，从权威输入或正式生产结果取得语义身份，不能由消费者根据数量和位置猜测。

## 4. 缓存键只表达会改变产物的事实

一个确定性单元的缓存身份至少由以下内容规范化组成：

```text
稳定单元身份
+ 生产者实际消费的规范输入投影
+ 生产者语义版本
+ 正式输出规格
+ 会改变结果的外部能力或模型身份
```

### 等价状态表示先收敛为同一规范投影

同一语义状态可能由实时内存、持久化重开、网络副本或迁移结果等多个正式生产者提供。先判断集合顺序是否属于业务语义：顺序影响最终结果时，顺序本身必须进入权威状态、版本和持久表示，全部生产者按同一正式顺序读取；顺序不影响结果时，由唯一规范投影边界按稳定语义身份生成确定顺序，并统一字段省略、默认值、精度和等价表示。不能让某个缓存消费者为了当前命中率临时排序，掩盖上游仍在产生不同事实。

同一语义状态必须在进入缓存前得到相同规范投影和内容身份，缓存键、工作单元切分和最终装配共同消费这份投影。不能让缓存键、工作单元切分或最终装配各自排序、补默认值或猜顺序，也不能把等价状态的表示差异登记成两个合法缓存身份；出现差异时先修复最早的生产或规范投影边界。

只有能够证明进入生产者并改变输出的事实才加入键。审核备注、诊断标签、展示顺序、输出目录、文件名、任务身份、进度、重试次数以及没有改变产物的更细原始测量，不因“与任务有关”就进入缓存键。原始输入比最终表现精细时，先由唯一生产边界生成实际消费的规范投影；例如下游只读取离散状态或固定精度值，就以该投影为键，而不是以不会改变输出的原始小数变化为键。

反过来，不能为了提高命中率而遗漏真正的语义依赖。字体、目标平台、模型版本、区域设置、随机性策略、编解码器或其它能力只有在当前生产者实际读取并改变结果时进入；随机生产者必须把固定种子或已物化输入变成正式合同，否则不能把结果冒充确定性缓存。

缓存条目记录规范键、生产者身份、结果内容身份、格式版本、完成状态和正式消费者。文件存在、非空或路径相同不能证明命中。损坏、不完整、生产者版本不匹配或内容身份不一致的结果必须在唯一生产边界失效；同键并发生产使用 `hard-to-reproduce-diagnostics.md` 的单一生产者合同。

## 5. 目标单元与安全上限是两种约束

工作单元的目标大小服务复用、并行和观察；安全上限负责资源、工具或平台的硬限制。两者必须分别命名和验证：

```text
目标单元大小及其性能依据：
最大连续单元及其硬限制来源：
允许切分的中性边界：
不得切断的连续语义：
目标附近没有中性边界时的选择：允许超过目标 / 改变上游表示 / 明确失败
跨单元接缝的生产者和验收：
```

不能把目标大小当成必须命中的硬切点。文本、事务、状态序列、结构块或其它连续对象在目标附近没有合法边界时，优先延长到下一个中性边界，但不得超过已经证明的安全上限。只有上游合同允许且消费者能完整重建时才拆分；不能生成孤立标记、半个事务、缺少前置状态的片段或其它单独无法解释的单元。

边界本身若会影响结果，就作为显式接缝产物进入派生图。局部单元变化只使该单元、读取它的相邻接缝和必要装配失效；不能让接缝被隐藏在全量导出中，迫使所有单元重算。空白、静止、无事务窗口或其它中性区可以成为可复用单元，但必须由正式语义判定，不以固定偏移猜测。

先区分语义、安全或平台硬限制要求的强制切分，与只为并行、缓存或复用服务的可选切分。强制切分以正确性和安全上限为通过条件；可选切分还必须证明每单元固定启动成本、接缝与最终装配开销，不能把工作单元数量本身当成优化。

可选策略至少比较短输入首次冷运行、代表性长输入首次冷运行和同计划暖缓存重跑。短输入没有并行或复用收益时可以保持一个单元；暖缓存胜出不能单独证明首次运行的分段策略正确，除非产品合同明确优先迭代复用并接受对应首次成本。自动策略为每次选择记录单单元或多单元的原因、阈值来源和本轮实际固定开销，不能在看到候选耗时后改写选择标准。

## 6. 共享连续资源只生产一次

多个单元共同消费但自身不应随单元边界切断的资源，建立独立稳定身份和生产边界。例如统一索引、公共依赖图、连续音频、共享数据快照或全局样式可以一次生产，再由单元通过范围引用或时间映射消费。不能为了方便逐单元处理而重复解析、编码、压缩、下载或复制同一资源。

```text
共享资源身份与权威输入：
唯一生产者和生产版本：
完整资源的验证与发布边界：
各单元引用的范围或映射：
资源变化影响的单元和装配：
单元变化是否需要重建共享资源及依据：
```

共享不等于全局失效。资源自身改变时，沿实际引用传播；单元的局部呈现改变但不影响共享资源输入时，保留共享结果。最终装配必须读取同一已发布资源身份，不能让每个单元各自生成看似等价的副本。

## 7. 先检查调度利用，再增加资源

结果出现重复、单调或覆盖不足时，在请求补充数据、素材、模板、模型或 provider 之前，先建立资源利用账本：

| 候选身份 | 资格与适用条件 | 实际可达 | 选择次数与连续重复 | 未被选择的原因 | 输出质量证据 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

从正式调度入口运行代表性计划，记录候选过滤、评分、最近使用历史、确定性随机源和最终选择。若多个合格候选存在，但选择器持续偏向最短、最早、固定权重或同一类别，根因是利用策略而不是资源库存。先修复资格、轮换、多样性或连续重复约束，再用原候选池复验。

### 选择器先冻结约束层级

选择器同时承担资格、配额、排序、数量目标、补位或 fallback 时，先建立一份约束合同：

```text
候选资格与拒绝原因：
硬约束、作用范围与显式例外：
软评分、排序、多样性与轮换：
请求数量语义：最大值 / 目标值 / 最小值
补位或 fallback 允许放宽的软偏好：
最终 selected / deferred / rejected 及原因：
```

资格和硬约束先过滤，软评分只给仍合格的候选排序。显式例外必须是带来源、作用对象和限制的合同输入，不能伪装成极高分或隐藏分支。最大值是上界，目标值是尽量达到的偏好，最小值才是交付保证；合格候选不足时按合同返回更少结果或准确的未满足状态，不能用补位绕过资格、排除项、类别硬上限或其它硬约束。补位与 fallback 只能放宽已经列出的软偏好，并保留每个候选最早命中的不可放宽原因。

验证至少包含候选高度集中在同一类别、候选稀疏、数量目标大于合格集合以及软评分偏好与硬上限冲突的对抗输入。测试从正式选择入口取得 selected、deferred 和 rejected 身份及原因，再让正式消费者使用结果；不能只断言总数够了，或由测试手写一份看似满足约束的列表。

只有以下证据同时成立，才判定资源确实不足：现有候选全部能够被正式选择器到达；代表性计划已经充分使用合格候选；剩余失败可以明确映射到缺少的状态、范围、持续时间、质量或授权；新增资源有正式注册、校验、选择和退出边界。不能把一次生成失败直接变成永久补素材流程，也不能保留不可达资源来虚增库存数量。

## 8. 为重复 Agent 工作提供紧凑自动化边界

当同类任务反复需要 Agent 先读取多个文件或接口才能知道项目状态，再逐项调用相邻操作并轮询结果时，把编排往返作为正式成本测量。只有重复工作负载和消费者已经确定时，才要求项目公共应用边界补充以下能力：

1. **结构化快照**：一次返回项目版本、活动对象、阶段、产物身份、缓存命中与失效原因、正在运行的任务以及仍需用户动作。
2. **原子批处理**：同一已冻结计划中的相邻操作一次校验、一次提交，全部成功或全部拒绝；连续决策批次仍逐步读取前一步正式提交结果，不能错误地冻结为一批。
3. **可观察长任务**：开始操作返回稳定任务身份，观察或等待只读取该任务的新状态和增量结果，不重新启动生产者。
4. **机器可读能力**：操作、参数、前置条件、成本、结果和错误来自实际公共能力描述，说明文档不复制另一份命令集合。

这些入口映射到现有唯一公共应用边界，不复制领域状态、缓存算法、阶段判断、任务恢复或错误解释。只减少 Agent 调用次数但让宿主和 CLI 分别决定业务语义，属于第二套架构。没有确定消费者或现有结构化入口已经足够时，不为了“更自动”新增协议服务。

测量时把 Agent 读状态与作决定的时间、工具调用往返、实际生产、等待外部系统和最终验证分开。优化后应证明调用次数和重复读取下降，且同一正式生产者、状态、权限与用户结果保持；不能把隐藏检查、跳过验收或扩大自动权限记作 Agent 效率收益。

## 9. 失效、装配与发布

变化发生时，从权威新输入生成规范投影，与各单元记录的实际消费投影比较，再沿派生图决定：

```text
变化事实与新版本：
规范投影是否改变：
直接失效单元及准确原因：
相邻接缝与共享资源是否受影响：
只需重新装配或重新验证的结果：
继续命中的单元及内容身份：
本轮实际启动的生产者数量：
正式消费者读取的最终身份：
```

输出路径改变通常只影响复制或发布消费者；诊断元数据改变通常只影响报告；输出规格改变会使读取该规格的单元失效；生产者语义变化会使它负责的全部对应单元失效。规则以实际依赖为准，不把这些例子写成无条件例外。

单元、接缝、共享资源和最终装配分别在完成校验后原子发布。最终结果只有在依赖集合、顺序、数量、内容身份和消费者合同全部成立后可见；不能把新旧单元临时拼接状态暴露为完成。缓存命中只节省生产，不免除最终装配和用户结果所需的验证。

## 10. 真实验证矩阵

至少使用下列工作负载，并记录实际生产者调用、内容身份、耗时和正式消费者结果：

1. **冷运行**：没有可复用产物，全部必需单元、接缝和共享资源各由准确生产者生成。
2. **同计划重跑**：输入、生产者版本和输出规格相同，确定性单元命中；正式消费者仍取得完整结果。
3. **等价表示**：分别从实时状态生产者和持久化重开生产者取得同一语义版本，二者生成相同规范投影、内容身份、工作单元和缓存键；无语义的枚举或序列化顺序变化保持命中，真正有语义的换序才改变缓存身份。
4. **局部语义变化**：代码生成任务只改变一个模块的规范输入，只重建该模块、依赖它的边界和最终装配，其它模块保持同一内容身份。
5. **非语义变化**：只改审核备注、输出目录或不会改变规范投影的更细原始值，不启动昂贵单元生产者；相应报告或复制边界按职责更新。
6. **边界对抗输入**：目标大小附近没有中性切点，连续对象安全延长到合法边界；达到安全上限时按正式合同改变表示或明确失败，不产生孤立单元。
7. **可选切分策略**：分别比较短输入首次单单元与多单元、代表性长输入首次运行和暖缓存重跑，记录固定启动、接缝、装配、实际选择原因及最终消费者结果。
8. **资源池利用**：多个合格候选全部可达，调度结果满足已经定义的重复和覆盖合同；仍缺能力时，缺口能够指向准确资源类别。
9. **选择器约束冲突**：集中和稀疏候选都先经过资格与硬约束；补位只放宽已登记的软偏好，数量不足时保留准确未满足状态。
10. **Agent 编排**：同一代表性计划比较改造前后的状态读取、操作调用和等待次数，原子批处理与任务观察仍经过唯一公共应用边界。
11. **定性评审投影**：一份权威评审经过确定性收尾同步全部状态镜像；成果或证据身份变化、决定矛盾及人工双写都会阻止完成，正式消费者不会读取彼此冲突的结论。

关键测试不能直接填充缓存、伪造命中报告、手写下游单元或 mock 掉本次验证的生产与装配边界。缓存报告由真实生产者和缓存边界生成，测试再从正式消费者确认最终结果。性能结论绑定冻结的输入、代码、配置、机器条件和输出合同，同时报告绝对耗时和命中范围；一次快速样例不能证明代表性工作负载已经优化。
