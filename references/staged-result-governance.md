# 阶段成果治理

用于高成本、需要主观选择或上游决定会显著影响下游的工作。它负责把一次大交付拆成可真实验收、可精确失效的用户结果阶段，避免在方向尚未确认时生产完整结果。任务运行状态与百分比仍由 `task-progress-governance.md` 负责；跨重启事务与物理产物完整性仍由 `durable-operation-governance.md` 负责；本方法不建立第二套任务状态机。

## 1. 进入条件与停止位置

以下任一条件会实质改变返工成本或用户决定时使用本方法：

- 内容、方向、结构、样式、资源或实现路线需要用户判断，且该决定会传播到多个下游产物；
- 完整生产、渲染、生成、迁移、训练、导出或外部调用明显昂贵；
- 用户要求每次出现可展示成果时先验收，或要求一次全自动完成；
- 历史返工表明系统在上游仍不稳定时就过早完成了全部下游；
- 已确认成果、当前执行状态和最终交付之间缺少稳定身份，无法判断一次修改应使哪些结果失效。

普通低成本、确定性、一步完成且没有实质用户选择的工作不增加阶段确认。内部函数、日志、计划文字和“已经做了什么”不能为了形式完整被包装成验收阶段。主路由已经冻结只读、实施或发布权限；本方法只决定何时停下来交付成果，不扩大写入、运行、提交或发布权限。

开始时记录：

```text
用户最终结果与当前停止位置：
高传播决定和它们的正式所有者：
昂贵或不可逆的下游动作：
用户要求的执行模式：逐阶段确认 / 明确授权的连续自动执行
现有成果、确认和执行状态的权威来源：
本方法退出后仍由其它方法负责的状态、事务与发布边界：
```

### 连续高成本工作先说明预计时间

用户已经授权连续自动执行，且完整生产与验证明显昂贵时，在开始第一个昂贵动作前给出预计墙钟时间范围、关键路径、估算依据和主要不确定性。时间范围来自同仓库或同类正式入口的新鲜历史耗时、当前阶段图、环境预检与外部服务事实；不能把各阶段简单相加而忽略并行关系，也不能把模型猜测或一次异常运行写成精确承诺。没有可靠历史证据时，明确说明总耗时仍未知，只报告能够证明的下限、已知等待和最可能改变范围的事实。

这份预告只帮助用户理解成本，不增加确认门槛或建立第二套运行状态。验证阶段的选择、耗时证据和重跑范围由 `ci-execution-governance.md` 负责，长操作的运行身份与恢复由 `durable-operation-governance.md` 负责，进行中的状态更新仍由 `task-progress-governance.md` 负责；本方法只从这些权威结果组装用户可判断的总范围和关键路径。

环境预检、上游身份、工作范围、必需检查或外部等待发生实质变化时，立即更新预计范围并说明原估算中的哪项事实失效。普通波动没有改变这些事实时不反复改口。实际耗时即将超出原范围时，在继续消耗主要成本前报告当前证据、剩余关键路径和新范围；不能等到用户追问后才解释工作为何扩张。

## 2. 先从决定传播关系派生阶段

阶段不是按工具步骤、文件数量或内部团队分工平均切分。先画出会改变用户结果的决定和传播关系，再把每个阶段放在“已经能让用户作出下一项实质决定、但尚未支付其全部下游成本”的位置。

```text
用户输入或内容真源
→ 上游决定
→ 可展示成果
→ 用户确认或连续执行授权
→ 下游生产者
→ 下一份可展示成果
→ 最终消费者与交付
```

每个候选阶段回答：

| 项目 | 必须成立的事实 |
| --- | --- |
| 用户决定 | 用户在这里实际选择、纠正或接受什么 |
| 真实成果 | 哪个正式生产者生成可直接查看、试用或读取的结果 |
| 成果身份 | 输入版本、生产版本、内容摘要或等价稳定身份 |
| 下游成本 | 只有本阶段成立后才值得执行的昂贵动作 |
| 继续条件 | 精确成果获确认，或用户已授权从这里连续自动执行 |
| 失效条件 | 哪些上游事实变化会使本阶段和哪些下游阶段失效 |

阶段数量由独立决定决定，不追求固定模板。大型研究报告可以是“论点与材料边界 → 章节样稿 → 完整草稿 → 发布稿”；界面重建可以是“体验方向 → 关键页面 → 完整流程 → 发布候选”。这些表面不同，但都只在成果已经足以判断下一项高传播决定时停一次。用户只改局部事实时，不把无关阶段重新打开。

## 3. 阶段成果必须是真实可观察结果

阶段验收对象必须来自该阶段正式生产者，并由实际消费者打开、呈现或读取。截图、预览、测试报告或结构化清单可以成为成果，但前提是它们正是用户下一步判断所需要的投影，并保留所代表产物的稳定身份。

下面这些不能独立充当成果：

- 助手写给自己的制作标签、占位说明、内部计划或调试文字；
- 与正式结果无身份关系的另做样稿；
- 消费端手写的假数据、被 mock 掉核心生产链的演示；
- 只说“阶段已完成”但没有可访问产物的状态回复；
- 旧成果的路径仍存在，但内容已经被后续生成覆盖。

为每个活动阶段建立唯一账本：

```text
阶段稳定身份与顺序：
本阶段负责关闭的用户决定：
输入身份与上游确认身份：
正式生产者和生产版本：
真实成果位置、内容身份与正式消费者：
当前状态：未开始 / 生产中 / 等待确认 / 已确认 / 已失效 / 失败
确认来源、时间与准确成果身份：
允许继续的下一阶段：
失效传播范围与原因：
```

聊天回复、任务卡和界面标记只是这份账本的投影。恢复会话或重启后必须重新读取账本与成果身份，不能靠对话记忆猜测用户确认过什么。若项目没有持久阶段状态而工作不会跨重启，可以用本轮结构化执行状态承载；不能把同一事实同时保存在聊天记忆、项目文件和工具内部三处并允许各自更新。

## 4. 确认绑定准确成果，不绑定模糊阶段名

用户确认的是当时实际看见的成果身份，不是“方向”“样片”这类名称本身。确认提交时重新读取成果内容身份；成果已经变化、缺失、正式消费者读到另一版本或确认请求没有稳定身份时，不得把旧确认应用到新结果。

### 复合产物按用户决策单元分别确认

文件、目录、版本、修订或交付包只是物理容器，不自动等于一个用户决定。一个容器包含多个可以被用户分别判断的部位、页面、章节、候选或功能时，为每个决策单元分别记录成果身份、正式消费者、检查证据和确认状态；同一容器可以同时包含已确认、等待确认、已失效和失败的单元。`latest`、`current` 或当前修订只说明活动容器身份，不能把其中一个单元的确认广播给全部内容，也不能抹掉已经成立的局部确认。

等待确认或尚未审查是认识状态，不等于成果失败、未制作、未完成或必须重新生成。准备创建后继版本、重新运行昂贵生产者或把单元标成失效前，先让正式消费者打开准确的现有单元，并运行适用的轻量检查。只有输入或目标合同变化、依赖图已经传播到该单元的真实失效、正式检查发现具体失败，或用户明确要求重做时，才启动对应生产者；仅仅缺少确认不能创建新版本。

用户确认整个复合产物时，确认范围必须指向准确容器身份，并且覆盖范围内每个必需决策单元都已经有可判断成果且状态得到解决；随后才把局部状态聚合为整体确认。仍待审查的单元保留原成果和证据并进入审查，不伪装成已接受，也不因为同容器其它单元已确认而被重做。用户指出某个局部缺陷时，只使该单元及其真实下游失效，其它身份和证据仍成立的单元继续保留。

逐阶段模式下，生产者到达等待确认后停止下游昂贵动作，只允许生成完成当前验收所必需的轻量投影。用户反馈先更新目标合同和当前阶段输入，再重新生成受影响成果；已经明确否定的内容退出活动方案，不作为兼容候选继续影响后续结果。

用户在任务开始或中途明确要求连续自动完成时，记录授权起点、终点和允许自动选择的范围。自动执行仍逐阶段生成成果、记录身份、运行适用检查并推进账本，只是不在每个阶段等待新的用户回复。以下情况会终止自动推进：

- 出现会实质改变结果、成本、风险或不可逆动作的新选择；
- 当前成果不满足阶段合同或正式检查失败；
- 输入、权限、用户结果或正式消费者与授权时相比发生范围变化；
- 需要新增下载、安装、删除、发布、外部写入或其它未获权限。

不能把用户曾经说过“继续”解释为此后所有阶段永久自动，也不能在用户明确授权全自动后又机械要求重复确认同一方案。

## 5. 用依赖图精确传播失效

每个阶段只声明它实际消费的上游事实。上游改变后，从变化事实沿依赖边传播失效：直接消费该事实的阶段失效，它们的下游随之失效；没有依赖关系且成果身份仍成立的阶段继续保留。文件修改时间、阶段顺序靠后或属于同一次项目，不足以触发全量失效。

```text
变化事实：
权威新版本：
直接消费者阶段：
需要重新生产的成果：
仅需重新装配或重新验证的成果：
仍然有效的阶段及其证据：
失效传播已经停止的边界：
```

内容变化可能使方向和全部下游失效；只改最终输出位置通常不应使内容与方向失效；改变正式消费者或输出规格可能保留上游决定，但使集成成果和最终交付失效。具体重算边界交给 `derived-artifact-governance.md`；本方法只决定哪些用户确认需要重新取得。

失效不是删除。旧成果按项目既有归档、版本或清理规则处理；没有删除授权时保留并清楚标为非活动版本，不能为了让阶段账本整洁而移除文件。

## 6. 用最小可判断成果控制成本

阶段成果应当足以暴露当前高传播风险，但不提前完成尚未获准的全部生产。选择成果范围时说明它保护什么决定、仍未覆盖什么：

- 内容或结构阶段使用足以判断完整逻辑的真实代表片段，不用与正式输入无关的占位内容；
- 方向阶段包含会决定整体语言的关键状态和真实内容，不需要穷举全部页面或全部数据；
- 集成阶段让主要生产者、边界和消费者第一次共同成立，优先暴露组合、时序、身份和资源问题；
- 完整预览覆盖全部目标范围，但仍与提交、发布、部署或其它独立权限分开；
- 最终交付消费已经确认且证据新鲜的准确候选，不重新发明方向。

代表成果不能刻意避开已知高风险内容，也不能小到只证明工具能启动。阶段越早，成果越聚焦当前决定；越接近交付，消费者链越完整。

## 7. 真实验收

至少使用两个表面不同的代表性结果验证该方法。一个大型研究报告任务应在论点边界和章节样稿形成真实可读成果后停下，确认准确版本后才生成完整稿；修改一个章节事实时，只使实际依赖它的章节、汇总和发布稿失效。另一个代码生成任务应证明明确全自动授权后可以连续推进，但新出现的部署权限不会被原授权覆盖。

实现阶段系统时还要验证：

1. 正式生产者生成成果，账本记录同一内容身份，正式消费者实际读取该成果。
2. 未确认阶段阻止下游昂贵生产者，而不是只在界面隐藏结果。
3. 用户确认准确成果后，下一阶段能够从该身份继续。
4. 确认后成果被改变时，旧确认失效；相邻无关变化不清空全部阶段。
5. 连续自动模式只在授权范围内推进，并在新增权限或结果变化处停止。
6. 中断或重启后从权威账本恢复，不重跑已确认且证据仍新鲜的阶段，也不跳过失效阶段。
7. 最终交付、提交和发布分别沿自己的正式边界成立，不能借“阶段都确认了”互相替代。

测试不能直接把阶段状态设为已确认，也不能手写一份成果摘要冒充正式生产者。关键断言从真实成果取得稳定身份，再观察下游生产者是否启动以及最终消费者读取了哪个版本。

## 8. 输出合同

```text
进入阶段治理的原因：
最终结果、执行模式与停止位置：
开始前时间预告：预计墙钟范围、关键路径、估算依据与主要不确定性：
阶段图及每阶段关闭的用户决定：
当前真实成果、内容身份与正式消费者：
已确认、等待确认、已失效和未开始阶段：
本轮变化及其精确失效传播：
连续自动授权的范围和停止条件：
预计时间的重估事实、当前范围与剩余关键路径：
下一个允许动作与仍需权限：
真实验收、未覆盖项与证据失效条件：
```

逐阶段模式在交付当前可判断成果后停止，等待用户确认。连续自动模式在授权终点、合同失败、新选择或新增权限边界停止。完成后返回主路由，由它报告实现、验收、提交和发布各自状态。
