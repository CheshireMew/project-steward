# 组件、内容与可访问性规格

用于制定组件、表单、排版、色彩、文案职责和可访问性规格。布局集合、动效、导航生命周期和运行验收由其它 reference 负责。

## 1. 信息结构和最短成功路径

用户应能知道当前位置、主要内容、下一步、操作对象、等待与失败状态，以及如何返回、撤销或继续。

创建、导入、设置、下载或导出流程先区分：不可推导的必要输入、可以可靠推导的值、选填内容和高级设置。只有必要条件缺失、前置检查未完成、存在互斥任务或继续有明确风险时才禁用主操作，并说明原因和恢复方式。

高频同级区域持续可达，低频能力进入次级入口。导航、执行动作、状态显示和状态切换使用与行为一致的名称和外观。

## 2. 用户语言、主要路径与渐进披露

先用“谁对什么做什么、得到什么”命名对象和行动。任务名称说明正在处理什么，等待、进行、完成与失败另外表达；不把“已完成”当作任务标题，也不用一个技术名词同时充当对象、行动和状态。

设备、窗口、文件、进程和其它机器对象进入面向人的选择器前，建立统一的用户显示投影：

```text
稳定机器身份：只负责后续操作和状态关联
用户标题：人能识别的名称
用户详情：只保留有助于区分、选择或判断状态的信息
主项或默认项：决定稳定排序和首次选择
诊断信息：只进入明确的高级或诊断入口
```

存在已确认的本地化名称时，用户标题随当前界面语言从同一显示投影产生；稳定身份、协议键和存储值不翻译，也不因切换语言进入主界面。列表、当前选择、任务、历史、错误和重新打开后的回显都读取同一语言版本；缺少目标语言标题时使用合同允许的产品名或可理解类别回退，不能退回内部 ID、文件名或协议值。

命令面板、统一启动器和行动搜索是正式能力目录的消费者。每项行动使用一个稳定身份执行，显示当前语言的标题与详情；匹配投影由同一规范元数据确定性生成，包含当前语言文案和合同内的稳定语义别名。不能只索引当前翻译，也不能让每种语言、每个入口各自维护同义词表，或者用显示文字充当执行身份。内部协议 ID 不因参与关联而自动成为可见标签。验收至少在一种非默认语言中，分别用本地化词和稳定语义别名找到同一行动，确认结果显示当前语言、遵守当前上下文可用性，并由同一稳定身份执行正确结果。

硬件路径、驱动名称、内部句柄、协议键和转义前缀不能因为“没有更好名称”就直接成为主标题。确实取不到友好名称时使用稳定、可理解的类别回退，并把原始标识留给诊断。列表、当前选择摘要、默认选择、重新打开后的回显和后续操作都消费同一个投影，不能在每个界面分别清洗字符串或自行排序。

内部准备、缓存、索引、解析和转换能由系统可靠完成时，默认随用户主任务启动，并在其会影响等待、流畅度或可用性时显示进度与恢复。只有当选择会改变输出、成本、风险或不可逆结果时，才让用户在主路径手动决定这些机制。

任务状态按用户仍需做什么决定是否占据主界面：进行中且影响使用时显示必要进度；完成后结果已经可用且没有下一步时退出主要工作区；需要确认结果、查看历史或继续行动时压缩到对应结果或历史入口；失败状态保留原因和恢复行动。后台技术步骤不能在完成后继续以大卡片占用高价值空间。

主要路径优先使用目标平台上用户已熟悉的直接操作。按钮、双击、右键菜单、快捷键和批量入口可以作为补充，但不得用一个只能猜含义的图标或不可发现的快捷键取代主行动。纯图标控件提供当前语境中可见的悬停或聚焦说明和等价的可访问名称。

可重复行动必须有可预期语义。再次触发时，按合同新建结果、更新当前结果，或在不允许重复时立即说明原因和恢复方式；禁止按钮仍可点击但结果没有任何变化和反馈。

默认值能可靠完成任务时，技术参数、低频设置和专家控制进入次级入口。基础层只保留会改变当前用户结果的选择；高级层首次出现的术语也要说明它控制什么和变大或变小的结果。

## 3. 控件拓扑和动作层级

选择控件前先确定用户面对的是一个行动、一个布尔状态、一组互斥状态、一个稳定顺序中的循环状态，还是一组需要展开后选择的命令。状态数量不直接决定可见控件数量；界面合同要求一个控件时，它始终是一个命中目标，由内部状态变化更新表现，不能按状态数展开成多个控件。

并列选项适合需要直接比较和随机跳转的少量状态；菜单适合低频、选项较多或需要标签解释的选择；循环控件只用于顺序稳定、切换代价低且用户明确预期逐次切换的模式。纯图标状态控件的各状态使用轮廓和结构可区分的图形，并一致表达“当前状态”或“将执行的动作”之一；悬停、焦点说明和可访问名称同时说明状态与操作结果。

重复条目只让高频、需要持续发现的主要行动长期可见。桌面端已有选择、拖放或双击主路径时，低频且明确作用于当前对象的命令可以进入右键菜单；仍需提供符合任务和平台的可发现入口或替代输入。把行动移动到次级入口时保留同一业务结果、禁用原因、反馈和恢复，不把隐藏控件误当成功能迁移。

## 4. 文案和内容职责

每段文字标记为身份、解释、状态、当前选择、操作提示或行动入口。没有职责的文案不因版面空缺而保留；优先把真实状态、选择或行动移动到用户需要的位置。

纯图标、分隔线、状态点、装饰框和永久空白也使用同样的职责判断。无法说明它帮助用户识别什么、理解什么、操作什么、确认什么或拖动什么时，应退出界面或并入已有结构，不能靠“以后可能有用”占据高价值空间。

只要求列出、比较或审核文案时不先改写。要求先重写供审核时并列原文与候选稿，确认前不写入产品。精确替换文字时，文字、标点、大小写和有意义的换行共同构成真源。

内容主题、角色设定、行业类别、沉浸式视觉和已有修辞不能自动决定文案语气。语气以用户提供的样稿、当前明确纠正和项目已确认的内容规范为准；没有这些证据时，候选稿保持中性、具体并明确标为候选，不能把诗化、拟人、宣传腔或模型惯用表达当作默认风格。

同一对象在不同页面使用同一名词和动词。错误信息说明发生了什么、影响什么、用户如何恢复；空状态说明这里会出现什么、为什么有价值和怎样开始，不用宣传语代替操作信息。

## 5. 排版、色彩和表面

排版先建立页面标题、区域标题、正文、辅助信息、标签和数据的稳定层级。相邻层级通过字号、字重、颜色和空间中的至少两个关系形成差异。

用户指出文字过小时，在实际视口、显示缩放和系统字体设置下读取最终字号、行高、字重、对比、裁切和点击区域，再按内容职责判断。源码搜索只能定位候选，不能证明真实可读性。

动态变化的计数、计时、价格、分数或表格数字如果因字宽不同产生跳动，使用当前字体系统提供的等宽数字能力，并在真实字体与极值数据下核对对齐和字形；静态、装饰或不需要列对齐的数字不为清单统一改变。标题需要稳定短行时可以采用均衡换行，短到中等正文需要避免孤行时可以采用更自然的换行策略，但先核对当前浏览器或平台支持、实际行数、语言和布局成本；长文、代码和预格式内容不套用同一规则。字体渲染细节不能替换项目已经选择的字体家族，也不能把某个平台的平滑方式写成所有项目的全局默认。

图标是独立的视觉组件家族，不是按钮尺寸的填充物。高频工具栏或多处共用的图标先建立家族合同：

```text
对象与行动语义：
共享图标真源与活动消费者：
名义图形尺寸与光学边界：
独立的按钮命中范围：
轮廓或填充语法，线宽、端点、转角与细节预算：
关键缺口、负空间与相邻文字关系：
默认、悬停、焦点、按下、选中、禁用和危险状态：
目标视口、系统缩放与实际显示尺度：
```

可命中范围服务指针、触摸和焦点进入；可见图形服务识别、层级和光学平衡。需要扩大命中时扩大按钮边界，不按同一比例放大图形和线宽。危险操作根据当前风险和注意职责决定默认时是否持续强调；安静的编辑工具栏不因为某动作可删除就必然长期显示高重量危险底板，但语义、焦点、悬停、按下与可访问名称必须让风险清楚。

用户说图标“大、粗、重、旧或不成体系”时，分别检查实际显示尺度下的光学占比、线宽、轮廓几何、负空间、轮廓与填充关系、按钮底板和相邻内容，不自动重做整个布局或调色板。同一家族失效时修改共享图标与状态来源，迁移全部消费者，不让页面或按钮各自维护局部尺寸、线宽和危险底板。

图标与文字或容器几何居中但视觉重量仍偏移时，按实际显示尺度调整图形的光学边界、路径、视框或内容组；共享图标自身能够修正时不让每个消费者各自追加边距。默认、悬停、选中和禁用只改变颜色或透明度时，由同一个语义图标和组件状态来源产生；Web 中的 `currentColor` 可以是实现方式，但不是跨平台规范。轮廓与填充确实承担不同状态语义时可以保留不同图形关系，不能为了“只用一个文件”抹掉可辨状态。

支持从右到左界面时按语义而不是整套图标机械镜像：返回、前进、缩进和阅读方向相关图形随方向改变，品牌标志、勾选、时钟和与阅读方向无关的对象保持原样；复合图标分别判断基础图形和覆盖层。方向变化后的图标、文字顺序、命中范围和可访问名称仍共同表达同一个行动。

颜色先定义背景与表面、主要与次要文字、图标、边界、焦点、选择、主要操作、状态与风险、稀缺强调。颜色角色不是彼此独立的色值：每个实际可达状态都要把最终表面、文字或图标、边界、焦点与选择反馈作为一个组合确定。悬停、按下、选中或禁用改变其中一项时，重新检查整组关系；强调色不因局部醒目就扩散成整页主色。

菜单、下拉列表、组合框弹出层、自动补全、提示、气泡、对话框、日期选择器和通知等临时表面，使用项目实际存在的组件组成同一表面家族。它们分别记录内容表面、行或选项状态、分隔和边界、文字或图标、焦点与选择反馈，并在当前主题或系统外观下读取同一语义来源。透明、图片、模糊或系统材料参与合成时，以最终画面中的实际背景为准。

项目或用户指定对比标准时按其当前版本核验；能够取得最终实色时计算实际前景与合成背景，存在透明、图片或系统材料时同时检查目标画面。默认、悬停、焦点、按下、选中、禁用和只读都以内容可辨、状态可区分的最终组合通过。

圆角、描边、阴影、玻璃、渐变和纹理只有承担分组、层级、识别或状态时才使用。相近的嵌套圆角表面需要保持同心关系，外层圆角由内层圆角和两层之间的实际间距共同决定；间距已经让两层成为独立表面时分别按各自职责选择，不强套同一算式。阴影优先表达高度和环境中的浮起，描边优先表达结构分隔、焦点、选择和输入边界；透明图片描边或其它边缘处理只有在最终合成中确实帮助分离内容时才使用，其颜色和强度来自活动设计系统与实际背景。一个手段已经清楚时，不叠加多个效果表达同一关系。

## 6. 组件和状态

关键组件至少定义：

- 必选与可选内容结构；
- 尺寸由内容、容器还是平台决定；
- 主要与次要操作；
- 默认、悬停、焦点、按下、选中、禁用和只读；
- 加载、空、错误、成功和缺失内容；
- 长文本、语言变化、极值数据和系统缩放；
- 指针、触摸和键盘行为。

控件同时有外部布局矩形、内部内容矩形和真实命中矩形。文字与图标先组成一个内容组，再由内边距和最小命中范围决定按钮、下拉框或字段的最终尺寸；内容组在可用区域内按同一对齐合同定位。固定宽高必须在目标字体、目标语言长文案、系统文字缩放和显示缩放下仍不裁切或越过边界。不能用负偏移、未经验证的固定坐标或只对齐布局属性来掩盖内容尺寸错误；同行控件还要核对用户实际看见的顶边、底边、标签区、基线和圆角外轮廓。

命中范围的最低要求由当前平台、输入方式和采用的现行标准决定，不把记忆中的固定像素当成跨项目默认。扩大后的相邻命中矩形不得重叠；空间不足时先重排或增加间距，再在仍可操作的前提下收缩扩展范围，不能让同一次输入可能命中两个控件。

主题或状态会改变可见组合时，使用下面的最小状态合同；只列当前产品实际可达的状态，不为清单制造不存在的分支：

| 组件家族与状态触发 | 最终表面 | 文字或图标 | 边界、焦点与选择反馈 | 唯一真源 | 真实到达与检查方式 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

相同职责复用同一组件、状态语义和行动目标。悬停可以是临时预览，但不能成为触摸端唯一入口；点击或键盘锁定后的结果不被稍后的悬停覆盖。

视觉上像按钮、链接、卡片或关闭区的对象，真实命中范围要符合用户理解。弹层面板、面板空白和遮罩分别消费自己的区域；遮罩显示时底层不响应，关闭后焦点回到合理位置。

选择器中的每个选项使用稳定对象身份和统一显示投影，当前值、列表行、重新打开后的回显和后续操作读取同一个身份，不用列表位置或显示文字充当主键。预设与已保存实例指向同一资源时合并成一个可编辑对象；确实是不同对象时用用户能理解的名称、来源或状态区分，不能显示两个无法辨认的同名项。下拉、菜单和组合框的验收必须实际展开目标弹层，确认模型中的每个应有选项都形成可见、可读、可命中且不被裁切的行；模型长度、当前值存在或委托已经创建不能代替最终选项可见。

向已接受的卡片、面板或弹层增加链接、关闭入口或其它功能前，分别记录：

| 可见标签 | 用于说明类别或用途的上下文 | 真实目标或动作 | 指定位置与命中范围 | 执行、关闭后的状态与焦点 | 是否获准改变容器尺寸或视觉 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

用户用来说明对象类别、用途或来源的措辞不自动成为界面标签；只有明确指定为显示文字的内容才进入可见文案。功能新增只接入内容和行为，不自动改变已接受容器的配色、宽度、层级、装饰和其它标签。

## 7. 表单

字段有可见标签、必要说明、输入格式、验证时机、错误位置、恢复方式和提交结果。占位符不替代标签。即时保存与统一提交不能在同一视觉组中混用而不说明。

值需要记忆时写清归属范围、写入时机、恢复时机、冲突规则和清除方式。提交方式按用户后果选择：本地、可逆、彼此独立的开关、模式和单项选择在改变后直接保存；连续文本输入使用有界防抖，并在失去焦点、关闭面板或退出应用前强制提交尚未落盘的最终值。只有多字段必须作为一个事务验证、提交会产生远程或高代价动作，或者用户确实需要先组合修改再确认时，才使用统一“保存 / 应用”。同一组不能一部分自动提交、另一部分依赖保存而没有清楚边界。

自动保存需要可观察的失败状态：写入失败时保留用户输入、说明尚未保存并提供恢复；正常写入结果已经从控件和再次打开后的状态自然可见时，不重复弹出成功提示。验收从正式输入事件经过持久化真源到当前控件回显，再关闭并重新打开由同一消费者读取；只检查内存属性、保存函数返回或文件里出现字段不能证明设置已经记忆。

密钥、令牌和其它需要隐藏原文的字段分开维护持久原值、编辑缓冲和显示投影。已经保存的值在非编辑状态显示足以说明“这里已有值”的掩码或等价状态，不能显示成空白；进入编辑时按产品合同替换、保留或清除，未输入新值则继续使用原值。掩码只用于呈现，不能回写成凭据；原值也不能为了回显方便散落到列表模型、日志或界面文案。保存位置、同步范围或只在本机存在等会影响用户决定的事实，用直白文案说明。

敏感或高代价操作优先提供可撤销结果；无法撤销且后果重大时才使用确认步骤。

## 8. 可访问性

- 主要任务可通过平台支持的替代输入完成；
- 焦点顺序跟随视觉和任务顺序，焦点状态在所有表面可见；
- 触摸目标、文字、对比和间距适合真实环境；
- 图片、图表和状态提供等价信息；
- 放大文字、系统缩放、窄窗口和高对比不隐藏主要内容；
- 减少动态效果保留因果、内容顺序和主要操作。

需要当前合规数值时，核实用户指定的标准和版本；未核实前只写设计建议，不把记忆中的数值描述成现行规范。

## 9. 交付规格

只输出当前界面需要的组件结构、状态、文案、颜色角色、排版关系、替代输入和可观察结果。不要机械附上完整清单；没有进入当前任务的组件和状态不扩张为额外交付。
