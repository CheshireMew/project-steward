# 任务型产品的综合体验审查

用于系统审查一个已经存在的任务型产品，覆盖跨页面、跨状态、完整旅程或熟悉产品对标。上层主路径应当已经提供用户、证据、旅程和任务模型；本文负责建立审查覆盖、根因、优先级和目标状态，不负责具体组件规格或实际运行验收。

## 1. 先从核心任务建立覆盖

综合审查不等于把导航栏从左到右评论一遍。先列出用户来到产品后最需要完成的少量任务，再从每个任务反推必须查看的表面和状态：

```text
核心任务与用户结果：
开始任务的触发与预期：
自然入口与第一步：
主工作区与持续可见状态：
次级页面、弹层和设置：
空、加载、成功、失败、缺失和离线状态：
首次使用、重复使用与恢复路径：
跨会话、通知、文件或外部交付：
指针、触摸、键盘或其它主要输入：
宽度、高度、系统缩放或内容变化的关键边界：
已有用户证据、产品事实与待验证假设：
必须保留和已授权改变的关系：
```

只纳入与核心任务有生产、消费或恢复关系的对象。用户列出的问题是定位同类缺口的入口，除非用户明确说只检查这些对象，不把例子误当完整覆盖。

静态截图能证明当前视觉关系，不能单独证明用户怎样进入、理解、完成和恢复。用户提供访谈、反馈、分析数据、支持记录或实际操作时，把它们与界面证据连接；缺少用户证据时明确这是专家走查，不声称代表真实用户研究。

## 2. 分开用户结果和内部机制

对每个用户可见对象回答：

```text
用户正在操作什么对象：
用户想得到什么结果：
用户必须做出哪个会改变结果的决定：
哪些步骤可以由系统可靠推导或在后台完成：
用户何时得知处理中、完成、失败和恢复方式：
```

只有当选择会实质改变输出、时间、成本、风险或不可逆结果时，才把内部机制升格为主要用户操作。能安全自动完成的准备、缓存、索引、解析或转换，使用用户结果语言表现为进度与状态，不要求用户先理解实现术语再开始任务。

高级选项在默认值能产生可靠结果时进入次级层；不得把技术参数包装成“推荐设置”后留在最短成功路径。

## 3. 按用户行动检查界面

对每个核心任务按同一顺序判断：

1. **发现**：用户能否在需要时找到主要对象和行动，名称是否说明“对谁做什么、得到什么”。
2. **开始**：平台上用户已熟悉的直接操作能否完成主路径；次级按钮、菜单和快捷键可以补充，不能迫使所有人绕过熟悉方式。
3. **进行**：当前操作对象、选中、范围、进度和不可用原因是否持续可见。
4. **结果**：行动后是否产生可见变化，任务名称与成功、失败状态是否分开表达，用户是否知道结果在哪里以及下一步是什么。
5. **重复**：同一有效行动再次执行时，应按产品合同产生新结果、更新现有结果，或明确说明不能重复的原因；禁止无反馈的空操作。
6. **纠错与恢复**：删除、取消、撤销、重试、重新定位、返回和重开后的结果与后果是否清楚。
7. **效率与替代输入**：高频操作可以有快捷键、批量和可记忆设置，但主功能必须可发现，文本输入时快捷键不得意外触发界面操作。
8. **跨时刻与信任**：离开再返回、跨会话等待、权限变化或外部交付时，对象身份、进度、后果和控制权是否仍然清楚。

## 4. 对标只提供熟悉关系

用户明确要求对标，或者成熟产品模式、平台惯例或版本相关行为会实质改变审查结论时，可以联网研究少量当前参考。会受版本影响的行为优先使用当前官方帮助、规范或产品文档；用户提供的当前截图、录屏和操作经历可以证明其熟悉模型。

每条借鉴关系必须回答：用户为什么已熟悉、它降低了哪个当前任务的理解或操作成本、会牺牲什么、是应用完整模式还是只保留平台惯例。不为“像某产品”复制品牌外观、专有内容、页面数量或与当前任务无关的功能。

## 5. 按根因和影响收口

先找最早失效关系：页面职责、对象与任务模型、名称和操作语义、共享组件、状态投影、布局规则、视觉表现或运行时消费。同一根因影响多个表面时，形成一个真源修法与全部消费者迁移，不把症状分成多个局部美化项。

按用户影响排序：

1. 核心任务不能开始、完成、确认结果或恢复；
2. 对象、行动、状态或后果容易被误解；
3. 熟悉任务被迫增加无职责的步骤，或高频操作缺少合理路径；
4. 局部不一致、层级、文案、对齐和视觉精度问题。

每个需要处理的根因输出：

```text
受影响的核心任务：
用户现在遇到的可见问题：
最早失效关系与真源：
目标状态：
所有受影响消费者：
用户可观察的通过结果：
证据缺口与停止条件：
```

## 6. 进入实施与验收

只读审查在形成根因、目标状态、优先级和证据缺口后停止。用户明确要求实施时，返回上层主路径，由其按已授权范围修改唯一真源并迁移全部活动消费者。

最终结论必须经过正式生产者、真实边界、活动消费者和用户可见结果的完整链路验收。至少检查自然入口、正式内容与状态、重复行动、主要输入、用户承诺的关键视口与受影响的最终消费者。之后的任何可见修改使受影响证据失效，必须重新检查对应链路。
