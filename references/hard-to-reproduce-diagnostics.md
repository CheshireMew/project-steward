# 高成本、难复现问题的证据诊断

本方法供改动前预防和根因治理共同使用。主路由已经选定任务路径、动作权限、停止位置、进入原因和适用的特殊维度；本方法只负责把这些条件转换成观测、实验、判断和最终验证，不重新选择任务类型。

## 1. 进入条件和输入

以下任一条件会实质改变诊断成本或证据质量时使用本方法：

- 只有昂贵、耗时或依赖外部系统的完整链路才容易看到问题；
- 失败间歇出现，或需要累计、负载、特定顺序、生命周期阶段才出现；
- 生产者、传输或存储、消费者之间缺少足以区分原因的状态；
- 同一表面结果同时存在多个合理解释，现有测试只能证明“仍然失败”；
- 测试驱动、轮询、等待方式、夹具或观测动作可能改变被测行为。

开始时从主路由接收：

```text
所处阶段：改动前预防 / 只读诊断 / 已授权修复
用户要得到的结果和停止位置：
一次代表性真实失败，或改动前明确的风险信号：
正式生产者 → 传输或存储边界 → 正式消费者 → 用户结果：
进入本方法的原因：
本次适用的特殊维度：
已有证据、未知项和动作权限：
```

能够廉价、稳定复现，并能直接证明最早错误边界的普通确定性问题不需要这项加重方法。若收到的事实不满足进入条件，只返回“无需加重诊断”的观察并在本方法停止，不自行改选其它路线。

## 2. 共同路径：先让一次实验能够排除解释

### 2.1 冻结结果与第一份证据

已有失败时，先保留一次代表性真实失败，记录它经过的真实入口、关键边界、最终表现和当时仍未知的状态。改动前尚无失败时，先定义什么可观察信号会证明风险发生，以及哪个最早边界应产生这个信号。

从取得这份证据开始，不再为了“看看还会不会失败”盲目重复昂贵链路。每一次后续运行都必须回答一个预先写明的问题、区分至少两个仍成立的解释，或承担最终确认；不能满足其中任何一项就不运行。

### 2.2 建立竞争解释

列出相互竞争的解释，不先把第一个合理猜测当成根因。解释应指向会产生不同观测结果的机制，而不是把表面症状换一种说法。为每个解释写出可区分信号：

```text
解释：
如果成立，唯一或明显更可能出现的信号：
如果不成立，应看到什么：
最便宜的区分实验：
需要临时增加或改变什么：
实验后恢复什么：
什么结果足以保留、排除或拆分这个解释：
```

如果两个解释在当前实验中会产生相同结果，这个实验不能区分它们，不应消耗一次昂贵运行。新证据可以拆分、合并或淘汰解释，但每次改变都说明由哪项观测触发。

### 2.3 在最早相关边界补足观测

沿真实生产者、传输或存储、消费者和用户结果检查，找到最早一个“输入仍符合预期、输出已经偏离”的候选边界。在该边界记录能够直接区分竞争解释的输入、输出、状态变化和所有权，不追求把所有内部状态都打印出来。

平均值、最终计数和“文件存在”常常会抹掉真正异常。观测应保留异常发生前后的短窗口、状态转移和因果上下文，例如等待原因、队列变化、当前代次、重试来源、数据身份或验证器动作。观测本身的开销也要记录；可能改变结果时，将其列为竞争解释之一。

临时日志、探针、开关和实验配置只服务当前判断。建立时同时登记恢复条件；除非证据证明它们是未来正式可观测合同的一部分，否则在最终实现冻结前退出。

### 2.4 先做最便宜的区分实验

按能够保留核心因果关系的最低成本选择实验：

1. 把纯状态转换或调度规则提成可确定运行的模型，用边界值和状态序列直接检查机制。
2. 用短小受控重现、加速输入或故障注入，让原本需要累计或偶发的条件尽快出现。
3. 在真实生产者和核心边界上做局部运行，让同一份真实产物交给下一消费者。
4. 只有前面证据无法替代最终链时，才运行完整端到端、长时间或外部系统验证。

短实验可以隔离无关部分，但不能 mock 掉正在判断的核心边界，也不能由消费端手写一份结果冒充生产者输出。一次只改变用于区分当前解释的产品变量、环境变量或验证变量，避免几个改动同时发生后无法归因。

### 2.5 把产品、运行环境和验证器分开

分别判断：产品机制是否错误，实际运行环境或外部进程是否与假设一致，验证器或测试驱动是否改变了时序、输入、对象身份或最终断言。三者使用各自证据，不能用某一层通过替代另一层成立。

验证器失败或明显扰动产品时，先修正验证边界，再用相同产品条件重新取得证据；不能修改产品去迎合错误夹具、轮询方式或断言。环境层要锁定实际执行文件、版本、实例、阶段和产物消费者，不能把外层等待结束直接当成产品失败。

### 2.6 收敛后再做昂贵确认

当短实验已经留下一个能解释全部关键证据的机制，并且修复或预防合同已经对应到最早错误边界时，先冻结产品代码、配置和验证器。随后列出最终验证的唯一目的、通过信号、失败时要保留的边界证据和停止条件。

昂贵的完整链路只用于最终确认：证明正式生产者、真实边界、正式消费者和用户结果在目标条件下共同成立。它不能替代机制证明；一次通过也不能抹掉尚未解释的反例。最终确认失败时先读取已布置的区分证据，更新竞争解释，再回到最便宜的有效实验，不直接开始另一轮相同的昂贵运行。

## 3. 特殊维度可以同时叠加

共同路径始终负责“竞争解释 → 可区分信号 → 最便宜实验 → 最终确认”。下面的维度只在主路由已经判定会改变观测、实验或验收时叠加；同一个问题可以同时选择多个维度。

### 时间与累计

- 列出参与决定的时钟、截止点、每轮增量、重置条件，以及会累计的超前量、滞后量或预算。
- 输入事件、消息或事务已经携带发生时间或序列时，决定手势、会话、空闲或批次边界的真源是生产者记录的发生顺序，不是消费者终于获得执行机会的墙钟。主线程、队列或传输停顿不能把早已发生的连续输入切成另一组；验证驱动必须保留这些时间与序列，不能用事件送达后的固定睡眠重新发明发生顺序。
- 同时记录期望状态和实际状态的变化，检查一次追赶或补偿是否给后续周期留下了不应存在的余额。
- 平均耗时不能代替异常窗口；保留间隔、突变点和突变前后的内部状态。
- 优先用可控时钟、确定性状态模型或加速输入复现；真实长时间只验证累计机制在最终链中没有再次出现。

### 并发、所有权与顺序

- 明确谁创建、拥有、取消、等待和销毁任务、线程、进程、订阅者与队列，以及状态属于哪个代次。
- 记录事件的产生顺序、交接顺序、消费顺序和关闭顺序，区分“尚未产生”“已产生未消费”“已消费未收尾”。
- 用受控屏障、固定顺序或短故障注入验证竞争解释；正常运行、取消、失败、排空和重启分别验收。

### 确定性派生产物的单一生产者

当多个线程或进程可能为同一稳定键生产同一个内容寻址缓存、代理、索引、分析结果或其它确定性派生产物时，正确性不仅是最终文件没有冲突，还包括同一结果身份在一次缺失或失效窗口内只有一个正式生产者。先冻结稳定结果键、结果格式版本和生产者身份；随后按以下顺序建立跨线程、跨进程的租约或锁：

```text
无锁快速检查现有结果
→ 取得覆盖整个生产过程的同键租约
→ 在租约内重新检查结果与版本
→ 唯一生产者生成、校验并原子发布
→ 等待者读取同一已发布结果
→ 释放租约
```

不能只在最终重命名时加锁，也不能靠原子重命名失败后重试掩盖多个昂贵生产者已经同时运行。相同稳定键必须合并为一个生产过程，不同键保持并行；损坏、不完整、格式过期或生产者身份不匹配的结果在同一租约内失效并重建。生产失败时不得发布部分结果，等待者只能依据明确失败或重新竞争合同继续，不能消费临时文件。验收用受控屏障同时启动同键请求，证明实际生产调用恰好一次且所有消费者取得同一身份；再用不同键证明没有被全局锁无谓串行化，并用损坏或旧版本结果证明只触发一次重建。

### 吞吐、背压与资源

- 同时测量生产速率、消费速率、队列或缓冲占用、阻塞发生在哪一侧，以及解除压力后能否恢复。
- 资源问题记录内存、句柄、连接、文件或工作项随操作次数和时间的变化，不只比较开始与结束两个点。
- 用缩小容量、提高输入速率或限制消费者等短实验放大机制；确认修复时恢复真实容量和负载。

### 受验证的高速路径与原子回退

并行 worker、GPU 或浏览器快速后端、向量化实现、缓存捷径和其它替代生产者只有在它们承诺与标准路径交付同一结果时进入这一维度。先冻结标准路径、输出合同和会触发不同实现分支的工作负载矩阵；矩阵只保留会改变内容复杂度、持久状态、媒体种类、执行单元或后端选择的真实维度。正确性要求应当是精确相等，或者由用户结果和消费者合同证明合理的差异阈值，不能在看到结果后临时放宽。

- 每个真正参与生产的 worker、进程、浏览器、GPU、设备或后端分别取得资格，不能由第一个实例代替其余实例通过。静态能力检查只能筛选候选，最终资格要由它将代表性真实输入送到同一消费者的结果证明。
- 能力验证使用与正式生产相同的代码边界，但验证状态、页面、会话、缓存或输出目录不能泄漏进正式运行；验证完成后从新鲜生产状态开始，避免预热、游标、时间或缓存让正式结果依赖验证副作用。
- 在“资格验证已经通过”之后注入一次运行期故障，证明中途失效会标记整个尝试不可发布。任何执行单元丢帧、异常、产生不合格结果或失去资格时，废弃本次高速路径的全部临时结果，从新鲜状态完整运行标准路径；不能保留前半段高速结果再接后半段标准结果。
- 输出或缓存只有在生产者完成、数量和顺序成立、语义探测通过、内容身份与本次输入一致后才原子发布。文件存在或非空不能代表成功；损坏、不完整或属于另一版本的产物必须被正式消费者拒绝并重建。
- 最终性能结论绑定冻结后的产品代码、配置、验证器、工作负载和机器条件，同时报告正确性结果、绝对耗时和同机相对变化。只在快速路径真的被选中且正式消费者读取了最终产物后，才能把速度记为该路径的收益。

### 环境与外部进程

- 锁定实际执行文件、版本、参数、进程实例、当前阶段、日志增长、产物变化和正式消费者。
- 区分命令执行器停止等待、工具自身失败、应用退出和原进程继续运行；原任务仍有进展时不启动争用同一资源的重复任务。
- 环境差异只有在同一产品输入下产生可区分结果时才保留为根因证据。

### 数据、缓存与版本沿袭

- 为输入、派生产物、缓存条目和消费者实际读取内容记录稳定身份、版本或内容摘要，以及写入、失效和读取顺序。
- 本应相互独立的部署目标、基础路径、浏览器场景、会话或数据版本使用新鲜进程、上下文、缓存和输出位置，或者执行有证据的完整重置。顺序复用同一环境时，必须把前一场景留下的缓存、游标、页面状态和后台任务列为竞争解释，不能把后一场景的结果单独归因于当前输入。
- 检查修复是否更新了唯一真源，却仍由旧缓存、旧生成物、错误路径或另一个实例提供结果。
- 用同一份生产者真实输出贯穿边界，分别验证冷启动、更新、失效、重开和迁移后的消费者结果。
- 大型内容在导入、复制、提交或发布后成为不可变对象时，可在这个状态转换中完成一次完整读取、内容校验和写入复核，并持久化同时绑定内容身份、版本、物理对象和成功状态的回执。后续消费者只在不可变约束和回执仍成立时复用该证明；内容仍可原地改变、回执缺少任一身份、发布未原子完成或消费者需要主动审计时，必须重新读取正式内容。把完整审计从每次消费中移出不等于取消完整性验证，而是把昂贵验证放到唯一能建立不可变事实的边界。

### 验证器与测试驱动干扰

- 检查事件循环、等待、轮询、睡眠、超时、输入夹具、对象引用和观测开销是否改变被测条件。
- 固定睡眠只能作为有界等待的上限，正常完成条件必须来自正式消费者可观察的状态变化。达到上限时保留生产者、边界和消费者的实际状态并判定超时，不能把“睡够了”当成结果已经产生。
- 请求次数、资源计时、回调次数、文件存在或瞬时元素出现，只有在正式所有者保证它与目标结果稳定一一对应时才能成为关键断言。自动生产者、缓存、分片请求、重试或观察器会改变信号时，替换为正式状态或最终结果；不能靠放宽阈值保留没有合同依据的指标。
- 对比等价产品条件下有无验证驱动时的边界状态；验证器必须证明自己确实启动、取得新鲜对象并读取真实结果。
- 如果干扰来自验证器，修复验证器并保留能防止同类失真的结构合同；不能把验证器制造的行为写进产品。

## 4. 输出与停止

```text
进入本方法的原因：
共同路径取得的第一份真实证据：
竞争解释及其保留或排除证据：
最早偏离边界：
本次叠加的特殊维度，以及每个维度改变了什么动作：
临时实验与退出情况：
产品、环境和验证器各自的结论：
高速路径资格、整次废弃与标准路径回退结果：
不可变内容回执及重新读取条件：
最终机制或仍未知的分歧：
修复或预防合同：
昂贵完整链的目的、结果和未验证项：
```

改动前预防在形成可执行的观测与验证合同后返回主流程。只读诊断在根因证据、影响范围和最终修法已经足够时停止，不写项目。已授权修复把证明成立的机制交回根因治理完成唯一边界、全部调用点、旧路径退出和真实用户链；本方法不自行扩大写入范围。
