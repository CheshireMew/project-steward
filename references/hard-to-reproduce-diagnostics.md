# 高成本、难复现问题的证据诊断

本方法供改动前预防和根因治理共同使用。主路由已经选定任务路径、动作权限、停止位置、进入原因和适用的特殊维度；本方法只负责把这些条件转换成观测、实验、判断和最终验证，不重新选择任务类型。

## 1. 进入条件和输入

以下任一条件会实质改变诊断成本或证据质量时使用本方法：

- 只有昂贵、耗时或依赖外部系统的完整链路才容易看到问题；
- 失败间歇出现，或需要累计、负载、特定顺序、生命周期阶段才出现；
- 生产者、传输或存储、消费者之间缺少足以区分原因的状态；
- 同一表面结果同时存在多个合理解释，现有测试只能证明“仍然失败”；
- 测试驱动、轮询、等待方式、夹具或观测动作可能改变被测行为。

开始时从主路由接收：

```text
所处阶段：改动前预防 / 只读诊断 / 已授权修复
用户要得到的结果和停止位置：
一次代表性真实失败，或改动前明确的风险信号：
正式生产者 → 传输或存储边界 → 正式消费者 → 用户结果：
进入本方法的原因：
本次适用的特殊维度：
已有证据、未知项和动作权限：
```

能够廉价、稳定复现，并能直接证明最早错误边界的普通确定性问题不需要这项加重方法。若收到的事实不满足进入条件，只返回“无需加重诊断”的观察并在本方法停止，不自行改选其它路线。

## 2. 共同路径：先让一次实验能够排除解释

### 2.1 冻结结果与第一份证据

已有失败时，先保留一次代表性真实失败，记录它经过的真实入口、关键边界、最终表现和当时仍未知的状态。改动前尚无失败时，先定义什么可观察信号会证明风险发生，以及哪个最早边界应产生这个信号。

从取得这份证据开始，不再为了“看看还会不会失败”盲目重复昂贵链路。每一次后续运行都必须回答一个预先写明的问题、区分至少两个仍成立的解释，或承担最终确认；不能满足其中任何一项就不运行。

### 2.2 建立竞争解释

列出相互竞争的解释，不先把第一个合理猜测当成根因。解释应指向会产生不同观测结果的机制，而不是把表面症状换一种说法。为每个解释写出可区分信号：

```text
解释：
如果成立，唯一或明显更可能出现的信号：
如果不成立，应看到什么：
最便宜的区分实验：
需要临时增加或改变什么：
实验后恢复什么：
什么结果足以保留、排除或拆分这个解释：
```

如果两个解释在当前实验中会产生相同结果，这个实验不能区分它们，不应消耗一次昂贵运行。新证据可以拆分、合并或淘汰解释，但每次改变都说明由哪项观测触发。

### 2.3 在最早相关边界补足观测

沿真实生产者、传输或存储、消费者和用户结果检查，找到最早一个“输入仍符合预期、输出已经偏离”的候选边界。在该边界记录能够直接区分竞争解释的输入、输出、状态变化和所有权，不追求把所有内部状态都打印出来。

平均值、最终计数和“文件存在”常常会抹掉真正异常。观测应保留异常发生前后的短窗口、状态转移和因果上下文，例如等待原因、队列变化、当前代次、重试来源、数据身份或验证器动作。观测本身的开销也要记录；可能改变结果时，将其列为竞争解释之一。

临时日志、探针、开关和实验配置只服务当前判断。建立时同时登记恢复条件；除非证据证明它们是未来正式可观测合同的一部分，否则在最终实现冻结前退出。

### 2.4 先证明多次观测针对同一个对象

把两个以上探测结果组合成“同一个对象前后矛盾、消失或变化”之前，先建立对象对照：

```text
声称正在观察的对象：
对象标识的权威发现来源：
每次探测实际收到的字面标识、工作目录或命名空间：
各次解析后的稳定对象身份：
这些探测是否确实针对同一个对象：
结果差异来自对象不同、探测失败、条件不可比、真实状态变化还是未知：
当前证据允许作出的结论：
```

对象标识一旦由目录枚举、进程表、API 响应、包解析器、任务系统或其它权威生产者发现，就直接把这个值传给后续探测，不凭记忆重新输入近似名称。路径至少记录工具实际收到的字面值、工作目录和解析后的绝对或规范身份；相对路径相同但工作目录不同，或者大小写、分隔符、符号链接、Unicode、转义与 Shell 解析使身份不同，都不能合并成同一个对象。分支、进程、URL、包、任务、远端引用和目标三元组等标识使用同一原则，只在相应命名系统可能改变身份时增加必要核对。

身份不同的探测分别描述各自对象。“未找到”只证明该次字面标识解析到的对象不存在，不能证明原本想查的对象消失。只有各次探测身份相同、工具本身成功且产品、环境和观测条件可比较时，结果差异才允许进入同一对象的状态变化解释；在此之前不得归因于同步、并发写入、缓存或外部进程，不得开始等待或重试，也不得让用户确认一个尚未被证据支持的外部原因。若同一身份在可比条件下确实变化，再把外部写入者、时间与缓存等列为竞争解释并取得各自证据。没有跨观测比较的单次稳定检查不增加这份对象对照。

### 2.5 先证明诊断指标确实测量了所声称的事实

系统用进度、漂移、丢失、健康、同步或其它数字支持结论时，为每个会影响判断的指标建立来源合同：

```text
指标名称与声称的事实：
正式测量生产者与测量边界：
采样、更新、聚合和允许滞后：
尚未测量、不可用和真实零值怎样区分：
正式消费者和它允许作出的结论：
用于校准的独立用户可观察结果：
```

默认值、常量、缺失回调、第一帧到达、相邻计数或其它代理信号不能冒充正式测量生产者。零是已经测量得到的值，不是“没有证据”的替代；无法取得测量时应保持未知或不可用，不能为了界面完整、兼容旧属性或让测试稳定而发布一个看似健康的数字。

至少在会暴露问题的代表性持续时间、负载、平台或数据规模上，将指标与一个独立的用户可观察结果对照一次。两者冲突时，用户结果是失败证据，指标失去诊断资格；先沿生产者、测量边界、传输与消费查找最早分叉，不能用健康指标否定已经发生的用户结果。若产品合同不需要该指标，就从公共表面、成功条件和测试断言中退出；合同确实需要时，建立真实生产者并明确表达未知状态，不保留没有来源的兼容属性。

### 2.6 先做最便宜的区分实验

按能够保留核心因果关系的最低成本选择实验：

1. 把纯状态转换或调度规则提成可确定运行的模型，用边界值和状态序列直接检查机制。
2. 用短小受控重现、加速输入或故障注入，让原本需要累计或偶发的条件尽快出现。
3. 在真实生产者和核心边界上做局部运行，让同一份真实产物交给下一消费者。
4. 只有前面证据无法替代最终链时，才运行完整端到端、长时间或外部系统验证。

短实验可以隔离无关部分，但不能 mock 掉正在判断的核心边界，也不能由消费端手写一份结果冒充生产者输出。一次只改变用于区分当前解释的产品变量、环境变量或验证变量，避免几个改动同时发生后无法归因。

### 2.7 把产品、运行环境和验证器分开

分别判断：产品机制是否错误，实际运行环境或外部进程是否与假设一致，验证器或测试驱动是否改变了时序、输入、对象身份或最终断言。三者使用各自证据，不能用某一层通过替代另一层成立。

验证器失败或明显扰动产品时，先修正验证边界，再用相同产品条件重新取得证据；不能修改产品去迎合错误夹具、轮询方式或断言。环境层要锁定实际执行文件、版本、实例、阶段和产物消费者，不能把外层等待结束直接当成产品失败。

### 2.8 收敛后再做昂贵确认

当短实验已经留下一个能解释全部关键证据的机制，并且修复或预防合同已经对应到最早错误边界时，先冻结产品代码、配置和验证器。随后列出最终验证的唯一目的、通过信号、失败时要保留的边界证据和停止条件。

昂贵的完整链路只用于最终确认：证明正式生产者、真实边界、正式消费者和用户结果在目标条件下共同成立。它不能替代机制证明；一次通过也不能抹掉尚未解释的反例。最终确认失败时先读取已布置的区分证据，更新竞争解释，再回到最便宜的有效实验，不直接开始另一轮相同的昂贵运行。

## 3. 特殊维度可以同时叠加

共同路径始终负责“竞争解释 → 可区分信号 → 最便宜实验 → 最终确认”。下面的维度只在主路由已经判定会改变观测、实验或验收时叠加；同一个问题可以同时选择多个维度。

### 时间与累计

- 列出参与决定的时钟、截止点、每轮增量、重置条件，以及会累计的超前量、滞后量或预算。
- 输入事件、消息或事务已经携带发生时间或序列时，决定手势、会话、空闲或批次边界的真源是生产者记录的发生顺序，不是消费者终于获得执行机会的墙钟。主线程、队列或传输停顿不能把早已发生的连续输入切成另一组；验证驱动必须保留这些时间与序列，不能用事件送达后的固定睡眠重新发明发生顺序。
- 同时记录期望状态和实际状态的变化，检查一次追赶或补偿是否给后续周期留下了不应存在的余额。
- 平均耗时不能代替异常窗口；保留间隔、突变点和突变前后的内部状态。
- 优先用可控时钟、确定性状态模型或加速输入复现；真实长时间只验证累计机制在最终链中没有再次出现。

验证“候选 A 应优先于回退 B”、消息事实应覆盖文件或缓存时间等优先级合同时，夹具必须显式构造两个可区分的竞争值，并在主断言前先证明它们确实不同。不能依靠短睡眠、连续读取墙钟或文件系统时间戳分辨率碰巧制造差异；回退值来自文件 `mtime` 或缓存时间时，显式设置并回读该值，再让正式消费者选择。主断言只证明消费者选择了预期来源与值；竞争值意外相同应让夹具前置条件失败，不能让相等关系把未执行的优先级判断伪装成通过或随机失败。

当“最新”、先后关系或按时间恢复本身是产品语义时，有限精度时间戳只能记录时间区间，不能单独建立全序；同一个分辨率窗口内的两次正式提交可以得到完全相同的时间值。由正式提交边界分配序列、revision 或事务内单调递增的排序值，并让持久化、查询和消费者共同使用；UUID、对象 ID、列表位置或其它与发生顺序无关的字段不能拿来猜时间先后。确定性验证冻结时钟，让正式生产者在相同时间戳下连续创建多个对象，再证明存储重开、查询和最终消费者仍按正式排序值选择真正的最新对象。

### 并发、所有权与顺序

- 明确谁创建、拥有、取消、等待和销毁任务、线程、进程、订阅者与队列，以及状态属于哪个代次。
- 记录事件的产生顺序、交接顺序、消费顺序和关闭顺序，区分“尚未产生”“已产生未消费”“已消费未收尾”。
- 用受控屏障、固定顺序或短故障注入验证竞争解释；正常运行、取消、失败、排空和重启分别验收。

每个逻辑操作由正式生产者分配稳定操作身份；同一业务对象允许发起新尝试时，再分配能够区分尝试的 generation。开始、更新、完成、失败、取消和清理事件必须原样携带同一操作身份与 generation。任何需要关联却缺少它们的事件都是合同失败，消费者不得退回“最后一个”“当前项”、当前选中项或列表位置猜测目标。

消费者按操作身份与 generation 建立索引，只更新、终止或移除精确匹配的对象；过期回调、较晚失败和取消只能收尾它们所属的旧尝试，不能触碰其它仍活动或已经完成的操作。区分实验从正式入口启动两个真实操作，用屏障让它们的开始、更新和终态交错经过实际事件、队列或传输边界，再由正式消费者处理；注入第一个操作的失败或取消后，必须证明第二个操作没有被修改、移除或错误终止并能独立完成。直接调用消费者 handler 或手写事件 payload 不能证明关联合同成立。

### 确定性派生产物的单一生产者

当多个线程或进程可能为同一稳定键生产同一个内容寻址缓存、代理、索引、分析结果或其它确定性派生产物时，正确性不仅是最终文件没有冲突，还包括同一结果身份在一次缺失或失效窗口内只有一个正式生产者。先冻结稳定结果键、结果格式版本和生产者身份；随后按以下顺序建立跨线程、跨进程的租约或锁：

```text
无锁快速检查现有结果
→ 取得覆盖整个生产过程的同键租约
→ 在租约内重新检查结果与版本
→ 唯一生产者生成、校验并原子发布
→ 等待者读取同一已发布结果
→ 释放租约
```

不能只在最终重命名时加锁，也不能靠原子重命名失败后重试掩盖多个昂贵生产者已经同时运行。相同稳定键必须合并为一个生产过程，不同键保持并行；损坏、不完整、格式过期或生产者身份不匹配的结果在同一租约内失效并重建。生产失败时不得发布部分结果，等待者只能依据明确失败或重新竞争合同继续，不能消费临时文件。验收用受控屏障同时启动同键请求，证明实际生产调用恰好一次且所有消费者取得同一身份；再用不同键证明没有被全局锁无谓串行化，并用损坏或旧版本结果证明只触发一次重建。

### 吞吐、背压与资源

- 同时测量生产速率、消费速率、队列或缓冲占用、阻塞发生在哪一侧，以及解除压力后能否恢复。
- 资源问题记录内存、句柄、连接、文件或工作项随操作次数和时间的变化，不只比较开始与结束两个点。
- 用缩小容量、提高输入速率或限制消费者等短实验放大机制；确认修复时恢复真实容量和负载。

性能诊断先冻结阶段账本，至少区分冷启动、首个可用结果、预热或惰性初始化、稳态、持续运行，以及过载场景与解除压力后的恢复。每个阶段分别记录入口、工作负载、采样起止、用户结果和资源趋势；前一阶段的缓存、页面、会话、GPU 保留量或其它初始化状态不能混入后一阶段基线。预热前后的单次差值不能命名为泄漏，也不能因为随后保持平台就直接判为健康；只有预热结束后，在代表性重复操作和持续时间内仍存在增长趋势，并能把未释放对象、所有者或重复工作对应起来，才升级为泄漏或无界增长。资源回落、稳定平台、可回收缓存、驱动或运行时保留与持续斜率分别报告，不用一个开始值和结束值合并结论。

同时建立端到端工作放大账本，沿正式生产者、每个传输或存储边界、正式消费者记录载荷字节数、对象数量、消费者实际需要的投影、是否发生完整物化，以及构建、上传、复制、解码、序列化或等价昂贵操作的实际次数。上游流式、分块或按需生产，不能证明整条链有界；预览、导出、恢复或其它后续消费者重新读取或物化完整内容时，仍按全链瓶颈处理。总耗时、帧率或最终输出达到目标，也不能掩盖同一结果被重复构建、上传或复制；用“实际次数 × 代表性单次成本”说明放大位置。消费者存在明确目标速率、容量或摘要需求时，由拥有该需求的最早边界决定采样、复用或投影，不能先完成全部高成本工作再在末端丢弃。

交互前台与后台整理、索引、预热、同步或维护任务共享排他 provider、锁、设备或执行槽时，先定义资源仲裁合同：前台用户动作是否必须优先、后台任务在哪个边界停止接收新批次、当前批次怎样取消或暂停、谁确认资源已经释放、未完成批次是否允许推进游标或检查点，以及前台结束后由谁重新调度。只有产品明确允许用户等待后台完成时才采用非抢占策略；不能让后台任务碰巧先取得普通互斥锁就决定用户结果的延迟。

需要前台优先时，标准顺序是“阻止后台重新取得资源 → 请求当前后台生产者停止 → 等待它确认退出或释放 → 开始前台生产者 → 前台完成后恢复调度”。取消中的后台任务不得提交成功、推进批次游标或丢失原输入；等待超时保持资源所有权未知并阻止第二个生产者，不能让前台和未退出后台同时使用同一非并发边界。

区分实验用受控阻塞生产者让后台先取得真实共享资源，再从正常用户入口启动前台动作。证据同时证明后台收到停止、资源确实释放、前台在合同时限内开始、未完成后台进度没有前移，以及前台完成后后台能够从原批次合同安全重试；只检查前台线程已创建或后台取消标志被设置，不能证明仲裁成立。

### 连续实时管线的进度真值与分层验收

播放、采集、动画、流式处理、实时控制或其它持续运行结果需要在墙钟内保持进度时，单一位置、最终计数、序列连续或“丢失为零”都不能独自证明成功。先确定调度、时钟、背压和丢弃决定的唯一所有者；跨框架、运行时或插件传递的调度参数要逐层列出每个实际读取者、精确版本或目标以及对应语义，不能用某一层的局部含义推断整条链。

- 同时记录墙钟、源或请求进度、正式生产完成序列、传输或队列交接、正式消费或展示确认，以及最终可见或提交结果；为每个观察量记录所有者、稳定身份和允许滞后。序列连续只能证明没有离散缺口，不能证明整条管线没有整体变慢。
- 丢失、超时、迟到或落后统计必须覆盖每一个可能跳过、丢弃、延后或追赶结果的决定点。观察器之前发生的静默丢弃，或者所有序列一起变慢而没有缺口时，“零”不是有效结论；正式边界必须输出可消费的截止时间错过、进度滞后或等价事实。
- 按故障出现的时间和运行边界分别冻结验收层：启动和短窗口验证首次结果与基本节奏；目标平台的真实消费者验证实际展示、提交或设备边界；持续运行与长时累计验证墙钟漂移、队列和资源趋势；过载、解除压力与恢复验证统计、降级和恢复。前一层通过不能替代后一层，每层只在相关产品、配置、验证器和环境条件冻结后取得证据。
- 把正常负载下的实时能力与过载时如实报告、触发降级并恢复分成两项用户承诺。环境饱和可以让正常能力基准失去代表性，但仍可证明过载合同；过载链正确也不能把未达到的正常能力判为通过，正常链通过同样不能替过载诚实性背书。

### 受验证的高速路径与原子回退

并行 worker、GPU 或浏览器快速后端、向量化实现、缓存捷径和其它替代生产者只有在它们承诺与标准路径交付同一结果时进入这一维度。先冻结标准路径、输出合同和会触发不同实现分支的工作负载矩阵；矩阵只保留会改变内容复杂度、持久状态、媒体种类、执行单元或后端选择的真实维度。正确性要求应当是精确相等，或者由用户结果和消费者合同证明合理的差异阈值，不能在看到结果后临时放宽。

比较基线与候选之前，先证明两边除目标变量外使用同一实际生产者、后端、资格状态和输入身份，并把最终选中的身份写入证据。若两边各自自动选择实现并落到不同后端，结果已经被后端差异混杂，不能据此判断调度、并行策略、优化收益或内容退化。需要自动选择时，要么先冻结同一个合格后端再比较目标变量，要么把后端作为显式矩阵，在每个相同后端单元内分别比较；不能把标准路径与高速路径的差异归到另一个被测变量上。

资格与正确性判定要同性能选择分开。资格仍由代表性真实输入经过同一消费者后的结果建立；性能结论由冻结条件下的系统工作负载建立。少量样本的微型计时可以形成待验证假设，但不能同时决定采用哪个生产者并充当该生产者更快的证明，否则选择噪声会直接改变比较对象。

- 每个真正参与生产的 worker、进程、浏览器、GPU、设备或后端分别取得资格，不能由第一个实例代替其余实例通过。静态能力检查只能筛选候选，最终资格要由它将代表性真实输入送到同一消费者的结果证明。
- 能力验证使用与正式生产相同的代码边界，但验证状态、页面、会话、缓存或输出目录不能泄漏进正式运行；验证完成后从新鲜生产状态开始，避免预热、游标、时间或缓存让正式结果依赖验证副作用。
- 在“资格验证已经通过”之后注入一次运行期故障，证明中途失效会标记整个尝试不可发布。任何执行单元丢帧、异常、产生不合格结果或失去资格时，废弃本次高速路径的全部临时结果，从新鲜状态完整运行标准路径；不能保留前半段高速结果再接后半段标准结果。
- 输出或缓存只有在生产者完成、数量和顺序成立、语义探测通过、内容身份与本次输入一致后才原子发布。文件存在或非空不能代表成功；损坏、不完整或属于另一版本的产物必须被正式消费者拒绝并重建。
- 最终性能结论绑定冻结后的产品代码、配置、验证器、工作负载和机器条件，同时报告正确性结果、绝对耗时和同机相对变化。只在快速路径真的被选中且正式消费者读取了最终产物后，才能把速度记为该路径的收益。

### 环境与外部进程

- 锁定本次执行尝试身份、实际执行文件、版本、参数、启动器、根进程、已知子进程、当前阶段、日志增长、产物变化、正式消费者，以及会被占用的端口、锁、缓存、设备和输出目录。
- 区分命令执行器停止等待、工具自身失败、应用退出和原进程继续运行；外层等待结束不改变原执行所有权。原任务仍有进展时不启动争用同一资源的重复任务。
- 进程、日志和资源探测分别保留自己的退出状态。查询失败、部分返回或空输出只让相应事实保持未知；一个进程已经消失不能替其它进程退出，也不能把整次执行判为完成。
- 重新执行前先取得原执行的正式终态，或者证明整个进程树已经结束、资源已经释放、产物和副作用已经分类且不会冲突。需要停止时只终止能由本次执行合同准确证明所有权的进程，并在停止后重新核对进程、监听端口、锁和输出位置。
- 环境差异只有在同一产品输入下产生可区分结果时才保留为根因证据。

自动恢复前先把失败归入精确类别：实际可执行文件与版本、平台、失败阶段、结构化退出状态或操作系统崩溃证据、进程树是否终止、stdout 与 stderr 是否完整，以及部分产物和其它副作用的状态。只有该精确类别被当前合同明确标记为可重试、整个进程树已经结束、全部副作用都能控制、占用资源已经释放，并且下一次尝试使用新鲜临时命名空间时，才允许在固定最大次数内自动重试。取消、校验或 schema 错误、确定性坏输入、内容错误和未知失败不得自动重试。

重试与标准回退属于同一张恢复图；一次失败只能沿一条已经声明的边继续，不能在快速或硬件路径内部重试后再隐式叠加另一轮回退重试。保留首次尝试的完整证据，隔离而不是合并部分输出，并让正式消费者重新校验新尝试或回退产生的完整结果。持久操作主路径继续拥有操作、尝试与批次身份及其终态，本方法只决定失败分类是否允许进入下一条恢复边。

正式入口跨越多个启动器、构建器、Shell 或子进程，并可能在交接中重新解释工具名、参数、环境变量或路径时，建立从父入口到正式消费者的多层工具链执行闭包。逐层记录实际可执行文件与版本、工作目录、Shell 和路径语法、继承后实际收到的环境、生成配置或命令文件中最终写入的调用，以及该层正式输出由谁读取。工具在当前终端能够单独运行，不能证明下游子进程选择了同一文件、模块、动态依赖或参数语义。

区分实验使用与正式入口相同的启动器和交接语义，每次只改变一个能够排除竞争解释的变量，并在最早出现身份或语义偏离的边界取证。诊断替代路径可以把真实生产物送给下游消费者以缩小故障范围，但只证明没有被绕过的部分；手工复制产物、跳过正式任务或直接调用下游命令不能证明正常入口已经恢复。阻塞条件由用户或外部环境改变后，只让该条件对应的旧失败证据失效，从新鲜输出状态重新运行同一个正常入口，并确认它实际选择目标分支、正式消费者读取本轮结果且最终产物成立；不能把替代路径留下的产物与新运行拼成一次通过。

### 数据、缓存与版本沿袭

- 为输入、派生产物、缓存条目和消费者实际读取内容记录稳定身份、版本或内容摘要，以及写入、失效和读取顺序。
- 本应相互独立的部署目标、基础路径、浏览器场景、会话或数据版本使用新鲜进程、上下文、缓存和输出位置，或者执行有证据的完整重置。顺序复用同一环境时，必须把前一场景留下的缓存、游标、页面状态和后台任务列为竞争解释，不能把后一场景的结果单独归因于当前输入。
- 检查修复是否更新了唯一真源，却仍由旧缓存、旧生成物、错误路径或另一个实例提供结果。
- 用同一份生产者真实输出贯穿边界，分别验证冷启动、更新、失效、重开和迁移后的消费者结果。
- 大型内容在导入、复制、提交或发布后成为不可变对象时，可在这个状态转换中完成一次完整读取、内容校验和写入复核，并持久化同时绑定内容身份、版本、物理对象和成功状态的回执。后续消费者只在不可变约束和回执仍成立时复用该证明；内容仍可原地改变、回执缺少任一身份、发布未原子完成或消费者需要主动审计时，必须重新读取正式内容。把完整审计从每次消费中移出不等于取消完整性验证，而是把昂贵验证放到唯一能建立不可变事实的边界。

### 验证器与测试驱动干扰

- 检查事件循环、等待、轮询、睡眠、超时、输入夹具、对象引用和观测开销是否改变被测条件。
- 固定睡眠只能作为有界等待的上限，正常完成条件必须来自正式消费者可观察的状态变化。达到上限时保留生产者、边界和消费者的实际状态并判定超时，不能把“睡够了”当成结果已经产生。
- 请求次数、资源计时、回调次数、文件存在或瞬时元素出现，只有在正式所有者保证它与目标结果稳定一一对应时才能成为关键断言。自动生产者、缓存、分片请求、重试或观察器会改变信号时，替换为正式状态或最终结果；不能靠放宽阈值保留没有合同依据的指标。
- 对比等价产品条件下有无验证驱动时的边界状态；验证器必须证明自己确实启动、取得新鲜对象并读取真实结果。
- 如果干扰来自验证器，修复验证器并保留能防止同类失真的结构合同；不能把验证器制造的行为写进产品。

验证器通过测试钩子引入暂停、定位、替代时钟、视口、缓存、选择或其它生命周期状态时，记录每项状态的生产者、作用域、退出条件和后续哪些断言会消费它。等价状态能够由公开产品动作到达且属于产品合同时，把它保留为显式产品场景，并通过公开动作完成最终验证；只由测试私有钩子产生时，在无关断言前正式复位或换用新鲜上下文。隐藏的测试状态泄漏只会让后续产品结果保持未知，不能据此判定产品通过或失败。

验证器把子进程 stdout 或 stderr 接到有界 `PIPE` 时，必须从子进程启动起为两条流分别登记消费所有者并并发排空到 EOF；这些文本不属于完成证据时，也可以明确重定向到受控文件、有界日志接收器或空设备。等待子进程终态的线程不能先停止读取，任一未消费管道写满都可能让子进程阻塞在输出而不是产品逻辑。此时外层超时只证明验证器破坏了运行条件，产品状态保持未知；不能通过延长超时、降低轮询频率或修改产品来掩盖。

结构化结果、致命错误和终态仍使用独立无损通道，或者使用有明确分帧与消费所有者的权威流；不能为了避免管道阻塞把权威结果静默丢弃。区分实验使用会持续高频输出的受控子进程，在可以控制时缩小管道容量，对比有无并发排空，并让正式消费者读取结构化结果；不排空分支只用于把验证器故障分类为测试驱动问题，不能拿来给产品失败背书。
