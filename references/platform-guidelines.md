# 平台表达与跨平台适配

用于平台差异会改变结构、输入、导航、窗口行为或组件惯例的任务。只保存稳定机制；用户需要当前 HIG、Material、WCAG 或平台数值时，查证用户指定版本的官方来源。

## 1. 先定义跨平台不变量

内容身份、主要任务、信息顺序、状态语义、成功结果和品牌关系先统一。跨平台不是复制同一布局，也不是建立不同业务真源；平台只改变表达和操作方式。

## 2. 网页

考虑流式重排、浏览器导航、键盘焦点、真实内容视口、加载与深链。移动网页仍属于网页，不因触摸输入自动采用原生 App 的导航和状态恢复规则。

浏览器原生标签、地址栏和系统菜单不属于网页渲染树。产品只能管理自己的文档、favicon、清单和页面内容。

浏览器扩展、下载管理器、密码管理器、翻译工具或操作系统悬浮层可能覆盖或注入网页，但其显示与控制权仍由外部所有者决定。先区分页内正式 DOM、扩展注入内容、浏览器外壳和系统覆盖层；问题属于外部所有者时，给出对应扩展、浏览器或系统设置路径，不通过破坏语义标记、媒体结构或添加规避性 CSS 来伪装成网页修复。只有外部工具公开并由网站正式支持的集成接口，才进入产品实现范围。

## 3. 桌面应用

考虑窗口持续缩放、低高度窗口、系统缩放、键盘与精确指针、多面板密度、窗口恢复、系统外观和平台菜单。标题栏、系统窗口按钮和应用内容先确认控制边界。操作系统直接绘制且应用无法配置的菜单或窗口装饰属于系统边界；由应用实例化的工具包菜单、下拉层和其它控件，只要应用调色板、样式或组件能够决定最终像素，就属于产品边界，即使工具包称其为原生控件。

桌面不等于固定大屏。主要任务在窄窗口、分屏和放大显示下仍可达；高频操作可以使用快捷键，但不能只靠快捷键发现。

桌面集合中的选择、拖放、双击和右键菜单可以形成分层操作：持续可见区域保留高频主行动，右键菜单承载明确作用于当前对象的次要命令。上下文菜单不能改变对象身份或使用另一套行动实现；关键能力仍要有可发现或键盘可达的入口。产品管理的菜单、组合框弹出层、提示、对话框和其它临时表面在项目支持的每个主题或系统外观中读取同一主题语义，并通过指针与键盘到达实际可用和不可用状态。

## 4. iOS 与 Android

先确定应用实际呈现的设计语言和系统行为，不用 Flutter、React Native 或其它工具链名称代替平台。分别核对安全区域、系统返回、导航层级、触摸与辅助输入、系统字体缩放、键盘、权限和生命周期。

平台标准控件承担用户熟悉的行为时优先使用；自定义表现必须保留等价语义、状态和辅助技术支持。当前规范数值需要官方查证，不把记忆中的触摸尺寸、字体或组件样式写成现行标准。

## 5. 自适应跨平台应用

真正的自适应应用可以在 iOS 与 Android 使用不同导航、控件和反馈，但共享内容顺序、任务结果和状态语义。只是在两个平台渲染同一套外观时，按那套实际设计语言审查，不因为能够编译到两端就声称已经适配。

## 6. 适配验收

每个平台记录真实内容宽高、固定区域、输入方式、系统缩放、主题或系统外观、导航与返回合同。检查布局变化究竟由宽度、高度、内容长度、输入方式还是系统行为触发，不把“桌面”“移动”名称当尺寸证据。平台适配涉及产品管理的临时表面时，从自然入口逐一打开当前任务覆盖的组件家族和状态，检查最终可读性、焦点、选择与关闭后的恢复。
