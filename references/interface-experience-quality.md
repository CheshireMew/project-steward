# 界面使用质感

用于判断和改善一个真实产品界面是否看起来一体、操作顺手、使用舒服，并且适合当前任务、平台与风险。它处理的是用户连续使用时的整体感受，不是单独挑选配色，也不以“功能能够完成”代替体验成立。

## 1. 先定义这个任务应该怎样被使用

使用质感没有一套适用于所有产品的固定答案。先根据真实任务写清：

```text
用户正在操作的核心对象：
自然入口和完成结果：
使用频率与单次持续时间：
设备、视口和主要输入方式：
用户已有的操作习惯：
错误或误操作的代价：
这段体验应该偏向快速、安静、紧凑、引导、审慎还是其它明确结果：
```

感觉词必须继续转成可观察关系。例如，“快速”意味着高频行动直接、反馈及时、重复使用少绕路；“安静”意味着状态不过度争夺注意、完成提示及时退出；“审慎”意味着高代价行动在正确时机说明范围和后果。不能只把形容词写进设计说明。

## 2. 从五种感受检查完整体验

### 顺手

用户想到一个行动时，入口出现在预期位置，操作方式符合对象、频率和平台习惯，行动结果与预期一致。

检查：

- 高频行动是否直接，低频行动是否仍然可找到；
- 视线、指针、手势和键盘是否频繁在无关区域之间往返；
- 用户是否反复切换模式、重新选择对象或记住上一步的临时状态；
- 同一对象的点击、拖动、菜单、快捷键和批量操作是否进入同一结果；
- 重复执行是否有稳定语义和即时反馈。

### 舒服

界面的信息量、空间、视觉重量和反馈节奏与持续使用相称，不让用户一直辨认、等待、确认或抵抗界面。

检查：

- 文字、图标、行高、缩进、留白和内容密度是否共同服务阅读与操作；
- 第一焦点、辅助状态和次级行动是否平均用力或互相争夺注意；
- 加载、刷新、展开、切换和完成状态是否闪烁、跳动、拖沓或长期占位；
- 长内容、深层级、窄窗口、系统缩放和重复操作是否造成视觉或操作疲劳；
- 临时表面出现和退出后，焦点、选择、滚动与上下文是否自然延续。

### 合适

设计符合当前任务发生的情境，而不是套用统一的“简洁”“现代”或“大按钮”标准。

检查：

- 高频、低风险操作是否足够快；
- 低频、高风险或不可逆操作是否在必要位置减速并说明后果；
- 桌面、网页、移动端及其主要输入是否采用用户熟悉的操作关系；
- 首次使用和熟练使用是否共享同一个核心对象，同时提供不同效率；
- 信息密度、反馈强度和默认值是否符合任务持续时间、内容规模和错误代价。

### 一体

窗口外壳、导航、内容、弹层、控件和状态像同一个产品系统。区域边界、视觉语言和互动方式不会让用户感觉自己在几套界面之间切换。

检查：

- 整个窗口或页面是否有一个清楚的空间骨架和视觉重心；
- 标题栏、侧栏、内容头、分隔线、滚动和覆盖层是否各有唯一所有者；
- 同义文字、图标、颜色、间距、形状和反馈是否来自同一设计系统；
- 原生表面、框架控件和应用自绘区域是否在产品边界内协调；
- 局部都正确时，整体是否仍显得拼接、失衡、松散或过度装饰。

### 可控

用户始终知道自己正在操作什么、系统发生了什么、结果在哪里，以及怎样取消、撤销、重试或恢复。

检查：

- 选择、范围、进行状态和不可用原因是否持续可见；
- 输入后是否立即出现与当前行动成比例的反馈；
- 后台工作是否只在影响等待和结果时占用注意；
- 错误是否说明影响与恢复，而不是只显示内部原因；
- 取消、返回、关闭、删除、重开和跨会话恢复是否保持对象身份与用户控制。

## 3. 用三次观察找到真正的不适

### 第一眼看整体

在目标视口打开真实界面，先不逐项检查组件。观察用户首先会看哪里，主要对象是否稳定，空间与视觉重量是否平衡，各区域是否像一个整体。第一眼只负责发现整体关系，不凭一张截图判断互动已经成立。

当用户连续指出“不知道这个图标做什么”“这行小字有必要吗”“为什么这里空一块”或“间距忽宽忽窄”时，在继续局部修补前建立一次可见元素职责清单：

```text
可见图标、文字、状态、分隔、边框、空白和拖动区域
→ 它帮助用户识别、理解、选择、操作、确认或移动什么
→ 它与相邻元素属于同组还是跨组
→ 去掉后损失什么
```

没有职责的元素退出；承担聚焦、分组、命中、拖动或阅读节奏的留白保留，并由拥有该关系的容器统一分配。同组间距使用一致规则，跨组间距用稳定层级表达，不按每一对控件分别微调。一次检查整个可见区域，避免修好一个空隙又把不均匀转移到相邻位置。

### 连续完成主要任务

从自然入口使用正式内容完成一次主要任务，不跳过中间状态。记录：

- 第一次犹豫、寻找、回看或误操作发生在哪里；
- 视线和输入在多少个区域之间切换，以及每次切换是否有职责；
- 哪些步骤要求记住界面没有持续显示的信息；
- 哪些反馈过迟、过强、过弱或与行动位置分离；
- 结果出现后，用户是否知道已经完成以及下一步在哪里。

这里关注连续节奏。单个控件可用不能证明整条任务顺手。

### 重复并施加真实压力

再次执行高频行动，并按当前产品实际承诺检查长内容、更多条目、深层级、窄窗口、主题、缩放、等待、失败、撤销和恢复。观察第一次尚可接受的步骤是否在重复后变得累、慢、烦或容易出错。

## 4. 从感觉回到最早失效关系

按下面的顺序找根因：

1. 核心对象和任务顺序是否符合用户理解；
2. 信息、行动和状态是否出现在用户需要它们的时刻与位置；
3. 控件数量、拓扑和输入方式是否符合行动语义；
4. 空间、密度、对齐和视觉层级是否表达前述关系；
5. 反馈、等待、动效和恢复是否保持连续；
6. 字体、图标、颜色、边框、圆角和阴影是否完成细节收口。

如果前一层没有成立，不在后一层增加装饰或说明文字。用户只能说“哪里不对”时，把这句话当成整体体验诊断的入口；Agent 负责沿真实任务找到可观察的摩擦和共同所有者，不要求用户先指出 CSS 属性。

## 5. 把目标感觉变成设计合同

完成诊断后写成：

```text
这段任务应有的使用感：
当前最明显的感受与摩擦：
用户为此多付出的注意、动作、等待或记忆：
最早失效的任务、空间、控件或反馈边界：
需要统一改变的关系和全部消费者：
必须保持的产品身份、内容和行为：
轻量调整或完整重做的范围：
用户在真实界面中能观察到的通过结果：
```

不要用总分或形容词数量代替判断。优先指出最影响连续使用的少量根因，并说明修复后用户少做了什么、少想了什么、能够更自然地看见或完成什么。

## 6. 按改动范围选择强度

- **轻量检查**：所有可见界面设计、修改和审查默认执行。确认目标使用感，走一次受影响的自然任务，检查相邻区域、反馈与最终画面，不扩张到整个产品。
- **完整检查**：用户明确说不顺手、不舒服、不合适、别扭、没有整体感、没有质感，或者多个界面症状指向共同边界时执行。覆盖整个相关表面、连续主任务、重复使用、压力状态和共享消费者。

精确文字替换、用户已经锁定关系的忠实重建和没有产品界面的项目不自动扩大为完整检查；仍需确认本次改动没有破坏已经成立的使用关系。

## 7. 在真实界面验收

使用真实入口、正式内容和目标平台。静态画面用于检查整体、层级、密度和细节；连续操作或录屏用于检查寻找、输入、反馈、状态转换、等待和恢复。两者不能互相代替。

至少证明：

1. 用户从自然入口能够找到并开始主要行动；
2. 连续操作不需要无职责的往返、记忆和模式切换；
3. 每次输入在合理位置得到与后果相称的反馈；
4. 重复、等待、失败和恢复仍保持上下文与掌控感；
5. 目标视口、主题、缩放和输入方式下，界面保持一体、可读和可操作；
6. 最后一次相关修改后重新检查受影响的完整任务和画面。

只有截图时可以判断可见关系，不能声称已经验证顺手、反馈或恢复。只有函数、组件和自动测试通过时，也不能声称界面舒服或合适。

## 8. 输出与停止

第一段直接说明当前界面给人的主要使用感、最重要摩擦和目标状态。随后说明目标使用感、连续任务中的可观察问题、最早根因、统一调整范围、必须保留的关系和真实验收结果。

只读审查形成判断后停止。用户明确要求实施时，回到上层产品体验路径完成唯一真源修改、全部消费者迁移和真实界面验收，不自动扩张到品牌重塑、用户研究、打包或发布。
