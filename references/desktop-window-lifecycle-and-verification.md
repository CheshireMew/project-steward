# 桌面窗口生命周期、持久化与实机验收

这份方法承接 `desktop-app-governance.md` 中的窗口关闭、持久化、恢复和真实 Windows 验收。窗口外壳、原生能力、辅助进程与界面工作仍由主文件治理；这里负责证明窗口在页面和平台约束生效后的最终状态，而不是只证明创建请求曾经发出。

## 1. 关闭语义

默认关闭合同是：

```text
用户请求关闭
  → 阻止重复关闭
  → 保存脏文档与项目状态
  → 处理外部修改冲突
  → 刷新或持久化必要原生状态
  → 等待成功或给出可操作失败
  → 请求窗口正常关闭
  → 进程退出
```

正常关闭和强制销毁是不同语义。只有确实要绕过关闭事件、清理和提示时才使用强制销毁，并为该决定建立单独合同；不能因为正常关闭链没有接通就换成 destroy。

自动化、验证脚本或发布前检查需要“关闭后立即重新打开”时，必须等待应用公开的释放完成或释放失败状态。私有 Future、内部 Promise、对象暂时消失和固定睡眠都不能证明文档、项目锁、浏览器、设备、辅助进程或持久化事务已经释放。只有公开状态表明正常关闭链完成且相应资源可重新取得后才能重开；公开失败状态要提供消费者可判断的原因，验证链据此停止或显式重试，不能继续调用打开入口制造第二条生命周期。公共关闭状态或方法迁移时，生产调用点、测试、自动化、验证与发布脚本必须在旧入口退出前一起迁移。

需要多窗口、托盘或后台驻留时，分别说明“关闭窗口”“退出应用”和“隐藏到后台”的用户结果。最后一个窗口消失不一定等于进程退出。

## 2. 持久化与恢复

核对：

- 文档内容、应用设置、窗口状态和缓存各自真源；
- 自动保存、手动保存、外部修改和关闭刷盘的顺序；
- 保存失败时窗口是否仍保持可恢复状态；
- 崩溃恢复副本是否会覆盖更新的磁盘内容；
- 再次启动是否由正式消费者读取刚才写入的状态。

窗口几何恢复不能停在构造参数或首次 `setBounds` 成功。分别记录持久化边界、创建时请求边界、页面与宽高比、最小尺寸和原生约束就绪后的原生边界、无用户输入时的稳定边界，以及最终回写值。平台或运行时在加载后改写尺寸时，由唯一窗口所有者在约束就绪后重新应用经过当前工作区校正的保存边界，并抑制这次内部恢复触发的错误回写；关闭重开后最终边界仍应稳定。

关闭链测试必须先制造真实脏状态，再通过界面关闭，重新启动后读取；直接调用保存函数不等于关闭刷盘成立。

## 3. 实机验收

启动真实设备、媒体、窗口或输入生产者前，先列出它会改变的音频输出、屏幕内容、窗口焦点、键鼠状态、文件、网络、设备占用和后台进程，并选择满足同一合同的最低扰动输入。音频传输、编码和解码优先使用静音或不可听输入，振幅与信号质量离线验证；不得用持续刺耳的测试音充当默认端到端证据。用户对副作用提出异议时，立即停止本次启动的准确生产者，确认设备和后台任务已经释放，再从测试调用点、工作流和说明中退出该模式，不能把同一副作用降级后继续播放。

### 按验证环境分层

离屏或 headless 环境用于验证组件能够创建、应用状态能够推进、布局几何成立，以及应用内部的信号、模型和交互链能够完成。它不能证明窗口管理器、系统标题栏、最大化与最小化、原生非客户区命中、DPI 与多显示器迁移、系统背景材质或 Windows 合成器行为。后面这些结果必须在真实 Windows 桌面会话和实际窗口中验证，并保留平台、缩放、显示器与合成条件。

离屏驱动缺少某项原生能力时，把对应检查隔离为实机专项并准确标记离屏范围，不修改产品来迁就测试驱动。反过来，实机截图也不能替代组件状态、模型消费和确定性几何检查；两层分别建立证据，只有共同覆盖同一用户结果时才合并结论。

桌面外壳至少检查：

1. Windows 实际开发或生产窗口，不只看浏览器预览。
2. 每个窗口呈现状态的外壳、内容区尺寸、系统保留区和用户位置。
3. 对需要恢复的窗口同时核对持久化边界、创建时请求边界、约束就绪后的原生边界、无用户输入时的稳定边界和最终回写值；关闭重开后不得被加载期约束再次改写。
4. 每条活动状态转换至少完成一次 `A → B → A` 往返；高频往返再重复一次，确认没有累计位移、错位或状态残留。
5. 用户先把窗口拖到其它位置，再执行展开、收起、导航和主要按钮，确认不会无故归位。
6. 正常、最大化、还原、最小尺寸，以及同缩放和不同缩放的多显示器移动。
7. 项目承诺的系统缩放与文字缩放，至少覆盖 100% 和一个高缩放目标；目标环境使用 200% 时必须纳入。
8. 浅色和深色主题，聚焦和失焦。
9. 标题栏拖动、调整大小边缘、双击、系统快捷键，以及与拖动区同层控件的真实指针命中和窗口按钮。
10. 侧栏、标题栏、系统按钮保留区和内容分隔线的准确边界。
11. 关闭成功、保存失败、冲突、重复点击和再次启动；自动重开通过公开释放完成或失败状态推进，不等待私有任务或固定睡眠。
12. 屏幕捕获产品从最终录制产物验证所有应排除和应保留的自有窗口。
13. 有辅助进程时验证连接前所有权、终止事件顺序、订阅者排空、退出码、流编码和无孤儿进程。
14. 有后台界面工作时使用代表性真实输入证明事件循环在任务终态前仍能处理无冲突输入，正常完成、替代、取消和关闭只提交匹配结果并排空任务。
15. 有延迟界面工作时验证页面替换、语言或主题重载、窗口关闭后的事件排空，没有销毁后访问、过期回调或延迟写入。
16. 从自然入口遍历全部主要、延迟创建和覆盖型表面，首次进入与再次进入都没有运行时框架错误。
17. 进程级启动或单例状态通过同一个生产 `main` 入口在新进程中验证。
18. 终端与应用界面都没有权限报错或未处理异常。
19. GUI 正常入口由实际 Windows 宿主执行，完整进程树只产生合同允许的窗口、托盘和通知，没有控制台、终端标签或脚本宿主错误框泄漏。
20. 有昂贵资源预备时，启动或目标变化能达到身份匹配的准备就绪，同时麦克风、摄像头、扬声器或其它活动会话仍未启动；开始和停止分别取得、释放活动资源而不重复冷准备。
21. 同时采集与播放时，连续模式的最终输出到达选中设备；说完后播放模式在播放前停用输入、只播放一次、输出排空后才恢复采集，环境噪音不会独立触发播放或形成反馈循环。
22. 多个子系统共用执行器时，在目标子系统工作之外同时放入一个受控的无关长任务；目标子系统关闭只等待并收口自己的登记项和结果投递，不被无关任务拖住，也不因共享池状态变化提前宣告完成。

截图只证明某个静态时刻。窗口行为需要真实输入和状态往返；系统保留区问题同时记录窗口、内容区、标题栏与控件矩形。关闭链需要真实操作与重启结果，捕获排除需要最终录制产物。

## 4. 输出

返回窗口外壳选择、呈现状态矩阵、外框与内容区边界、系统保留区、位置与拖动合同、材质适用性与不透明回退、原生权限映射、分发模式与目录所有权、组件就绪快照与首次或重复启动结果、捕获可见性、GUI 启动进程树与可见表面、辅助进程与终止合同、界面线程和后台工作所有权、被动准备与活动会话、音频采集播放模式、延迟界面工作所有权、关闭链、持久化链、请求边界、约束就绪后的原生边界与稳定回写值、离屏与实机证据边界、实机检查和仍未验证的平台。只完成静态或离屏检查时明确说明没有验证真实窗口。
