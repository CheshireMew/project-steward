# 改动前预防

用于功能开发、重构、迁移和跨层变更开始之前。它把 Project Steward 当前方法、当前项目的真实规则和本次用户结果转换成实现边界与验收合同，让同类错误在代码和交互固化前暴露。

## 1. 先写行为差异

先根据当前用户结果、改动对象、平台和主要机制，按固定顺序读取：

1. 当前项目已有的规则、设计文档、代码、配置和测试；
2. 当前项目已经采用的模板和明确项目决定；
3. Project Steward 主路由为本次任务直接选定的方法与平台资料；
4. 用户本次直接提供的历史、纠正、成功结果或外部材料。

只选择会改变本次判断、动作或验收的机制。写清它将改变哪个最早决定；已经验证不适用但据此排除了一条错误路径的方法也写清排除结果。只是读过、没有改变决定，或者与当前改动无关的内容不进入本次预防合同。当前项目没有 Project Steward 配置时仍可完成预防，不为了留痕创建经验目录。

工具位置、包或缓存根、终端、SDK、构建入口或长任务状态会改变本次动作时，再读取已有用户环境档案中的相关条目，通过正式解析入口取得绝对可执行文件和必要环境变量。没有档案时以当前只读检测结果继续，不为了普通项目任务自动建立或更新档案；建立档案、安装工具和修改系统环境变量分别需要各自授权。

### 多层工具链执行闭包

正式入口跨越两个以上能够重新选择或解释命令的启动器、构建器、Shell 或子进程，并且工具身份、参数、环境或路径语义可能在交接时改变时，先冻结一份执行闭包。普通单进程命令或已经能由最早错误边界直接解释的确定性失败不增加这项合同。

```text
正常入口及其用户可见承诺：
父入口 → 子进程 → 正式消费者的阶段顺序：
每一阶段实际可执行文件、版本、工作目录与 Shell：
参数和路径采用的语法，以及继承后实际收到的环境：
生成配置、命令文件或包装层最终写入的调用：
最早发生身份、路径或语义偏离的交接边界：
使用同一启动器和交接语义的最小预演：
正式输出及其消费者：
```

工具在当前终端单独输出正确版本，只证明该终端可以运行它，不能证明正式父进程的后代选择了同一文件、模块搜索路径、动态依赖或参数语义。优先读取正式入口实际生成的配置、命令行、Makefile、响应文件、环境快照或结构化报告；每次区分实验只改变一个能够排除竞争解释的产品、环境或验证变量。机器级工具位置仍由用户环境档案负责，项目入口、子进程交接和生成命令属于本次项目执行合同，不能写回档案形成第二套项目配置。

### 受限执行路径与临时产物

正常工具或入口无法完成已经授权的动作，而替代方案会复制可执行文件、建立暂存副本、生成包装脚本、桥接文件或大型中间产物时，把创建、消费和清理作为同一条生命周期，在创建前写清：

```text
准确受限层：目标权限 / 工具契约 / 启动器权限 / 缺失依赖 / 宿主或安全策略
方案身份：受支持的正式分支 / 仅用于诊断的替代分支
它绕过的正常入口步骤与用户可见承诺：
最小只读探测或无副作用预演及其结果：
准确目标根与临时根：
将创建的对象、预期体积与时间或空间成本：
读取它的正式消费者及成功证据：
外部条件变化后重新进入正常入口的准确条件与入口：
保留或清理动作、清理授权、执行者与完成证据：
失败、中断或策略拒绝后可能留下的对象及报告位置：
```

临时根优先位于目标项目自己的受控范围，或用户已经确认的环境工具与临时目录；无关项目不能因为可写而充当中转站。先用最小探测区分目标权限、工具调用合同、启动器权限、缺失依赖和宿主策略，再决定是否需要替代路径。宿主或安全策略已经明确拒绝状态变更时，把该结果作为当前边界；除非取得新证据并形成实质更安全的新路径，不再借另一种语法、Shell、包装层或工具重试等价写入。

创建前确认当前环境能够执行获准清理；不能获得清理授权或无法可靠清理时，改用用户接受且有明确所有者的持久工具路径，或者停在创建之前。创建后记录对象身份、来源和必要的哈希或基线；写回前重新读取目标，避免旧副本覆盖并发变化；使用后依次验证目标状态、正式消费者和清理结果，并把仍存在的残留准确交付给用户。诊断替代分支即使把等价字节交给正式消费者，也只证明没有被绕过的生产、传递和消费边界；它不能把正常入口承诺升级为已验证。阻塞条件改变后，从不受替代产物影响的新鲜输出根或经过授权且有证据的重置状态运行同一个正常入口，核对它实际选择目标分支、消费者读取本轮结果并形成最终产物。普通工具能够直接完成动作且不会建立这些产物时，沿用正常执行路径，不增加临时流程。

### 大型内容默认根先消费用户环境策略

改动会为应用内容、项目、媒体或生成结果选择新的默认物理根，并且正常生命周期会持续产生大型文件或派生目录时，在冻结项目目录和路径预算前先读取用户环境档案，通过 `scripts/user_environment_profile.py resolve-storage --category <application-content|project|media|generated-output>` 取得已确认根。档案要求规避系统盘时，默认配置、初始化器、CLI、桌面入口、后台任务和测试 fixture 都不能静默回退到系统盘；没有可用根时停在创建之前，报告缺失策略或冲突。小型配置、平台强制文件和普通日志不自动迁移，项目明确要求系统盘时把它作为新的存储决定单独确认。

环境档案只决定用户级候选根，项目真源继续决定具体项目路径、内部目录和命名。正式项目生产者消费解析结果，在所选根下创建项目受控目录并返回规范化真实路径；所有后续调用点消费该项目路径，不再次解析或拼接另一根。影响图同时覆盖默认参数、配置生成器、创建 API、恢复与缓存入口、导出和测试，让“路径规则还在”不能掩盖某个消费者仍写入旧默认目录。

### 机器和部署事实先进入项目运行配置边界

源码、README、启动脚本、测试或示例出现绝对路径、工具安装位置、用户名、主机名、端口、服务地址、工作区根或外部项目根时，先按事实职责分类，再决定是否以及怎样外置：

| 事实类别 | 正式所有者与表达 |
| --- | --- |
| 项目不变量或可移植默认值 | 项目已有配置 schema、类型化默认或版本化配置真源 |
| 用户机器事实 | 用户环境档案提供候选；项目只通过自己的受支持配置入口消费 |
| 部署事实 | 部署配置、服务编排或部署环境的正式输入 |
| 凭据 | 项目支持的秘密注入边界，不进入仓库、示例值或日志 |
| 单次运行覆盖 | CLI 参数或进程级环境覆盖，不反向写成长期默认 |

先复用项目已经采用的配置系统；`.env` 不是所有项目的统一答案。只有项目本来以环境文件作为受支持入口时，才跟踪不含机器值和凭据的 `.env.example`，把实际 `.env` 保持在本地并通过忽略规则退出仓库。使用 TOML、YAML、JSON、系统设置、注册表、CLI profile、部署清单或其它正式配置的项目继续沿同一边界表达，不并行增加环境变量别名。README 只记录配置键、语义、优先级、占位示例和取得方式，不写维护者机器的真实路径、用户名、端口或相邻仓库位置。

代码、CLI、桌面入口、后台任务、脚本、测试和文档示例必须消费同一个加载器、schema、校验、优先级和规范化结果。迁移时从唯一配置真源开始，一次修改全部生产者和消费者，退出调用点自己的路径拼接、本机值 fallback、旧环境变量别名、双读和测试专用配置解释器；外部独立发布节奏确需兼容窗口时，仍按公共身份迁移合同记录所有者和退出条件。

验收先做标识符和路径形态残留扫描并逐项分类，再从不含开发机配置与相邻项目的干净检出开始，用一组与维护者机器不同的合法配置经过项目正常启动入口，让正式消费者实际读取并形成用户结果。默认配置、替代配置和缺失必需配置分别证明可移植默认、覆盖优先级和准确失败；当前机器恰好能找到硬编码路径，或测试直接实例化配置对象，都不能证明配置外置已经完成。

### 规范化真实路径预算与工程根所有权

改动会创建工程、工作区、缓存、恢复文件、代理文件、临时媒体或导出物，并且正式消费者会在所选根下继续派生目录时，在创建入口和目录结构冻结前建立路径预算：

```text
用户选择的来源或内容工作区：
解析 SUBST、PowerShell 驱动器、符号链接和目录联接后的规范化真实根：
所有正式消费者共同支持的最大路径预算，以及最窄限制的来源：
工程内最长合法后缀：状态 / 缓存 / 恢复 / 代理 / 临时文件 / 导出 / 工具内部文件
保留余量与计算后的最深真实路径：
实际生成这些文件的系统与它拥有的短工程根：
公开创建入口接受的业务参数，以及返回的真实工程路径：
源素材原位置与消费系统工程状态之间的引用方式：
接近、达到和超过预算时的失败与用户可见结果：
```

路径预算使用规范化后的真实绝对路径和 UTF-16 等正式消费者实际采用的计量方式，不能按别名字符串、当前样例文件或工程根本身的长度估算。最长合法后缀来自真实目录规范和下游工具会生成的文件；Python、FFmpeg、数据库、浏览器、原生库或编辑器限制不同时，采用共同链中最窄的已证明预算并保留明确余量。现有路径保护在共同消费者无法保证更长路径时是合法的失败前置条件，不能为了让当前样例通过而放宽或删除。

工程根由持续创建和维护工程状态的系统拥有。公开创建 API 接受逻辑名称和必要业务选项，由该所有者选择短根、创建工程并返回规范化真实路径；调用者不得拼接另一个项目的深层输出目录再把物理根注入。源素材可以留在生产者原目录，由工程通过引用、导入记录或正式素材边界消费；编辑状态、缓存、恢复文件和导出中间物进入消费系统自己的工程根。只有用户明确要求工程本体位于来源旁，且完整路径预算经过全部正式消费者验证时，才允许合并两者。

`SUBST`、PowerShell 驱动器、符号链接和目录联接只改变入口写法，不自动改变消费者解析后的真实路径，因此不计入预算收益，也不是根迁移的完成证据。确需用别名做有界诊断时，把它放入“受限执行路径与临时产物”合同，记录准确映射、所有者、生命周期、持久性、清理授权和中断残留；正式方案仍必须从真实根通过正常入口运行。验收至少覆盖普通路径、接近限制和超过限制三类输入，并从公开创建入口取得实际路径，让正式消费者继续生成最深后缀并形成用户可见结果。

现有工程已经位于所有者控制的短根、最长合法后缀仍有明确余量，且改动不会新增路径派生层或文件系统别名时，只记录适用性结论并沿普通影响图实施，不扩张成工程根迁移。单个文件名或技术标识的长度变化若不会改变正式消费者的最深真实路径，同样不触发完整路径预算合同。

写行为差异前先消费主路由建立的目标行为基线，不把“旧实现曾经这样”“当前代码正好这样”和“用户现在要这样”合并成一个事实。当前任务存在历史实现、旧提交、旧截图或多轮纠正时，至少列出：

```text
本轮正在回答：目标意图 / 当前实现 / 历史原因
目标行为及其当前确认来源：
当前实现及其准确项目状态与运行证据：
只用于解释历史的来源：
来源冲突、已否定行为与仍未知项：
```

没有可靠的目标行为来源时，行为差异本身就是待人工核对的合同；不能先按旧 Git 或过期测试实施，再让最终画面替用户决定产品意图。

用可观察行为说明：

```text
用户现在看到或得到什么：
完成后应看到或得到什么：
必须保持的旧行为：
明确退出的旧行为：
不在本次范围内的行为：
停止位置：
```

不要用“优化架构”“提升体验”代替结果。用户只要求诊断或计划时，停止位置不能偷偷变成写代码。

### 用业务不变量限制架构复杂度与内容默认值

方案会因为多个输入、对象或阶段是否重叠、并发、互相影响或需要合并而走向不同架构时，先冻结实际业务条件，不从技术上可能发生的最坏情况反推核心路径：

```text
普通用户动作与代表性工作负载：
已经由用户目标、产品合同或真实数据证明的业务不变量：
明确支持的例外，以及例外改变的动作、边界和验收：
尚无证据、不得进入核心路径的极端场景：
例外启用所需的可观察信号、所有者和失败收口：
据此采用的正式路径，以及被排除的合并、同步、缓存或恢复边界：
```

通用性只来自当前合同实际需要覆盖的结果。未经证据支持的极端场景不能让普通路径先做聚合、转码、合并、全量扫描或其它前置工作，也不能为它建立第二套状态、时间轴、缓存和恢复边界。例外后来被可靠事实证明存在时，在最早能够识别它的正式边界重新建立合同；不能让一个未来可能发生的分支永久提高所有普通输入的成本。

一步到位的最终方案表示职责、调用点和旧路径已经完整迁移，不表示使用最多的抽象、服务、缓存、兼容层、测试 helper 或组合矩阵。每增加一种机制，必须指出它保护的已证明用户结果、失败风险或正式消费者；说不出这三者之一时，不把它加入核心路径。优先选择能够完整表达最终合同的最少活动边界，旧架构退出后停止，不为展示过程机械保留中间实现或红绿灯式脚手架。

验证从用户承诺、稳定公共边界和高风险失败模式推导，不从实现步骤、源码行数或调用点数量反推测试数量。共享合同保留至少一条有代表性的正式生产者 → 边界 → 消费者证据，其余排列组合只在会改变合同结果时进入更便宜的单元或合同测试；不能为每个调用点复制一条红灯、绿灯和重构测试。README、许可证、致谢、仓库可见性和普通元数据修改不创建产品测试，也不触发无关完整回归。先运行覆盖本次变化的目标检查并在证据充分时停止；只有公共合同、核心运行时、跨仓库或发布边界、目标检查暴露的系统性影响，或项目明确门槛成立时才扩大验证。

### 分区语义先于全局聚合

差集、空缺、冲突、变化或所有权事实由轨道、租户、作用域、资源所有者或其它语义分区定义时，在选择集合算法前冻结：

```text
语义分区键及其正式来源：
只能在同一分区内解释的事实：
每个分区的变更前与变更后状态：
分区内先执行的差集、空缺、冲突或变化计算：
允许跨分区合并的最终结果及合并律：
合并后仍需保留的分区身份与来源证据：
```

先在每个语义分区内计算，再合并已经成立的结果；不能先把各分区状态做全局并集，再计算缺失或变化，因为提前聚合会丢失归属并让一个分区仍存在的同值事实掩盖另一个分区已经发生的变化。只有产品合同明确声明分区等价、来源身份与消费者都不再区分时，才允许在计算前合并。测试至少包含一个对抗输入：同一值、区间或资源在一个分区仍然存在，在另一个分区已经移除或腾空；正式结果必须保留后一个分区的差异及身份。

默认角色、主对象、首选通道或其它语义默认依赖内容存在与资格时，再建立内容资格合同：

```text
合格内容的正式判定与稳定对象身份：
第一份合格内容真实进入的事件和所有者：
没有合格内容时的明确状态：
首次自动分配的角色或默认值：
用户显式覆盖的记录与优先级：
默认对象退出或失去资格后的重新分配规则：
读取该默认值的正式消费者与最终可观察结果：
```

空容器创建、预先分配的编号、渲染顺序或测试夹具不能代替内容资格事件。自动分配只在没有用户显式覆盖且当前没有合格默认对象时发生；后续内容到达、重新枚举或界面重建不得再次抢回默认值。默认对象退出后的处理按同一合同选择保持空缺、选择下一份合格内容或要求用户决定，不能由不同消费者各自猜测。

### 可编辑设置必须连到真实能力和运行结果

设置页、首次运行向导、托盘菜单或命令行只要允许用户填写、选择或切换一个值，就先为该设置建立效用账本：

| 稳定设置身份 | 所属决策阶段与精确效果 | 能力、设备或 provider 真源 | 允许值与适用条件 | 界面入口 | 持久化边界 | 当前运行时应用或重建 | 重启恢复 | 用户可观察结果 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | | |

能力真源负责说明某个 provider 支持哪些声音、参数和执行模式，操作系统或驱动枚举负责设备身份，产品配置只保存已经通过该真源校验的稳定值。显示名称只用于呈现；设备重名、顺序变化或重新枚举时仍使用稳定身份。provider 专属字段只在当前能力适用时可编辑，枚举失败、能力不支持或没有真实消费者时，界面应显示准确的不可用状态、只读说明或退出该字段，不能保留一个看似可改但会被忽略的控件。

保存成功必须同时说明值进入哪个配置提交边界、是否立即应用、需要重建哪个运行时对象，以及失败时当前活动值是否保持。首次运行向导与正式设置页消费同一能力目录、校验器、连接或设备测试和配置提交入口；向导完成标记还要绑定向导版本与必需能力，不能因开发模式、窗口重建或一次未改变配置的启动反复出现，也不能用另一套默认值让首次配置与日常设置产生分歧。

用户询问“这个设置是否有效”、报告修改后结果没有变化，或者一个宽泛设置名称实际横跨分类、门控、聚合、解码、过滤等多个阶段时，先建立阶段效用图：

```text
用户实际反馈的现象与输入条件：
从正式输入到最终结果的决策阶段顺序：
每个阶段实际读取的参数、默认值或硬编码值：
现有设置准确控制哪个阶段，哪些相邻阶段仍会主导或改写结果：
配置提交后活动实例取得新值的时点，以及是否需要重建或重启：
最终消费者能够观察的变化与仍未覆盖的现象：
```

结论必须区分三个逐级增加的层次：**已经接通**只表示稳定设置身份经过配置边界到达正式运行时消费者；**活动运行时已经应用**还要求当前实例实际读取新值，或者准确说明需要重建或重启；**对用户所说的结果有效**则要求该阶段确实能改变目标现象，并且没有更早的门控主导输入，也没有更后的阶段重新产生或覆盖同一结果。接口返回成功、状态端点回显、对象属性变化或代码中出现读取点，各自不能把前一层升级成后一层。回答设置是否“有用”时要报告实际证明到哪一层，不能把局部接通说成已经控制整条链。

同一用户结果受多个阶段共同决定时，界面名称、方向说明和帮助文字必须对应准确阶段及其取舍，不能用“灵敏度”“质量”或“强度”等宽泛名称替一个局部比例、窗口或后处理参数承担整条链。隐藏的默认值或硬编码参数只有在环境差异会稳定改变用户结果、取值范围和取舍可解释、正式运行时能够校验并回读当前值时，才成为用户可调能力；随后以一个稳定身份一次迁移能力描述、配置模型、提交接口、持久化、活动实例、状态回读、界面与测试。条件不成立时它继续由内部能力真源拥有，界面不得暗示现有控件能够调节它。针对最终文本、标签或输出增加关键词过滤等下游补偿，只有存在独立产品合同并验证误杀与漏放时才可保留，不能充当上游设置修复或根因退出证据。

一次设置动作还要从用户点名的稳定设置身份推导准确目标集合，并在提交前记录未选中的同级路由、provider 或设备设置基线。请求对象没有携带目标身份时，不能通过遍历全部同级项来猜测修改范围；目标只属于一个路由时，兄弟路由必须保持逐字段不变。全部目标值先完成能力和业务校验，再通过一个配置事务或一次持久提交同时发布；不能在循环中逐项保存，也不能先改活动运行时再依赖补偿回滚。任一校验、应用或持久化步骤失败时，旧的持久状态和活动状态都保持可用，不能留下部分新值。

验收从正常设置入口读取真实能力列表，修改一个会改变行为的值，经过正式配置服务和活动运行时，再观察目标 provider、设备、角色、背景、模型或其它消费者的结果；多阶段链路还要让同一份由正式生产者取得或按正式输入合同记录的受控输入，在变更前后经过真实决策阶段和最终消费者，证明差异来自该设置负责的阶段。测试不能手写已经分类、识别或过滤完成的下游结果来绕过正在验证的阶段。随后关闭并重启正式入口，确认相同稳定值恢复且仍被消费。测试直接改配置文件、手写下拉选项、只断言控件文字变化或只证明序列化成功，都不能替代这条链。没有办法证明最终消费者使用该值时，该字段仍属于未接通，而不是“已实现设置”；只证明接通或活动应用时，也不能宣称它已解决目标现象。

### 语义记录修改与连续决策批次使用已提交状态

记录除了展示内容，还携带会决定资格、可信度、归属、关系或派生结果的来源、证据、权威性等事实时，或者同一批处理中后一步决定会受前一步提交影响时，在实现前建立：

```text
稳定记录身份与当前版本：
用户或生产者允许修改的事实：
必须随修改一起更新或重新计算的来源、证据、权威性、资格和关系：
唯一提交边界与原子提交范围：
读取这些事实的正式资格、筛选、关系或派生消费者：
批次语义：固定计划批次 / 连续决策批次
每一步读取的已提交版本，以及状态怎样推进：
最终持久状态、派生结果和用户可观察结果：
```

界面允许编辑哪些字段不等于完整修改合同。正式修改入口必须把可编辑事实和受它影响的语义事实作为同一次原子提交更新，或者由同一边界在提交前重新计算；不能只保存正文，却保留与新事实矛盾的旧来源、旧证据或旧资格。记录仍存在于真源、但正式筛选器或派生消费者不再接受它，属于修改链失败，不能用界面刚显示过新正文证明成功。

固定计划批次中的全部动作由同一个变更前版本决定，提交前重新核对该版本，再整体提交或整体拒绝；不能让前一项的中间状态重新解释已冻结的后续动作。连续决策批次则相反：每次动作都会改变下一次选择的候选、资格或关系，后一步必须消费提交边界返回的新版本与正式结果，或者重新读取权威状态；不能在整个循环中反复使用同一份初始快照。只有能够证明本地状态推进与正式提交返回完全同义时才允许复用本地投影，不能在批处理器中复制一套资格或关系规则。

验收从正式修改或批处理入口产生记录，让它经过真实持久化边界，再由资格、筛选、关系或派生消费者读取。连续决策批次至少包含两个互相影响的动作，使第二步在使用初始快照时会稳定产生重复对象、错误关系或错误资格；测试必须从第一步的正式提交结果取得第二步状态，不能由消费端手写更新后的来源、证据或关系。

### 计划范围与实际变更事实分离

命令可能触及多个对象或集合、允许无变化成功、产生合同内副作用，或者提交后的版本、事件、历史、撤销、缓存和界面通知需要说明“实际发生了什么”时，在实现前分开四类集合：

```text
用户意图与授权范围：调用者允许请求改变什么
冲突集合：执行前哪些身份与版本必须保持稳定
观察集合：提交前后必须读取哪些权威事实，包含全部合同内副作用
实际变更集：提交后真实创建、更新或退出的稳定身份、事实类别、前后版本或内容身份
消费实际变更集的版本、事件、历史、撤销、缓存和活动投影：
```

前三类是执行输入，不能直接成为已经发生的事实。实际变更集只能由权威提交结果，或同一提交边界内对观察集合的前后状态比较产生；命令声明、目标参数、冲突锁集合和调用者预计会影响的对象都不能冒充它。操作合法但没有改变权威事实时，实际变更集为空，不增加内容版本，不发布“已改变”事件，也不制造撤销项或缓存失效；产品确实需要记录尝试行为时，使用与状态变更分开的操作审计事实。

观察集合必须对合同内副作用闭合。移动、拆分、合并、重排或删除一个对象会同时改变关系、容器、索引或相邻对象时，局部读取必须覆盖这些正式副作用；无法证明闭合时扩大到相应权威聚合，或者让唯一提交边界直接返回完整实际变更集，不能为追求性能漏掉事实。冲突集合可以比实际变更集更大，实际变更集也可以包含由正式规则产生、但未在用户参数中逐项列出的副作用；两者拥有不同语义，不能共用一个笼统的 `affected` 列表。

版本、语义事件、历史记录、撤销、缓存失效和活动投影只消费实际变更集及其提交版本。冲突检测只消费冲突集合；授权检查只消费用户意图与授权范围。验收至少覆盖一次带关联副作用的真实修改、一次合法无变化操作和一次提交前冲突拒绝：从正式命令经过权威提交取得实际变更身份，再让事件、版本、历史、缓存和最终消费者读取同一结果。测试不能根据命令参数手写预期变更集，也不能用消费者收到一条看似合理的事件代替提交事实。

### 为用户可见承诺建立证据覆盖表

行为合同中每一项用户会据此判断“已经完成”的承诺，都要单独建立证据覆盖；启动服务、自动打开网页、保存文件、完成迁移和恢复状态是不同承诺，不能因为它们出现在同一个入口里就合并成一个通过项：

| 用户可见承诺 | 正常触发或入口 | 必须经过的实际分支 | 正式生产者、边界和消费者 | 最终证据 | 当前状态和允许交付措辞 |
| --- | --- | --- | --- | --- | --- |
| | | | | | 已验证 / 仅诊断 / 未验证 / 受阻 |

环境变量、测试开关、手工注入状态、直接移除遮罩、手工复制产物、跳过正式构建任务或其它诊断动作绕过某个承诺时，只能证明未被绕过的部分。例如关闭“自动打开浏览器”后验证服务可访问，只证明启动和服务链成立，不能证明默认启动器确实打开了网页；手工把生产物交给下游消费者，也不能证明正常入口负责的传递步骤成立。实施和验证可以分批进行，但最终报告必须保留逐项状态，不能把一条成功链概括成全部承诺完成。阻塞正常入口的外部条件后来改变时，重新运行同一个正常入口并取得目标分支、正式消费者和本轮产物证据；不能把较早替代分支的产物拼接成正常入口通过。

### 先证明验收门槛适用

项目规则、模板、发布流程或专项方法列出了一项检查，不表示它在每次相邻改动中都自动成为完成门槛。列入验证计划前先建立：

| 验收项 | 规则来源与精确触发条件 | 本次改动怎样命中条件 | 验证器实际覆盖的输入、分支与承诺 | 前置条件、成本与副作用 | 分类 | 对完成的影响 |
| --- | --- | --- | --- | --- | --- | --- |
| | | | | | 适用且必需 / 辅助 / 范围外 / 用户取消 | 阻塞 / 补充证据 / 不参与结论 / 更新完成合同 |

规则写着“修改 X 时运行 Y”，必须先用变化事实证明本次确实触及 X；同一个仓库、相邻模块、相似主题或任务规模较大都不能代替触发证据。公共接口变化时，验证器、发布脚本和真实用户链工具仍是正式消费者，必须迁移它们对旧接口的调用；但“验证器必须完成迁移”不等于它承载的每个高层场景都自动成为阻塞项。只有场景实际经过本次改变的边界，或它独占一项必须交付的承诺时，才列为适用且必需。

适用且必需的门槛缺少凭据、运行时、目标平台或其它前置条件时，结论是受阻；辅助或范围外检查的缺口只影响其自身证据，不能借高成本或失败状态扩大完成合同。用户明确取消一项验收时，保留已经发生的失败、未运行原因和覆盖缺口，更新本次完成合同，并追踪哪些承诺只依赖该验收：这些承诺继续标为未验证；没有剩余承诺单独依赖它时，该验收不再阻塞其它已经成立的结果。后续改动若重新命中触发条件，必须重新分类，不能沿用较早的范围外或取消结论。

### 已有对象使用一份关系变更合同

当前结果会连续修改已有页面、路由、章节、链接、控件、媒体、文件或其它稳定对象时，先为每个受影响对象建立同一份关系变更表，再进入布局或实现：

| 稳定对象身份 | 当前所有者与位置 | 本轮动作 | 目标所有者、相邻锚点与顺序 | 内容或真实行为是否改变 | 必须保持的兄弟对象 | 最终可观察结果 |
| --- | --- | --- | --- | --- | --- | --- |
| | | 保留 / 新增 / 移动 / 换序 / 改名 / 替换 / 合并 / 退出 | | | | |

“新增”只创建点名对象，不隐含替换、隐藏或删除现有对象；“移动”只改变所属关系或位置，不隐含改写内容和行为；“改名”只改变显示身份，不自动改变职责；“退出”才表示对象不再出现在活动结果中，实体文件是否删除仍由独立权限决定。位置要求优先表达为稳定所有者、相邻锚点、前后关系和正式顺序，不把参考截图中的临时像素坐标当成产品真源。

后续纠正只更新用户明确改变的字段，其余已经确认的关系继续保持。多个对象同时移动时，目标位置仍按同一个变更前快照解释，再由正式最终顺序派生序号、选择、预热和其它消费者；不能按请求书写顺序逐项修改后让中间状态重新解释下一项。

### 把已接受差异从阻塞项中分开

在实现和验收前同时记录：

```text
必须通过的结果：
用户已经看见并明确接受、不得阻塞本轮交付的现有差异：
不在本轮范围内的行为：
哪些新证据会使已接受差异重新成为问题：
```

用户接受的现有差异继续作为目标合同的一部分，后续通用质量检查不能擅自把它恢复成阻塞项。接受不会授权本轮改动扩大该差异、把它传播到其它对象或引入新的回归；它开始妨碍主要任务、正式消费者或用户点名结果时，先展示新证据并重新确定范围。

### 技术迁移与呈现变化分开授权

React、Vue、原生框架、播放器、状态架构、构建工具或其它实现迁移会经过可见产品表面时，不能把“迁移后更容易维护”和“迁移后应该换一种设计”合并成一个结果。实施前建立两份相互关联但独立授权的合同：

```text
实现迁移合同：本次替换什么技术责任，最终唯一所有者、接口、状态和旧路径退出条件是什么
呈现保护合同：加载、首个稳定页面、目标视口、真实内容、媒体时刻、控件与互动中哪些必须保持
获准呈现变化：用户明确允许改变哪些区域、状态和关系
等价证据：迁移前后用哪些相同入口、内容、视口、时序里程碑和操作比较
设计改造入口：保护项等价成立后，哪些获准区域才进入视觉或体验改造
```

框架、组件库和动画工具按状态复杂度、生命周期、渲染能力、平台集成、性能和维护责任选择；它们本身不能证明画面更有设计感。一个请求同时要求迁移和局部改版时，可以在同一实施中完成，但仍先固定两份合同并分别验收：保护区不能借改版被替换，改版区也不能因追求等价而停留在旧结构。若根因修复确实必须改变保护项，先展示冲突、影响和新的可观察目标，取得授权后更新呈现合同，不能在实现层静默改变。

### 核心路径与可选能力

产品存在同步、版本管理、插件、账号、云服务或其它高级能力时，先写清：

```text
主要用户和核心对象：
不启用高级能力时的第一条成功路径：
高级能力的启用条件：
启用前后增加的状态、命令和界面：
能力不存在、关闭或失败时核心路径怎样继续：
```

被定义为可选的能力不能成为创建、打开、读取或完成主要任务的隐含前提。正式模型应让核心对象独立成立，再用非空能力描述高级路径；不能用一个“没有能力时跳过报错”的分支掩盖核心类型仍由高级能力命名和拥有。

### 自动化协议入口先证明消费需求

项目已经通过 CLI、API 或机器可读能力描述公开同一组业务语义时，新增 MCP、RPC 服务、daemon、插件桥接或其它协议表面之前先建立：

```text
现有唯一公共应用边界及其机器可读能力真源：
已经确定的消费者及其正式调用入口：
现有 CLI 或 API 已经满足和仍未满足的需求：
新增表面必须补充的传输、工具发现、会话、流式结果或取消能力：
协议请求、结果、错误和生命周期到现有边界的映射：
新增进程、连接、配置、部署与恢复成本：
不允许进入适配层的业务任务、领域状态、持久化、恢复和参数语义：
采用 / 暂不采用的目标侧证据：
```

仅靠“以后可能有用”、参考项目提供了同名入口或某个客户端理论上支持该协议，不能建立第二个自动化表面。没有已经确定的消费者，或者结构化 CLI、公共 API 与能力发现已经满足该消费者时，停在暂不采用；不能先实现服务、状态和配套工作流，再等待未来需求为它补理由。

确有消费者只能通过新协议满足传输、发现、会话、流式结果或取消需求时，新表面只作为唯一公共应用边界外侧的薄适配器。它可以转换协议消息并协调协议生命周期，但不得复制业务任务、领域状态、持久化、恢复、参数语义或错误解释，也不得让 CLI 与新适配器分别维护命令集合。机器可读能力描述继续是实际操作与参数的真源；适配器和说明文档都是消费者。验收用同一业务请求分别经过原入口和新适配器，证明它们到达同一应用边界、产生同一领域结果与失败语义，并在连接、取消和关闭时只收口各自增加的传输生命周期。

### 实时连接先建立权威身份与可调用状态

WebSocket、事件流、IPC 或其它长连接会在握手前排队请求，或者把 session、generation、sequence 与运行端点暴露给客户端时，先冻结以下合同：

```text
会话身份与 generation 的唯一运行时所有者：
传输已经连接与领域已经就绪的不同里程碑：
权威身份握手及允许释放排队请求的准确条件：
首次连接、重新连接与显式 reset 各自保留或创建什么身份：
旧 generation、迟到分片和过期完成事件的唯一拒绝边界：
configured、process online、endpoint reachable、callable 四种能力事实的生产者：
可以公开调用 URL、流式 URL 或控制入口的准确条件：
```

传输通道打开不等于领域已经就绪。session 或 generation 由一个服务端或运行时所有者签发，并在客户端释放排队消息前通过正式握手到达；客户端默认值、`0`、缓存身份或待发送消息不能反向创建权威会话。重新连接按产品合同重新取得当前权威身份，不得暗中等同于 reset；显式 reset 必须由同一所有者创建新 generation，并让旧 generation 的请求、分片和终态在一个边界被确定性拒绝。队列清空只能消费已确认的当前身份，不能用 socket `open`、固定延时或乐观本地状态猜测准备完成。

能力快照把“已经配置”“进程在线”“准确端点可达”和“当前可调用”分成不同事实。静态配置可以描述预期目标，进程存活可以描述宿主状态，但只有精确路由、所有者和依赖在当前 generation 中已经就绪时，快照才允许发布可调用 URL、流式 URL 或控制入口；离线、启动中、旧 generation 或路由不匹配时应返回不可调用状态并隐藏这些活动入口。验收至少覆盖握手前已有一条排队请求的首次连接、不断开产品语义的重新连接、显式 reset 后的第一条请求、旧 generation 迟到消息，以及离线到在线过程中能力快照与正式消费者实际调用的一致性。

### 外部参考实现与性能方案

用户指出另一个项目、引擎或已有实现，希望当前项目“也这样做”、直接接入或借鉴时，先把参考实现从目标架构中拆开。当前项目的用户结果、唯一真源、正式生产者、持久化边界、消费者和停止位置仍由当前项目事实决定；参考实现只提供待验证候选，不能因为名称、协议或表面结构相似就成为新的运行依赖。

上层已经形成来源能力台账时，先核对它对应的研究根、版本、完整范围和未知项，再消费其中的独立行为、运行假设与授权边界；不能把过期台账或只覆盖 README 的介绍当成完整来源。实施目标要求吸收能力而来源证据仍不足时，先补齐来源研究，不在目标 schema、目录或代码中猜测参考项目的真实职责。

解释参考项目时，先用用户能够执行和观察的语言说明实际动作、操作中的连续反馈、最终结果，以及它减少了什么理解或操作成本；随后才映射到字段、接口和内部模块。只列参数名、类型或实现组件，不能证明已经理解参考能力，也不能作为当前项目采用它的理由。

先建立：

```text
参考项目中用户实际执行的动作：
操作过程中连续看到的反馈：
最终可见结果和减少的理解或操作成本：
当前项目必须保持的唯一边界：
参考实现完整提供了什么结果：
可独立迁移的机制：
依赖的运行时、平台、编解码、缓存和生命周期假设：
当前项目已经具备、不能重复建立的职责：
整体采用 / 局部吸收 / 拒绝各自会改变什么：
```

候选能力会改变可见产品的对象分类、主导航、主要按钮、工作区或设置层级时，先消费体验路径已经形成的目标对象与入口层级判断，再建立采用位置合同：

```text
目标用户任务、发生频率与当前阻碍的证据：
候选职责：核心对象 / 现有对象操作 / 获取渠道 / 视图或筛选 / 状态反馈 / 可选集成
它产生、读取或改变的现有用户对象：
创建后共享的保存、查找、编辑、删除、恢复和交付生命周期：
现有自然入口及其能够承担的范围：
目标入口：现有统一入口 / 对象内行动 / 次级入口 / 独立工作区 / 不采用
若要成为主入口，现有路径不能承载的目标侧证据：
因此退出或不得新增的平行入口、状态、设置和恢复分支：
从自然入口到正式消费者的可见验收：
```

参考项目的导航结构、显眼程度、功能数量、供应商数量和实现复杂度都不能证明目标项目需要同级入口。结果进入目标项目后若与现有对象共享同一生命周期和主要行动，采用合同默认复用现有对象路径，把差异留给类型、元数据、筛选或上下文控制。只有独立且反复发生的用户结果、不同的关键决定或持续生命周期，以及现有路径无法自然承载的目标侧证据同时成立时，才允许把候选能力提升为主导航、主要按钮或独立工作区。关键证据仍未知而实施会改变核心信息架构时，停止在可选择的入口方案，不先写界面和配套后台再等待用户纠正。

局部吸收或目标原生重写还要建立能力采用合同：

```text
来源规范真源、手工来源和派生视图：
按可观察行为和执行合同识别的独立能力：
一份目标规范记录及其所有者：
由目标规范确定性生成的目录、索引、预览或运行投影：
机器会消费的宿主条件、限制和失败语义：
公开发现、选择、采用或物化入口：
制作期能力还是共享契约，以及判断依据：
来源身份、内容哈希、适用授权和下游通知：
工具拥有的生成文件与用户拥有文件的写入边界：
正式消费者和最终可观察结果：
```

名称与别名只负责发现；同一可观察行为和执行合同只算一项能力。目标项目使用一份目标规范记录表达语义意图、可执行合同和机器会消费的条件，再让目录、搜索索引、预览和其它投影由它确定性生成；不能把参考项目的并行数据文件、展示名称或手工目录复制成目标项目的第二真源。会改变宿主尺寸、资源到达、时间、生命周期、输入所有权或失败收口的要求必须进入可校验合同，说明文字只解释，不能独自承担运行条件。

可扩展字段由生产者的机器可读描述拥有稳定字段身份、默认值、范围、单位、建议控件和是否可动画等语义。消费者只把建议控件映射到自己的界面组件，并通过现有公共编辑边界读写值；不得再维护一份字段清单、默认值表或参数语义。工具已经提供可执行的能力描述、操作发现或参数 schema 时，以该机器可读边界为真源；说明文档是契约消费者，只负责解释和示例，不能复制维护另一份实际操作集合。

能力被找到不等于已经进入产品。完整采用链至少是 `发现或选择 → 公开采用或物化入口 → 目标产物或存储边界 → 正式消费者 → 最终可观察结果`；演示页、样例或画廊只证明预览，不能代替正式采用入口。公开文档中的选择示例必须对当前生成索引实际执行；面向用户的语义搜索存在多种语言或叫法时，由同一规范元数据生成别名和检索投影，不另建手工同义词真源。

先决定它是制作期能力还是共享契约。若生产者只需在制作阶段选择能力并把结果物化进现有自包含产物，正式消费者仍能完整读取既有协议，就保持共享契约不变；若消费者必须识别、编辑或依赖能力身份、参数或语义，则升级产品无关的共享契约并一次迁移所有生产者、存储、消费者、示例和验证器，不能把消费者需要的状态藏在入口代码或私有文件中。

复制、改写或再分发参考代码、配方、素材或生成包时，来源身份、内容哈希和适用授权说明必须随正式产物跨过存储或分发边界；权利或通知义务无法确认时，不把相应内容进入活动产物。确定性格式化和整体重写只用于工具拥有的生成文件；修改源码以及用户拥有的清单、配置或文档时，只改变本次获准的路径和语义范围，保留无关内容、顺序和表达。格式化器、行尾转换或批量改写运行前记录范围与基线，运行后检查实际差异；若工具因格式版本、行尾或全文件重排扩大了改动，就缩小工具范围或从最新基线重新应用本轮修改，不能把机械噪声当成顺带整理，也不能为了生成哈希稳定而重排整个用户文件。

随后使用会触发不同路径的最小代表性工作负载矩阵。只选择本次真实存在的维度，例如简单与复杂内容、标准与快速生产者、新旧持久状态、纯内容与混合媒体、单执行单元与并行执行；不为形式完整穷举组合。参考项目自己的基准只能说明它在自身条件下成立，当前项目必须在同一输入、输出合同和正式消费者上测量。整体依赖只有在它能接管完整责任且不会建立第二套状态、时间轴、缓存或恢复边界时采用；否则逐项吸收已经证明有价值的机制，并明确拒绝不匹配部分。

性能目标同时冻结正确性与速度。先定义标准路径的正式结果、允许精确相等还是具备业务依据的差异阈值、需要保护的工作负载类别和最终消费者；再测量速度。简单夹具通过不能代表复杂内容，单一新项目不能代表旧状态，某个快速后端通过不能代表每个 worker、GPU、浏览器或并发实例都具备同一能力。新增替代生产者、并行执行、缓存捷径或快速后端时，按主路由进入高成本、难复现问题方法的“受验证的高速路径与原子回退”维度。

## 2. 找到真实边界

按当前改动建立一张最小影响图：

```text
输入或用户动作
  → 正式生产者
  → 唯一业务或平台边界
  → 传输 / 持久化 / 原生接口
  → 正式消费者
  → 最终可观察结果
```

### 公共合同先核对身份

跨仓库、跨进程或跨工具消费公共协议、schema、清单或能力描述时，在比较字段前先核对：

```text
合同名称与版本：
权威生产者及其来源身份：
正式 schema 或规范化内容身份：
当前消费者快照的来源身份与内容身份：
机器可读的能力描述或操作发现入口：
```

合同名称与版本相同，只能说明标签相同。正式 schema、规范化内容身份或字段语义不同，就是合同身份碰撞，不能判定兼容，也不能让消费者猜测实际含义；停止普通接入，转入根因治理，由权威生产者建立新的明确版本并一次迁移生产者、同步边界和消费者。没有稳定内容身份时先建立可重复比较的规范化表示或来源哈希，不能用文件名、目录位置或手工复制时间代替。

### 复合交付包先证明合同与采用闭包

一个正式输入由顶层清单、伴随 schema、素材或资源账本、运行时接口、实际资源和采用引用共同决定行为时，兼容身份不是顶层协议名称、版本或单份 schema 哈希，而是这些节点及其引用关系形成的闭包。开始比较前，从权威生产者本轮实际入口递归取得全部正式引用，不根据消费者已有字段或样例反向猜测；为每个节点和边记录：

| 节点或引用边 | 唯一所有者 | 合同、版本与内容身份 | 声明、采用或执行职责 | 正式消费者 | 最终可观察贡献 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

资源进入账本只证明它可被发现，不能证明已经被正式采用。可用性声明与正式采用关系必须分开：场景、配置、数据字段或其它权威入口要引用同一稳定资源身份，消费者再把这项采用编译成自己的执行计划，实际工作单元最后对可见、可听或可使用结果作出可辨认贡献。账本存在、解析器识别、执行计划非空、容器中碰巧存在某类轨道或最终文件能够打开各自只证明一层；任何中间采用边缺失时，对应能力仍未接通。

消费者自行迁移或手写的样例只证明消费者内部链路，不能代替真实生产者的互操作证据。跨项目时继续使用跨项目根共享合同与交付账本：长期回归消费带来源与内容身份的同步快照，跨根验收消费真实生产者本轮输出，并分别证明快照一致和实际互操作。生产者合同、任一闭包节点、采用边、适配器、消费者或执行环境发生相关变化时，只使依赖这些身份的证据失效；受影响边必须从新鲜生产输出重新验证，不能把变化前后的局部通过拼成一个完整兼容结论。

### 产品升级先核对公开身份

产品升级、接替或更名会改变用户看到的名称，而包名、命令、协议、模块命名空间或安装目录可能需要保持稳定时，在修改字符串前建立公开产品身份台账：

| 身份类别 | 唯一真源与当前值 | 允许出现的位置 | 必须迁移或保持的活动消费者 | 退出或兼容条件 |
| --- | --- | --- | --- | --- |
| 当前公开产品名称 | | 用户界面、标题、面向用户的 CLI 能力描述、Skill、活动文档与示例 | | |
| 稳定技术标识 | | 包名、命令名、协议、模块命名空间、安装或数据目录 | | |
| 旧公开名称 | | 已明确标为历史或迁移说明的非活动材料 | | |

公开名称由一个活动产品身份真源拥有，全部面向用户的活动消费者只读取或核对该值；版本化配置和能力档案先判断当前活动版本，再迁移当前消费者，不能让已经退出的历史记录反向决定产品名称。稳定技术标识只有外部合同、数据兼容或安装边界确实要求时才改名，并另行完成协议或数据迁移；不能为了让所有字符串相同而破坏兼容身份。实施前扫描公开名称与旧名称的活动消费者，实施后证明真实界面、公开 CLI 或其它正式入口显示当前名称，并把旧名称限制在明确的历史范围。

只修改内部包名、命令名、协议标识或其它技术标识，而用户可见产品名称没有升级、接替或更名时，不触发公开产品身份迁移；该改动继续按相应公共合同、协议或数据迁移边界治理。

### 公共运行时与配置身份迁移

配置键、环境变量、端口、服务名、运行时 API 字段、进程角色或公共类型从旧架构身份迁移到新身份时，先建立身份迁移台账，避免把同名业务概念误删，也避免只改显示名称留下双路径：

| 旧身份 | 新身份与唯一真源 | 仍然有效的同名业务概念 | 生产者与传输或存储边界 | 全部正式消费者 | 旧身份退出证据 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

“仍然有效的同名业务概念”必须说明它的领域职责和正式边界。例如旧服务身份叫 `memory`，不表示记忆领域的路由、接口或提示文字也应删除；反过来，业务中仍存在记忆概念，也不能替旧端口键、服务别名或环境变量继续存活辩护。残留扫描先使用标识符边界覆盖配置、环境、schema、类型、运行时 API、IPC 或网络消息、启动器、脚本、测试、夹具、文档、示例、生成入口和维护工具，再逐项按职责人工分类；宽泛文本零匹配或把全部同名文字批量替换，都不能作为退出证据。

迁移顺序从唯一真源开始，让正式生产者只接受并产生新身份，再一次迁移传输或持久化表示、公共类型与导出、运行时消费者、启动与运维脚本、测试和夹具、文档与示例。内部迁移完成后不保留旧键回退、双读、双写、旧环境变量别名、旧类型、旧 helper、旧导出或由消费者猜测两种字段的兼容逻辑；只有外部独立发布节奏或用户明确迁移窗口进入最终合同时，才允许带所有者、截止条件和删除验证的兼容层。

结构搜索、配置解析、类型检查和定向单元测试只证明新身份能够被表达、旧结构可能已经退出。完成验收必须从正常启动或正式用户入口开始：权威配置生产者实际读取新键或环境变量，启动器和进程边界把新身份传出，运行时 API、IPC、网络消息或持久记录实际产生新字段，正式消费者从该边界读取，并在状态、连接、脚本输出、界面或其它用户结果中观察到新身份对应的行为。测试不能由消费端手写新字段，也不能 mock 掉正在验证的配置加载、启动、传输或消费边界；旧身份的拒绝或缺失还要由正式入口证明，不能只依赖源码搜索。

### 跨项目根共享合同与交付账本

同一个用户结果会修改或验证两个以上准确项目根，或者公共合同的权威生产者、派生快照与正式消费者位于不同项目根时，在实施前建立一份跨根交付账本。项目根是职责和交付边界，不要求每个根都是 Git 仓库；每个根的 Git 能力只能由该根直接存在的仓库标记证明，不能从父目录、相邻目录或另一个参与项目继承。

| 准确项目根与身份 | 本轮职责 | 权威合同、派生快照或正式消费者 | 获准变化与停止位置 | 正式验证器及实际输入 | 本地完成与互操作证据 | Git、提交、推送与远端状态 |
| --- | --- | --- | --- | --- | --- | --- |
| | 生产者 / 同步边界 / 消费者 / 维护工具 | | | | | 非仓库 / 未提交 / 已提交 / 已推送 / 远端已验证 |

账本同时冻结权威合同所有者、合同名称与版本、规范化内容身份、唯一同步入口和单向同步方向。权威生产者拥有 schema、运行语义、默认值与正式案例；消费者仓库中的 schema、夹具、starter 或其它副本只能是带来源身份的派生快照，由唯一同步入口确定性更新。不能在消费者中手工修补快照，再让生产者反向迁就；也不能在两个根分别维护同一版本的可编辑真源。

共享合同变化按以下顺序完成：

```text
权威生产者更新合同、运行时与正式案例
→ 生产者正式验证器消费本轮结果
→ 唯一同步入口写入带来源身份的消费者快照
→ 消费者解析、状态、编辑、运行与导出链完成迁移
→ 消费者正式验证器消费同步后的准确输入
→ 从真实生产者经过同步边界到正式消费者的跨项目链形成可观察结果
→ 每个项目根分别记录本地与发布状态
```

消费者的正式回归不能默认读取开发机上相邻项目的绝对路径，也不能用“当前机器能找到生产者目录”代替可移植输入。需要长期、确定性运行的合同测试使用仓库内同步快照并核对来源身份；必须连接活动生产者工作区的测试明确标为跨项目集成测试，先取得外部根身份并在缺失时报告受阻，不能让普通干净克隆测试静默依赖它。同步快照通过不等于跨项目互操作通过，跨项目链通过也不等于每个根已经提交或发布。

完成结论分别回答本地实现、各根正式验证、跨项目互操作和每个根的远程发布。一个根是普通目录、存在未提交变化、没有远端或尚未完成正式验证时，准确报告该根状态；不能把另一个根已推送、共同链本机通过或最终产品可见，概括成“所有项目都已发布”。

### 跨项目接入分开实现、互操作、采用和运行绑定

一个能力需要跨项目、跨工具或跨 Skill 接入当前用户实例时，不能把本机测试中连续成功的步骤合并成一个“已经接通”。在写入目标实例配置前，分别建立以下交付状态；每一项都有自己的前置条件、获准写入、正式消费者和允许交付措辞：

```text
能力实现：生产者或公共边界已经具备目标能力
各根正式验证：每个参与根在自己的合同和正式入口下通过
隔离互操作：在已登记且满足双方不变量的新鲜实例中完成真实跨边界消费
当前实例正式采用：用户实际实例满足双方强制不变量，并从正式配置入口启用能力
稳定运行入口：跨会话消费者绑定到有明确所有者、生命周期和升级方式的运行产物
持久配置：配置写入已获授权，且只引用符合其承诺期限的实例与运行入口
发布状态：每个参与根的提交、推送、远端或部署状态分别成立
```

隔离互操作通过不等于当前实例已经正式采用。正式采用前从每个参与项目的活动真源读取当前实例必须满足的存储根、内容真源、版本、能力启用和生命周期不变量，并回读实例的真实状态；不能只从适配器能够运行或样例文件已经产生反推采用条件成立。当前实例违反任一参与系统的强制不变量时，能力实现和隔离互操作可以分别完成，但当前实例采用必须标为受阻：不得写入持久配置、不得静默把不变量降级成建议，也不得为了得到完成结论擅自移动数据。可以在独立合规实例中继续互操作验收，或在消费者支持时使用会话级覆盖；当前实例仍需要用户选择合规根、迁移、明确例外或退出采用。

持久配置引用外部可执行文件时，再读取 `user-environment-governance.md` 的稳定运行入口合同。构建输出、缓存、下载解压或临时目录中的文件即使当前存在并能报告版本，也只形成当前运行证据；它们不能自动成为跨会话绑定。安装、复制或建立稳定工具入口是独立动作，没有相应授权时使用会话级参数或环境覆盖完成隔离验收，并把稳定运行入口和持久配置保持为未完成或受阻。

最终报告按上面的状态逐项给出 **已验证 / 仅诊断 / 未验证 / 受阻**，并列出当前实例不变量、实际运行入口来源、已经写入的配置及其期限、仍需用户决定的动作。不能用能力实现、隔离实例的成功或当前进程能启动，替当前实例正式采用、稳定安装、持久配置或发布背书。

同时记录：

- 内容或状态的唯一真源；
- 所有创建、读取、更新、移动、删除或恢复调用点；
- 导出、复制、保存、下载、同步或最终化等持久操作的接受点，以及接受后 `pending → 输入重校验 → 正式生产者 → 物理结果或证据保全 → 唯一终态 → 正式消费者 → 可见确认` 的所有者；接受后的失败不能绕过账本成为无身份错误；
- 公共类型、命令、事件或扩展接口改变时，所有正式契约消费者，包括生产代码、测试夹具、schema、公共导出、文档、示例、SDK 片段、验证与发布脚本、真实用户链工具、生成物来源和维护工具；
- 运行时、桌面原生层、移动端、远程服务和缓存之间的责任；
- 跨进程生产者的业务结果、诊断日志、进程退出和传输收尾分别由哪个通道表达，哪个消费者可以据此改变任务状态；
- 回调、事件处理器或不返回 Promise 的命令若会派生异步工作，由谁登记这些工作，以及空闲、取消、关闭、重启和测试完成边界怎样等待它们；
- 失败、取消、重试、冲突和关闭时怎样收口；
- 现有测试究竟覆盖哪一层。

### 新增写入能力先建立副作用激活图

新增或启用持久化、缓存、日志、恢复、窗口状态、自动创建目录或其它文件写入时，原本只负责构造对象的调用点也可能成为新的生产者。实施前枚举生产对象的全部构造与启动位置，包括正式入口、CLI、后台任务、桌面窗口、smoke、测试 fixture 和共享 helper，并逐项记录：

| 构造或启动位置 | 触发写入的条件 | 解析后的实际输出根 | 生命周期与清理所有者 | 测试隔离或用户保留合同 |
| --- | --- | --- | --- | --- |
| | | | | |

不能只检查新增保存函数的直接调用者。配置默认值、默认数据目录、初始化顺序或构造时副作用改变后，所有能够实例化该对象的路径都要重新进入影响图。共享 helper 和 fixture 除非合同明确说明，否则不得静默创建工作区、目录、文件、安装运行时、注入配置或替测试满足核心前置条件；需要这些动作时用明确参数或专用 fixture 表达，让“无副作用”“输入无效”“取消前未开始”等测试仍能建立真实前置状态。

在运行会写文件的验证前，记录准确项目状态和已登记输出根的存在状态与内容身份；运行后比较同一范围，把每个新增或改变的对象映射回正式生产者、消费者、保留期限和清理责任。不为此扫描整台机器，也不把用户已有未跟踪文件当成测试残留。新增对象来源不明、落在未登记根、清理失败或与“无副作用”承诺冲突时，该项验证不能宣告完整通过；用户没有允许删除时，按已同意的归档方式处理，未获归档授权则保留并准确报告。

改动会影响产品界面时，再补充一份轻量界面合同：当前用户任务、区域与滚动所有权、控件拓扑、关键状态、设计系统真源、目标视口和最终可见验收。结果需要被确认、标记已读或停止重放时，同时写明哪个活动窗口或表面负责展示，以及只有在内容真实出现、非离屏并具有非零几何后才允许确认；把文本写入隐藏控件、虚拟化容器或尚未呈现的树节点不算用户已经看见。纯后端、CLI 或库改动不增加这一步。

全局页面推进、章节内部演出、局部步进、媒体完成或导航恢复中有两个以上会共同改变连续体验时，轻量界面合同进一步冻结交互架构：列出硬保证、可调整目标、互相制约的要求、每个区域的唯一主架构、进入构图到再次进入的阶段、按输入来源与方向划分的所有权，以及自然反向、保持终态或明确重播的返回策略。多个跨页面症状在局部修正或测试通过后继续出现时，先重新打开这份合同并检查是否叠加了第二套滚动或状态所有者；不能继续增加阈值、冷却时间、追赶动画或恢复分支。

用户结果依赖首次渲染、加载、过场、滚动进入、异步资源到达、媒体播放或自动切换的先后关系时，再建立时间过程合同，而不是只写最终状态：

```text
触发动作与正式接受点：
必须依次出现的可观察里程碑：
每个里程碑的状态与资源所有者：
禁止闪现、空白、重叠、回跳或重放的中间状态：
中断、反向、离开再返回和完整重启怎样处理：
证明每个时刻而非只证明终点的验收证据：
```

最终画面正确不能证明启动过程、资源到达窗口或切换过程正确。时间过程里的每项状态仍必须落回同一生产者、边界、消费者和用户结果，不能为测试另建第二套时序解释。

### 代表性规模、消费者扩散与编辑状态

改动涉及列表、时间线、字幕、节点图、日志流、素材库或其它可能达到大量对象的界面时，在选择控件结构和状态通知前冻结代表性规模与用户操作：总对象数、首屏可见数、活动或选中对象数，以及打开、首个稳定画面、选择、编辑并持久化、首次进入可选面板和再次进入。规模来自产品合同或当前真实数据；没有可靠目标时明确标为待确认，不拿一个小夹具证明高基数路径。

随后建立消费者扩散图：

```text
一次正式数据变化
→ 实际实例化的界面对象数
→ 收到通知的消费者数
→ 重新计算、布局、序列化或跨边界传输的次数与范围
→ 尚未可见或尚未访问的面板、预览器和嵌入运行时
→ 用户看到首个结果与完成一次编辑的时间
```

隐藏、折叠或尚未访问的消费者除非承担首次成功路径，不应在启动时创建昂贵对象、启动嵌入运行时或消费全部通知。被动展示项可以按正式内容合同选择聚合绘制、虚拟化或按可见范围物化，交互对象可以限于当前活动或可见子集；这些是根据可访问性、命中、选择和编辑合同作出的候选，不是所有集合的固定实现。选择延迟创建或缓存时，必须同时定义首次访问的加载与错误反馈、再次访问的复用、状态保持、资源释放，以及快捷键、对话框和信号连接如何取得当前活动实例。

状态事件还要表达具体发生了什么、稳定对象身份和必要版本。无参数的“某处变化”通知不能授权所有消费者重建全部投影，也不能让无关选择变化覆盖本地草稿。编辑表面应把草稿绑定到正式对象身份与基线版本，只在对象真正切换、明确放弃或按冲突合同提交时重载；后台任务与表单可能同时更新同一设置时，表单只提交相对于当前权威状态的脏字段补丁，不能把加载时的完整旧快照写回并覆盖后台新值。

### 状态提交必须到达当前活动投影

同一聚合会被两个以上正式编辑命令、控制器、后台任务、导入器或回调修改，或者界面会在运行中动态增加、移除或重新分类集合对象时，在实现前建立一份活动投影合同：

```text
正式变更入口及各自允许改变的事实：
唯一提交边界、聚合身份与提交版本：
提交成功后发布的语义事件、对象身份、事实类别和版本：
打开中的编辑器、缓存聚合与派生视图怎样共享、协调、失效或重载：
界面绑定实际订阅的框架可观察属性、模型信号或事件：
本地草稿、并发提交和版本冲突怎样保留或拒绝：
无需关闭、重开或手工刷新即可观察的最终结果：
```

优先让所有变更经过同一个活动聚合所有者；入口必须独立提交时，由唯一提交边界发布带稳定身份和版本的完成事件，缓存消费者按合同协调、失效或重载，再允许后续编辑。不能让一个入口直接改存储，另一个入口继续持有无版本旧快照；也不能用无参数全局通知让全部表面盲目重建。存在本地草稿时，后台提交只使相关事实进入版本协调或冲突处理，不得静默覆盖草稿，也不得让草稿稍后把后台新值整份写回。

异步加载的持久化历史、远端基线或初始快照可能与实时事件同时到达时，快照必须携带读取时的聚合身份、基线版本或等价顺序边界，并与基线之后的实时增量交给同一个 reducer 或活动聚合所有者。较晚返回的旧快照只能更新它负责的基线分区，再合并或重放所有更新版本的实时事件；不得用整表替换删除快照请求发出后已经进入界面的消息、任务或状态。无法提供稳定版本时，在加载期间由同一所有者无损缓存增量并在快照提交后重放，不能让快照生产者和事件消费者各自维护一份当前列表。

验收用受控屏障暂停正式快照生产者，让实时生产者经实际事件边界提交至少一项新状态，再释放快照；当前活动表面最终同时包含基线内容和实时增量，并立即允许一次依赖新状态的后续动作。只分别测试快照替换和事件追加，或者由测试直接调用 reducer 手写两边输入，不能证明真实并发链不会丢失结果。

响应式框架中的绑定必须依赖框架能够观察的属性、集合模型通知、计数信号或等价事件。模板或表达式调用一个能够查询最新数据的普通方法，只证明重新调用时返回正确，不证明底层状态改变会触发重新求值。动态集合至少明确空集合到首项、首项到更多项以及移除末项时，哪些可见性、数量、可用性、布局和命中投影更新；为修复一处界面而手工调用刷新函数，不能代替正式状态链。

没有活动缓存、动态投影或多个变更入口的普通单入口状态修改不增加这份合同。触发条件成立时，它补充消费者扩散与编辑状态，而不建立第二套事件总线、状态容器或界面模型。

名称相同不表示职责相同。两条路径只有在输入、责任、输出、消费者和停止位置都相同时才可合并。

文档和示例如果教用户或扩展作者调用公共接口，就是契约消费者，不是发布前再顺手更新的说明材料。验证脚本、发布前检查和真实用户链工具同样是公共接口的正式消费者；接口或生命周期状态迁移时必须与生产调用点一起迁移，不能等昂贵的最终链首次运行时才发现它仍调用旧入口、私有状态或已经退出的 helper。事件处理器本身被 `await` 也不代表生命周期已经收口：只要它在内部启动了未登记的异步工作，任务就可能在空闲、关闭或测试完成之后继续改变状态。

### 工作区存在其它写入者时

把前后结果解释为同一路径被外部改写前，先消费验证输入覆盖合同：从目录枚举、清单、正式事务或其它权威发现结果取得准确路径并直接复用，记录每次工具实际收到的字面路径、工作目录和解析后的稳定身份。身份不同的结果只能分别描述各自对象；“未找到”不能证明另一条近似路径对应的文件曾经存在或已经消失。只有同一身份在可比条件下确实变化，才进入外部写入者判断和后续等待，不能先把同步软件、生成器或其它进程当成已经成立的原因。

如果文件位于同步目录，项目运行着生成器、编辑器监视器或开发服务器，另一个 Agent、终端或进程也可能写入，或者状态在本轮没有执行对应动作时自行变化，就把这些来源作为并发生产者纳入影响图。开始写入前记录受影响路径的存在状态、内容身份和项目状态；只记录当前结果会消费的范围，不为此扫描整台机器。

在覆盖、恢复、格式化、批量改写、暂存或用旧验证继续下一步之前重新读取这些路径，并把变化分为：本轮动作直接产生、开始前已经存在、已确认的正式生产者产生、外部或来源未知。前两类按原范围处理；正式生产者需要进入生命周期与完成边界；外部或未知变化不得被恢复、覆盖、混入本轮修改或用作成功证据。只冻结与变化路径冲突的写入动作，安全的只读调查可以继续。

外部变化若确实是当前用户结果需要的新输入，先确认它的来源、产品含义和唯一所有者，再更新生产者、清单或存储边界、全部消费者与验收。文件刚好出现在运行目录、现有布局能够容纳或测试夹具已经支持，都不能代替完整迁移。外部变化与当前结果无关时保留原状并从本轮写入和验证中排除，不能为了得到干净状态使用恢复或删除。

把写任务委派给共享同一工作区的 Agent、线程或其它执行单元前，主任务先冻结委派合同：准确用户结果、允许修改的根与文件、禁止重叠的所有者、必须运行的验证，以及返回时必须交付的实际变更、证据、未验证承诺、仍在运行的进程和残留。多个写入者不得同时拥有同一文件或同一业务边界；必须并行改相邻消费者时，由主所有者明确合并顺序和最终迁移责任。

共享写入者结束、失联或中断后，只要它可能已经改变状态却没有完成上述交接，就把现有改动视为**未验证的部分交付**，不能根据任务状态、先前计划或文件时间推断完成。主所有者要从当前工作区重新清点实际变化和内容身份，把每项变化映射回生产者、边界、消费者与权限范围，检查是否留下半迁移、并行实现或未归属文件，再从这份最新状态取得受影响检查的新鲜退出证据。并发期间被观察到的中间状态不是产品失败证据；只有冻结后的交接状态或主所有者复核后的稳定状态才能进入缺陷与完成结论。

## 3. 派生边界不变量

当改动涉及跨进程或网络通信、持久化、临时状态、恢复、凭据、运行时解析，或者源码之外还有生成文件、脚本包装器和原生产物时，在影响图完成后派生本次适用的不变量。这里只检查受影响的事实和边界，不把它扩张成与任务无关的安全或平台清单。

| 维度 | 实施前必须回答 |
| --- | --- |
| 权限归属 | 谁能创建、读取、改变、取消和恢复；连接、会话、客户端、进程与持久化所有者怎样精确对应；身份不匹配时在哪个唯一边界拒绝 |
| 状态生命周期 | 创建、持久化失败、等待、断开、重试或重新调度、取消、终态、重启恢复和关闭时，状态由谁拥有、何时转移、何时清理 |
| 数据表示 | 同一值以原文、序列化或转义文本、结构化字段、流式分片、参数、环境、请求头、日志、事件和持久化记录出现时，分别在哪个正式边界验证、转换或清理；分片边界改变时结果是否等价，结束时由谁完成 flush |
| 边界转向 | 重定向、代理、重试、回调、并发写入、关闭和中止是否会改变目标、顺序、所有者或失败收口；改变后是否仍满足原合同 |
| 实际运行入口与产物 | 用户入口及其子进程实际选择源码、生成文件、包装脚本、解释器还是原生产物；选择顺序、绝对路径、新旧判定、工作目录和相邻依赖或资源的精确允许集合由谁决定 |

协议、schema 或持久格式变化时，数据表示不变量必须落到正式序列化器真正产生的文件、数据库记录或线上消息。让该实际表示通过正式 schema、存储或线协议校验器，并分别检查字段省略、显式 `null`、默认值注入、类型与版本；只验证序列化前的内存模型，或者由测试手写一份“等价 JSON”，都不能证明生产边界成立。

跨进程辅助程序、后台宿主或事件流存在时，状态生命周期和数据表示还要形成一份终止合同：进程从创建到连接前由谁拥有，连接和退出是否有界；终止原因、结果状态和传输收尾是否分别表达；终止事件何时成为不可丢失事实，读取器、订阅者和最终消费者何时排空；主动停止造成的取消在哪个生产者边界被识别；正常关闭需要什么退出码；标准输出和标准错误的编码由哪一端声明和哪一端解码。不能等到 EOF、通用失败状态或乱码日志出现后再猜真实原因。

跨进程生产者还会产生任务结论、生成结果或其它业务结果时，业务结果使用与诊断文本分离的结构化权威通道，并定义至多一次、必需字段、版本和缺失结果的失败语义。stdout、stderr、日志尾部、退出码和 EOF 只证明各自的文本、进程或传输事实，消费者不得从自然语言、最后一行或内容关键词推断业务结果。完整事件和原文由无损持久真源保存；列表或任务摘要可以有界，但必须明确截断并提供读取完整原文的稳定游标或身份。

流式解析、脱敏、编码转换和帧组装要满足分片不变量：对同一字节序列任意改变 chunk 边界，最终输出和识别结果仍与一次性处理等价；敏感模式、字符编码和结构化帧允许跨分片，结束时必须 flush 尚未输出的安全尾部。测试至少把关键 token 或帧边界拆在每个可疑位置，并同时检查不泄漏、不丢失、不重复和周围普通内容逐字节保持。

每个适用维度都写成：

```text
不变量：
正式生产者：
执行或拒绝它的唯一边界：
失败、取消、重启和关闭怎样收口：
从用户入口观察的证据：
```

临时数据“没有写入数据库”并不等于生命周期完整。若任务重启后必须知道某项临时依赖已经丢失，持久化记录应保存不含该数据的所有权或需求标记，让正式恢复路径进入明确的等待或失败状态；不能静默换用另一个依赖，也不能把临时值转存到参数、环境、日志或事件中。

源码、普通构建和用户实际运行的产物是不同证据层。生成或原生产物存在时，必须从真实入口验证父进程与子进程的解析结果、产物身份、新旧关系和完整依赖或资源闭包。内容清单既要逐项验证声明文件的身份，也要比较清单允许集合与运行目录实际集合；缺失、改变、额外陈旧文件或来自另一构建的相邻依赖都必须失效。生成目录应从新鲜暂存或确定性清理后的目录形成，不能把上次构建遗留文件一并签入新清单。用户没有授权生成或打包时，合同应让过期产物明确失效，并把尚未生成的层级列为证据缺口，不能继续静默运行旧产物。

## 4. 读取适用模板

项目配置存在时，按固定模板版本读取当前改动涉及的不变量、检查和人工验收。没有配置时，以当前源码和项目规则完成同样判断，不强制采用模板。

模板用于提前发现：

- 项目真源被数据库、缓存或镜像副本替代；
- 前端和原生层都在决定同一状态；
- 平台能力已经调用，但权限、配置或生命周期没有接通；
- 桌面窗口、移动端、远程同步或构建链只有一侧实现；
- 旧类型、旧 helper、旧导出和旧恢复路径仍会继续被调用；
- 测试只给消费者手写结果，没有经过正式生产者和边界。
- 可见界面只有局部样式决定，没有用户任务、状态族、布局所有权或设计系统真源。
- 可选或高级能力仍在核心对象、主入口、默认状态或错误文案中充当前提。

模板不替当前项目选择业务方案。发现模板与用户目标冲突时，列出冲突和项目覆盖候选，由上层决定，不在此方法内修改模板。

## 5. 冻结最终合同

开始实施前确认：

| 项目 | 必须回答 |
| --- | --- |
| 真源 | 最终只有哪个对象或文件负责事实 |
| 行为基线 | 当前目标、当前实现与历史原因分别由什么来源证明；来源冲突和未知项怎样收口 |
| 业务不变量与复杂度 | 普通工作负载、已证明不变量、明确例外和不支持场景分别是什么；哪些最坏情况没有证据、不得提高核心路径成本；例外由哪个可观察信号启用 |
| 内容资格默认值 | 哪个正式事件证明第一份合格内容真实进入；默认怎样首次分配、怎样尊重用户显式覆盖，以及默认对象退出后怎样收口 |
| 语义记录与批次状态 | 修改哪些事实时必须原子更新来源、证据、权威性、资格或关系；正式派生消费者读取什么；固定计划与连续决策批次分别使用哪个版本，后一步怎样取得已提交状态 |
| 计划与实际变更 | 用户授权、冲突和观察集合分别是什么；观察是否覆盖全部合同内副作用；实际变更集怎样从权威提交或前后事实产生；版本、事件、历史、撤销、缓存和活动投影怎样只消费实际结果 |
| 自动化协议入口 | 已经确定的消费者是谁；现有 CLI、API 或能力发现仍缺什么；新协议怎样只映射唯一公共应用边界；哪些业务任务、状态、持久化、恢复和参数语义禁止复制 |
| 实时交互边界 | 谁签发 session 与 generation；什么握手证明领域就绪；首次连接、重新连接、reset、排队请求和过期消息怎样收口；能力快照何时才允许公开可调用入口 |
| 设置提交范围 | 用户动作准确选择哪些稳定设置身份；多阶段链路中各设置属于哪个决策阶段，当前证据达到已经接通、活动运行时已经应用还是对目标结果有效；哪些同级项必须保持不变；全部目标怎样经过一次配置提交发布；失败时旧的持久状态与活动状态怎样保全 |
| 分区语义 | 哪个稳定键定义语义分区；哪些差异、空缺、冲突或变化必须在分区内先计算；何时才允许合并；最终结果怎样保留来源身份 |
| 接口 | 生产者和消费者通过哪个稳定边界交互 |
| 迁移 | 哪些调用点、类型、状态和数据需要一次迁移 |
| 退出 | 何时证明旧路径可以退出，怎样检查残留 |
| 失败 | 错误、冲突、取消、重试和恢复由谁处理 |
| 平台 | 每个平台哪些行为一致，哪些是明确差异 |
| 运行 | 用户入口实际选择哪个可执行产物，怎样证明它来自当前源码和配置 |
| 目标覆盖 | 本次变化影响哪些平台、编译目标、构建 profile、feature 与条件编译分支；宿主测试、生产构建、静态检查和目标平台编译各自证明什么 |
| 产物闭包 | 父子进程、包导出、相邻依赖和资源实际解析到哪些文件；清单允许集合怎样与运行目录实际集合完全相等，额外陈旧文件怎样拒绝 |
| 跨进程结果 | 业务结果、完整日志、进程退出和传输收尾分别由谁生产与消费；分片、flush、关闭和缺失结果怎样收口 |
| 序列化合同 | 正式序列化器实际产生什么文件、记录或消息；由哪个 schema、存储或线协议校验器检查；字段省略、显式 `null`、默认值、类型和版本怎样表达 |
| 执行环境 | 本次使用哪个终端、绝对工具路径、包或缓存根和必要环境变量；这些事实来自项目真源、用户环境档案还是本轮只读检测；多层工具链的父子进程、工作目录、Shell 与路径语法、继承环境、生成命令和正式消费者怎样形成一份执行闭包 |
| 执行替代 | 准确受限层、正式或诊断分支身份、被绕过的正常入口承诺、目标与临时根、产物及预期体积、正式消费者、清理授权与执行者、失败或中断残留分别是什么；创建前的最小预演和使用后的目标、消费、清理证据怎样取得；外部条件改变后怎样从新鲜状态重新运行同一个正常入口 |
| 路径预算与根所有权 | 解析全部文件系统别名后的规范化真实根是什么；共同消费者的最窄路径预算、最长合法后缀和保留余量是多少；哪个文件生成系统拥有短工程根；公开创建入口怎样返回真实路径；源素材与工程状态怎样分离；接近和超过限制时怎样失败 |
| 公开产品身份 | 当前公开产品名称、稳定技术标识和旧公开名称分别由什么真源拥有；哪些活动消费者必须迁移；哪些历史位置允许保留旧名称；真实入口怎样证明当前名称 |
| 连续收口 | 用户是否要求自行迭代；内部轮次怎样复用原结果和权限；什么新证据允许继续，什么情况必须停止或重新授权 |
| 交付承诺 | 每项用户可见承诺的正常入口、实际分支、生产者、边界、消费者、最终证据和当前状态是什么；哪些测试开关或诊断动作绕过了承诺 |
| 门槛适用性 | 每项验收的规则来源和精确触发条件是什么；本次变化怎样命中；验证器实际覆盖哪些输入、分支和承诺；它属于适用且必需、辅助、范围外还是用户取消，怎样影响完成结论 |
| 交互架构 | 多层滚动或时序体验选择哪个唯一主架构；硬保证与代价、阶段生命周期、方向性输入所有权、返回策略和旧控制器退出条件是什么 |
| 时间过程 | 哪些里程碑和禁止中间状态必须成立；一次性状态在哪个生命周期接受、保留和重置 |
| 代表性规模与消费者扩散 | 目标对象数和关键操作是什么；一次变化实例化、通知、重算和跨边界消费多少对象；隐藏或未访问消费者何时才允许启动；首次访问与再次访问怎样验收 |
| 语义事件、编辑状态与活动投影 | 事件表达哪个对象、事实和版本；草稿怎样绑定与处理冲突；并发后台更新存在时表单怎样只提交脏字段补丁；缓存聚合怎样协调、失效或重载；界面绑定消费哪个框架可观察依赖 |
| 技术迁移与呈现 | 实现责任怎样迁移、哪些可见关系保持、哪些呈现变化另行授权，以及保护区等价与改版区目标怎样分别证明 |
| 参考能力采用 | 来源能力台账对应哪个研究根与版本；候选在目标项目中属于什么用户对象和职责类型、与现有对象共享哪些生命周期与行动、入口层级由什么目标侧证据支持；目标规范记录和确定性派生视图由谁拥有；公开采用或物化入口怎样把选择送到正式消费者；制作期能力是否足够，何时必须升级共享契约；来源、哈希、授权和写入所有权怎样随产物成立 |
| 跨项目根交付 | 各准确项目根的职责、权威合同或派生快照、唯一同步方向、正式验证器、可移植测试输入、本地完成和互操作证据是什么；每个根的仓库、提交、推送与远端状态怎样独立成立 |
| 当前实例采用与运行绑定 | 能力实现、各根验证、隔离互操作、当前实例正式采用、稳定运行入口、持久配置和发布分别是什么状态；当前实例满足哪些参与方强制不变量；持久消费者引用的可执行文件由谁安装、升级和清理；缺少采用条件或安装授权时怎样停在会话级验证而不写长期配置 |
| 验证 | 单元、集成、真实生产链和用户链各证明什么 |
| 断言真源 | 每项断言由哪个正式生产者或边界拥有；测试怎样读取实际事务、路径、时间和当前界面元素，而不建立第二个分配器、时钟、状态机或恢复解释器 |
| 写入激活 | 新增持久化、缓存、日志、恢复或自动创建目录后，哪些正式入口、构造点、smoke、fixture 和 helper 会成为生产者；各自解析到哪个输出根，怎样隔离、保留或收口 |
| 测试副作用 | 音频、视觉、窗口、输入、文件、网络、账号和系统资源会产生什么可观察影响；怎样使用满足同一合同的最低扰动输入并准确停止本次生产者 |
| 机械改写范围 | 格式化、行尾转换和批量改写获准改变哪些路径与语义范围；运行前基线和运行后实际差异怎样核对；无关全文件噪声怎样退出 |
| 证据有效期 | 哪些源码、配置、产物、测试驱动、视口和外部写入者共同决定当前证据；后续相关修改使哪些结论失效，长时间或高成本验证应在什么冻结点运行 |
| 权限 | 本次是否允许写入、运行、删除、提交或发布 |

兼容层只有在外部协议、独立发布节奏或用户明确迁移窗口确实需要时才进入合同，并写明拥有者、截止条件和删除验证。内部重构不能把长期双路径当成“稳妥”。

### 迁移先预检，再进入昂贵全量回归

schema、公共接口、公开能力身份或确定性生成源发生迁移时，在第一次昂贵全量测试前先从最终合同列出本次改变的真源身份、旧身份和全部直接消费者，并执行迁移预检。预检至少核对硬编码旧版本或旧操作身份、工具拥有的生成快照、模型或列表角色、国际化生成输出、公共能力描述及其消费者、测试框架实际收集的唯一身份，以及被本次变化触发的架构或静态预算。未触及这些边界的普通局部改动不增加该步骤；不能仅因仓库较大或改动相邻就启动全面迁移扫描。

先运行能够分别证明合同、迁移器、生成链和直接消费者的定向检查，修复预检发现的身份残留、漏生成、漏收集或预算问题；随后冻结相关代码、配置和测试驱动，再运行适用的昂贵全量回归。全量回归发现新问题时，先把它归入产品链、环境、测试驱动、收集边界或静态门槛，运行最小定向回归取得根因证据；只有影响全局、触及其它消费者，或项目规则明确要求时才重新运行全量套件。这样减少的是无信息的重复长测，不是削弱最终回归门槛。

## 6. 设计真实验收

测试按风险选择，但关键链至少包含：

1. 正式输入或用户动作。
2. 正式生产者实际生成结果。
3. 结果穿过真正的传输、持久化或原生边界。
4. 正式消费者读取。
5. 用户在界面、文件、远程状态或导出中得到最终结果。

可以在边界外部 mock 昂贵或不可控依赖，不能 mock 掉本次正在验证的边界。消费端手写一个“像生产者结果”的对象只能测消费者，不能证明核心链。

参考能力吸收还要从一份新鲜目标状态执行公开发现与采用示例，让正式入口生成或物化目标产物，再由正式消费者读取并形成最终结果。重复生成应得到相同规范身份和派生视图，重复行为应被拒绝或合并为别名；来源与授权记录必须出现在实际下游产物中。断言读取规范语义和平台实际测量结果，不比较浏览器、序列化器或格式化器可能合法归一化的偶然字符串。演示页面通过、目录文件存在或消费端手写等价对象都不能替代这条链。

先按门槛适用性表执行适用且必需的检查，再选择会改变结论的辅助检查；范围外检查不进入本次完成条件，用户取消项按更新后的完成合同处理。随后按证据覆盖表逐项执行正常入口和实际分支。某项只能通过测试开关禁用、手工状态注入或诊断操作绕过时，把它标为未验证或仅诊断，并准确说明已证明的是哪一段；不得让没有经过正常触发的承诺借用相邻分支的证据。

每项关键断言都要注明它消费哪个正式真源。事务型操作先记录动作前的事务身份集合，动作后等待实际新增事务，再从该事务读取真实目标路径、终态和时间；不能根据成功次数预测文件名，不能用测试自己的计数器或时钟复刻生产规则。生产者会动态刷新、虚拟化或重建界面元素时，每次状态变化后从当前活动树重新取得元素，不能复用旧引用、旧矩形或缓存坐标。

活动投影合同被触发时，真实链保持同一编辑器或界面打开：从空集合通过正式入口产生首项，再增加一项并移除到空，逐步核对提交版本、活动缓存、可观察依赖以及可见性、数量、布局和命中结果。随后让另一个合同内正式入口修改同一聚合，证明当前表面无需关闭重开或手工刷新即可显示该提交，并立即完成一次依赖新状态的后续编辑。只证明重新打开后持久状态正确，或测试直接调用刷新方法，只覆盖存储或内部刷新，不证明提交已经到达活动消费者。

生产者输出集合、关系或多个合法对象时，每项关键断言还要注明目标对象的稳定语义身份和事实类别。真实链先从正式生产者的本轮结果取得目标 ID、名称、类型或合同规定的其它身份，再沿边界找到同一对象；对象总数、列表位置和当前选中项只有在它们本身属于产品合同时才能作为断言。把可编辑或持久事实与派生或瞬态投影分开：前者由权威状态、持久化和重开证明，后者由正式计算或展示消费者证明。生产者新增合法对象是输入数据变化，不能据此断言消费者丢失、重复或选错对象。

运行真实生产者前先建立测试副作用合同，盘点音频、视觉、窗口、键鼠输入、文件与目录、网络、账号、设备、时间和后台进程的可观察影响，并选择仍能证明同一边界的最低扰动输入。音频链路优先使用静音或不可听输入证明传输、编码和解码，振幅与信号质量离线分析；不得播放持续刺耳的测试音。用户对测试副作用提出异议时，立即停止准确的生产者，并从调用点、工作流、说明和静态检查中退出导致该副作用的测试模式，不能只把音量调低后继续。

验证新增文件写入能力时，实际测试必须消费副作用激活图：让每个相关入口使用已登记且隔离的输出根，测试结束后比较运行前后的项目状态和这些输出根。只断言 API 返回、目标文件存在或临时目录对象离开作用域，不能证明仓库根、默认用户目录或共享工作区没有留下旁路状态；残留检查发现的新对象要先追到真实生产者，再依据清理与归档权限处理，不能为了得到干净结果直接删除来源不明的文件。

涉及后台服务、调度器或其它有状态运行时时，重启验收先通过权威端点、命名端点对应的进程标识、锁文件或服务管理器确定确切实例，处理好正在运行的工作并记录重启前的正式消费结果；随后只停止该实例、重新启动，再由同一个消费者核对状态、日志、调度或恢复结果。按宽泛进程名终止一组进程，不能证明目标服务真的完成了恢复。

每条测试、扫描和审计命令都要单独证明执行成功并立即保留退出状态，不能让后续命令掩盖前一条失败。只有扫描器成功运行后，零匹配才表示零发现；残留搜索应使用能区分标识符和普通文字的边界，并检查命中项，而不是把过宽正则的误报直接当成架构残留。

每项验证还要建立输入覆盖合同：

```text
验证项：
预期覆盖对象及内容身份：
对象标识的权威发现来源与传递方式：
每次工具实际收到的字面输入、工作目录或命名空间：
各次输入解析后的稳定对象身份，以及是否相同：
工具实际选择的输入、版本、过滤和排除项：
未覆盖或无法确认的对象：
执行状态与退出语义：
允许的结论：通过 / 零发现 / 未覆盖 / 未知 / 失败
```

输入合同由本轮候选对象、生产版本和预期消费者决定，不由验证器碰巧看到的内容反推。命令退出成功，但实际输入为空、仍指向旧版本、遗漏候选对象或被未经核对的排除规则遮蔽时，该项只能记为未覆盖或未知。验证器能报告输入清单、数量或内容身份时直接核对；不能报告时，用与它同一选择语义的只读预演、清单或小型已知对象试验证明覆盖边界。多个探测只有在实际输入与解析身份相同、执行成功且条件可比时，才能共同证明同一对象发生了变化；身份不同只证明分别查询了不同对象，不能触发同步、并发写入、缓存、等待或重试结论。单次稳定验证没有跨观测比较时，不需要额外制作对象对照表。

源码、配置或依赖会按平台、编译目标、构建 profile、feature、条件编译或打包入口选择不同生产路径时，再建立目标覆盖矩阵：

| 变化事实 | 宿主或测试目标 | 正式目标、profile、feature 与条件分支 | 必需命令 | 正式消费者 | 最后一次相关变化后的证据 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

宿主上的单元或集成测试只证明实际参与该次编译和运行的分支；被目标条件排除的导入、类型、资源、权限和生命周期代码必须由对应正式目标编译或运行。测试、生产构建、静态检查或 lint、目标平台检查和真实用户链有不同退出合同，任何一项通过都不能替代另一项。目标工具链当前不可用时，把对应目标标为未覆盖或受阻，不能借宿主侧绿色结果宣告跨平台完成。最后一次修改只使矩阵中受影响的目标和消费者证据失效，但该目标必须重新取得独立退出状态，不能与修改前的其它层拼成一次完整通过。

多项验证开始前标明前置条件、相互依赖、是否必需以及各自产生的证据。前置条件尚未确认的可选探测先单独执行，不能与确定性检查放进会整体失败的批次。相互独立的检查可以并行，但编排器必须逐项保留输出、错误和退出状态；如果一项异常使其它检查结果无法返回，该批次本身不具备证明力。已经成功且证据仍新鲜的检查继续保留，只补跑被遮蔽、未执行或状态未知的项目。

可能长时间运行的下载、构建、原生检查或测试，在执行前写明可观察阶段、后台进程标识、日志或产物进展、成功与失败退出证据、允许的时间或成本边界，以及重试前怎样证明原任务已经结束。外层等待超时后先观察原进程、日志和产物；仍有进展时继续观察原任务，不启动重复执行。停止必须由成功退出且产物可消费、明确失败退出、进程消失且无产物、连续观察无进展并取得诊断证据，或达到用户明确边界之一支持。

验证计划同时记录证据的生产版本和失效条件。影响同一生产者、边界、消费者、测试驱动、产物或最终视口的后续修改，会使对应旧证据失效；只重跑受影响层，但不能把修改前的通过与修改后的局部结果拼成完整通过。长时间浸泡、资源占用和高成本真实链只在相关生产代码、配置与测试驱动冻结后运行，运行期间再次发生相关修改就重新建立该项证据。

真实链路测试失败时，预先规定怎样区分环境、测试驱动或夹具、正式产品链和最终断言。动态或虚拟化界面需要从当前活动树重新取得元素并使用正式交互语义；有瞬态依据时允许一次有界原样重跑，稳定复现后修复测试边界。不能修改产品来迁就测试驱动或夹具，也不能降低可见性、生命周期或产物标准换取绿色结果。

协议、schema 或持久状态迁移的代表性链至少覆盖：当前版本从零新建；由旧版本正式生产或保存的真实历史状态进入一次迁移；正式序列化结果通过当前合同校验并由当前消费者读取；迁移失败时原状态和身份保持可恢复；迁移后关闭并重新打开仍得到相同或已明确授权改变的用户结果。消费端直接手写旧对象或迁移后对象，不能替代旧生产者、正式迁移器和当前消费者组成的链。

对于视觉和交互问题，自动测试之外还要写清实际窗口、屏幕尺寸、主题、DPI、输入方式和用户动作；截图存在不代表交互成立。

存在生成文件、脚本包装器、解释器或原生产物时，从用户实际入口和它启动的子进程记录最终解析到的绝对路径、产物身份、新旧判定和依赖或资源集合，并让正式消费者使用该闭包完成代表性结果。清单测试同时篡改一个声明文件、删除一个必需文件、加入一个未声明陈旧文件，并证明三者都会被真实入口拒绝。源码测试、某一层构建成功、文件存在或只校验清单内已有文件各自只证明一层，不能替代运行时选择与集合闭包证据。

实现完成后交付本次预防合同的实际结果并停止。只有用户在请求开始时同时明确要求 Project Steward 自我进化，才把新的完成证据交给对话学习路径；项目自己的长期事实写回原有正式来源，不为了留痕扩大写入权限。

## 7. 输出合同

第一段直接说明当前方案能否开始、哪项 Project Steward 方法或项目规则已经前移使用，以及最大的前置问题。随后交付：

1. 行为差异。
2. 读取并通过适用性判断的方法和项目规则，以及实际采用、调整或排除的位置。
3. 真源与影响图。
4. 派生边界不变量、适用模板与触发条件。
5. 最终接口、迁移和旧路径退出条件。
6. 失败与恢复边界。
7. 真实测试和用户链。
8. 本次停止位置。

用户只要预防或计划时到此停止。用户同时要求实现时，该输出成为后续完成定义；实现中发现边界事实不同，先更新合同并说明影响，不能在下层悄悄换方案。
