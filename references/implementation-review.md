# 已实现产品体验的真实验收

只有用户要求检查实际运行、已实现或生产可用结果时使用。设计推演、源码审查和确定性脚本都不能替代真实入口中的任务完成、理解与恢复，以及最终画面和操作结果。

自动验收依赖本地服务、浏览器调试端点或辅助进程时，启动前先探测所需端点，并记录现有所有者的可执行文件、参数、工作目录和项目来源。现有端点只有在能够证明它服务于本轮项目和当前产物时才可复用；缺失时只启动缺失部分，同时记录发起进程和最终占用端点的进程。包装器提前退出或子进程重新托管时，不能根据启动命令推定所有权。产品自然入口尚未开始前发生的端点、驱动或夹具失败，结论是环境或验证器未就绪，不是产品回归。结束后只停止由本轮启动且能够证明归属的最终进程；预先存在或归属不明的进程保持不动，除非用户明确授权。

桌面 GUI 的启动体验从用户实际使用的快捷方式、包装脚本或等价正常入口开始，不直接运行内部 `main` 或解释器替代。Windows 包装入口由实际宿主解析执行，从启动前记录新进程和顶层窗口，直到主窗口稳定或失败完成；主窗口、辅助窗口、托盘、通知、控制台、终端标签和脚本宿主错误框逐项与可见表面合同对应。主窗口出现、包装器自身退出码为零或内部解释器单独可运行，都不能替完整进程树没有泄漏意外窗口背书。

能用静音或不可听输入验证音频传输、编码与解码时，不播放持续测试音；信号振幅和质量使用离线分析。用户对任何验收副作用提出异议时，立即停止准确生产者并退出对应测试模式，不以降低强度或换一个近似来源继续。

## 2. 走真实链路

```text
用户自然入口或操作
→ 数据、状态或素材由正式生产者产生
→ 存储、网络或进程边界
→ 当前生产组件读取
→ 用户理解、完成并使用结果
```

关键测试不能由消费端手写假数据、追加节点、覆盖选中状态或 mock 掉正在验证的核心链路。无法取得真实生产数据时，说明证据缺口，不把替代数据描述成通过。

验收开始时读取已经冻结的接受差异台账。用户明确看见并接受的现有瑕疵不再被通用质量检查列为本轮失败，也不能在末尾以“最佳实践”为由重新扩大范围；仍需证明本轮改动没有放大该差异、传播到其它对象或新建同类缺陷。新证据表明它已经妨碍主要任务、正式消费者或用户点名结果时，把它作为范围变化交给上层重新决定，不能在验收层自行改写合同。

系统性的体验审查按核心任务选择相关入口、表面、状态和视口，不要求为了“全面”浏览无关页面。实施后的验收还要检查同一有效行动再次执行、失败后恢复和离开再返回，确认结果由正式链路产生，而不是只证明第一次点击有响应。

### 直接操作按入口矩阵验收

拖动、缩放、区间调整、画布移动或其它直接操作改变一个或多个对象时，从互动合同读取选择集合、持久关联、本次操作集合和等价入口，建立实际入口矩阵：

| 操作入口与输入方式 | 选择与关联状态 | 预期本次操作集合 | 目标映射 | 中间可见反馈 | 释放结果 | 取消与退出结果 |
| --- | --- | --- | --- | --- | --- | --- |
| | | | | | | |

从每个合同内等价入口使用真实指针、键盘或触摸完成按下、中间移动、释放和取消；多对象关系还要覆盖关联有效、关联解除、单选和显式多选。验收时让父级滚动、手势或拖拽容器保持活动，证明自然输入实际取得并保持正确捕获；祖先容器窃取输入、对象因半发布状态变为不可见或某个成员入口中途取消，都属于产品失败。直接调用内部处理器、控制器方法、拖动 helper 或提交函数只能作为计算层证据，不能证明真实输入链成立。

临时选择或模式还要逐项执行合同内的空白或无目标区域输入、平台取消键、明确清除动作和模式切换，核对选择、当前操作、持久关联、焦点和后续命中分别得到规定结果。入口矩阵通过后，再从正式存储或状态边界读取最终对象身份、位置、关系和选择状态；画面移动或函数返回正确不能代替正式提交成立。

### 动态状态必须在不重开界面的情况下进入活动投影

预防合同命中多个正式变更入口、缓存编辑器或运行时动态集合时，从自然入口打开目标表面并保持它活动。先记录权威聚合身份与版本、活动缓存版本，以及界面可见性、数量、可用性、布局和命中状态；随后通过每个合同内正式入口改变同一聚合，取得本次提交的稳定身份与版本，观察语义事件到达、活动状态完成协调或重载，并由框架可观察属性、模型信号或事件驱动当前画面更新。验收不得关闭重开、切换页面、直接调用刷新方法或用固定延时碰巧触发重新求值。

动态集合至少走完“空集合 → 第一项 → 更多项 → 移除末项后重新为空”，逐步核对首个对象出现、集合数量、空态与操作区可见性、布局和命中。另一个正式入口或后台任务能够修改同一聚合时，在编辑器保持打开并存在相关草稿的情况下触发一次修改，证明无关草稿不会被覆盖、相关冲突按版本合同处理；界面更新后立即执行一次依赖新对象或新关系的后续编辑，再从权威边界读取结果。重新打开后状态正确只证明持久化，不能证明活动投影链成立。

### 技术迁移先证明呈现保护合同

React、Vue、原生框架、播放器、状态架构或其它实现迁移触及可见产品时，从改动前预防读取实现迁移与呈现保护合同。使用同一自然入口、真实内容、目标视口、媒体对象和可比较时刻，分别记录迁移前基线与当前结果，至少覆盖最早可见表面、加载过程、首个稳定页面、第一次主要操作、返回或恢复，以及本轮承诺的桌面、窄屏或其它平台状态。

保护区先按可见与行为等价验收，获准改变的区域再按新的目标合同验收。迁移和改版可以由同一构建交付，但不能用改版区的“更好看”抵消保护区回归，也不能用保护区保持原样证明改版目标已经完成。组件已经拆分、框架已经替换、状态测试通过和单张最终截图只证明中间层；加载动画、首屏媒体和自动互动等时序表面需要从对应触发前开始取得连续证据。

### 时序结果建立逐里程碑证据

启动、加载、过场、滚动进入、异步资源、媒体播放或自动切换的正确性必须从触发前开始记录，不能用稳定终点反推中间过程。根据当前合同建立时间线：

```text
触发动作或请求被接受
→ 最早可见表面或前一稳定状态
→ 加载、预热或切换请求
→ 最终消费者绑定目标对象与资源
→ 解码、可播放或其它就绪条件
→ 第一帧或第一份内容真实可见
→ 当前状态激活
→ 完成策略执行
→ 后一稳定状态
```

每个里程碑同时记录时间、稳定对象身份、实际资源或 `currentSrc`、真实节点或图层、操作身份、可见与命中状态，以及负责推进的所有者。还要记录合同禁止的闪现、空白、双主视觉、回跳和重放是否出现及持续多久。启动成功路径从最早 HTML 或原生窗口首帧开始使用录屏、filmstrip 或等价连续证据；最终首页截图不能排除加载界面之前短暂出现了兜底页或未初始化页面。

排他操作还要从请求刚被接受的时刻开始，分别在资源等待、实际播放或动画、完成回调、导航和最终落位期间使用合同列出的竞争入口。点击、滚轮、触摸、键盘、自动推进或旧回调只能得到忽略、排队或明确中断中的既定结果，不能改写目标或提前释放所有权；到达后一稳定状态后，再证明正常输入已经恢复。

页面或状态存在正式顺序时，从自然入口开始记录实际稳定身份，再按本轮适用范围覆盖直接入口、菜单或导航、锚点或滚动推进、前后项、返回和恢复。开门、揭幕或其它过场完成后必须通过共同导航或状态边界得到正式下一状态；组件或文档顺序、指示器、历史、深链、预热、响应式顺序和回调等全部顺序消费者要与同一真源一致，不能只凭最终画面看起来相邻判定通过。

自动等待必须绑定本次预期对象、资源和当前活动消费者。任意视频进入 `readyState`、任意节点开始播放、缓存命中、请求最终结束或预热集合为空，都不能证明目标已经就绪；固定延时只作为超时上限。最终“过一会儿能播放”也不能证明用户到达时没有空白、切换中没有重叠或旧回调没有重播当前对象。

昂贵资源准备进入本轮承诺时，从新鲜正常入口开始，在不触发开始操作的情况下等待正式准备所有者提交身份匹配的就绪状态，同时从设备、会话或服务边界证明活动会话仍是停止状态且没有取得麦克风、摄像头、扬声器、捕获流或远程处理权。随后通过正式开始入口消费同一准备结果并取得活动资源，再停止并证明会话已经释放；资源目标变化时核对旧准备失效、新目标准备完成且过期回调没有改写当前选择。只看到 worker 存在、模型加载日志、缓存文件或开始后的快速响应，不能证明启动预热与激活副作用已经分开。

### 动效在正常速度与慢放中分别验收

动效、微交互或状态切换进入本轮范围时，先用正常用户输入从触发前进入默认、悬停、焦点、按下、选中、加载、退出以及当前产品实际可达的其它状态，再使用平台调试工具的减速播放、逐帧、filmstrip 或录屏回放观察起点、运动中画面、交叠、终点和命中变化。减速工具只改变观察方式，不能修改生产时长或绕过正式输入；没有对应状态时不为清单制造状态。

在减速或逐帧过程中至少执行一次中断、快速重复或反向输入，确认新意图从当前可见状态接管，没有先跳回旧起点、双主视觉、透明旧命中层或完成后的残留样式。慢放发现的问题修复后重新取得慢放证据，并回到正常速度完成同一任务，确认技术上连续的运动在真实节奏下仍然及时、克制且不阻塞下一步。

## 3. 先验证确定性合同，再验收可见体验

如果项目已经有与本轮交付直接相关的结构检查、类型检查、设计 token 校验、组件测试、可访问性检查或构建检查，先确认它实际覆盖本轮规范真源、主要产物和正式入口，再运行必要部分。检查发现进入同一轮修正；修改后重新运行受影响检查，不能把旧结果与新画面拼成通过。

自动化在产品链开始前或交互途中失败时，先定位环境、测试驱动或夹具、正式产品行为和最终断言中的最早失败层。动态列表、异步刷新或虚拟化容器会让旧元素引用失效时，应重新取得当前活动元素，滚入或实现当前容器，并优先使用产品平台的语义选择、输入和命中接口；展开、折叠、导航或状态变化后重新查询当前元素，优先使用自动化模式或当前可点击点，再从新鲜布局确认最终状态。不能拿离屏坐标、过期引用或直接写状态冒充用户操作。只有存在瞬态依据时才做一次有界原样重跑；稳定复现后修复测试边界并重走同一链，不能修改产品来迁就测试驱动或夹具。

只有不依赖审美推断、结果稳定且能够定位正式来源的不变量才适合自动检查，例如：声明的主要文件存在并由自然入口读取、派生 token 与活动来源一致、旧组件不再被生产入口引用、必要状态和可访问名称存在；取得最终实色时，也可以按项目采用的标准计算实际前景与背景。颜色是否适合当前内容、透明或图片背景上的最终可读性、层级是否清楚、内容是否可信和用户能否完成任务仍由目标界面的可见验收决定。

界面自动化还要把“怎样找到对象”和“怎样得到预期值”分开。对象身份优先来自稳定对象标识、可访问语义或组件公开身份；当前翻译文案、列表位置和临时像素坐标只有在文案、顺序或坐标本身就是产品合同时才可作为断言对象，不能充当其它行为的定位键。字号、间距、颜色、尺寸和其它设计值从活动 token、组件公开属性或正式布局合同取得，测试验证生产组件已经消费这些来源并形成目标关系；不能把当前像素常量复制进测试形成第二套设计真源。几何断言验证边界和关系，整体与局部画面验证可读性、视觉重量和构图；共享组件修改还要覆盖全部正式消费者，实例级覆盖则证明共享默认值未被改变。

对图标尺寸、线宽、按钮边界或面板间距等关系的自动断言只能证明结构约束已生效，不能单独证明界面已经轻量、现代或具有目标质感。图标家族是否协调、光学重量是否符合当前任务，仍由目标界面的可见验收决定。

没有现成检查时，不为证明“严谨”临时增加宽泛的风格扫描器。只有用户授权实施、该不变量会重复发生且脚本能够检查正式生产链路时，才把它加入项目；普通审查直接记录证据缺口并继续可见验收。

## 4. 验收体验，不只验收界面响应

从用户自然入口开始，在不提供设计稿之外额外提示的情况下检查：用户能否理解当前位置和可操作对象，找到并开始主任务，作出必要决定，看见系统反馈，判断是否完成，找到和使用结果，并在出错、取消、重复执行或离开再返回时恢复。

参考能力或新增能力改变了主导航、主要按钮、工作区或设置层级时，先从设计与预防合同读取它在目标产品中的用户对象、职责类型、共享生命周期和入口层级依据。验收不仅要证明功能能运行和入口能找到，还要证明它在当前层级承担独立用户结果：现有路径为什么不能自然承载，它有哪些不同的关键决定、持续状态、失败恢复或交付结果，以及主要用户为什么需要反复直接进入。属于获取渠道、格式、供应商、对象操作、视图或状态反馈的能力，如果结果进入后与现有对象共享同一生命周期，应从现有统一入口或对象上下文完成任务，不能因后台实现独立就在界面上保留平行工作流。

自动化能够定位控件、几何没有裁切、界面矩阵通过、正式链路能生成结果，各自只能证明实现和显示的相应部分，不能证明入口层级正确。还要从自然初始路径观察主任务是否被次要能力挤占，用户是否需要先理解生产渠道或内部格式，是否出现职责重复的按钮、页面、设置和恢复路径。缺少真实目标用户时可以形成专家验收结论，但不能把“能够发现和使用”写成目标用户已经认可这项产品层级。

本轮新引入或提升为主操作的控件，必须出现在目标视口的自然初始任务路径中，或者有持续可见、语义明确的入口能够直接到达。用户必须先知道它存在，再滚过与当前任务无关的长列表才能找到，不算已经建立主入口；自动化能够按对象名定位它，也不能代替自然发现。

结果需要确认、已读或不再重放时，确认条件必须落在当前活动窗口或表面：目标内容已经挂入实际呈现树，窗口与承载区域可见，元素非离屏且具有非零几何，文字、状态或结果与本次操作一致。后台状态已写入、隐藏页面能查到节点、布局事件曾触发或自动化树返回了文本，都不能证明用户已经看到。确认后还要重新进入一次，验证已读结果不会重复，正式产物和恢复状态没有因确认而改变。

恢复路径、长错误或状态详情不得把重试、保存、打开目录、确认或关闭等行动挤出低高度窗口。状态内容可以在有界区域内滚动，行动区必须保持可达；验收要取得实际窗口、状态区和行动区矩形，并通过真实输入执行至少一个关键行动，不能只断言按钮存在于树中。

记录任务是否完成、理解偏差、犹豫、无效操作、错误、完成时间、恢复路径、重复使用效率和主观信心。只选择与本轮目标有关的证据；步数少不自动表示体验好，视觉精致也不能补偿任务失败。

Agent 或设计者自己的走查只能作为专家审查。没有真实目标用户按一致任务参与时，不声称已经完成用户研究、可用性测试或证明所有用户都会成功；结论要分别说明正式生产链路已通过、确定性约束已生效、专家可见对照符合什么，以及哪些主观目标仍等待用户接受。用户没有明确接受时，不把“现代、轻量、舒服、美观或与参考一致”写成已证明结论。

## 5. 同时收集几何和画面

几何用于证明元素、滚动和命中是否落在合同边界；截图或录屏用于证明层级、可读性、视觉重量、裁切和状态表达。两者都需要时不能互相代替。

截图或录屏只有被实际打开、解码并在目标显示比例下查看后，才能成为可见体验证据。文件存在、路径可读、数量正确、尺寸符合或捕获命令成功只证明已经产生媒体，不能证明画面内容成立。审查要记录准确媒体身份、视口、主题、缩放和对应状态，并实际比较信息层级、内容密度、裁切、对比度、焦点与状态表达；需要验证悬停、按下、禁用、加载或错误时，分别取得并查看对应画面。媒体无法打开、只取得元数据或审查者没有看到目标比例画面时，可见结论保持未知，不能写成视觉验收通过。

### 空间对象按视角与状态矩阵验收

SVG、Canvas、场景图或 3D 对象的层级、挂载、姿态或动画发生变化时，从自然运行入口建立以下矩阵：

```text
自然运行入口
× 关键摄像机或观察方向
× 姿态、交互与动画状态（开始 / 进行 / 结束）
× 受影响的视口或设备条件
→ 父级与挂载身份、局部变换、轮廓、对齐、遮挡、方向、尺寸和最终截图或录屏
```

结构身份和最终画面不能互相代替：运行时父级、局部坐标和变换数值证明对象消费了正确链路，关键画面证明用户实际看到的轮廓、方向、尺度和遮挡关系成立。最后一次可见改动后必须重新取得两类证据。用户只指出一个视角时，继续覆盖同一变换链会影响的其它关键视角和状态，但不扩大为无关场景的全面审查；按实际风险至少覆盖关闭与重新打开、姿态切换后返回、动画前中后，以及会改变投影关系的视口变化。

用户结果包含“轻量、现代、有质感”等整体感受，或用户已指向工具栏、图标、文字、字段等具体家族时，同时取得目标视口的整体画面和实际显示尺度的代表性局部画面。整体画面证明空间骨架、密度和视觉重心；局部画面证明字形或图形语法、光学占比、线宽、负空间、表面状态和相邻关系。明确对标时两种画面都使用与参考对应的视口、缩放和状态；任一尺度通过都不能替另一尺度通过。

对新增或重新排序的主要控件，记录控件矩形、实际滚动视口矩形以及两者的相交区域；组件树存在、`visible = true`、非零自身尺寸或自动化可调用，只能证明对象存在，不能证明用户在当前视口看得到并找得到。验收必须同时包含从自然入口完成任务的真实输入证据和该实际视口的截图或录屏。控件拓扑、布局顺序、外壳尺寸或滚动所有权变化后，先前相关的功能结果和截图同时失效，必须从自然入口重新取得。

用户已选择的图标、标志或其它独立视觉资产要在两个尺度验收。放大构造尺度核对外轮廓、比例、关键折点、缺口、负空间、图层和颜色关系；实际显示尺度核对最终布局矩形、内在比例、清晰度和周边文字关系，确认没有压扁、拉伸或因缩小丢失识别特征。用户只调整一个局部时，只改变该变量，并在前后画面中复核其余已确认关系；源文件正确但生产界面的实际显示失真，不能判定通过。

媒体预览不能只量最外层容器。分别记录源或输出比例、布局容器矩形、活动渲染表面的逻辑与物理尺寸、最终内容矩形和裁切决定；再使用同一正式媒体执行播放、定位或其它实际消费动作。由外壳、固定操作或状态提示释放出的空间会改变下游几何，相关修改后必须重新取得媒体画面和操作证据。

网页图片的 `complete` 只能说明当前请求周期结束，不能单独证明目标内容可用；同时核对最终元素的目标 `src` 或 `currentSrc`、非零 `naturalWidth` 与 `naturalHeight`，并在需要时等待解码。视频的 Resource Timing 条目数量会受缓存和 Range 请求影响，不能用来证明播放器复用或节点身份；应核对最终媒体节点、`currentSrc`、预热状态延续和实际可播放画面。

透明媒体出现矩形薄雾、整幅画布噪点、主体暗边或 poster 与播放画面不一致时，按高频问题模式把母版、Alpha 处理、交付编码、poster、正式清单和活动消费者放进同一条证据链。确定性检查分别比较源与产物的尺寸、帧数、时长、Alpha 数值与空间分布、外圈和角落、主体边缘及有意义的半透明区域；不能只读“存在 Alpha”或 `alpha_mode`。可见验收把 poster、首帧和实际播放连续合成到一明一暗且足以暴露缺陷的背景上，再在合同视口、减少动态效果和静态回退中核对活动节点的 `currentSrc`。只修播放文件而不重新生成同源 poster，或只清理有损编码后的末端文件，都不能证明派生链已经收口。

外部生产工具参与素材链时，从产品体验合同读取工具能力、正式生产者和素材状态。直接静态、视频取帧、可抠像源或批次拆分分别核对准确源身份、中间处理、派生物和最终消费者；页面实际使用的文件必须能够回到同一条记录。只查看生成任务成功、批次大图、导出目录或消费端临时路径不能证明正式素材成立。标为“只使用已指明部分”的素材只验收并消费被确认部分；需要重新生产或不进入项目的对象不得继续留在活动清单、poster、预热或回退路径中。

媒体切换还要把操作身份、传出节点快照、传入节点、当前对象和可见层放在同一条时间线上。旧操作完成或清理后，当前节点、播放位置、选择和说明不得发生变化；稳定帧最多存在一个主视觉对象，两个对象同时可见只能落在合同明确的有界过渡区间。传入对象在未就绪前保持隐藏，资源身份、可见层、说明和交互目标必须在同一次正式切换中一致。

多状态或多视图界面从自然入口使用真实控件按合同顺序逐次操作，不直接写组件属性或跳过中间状态。最后一次相关修改后，为每个用户可见状态重新记录控件数量、控件矩形、图标或文字、内容布局和画面；同一个控件承担循环时，验证过程中始终操作同一个命中目标。

集合含自动演示或自动轮动时，先记录已提交选择和正式稳定顺序，再从自然入口观察系统临时预览是否按合同推进。用真实指针或键盘产生人工预览，确认人工输入立即接管，显示投影和临时读数同步更新，而 `aria-pressed`、持久行动与已提交选择保持不变；再通过点击、回车或正式触摸动作提交选择。人工预览结束后，验证系统只在约定的空闲条件满足时恢复，键盘可见焦点仍在集合内时不会恢复。还要在粗指针或触摸边界、减少动态效果、离开再返回和卸载后检查系统推进是否按合同关闭、重建并清理，不能只等一轮动画播放完。

集合同时存在内容全集和本轮样本时，先从正式内容生产者读取两者的稳定对象身份，再证明自动演示只消费本轮样本。随后使用合同指定的按钮、键盘、手势、目录或深链访问样本外对象，核对当前项、已提交选择、文案、媒体、读数和行动目标共同更新；刷新、返回和重新进入只按生命周期合同决定是否重建样本。只看到本轮样本按顺序播放，不能证明全集仍可访问。

高基数集合还要从正式生产者取得代表性对象规模，分别记录打开到首个稳定画面、选择、编辑并持久化的结果，以及一次数据变化实际实例化、通知、重算、布局和跨边界消费的对象范围。不能只测一个条目响应快，或用小夹具推断大量对象时仍然成立。被动展示采用聚合或虚拟化时，继续通过真实输入验证可访问名称、滚动、命中、选择与编辑；活动覆盖层只能代表当前对象，不能让非活动对象失去正式入口。

延迟创建的面板、预览器或嵌入运行时要分别验收应用启动、第一次访问、离开后再次访问和关闭。未访问前不应产生昂贵对象或后台工作；第一次访问必须有真实加载、失败与可用结果，再次访问按合同复用状态或明确重建。快捷键、对话框、信号和状态投影每次都要取得当前活动实例，不能引用尚未创建或已经退出的对象。编辑期间再触发同一对象、无关选择变化和后台字段更新，草稿不得被无参数通知覆盖；提交后由正式存储证明只改变脏字段，后台已经写入的其它字段保持不变。

活动媒体按角色验证实际播放速度、起点、默认静音、声音归属，以及 `loop`、`hold`、`replay` 或 `advance-on-ended` 的正式完成结果。声音入口只应改变责任矩阵分配给它的声音源，不得误改其它视频、语音、环境音或背景音乐；验收优先使用静音、不可听输入或离线信号分析证明音频状态，不制造持续可听副作用。自动前进必须与点击、键盘或滚轮得到同一对象身份、稳定顺序、预热、可见层、说明和恢复状态；无缝循环从真实连续画面连续跨越多个循环边界，检查主体与背景运动、显著轮廓、构图、光线和色彩，双重轮廓、非合同内跳变、短暂空白或首次正常而后续失稳都不能通过。存在多个编码变体时记录最终节点实际选择的 `currentSrc`，不能用磁盘上已有的转码文件或请求成功代替消费证据。默认行为和每个实际媒体角色或对象级速度、声音、起点、完成与回访覆盖都至少各走一个代表项，不能只检查第一个视频。一次性过场分别验证同一生命周期内滚动返回、组件重建或产品内导航不会重放，以及合同允许重置的完整加载、刷新或其它生命周期确实会重置。

应用同时采集和播放音频时，先从正式设备枚举与持久设置取得本轮输入输出身份。连续实时模式使用受控输入证明处理结果到达实际选中输出消费者；说完后播放模式分别输入环境底噪、短促脉冲和一段有效语音，证明前两者不会独立形成一次播放，有效语音只生成一次结果。记录语音端点、输入停止或丢弃、输出开始、输出排空和输入重新启用的先后关系；输出期间不能接受播放声形成的新语段，播放结束前也不能提前恢复采集。只观察波形、推理结果、播放 API 返回或界面状态变化，不能证明用户选择的输出设备实际消费结果，也不能证明回声环路已经断开。

一次变更包含多项同时重排时，验收记录重排前稳定身份顺序和同一快照上的全部目标位置，以正式内容生产边界执行一次变更，再核对精确最终顺序。序号、默认项、选择、读数、预热、不同视图和其它顺序消费者必须读取这份最终顺序；刷新、重新枚举或返回后仍得到相同结果。只看卡片位置改变，或按请求书写顺序逐项修改后碰巧得到某个画面，都不能证明同时重排合同成立。

主题、调色板或共享组件问题只在一个表面显现时，先按正式来源列出同源组件家族和实际可达状态，再逐个从自然入口打开。悬停、焦点、按下和选中由真实输入产生；禁用、只读、空、错误和权限状态由正式业务前提产生。每个状态同时检查最终表面、文字或图标、边界、焦点与选择反馈，以及文字、快捷键、说明和分隔是否完整显示。表示对象角色、类型或职责的图标与颜色要在未选中和选中状态下与相邻同类对象一起比较，不能让选中高亮成为角色身份的唯一载体。临时表面关闭后继续检查焦点、选择和底层命中恢复。

记录页面或窗口总内容高度、滚动容器可见与完整尺寸、固定区域和关键组件矩形。一屏合同不能以“仍可滚到”通过；连续浏览内容则按它自己的局部滚动合同判断。

多章节、作品集或媒体叙事页面还要逐章记录真实内容视口高度、实际消费的滚动距离和两者之比，并从自然入口使用真实滚轮、触控板或触摸取得开始、一个或多个有信息增量的中段、结束释放和第一次反向输入画面。每段距离都要能对应新的信息、构图关系或状态；存在连续空滚时，不能用全局输入倍率或强制翻页把它描述成已经变快。压缩跑道后重新取得进入构图和内部推进证据，确认内部动画没有在舞台完整就位前结束。

验收还要逐阶段对照所选主架构的硬保证：进入构图时内部进度是否保持在合同起点，完整就位时关键内容是否无遮挡，内部演出时相邻内容是否按约定保持在外，终态释放后页面输入是否恢复，再次进入是否采用正确返回策略。第一下有效反向输入必须立即改变局部可见状态或页面位置；两者都不发生就是无反馈空滚。滚轮、按钮、键盘和触摸改变同一对象时，从正式生产者读取同一对象身份、顺序、选择、媒体和说明，但仍按各自方向合同验证允许的转换。单项切换延迟、最终落点或一张稳定截图通过，不能单独证明整段滚动顺手，也不能掩盖旧吸附、隐藏跑道或并行控制器仍在消费输入。

滚动或动效性能在同一真实内容、实际视口和输入方式下记录输入与主线程脚本、样式与布局、绘制、合成、媒体解码与上传、资源加载与并发。临时关闭单个图层、动效或媒体只用于区分成本来源；最终验收恢复完整内容和正常用户路径，再证明目标设备上的响应、画面连续性、输入所有权和内容职责同时成立。

作品与案例区域同时核对真实名称、说明、过程或结果证据和有效入口由正式内容链产生并可见可用。独立图片、饰品、粒子、标签和动画层逐项说明内容、身份、结构或交互职责及移除后果；文件存在、资源加载成功和风格相近不能证明它们应该出现在页面。

- 设计系统：规范来源与全部生产消费者是否一致，组件库和审美参考没有被误作第二真源，旧入口和烘焙旧界面是否退出；
- 入口层级：核心对象、现有对象操作、获取渠道、视图或筛选、状态反馈和可选集成是否按目标任务与共享生命周期落在正确层级；主导航、主要按钮或独立工作区是否有独立且反复发生的用户结果和现有路径无法承载的目标侧证据；自动化可见、几何通过和功能链成功不能替代这项判断；

- 任务语义：对象、行动和任务名称是否使用用户能理解的结果语言；等待、进行、完成和失败是否作为状态单独表达；能可靠自动完成的内部机制是否随主任务启动并在必要时提供进度、失败与恢复，而不是成为阻塞主路径的技术操作；
- 重复行动：再次触发时是否按合同新建、更新或立即解释不可重复的原因，按钮和快捷方式不得形成无反馈的空操作；
- 改版保护合同：本轮承诺保留的内容、任务结果、路由或窗口入口、数据身份、外部消费者和可访问性行为仍由正式生产链路产生并可用，获准改变的关系没有留下活动旧版本。

## 7. 处理证据和结论

检测脚本的发现是缺陷证据，干净结果不是设计质量证明。属性、日志、网络和函数结果只证明中间步骤；最终结论必须回到用户能够自然到达的可见结果。

任何影响界面、素材、数据、规格、正式生产者、测试驱动或最终视口的后续修改都会使相关证据失效。至少重新运行受影响的入口、边界、消费者和视口，不能拼接修改前的完整报告与修改后的局部截图。长时间浸泡、资源占用和高成本真实链只在相关生产代码、配置与测试驱动冻结后运行；运行期间再次发生相关修改，该项证据重新建立。

实施迁移还要检查旧名称、旧控件、旧 helper、旧导出和旧消费者是否已经退出全部活动路径。控件拓扑发生变化时，同时确认旧入口不再显示、响应输入或占据布局。未获删除授权的实体可以归档，但不能继续参与生产；如果旧架构仍能被正常入口调用，本轮迁移就没有通过。

按用户影响排序：用户目标或主要任务受阻、对象与结果容易误解、失去控制或无法恢复、高频使用低效、跨页面或平台不一致、视觉精细度。先指出哪些有效关系直接支持用户完成任务、后续修改必须保留，再说明最重要问题、根因、必须修复项和低成本改进。第一段仍直接说最重要问题、根因和目标状态，不用优点清单或大量低影响检查项稀释结论。
