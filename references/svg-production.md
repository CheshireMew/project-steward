# GitHub README SVG 制作

在上层已经选择 SVG 产物并冻结视觉合同时使用。SVG 负责把已选颜色角色、字体角色、内容关系、形状语义和主题元素实现为确定性排版、文字、关系图或代码原生插画；它不自行发明配色、构图和容器语言。完成源文件与渲染检查后返回当前 README 子类型。

## 1. 使用已确定的画布

全宽素材使用上层已经确定的 `1200` 单位 `viewBox`。常见起点：

```text
Hero:          1200 × 300–420
章节标题:      1200 × 120–170
关系或解释图:  1200 × 320–760
```

重要内容离边缘 `48–64` 单位。尺寸是起点，不是模板。

实际字号按显示宽度计算：

```text
显示字号 = SVG 字号 × 显示宽度 ÷ viewBox 宽度
```

不要通过把 `viewBox` 从 `1200` 改成 `900` 伪装文字变大；比例不会改变。增加文字相对尺寸、减少密度、缩短标签或拆图。

## 2. 无风格骨架

```svg
<svg xmlns="http://www.w3.org/2000/svg"
     viewBox="0 0 1200 360"
     role="img" aria-labelledby="title desc">
  <title id="title">Repository name</title>
  <desc id="desc">Plain-language description of the visual.</desc>

  <defs>
    <!-- 只放视觉合同确实需要的图案、渐变或裁剪。 -->
  </defs>

  <g id="composition">
    <!-- 按已选内容关系实现；这里不提供背景、分栏或容器默认值。 -->
  </g>
</svg>
```

`1200` 宽度来自 GitHub 全宽画布约束；高度由当前内容决定。背景、位置、圆角、描边、颜色和分组数量来自上游视觉合同，不从骨架继承。按当前项目的语义职责命名 `<g>`，让后续移动、替换和动画能够定位。

## 3. 制作顺序

1. 把视觉合同中的对象、关系、阅读顺序和表面来源映射到 SVG 图层。
2. 建立 `<title>`、`<desc>`、`viewBox` 和当前设计需要的背景。
3. 按已选构图放置项目名称、具体描述和真实项目材料。
4. 只为真实分组、连接、状态和层级增加边界与结构。
5. 必要信息成立后，再判断已选主题元素是否需要出现。

信息与项目材料已经清楚时停止增加元素。

## 4. 字体

- 从视觉合同取得标题、说明和元数据的字体角色，再选择 GitHub 能可靠渲染的系统字体实现。
- 真实代码保持等宽排版；元数据是否等宽由项目证据和视觉合同决定。
- 项目已有编辑或传统字体角色时，可以使用 `Georgia`、`Songti SC` 等可用系统字体实现。
- 先用字号和字重建立层级，再增加颜色。

SVG 文字不会自动换行，明确拆行：

```svg
<text x="0" y="90">First line</text>
<text x="0" y="128">Second line</text>
```

中文、英文、衬线和无衬线宽度不同。每次关键文案变化后重新渲染，不依赖字符数估算。

## 5. 用几何表达项目材料

根据视觉合同中的内容关系选择小型、可维护的 SVG 词汇：

- `<rect>`：确有边界的表格、终端、模块、设备和样本。
- `<circle>`：节点、端口、状态和标记。
- `<path>`：连接、曲线、流程和轮廓。
- `<g transform="…">`：可移动组件。
- `<clipPath>`：真正需要裁切时使用。

简化真实架构、关系、代码、输出或界面。连续过程优先共享路径，系统关系优先共享空间，独立对象才各自获得容器。几何必须能对应项目事实。

## 6. 手写 SVG 与布局引擎

视觉紧凑、与 hero 深度融合或只有少量框和连线时，直接写坐标通常最容易维护。

关系密集、自动排边、分组和标签换行占主要工作时，可以把现有且许可证合适的布局引擎作为制作工具。保存语义 JSON 或其它可编辑源，导出静态 SVG/PNG。使用引擎时：

- 应用当前项目配色，不保留引擎默认皮肤；
- 使用视觉合同指定的系统字体角色；
- 移除远程资源、`script`、`foreignObject` 和不稳定 CSS；
- 检查标签裁切和 GitHub 缩放；
- hero 中只让引擎负责已选关系的结构层；
- 不把该引擎变成 Skill 默认依赖。

## 7. 颜色与效果

- 开始绘制前把视觉合同中的颜色角色落实为成品值，并保留其项目或家族来源。
- 背景明暗、颜色数量和强调关系服从已选合同；SVG 制作阶段不增加“技术感”配色。
- 渐变只在合同需要表达材质或深度时使用。
- 阴影只在真实重叠关系需要分层时使用；复杂截图合成改用栅格格式。
- 圆角、顶部标签和图案只实现已经确定的内容职责，不按模块批量添加。

## 8. 决定最终格式

以下内容保持 SVG：

- 文字；
- 几何图；
- 关系和流程；
- 代码原生插画。

以下内容发布 PNG/WebP：

- 多张截图或照片；
- 生成图；
- 复杂裁切与合成；
- GitHub SVG 清理可能破坏的效果。

标题与截图属于同一证据时合成一张栅格板。命令、链接和长说明留在 Markdown。上层选择混合构图时，SVG 是排版源，不把大幅栅格 base64 塞进成品 SVG。

## 9. 嵌入与验收

推荐：

```html
<p align="center">
  <img src="./assets/readme/hero.svg" width="100%"
       alt="仓库名称及其具体用途">
</p>
```

运行 README 审计脚本并实际渲染 SVG。检查：

- 文字和路径裁切；
- `900px` 和 `360px` 下的必要文字；
- GitHub 深浅页面周围的对比度；
- 缺失 `<title>`、`<desc>`、`viewBox` 或 alt；
- 远程引用、不支持元素和脚本；
- 装饰是否抢过项目名；
- 暂时隐藏文字后，构图和项目材料是否仍对应当前项目，或诚实地只剩排版留白；
- 成品颜色、字体、边界和构图是否能逐项回到视觉合同。

一次只改一个目标并重新渲染；两种设计同样清楚时保留更简单的版本。
