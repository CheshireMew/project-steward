# 外部 CLI、工具与协议兼容性治理

用于检查、设计或修复一个项目与外部 CLI、执行器、daemon、SDK 或网络协议的兼容关系。目标不是证明某个可执行文件能够启动，而是让每个明确声明支持的适配器都能把正式输入经过真实执行边界交给对应工具，再把结构化结果送回正式消费者并形成用户可见结果。

普通项目内部接口迁移继续使用改动前预防或根因治理。只有用户结果包含外部工具身份、版本、调用合同、隔离边界、上游线协议或跨项目互操作时，才叠加本方法。检查、审计和评估保持只读；用户明确要求修复或接入时，才修改获准项目根。

## 1. 先冻结兼容性声明

兼容性必须是一组可枚举、可验证的声明，不能由“其它 CLI”“OpenAI-compatible”“支持自定义命令”或“理论上都能接”无限扩张。开始前建立：

```text
用户要完成的动作和最终结果：
明确支持的适配器集合：
每个适配器对应的工具、版本范围和来源身份：
产品必须保持的可用性合同：是否允许或要求凭据、是否承担默认或零配置能力、成本、隐私和能力边界
正式认证与传输合同：端点、方法、头、请求体、流式模式、超时、重试、响应与错误解析
项目自己的唯一执行边界和正式消费者：
兼容指的是能力发现、实际执行、结果语义还是完整用户链：
明确不支持、尚未验证或需要扩展合同的工具：
检查、修复、安装、配置和真实外部调用的权限与停止位置：
```

只有具体适配器通过本方法的全部必需层，才能报告该适配器兼容。项目提供公开扩展接口时，可以声明“能够实现新的适配器”，但不能把尚未实现和验证的具体工具写成已经兼容。一个适配器通过也不能替同系列、同供应商或命令行参数相似的其它工具背书。

上游当前推荐、版本更新或新端点不能自动改写产品可用性合同。若迁移会把匿名能力改成必须凭据、把用户配置能力改成内置默认、改变成本或隐私边界、移除正式消费者依赖的模式，或者让原本可用的用户路径失去能力，这不是普通兼容更新，而是新的产品决定；在取得明确目标前停在差异、影响和可选方案，不能为了使用“最新版”先改适配器再用文档或错误提示解释退化。

### 服务可用性测试必须复用正式调用合同

面向用户的连接测试、保存并测试、健康检查或首次向导不是独立探针，而是正式适配器的消费者。它必须复用生产调用的适配器身份、认证模式、端点选择、请求序列化、方法与头、流式或非流式模式、响应解析和稳定错误；只有测试内容、结果投影和有界等待可以按测试职责变化。正式运行使用流式响应而测试只发非流式请求、正式运行要求凭据而测试绕过认证、测试访问另一个端点或只检查 HTTP 状态时，通过只能证明该探针，不能把连接或聊天标成可用。

测试成功后仍要从正常用户入口执行一项代表性能力，由同一个正式消费者读取结果。测试失败则保留准确协议层和产品合同差异，不静默尝试多个端点、切换认证方式、关闭流式、替换 provider 或降级成另一条路线。外部服务自身暂时不可用时可以把现实可用性标为受阻，但不能据此改写已经冻结的产品用途。

## 2. 为每个适配器建立分层证据表

每层分别记录正式生产者、真实边界、消费者、当前证据和允许结论：

| 证据层 | 必须证明什么 |
| --- | --- |
| 可执行产物 | 用户入口最终选择的绝对文件、版本、来源、运行时、相邻依赖和资源闭包属于本轮目标，不是帮助输出可用但正式入口仍选择旧产物 |
| 能力合同 | 机器可读能力、操作、参数、权限、模型或执行模式与项目声明一致；静态握手只证明这一层 |
| 调用与隔离 | 正式启动器实际传入参数、工作目录、环境、标准流、权限和隔离配置，目标进程在该边界中真实启动并按合同退出 |
| 临时输入 | 凭据、授权令牌或仅本次执行需要的数据通过隔离边界实际到达唯一消费者，并且没有进入合同禁止的参数、配置、持久状态、日志或事件 |
| 上游线协议 | 实际安装的外部工具真正发出的请求方法、路径、头、消息体、流式分片和版本，以及它对响应、错误和结束帧的读取符合目标服务合同 |
| 业务结果与生命周期 | 任务结论、输出、错误、取消、重试、退出和传输收尾由结构化合同表达，不能从普通日志、最后一行或退出码猜测业务结果 |
| 正式消费与用户结果 | 项目自己的正式消费者读取同一次执行的结果，用户从正常入口真实看到或使用目标结果 |

使用以下矩阵结项：

| 适配器与版本 | 可执行产物 | 能力合同 | 调用与隔离 | 临时输入 | 上游线协议 | 结果与生命周期 | 用户结果 | 允许结论 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| | 已验证 / 仅诊断 / 未验证 / 受阻 | | | | | | | |

版本命令、帮助输出、进程启动、能力握手、假适配器单元测试和最终文本看起来合理各自只证明对应局部。所有必需层都成立前，结论只能停在准确层级；不能用“基本兼容”“相性很好”模糊未验证项。

## 3. 实际安装工具与测试替身分开证明

项目自己编写的假 CLI、假 ACP 客户端或消费端手写结果，只能证明项目一侧的解析和投影，不能证明外部工具当前版本的真实行为。验证线上协议时，应让准确安装版工具经过它的正式启动和配置入口，向受控的协议记录端点发送真实请求；记录端点可以避免访问不可控服务，但必须按目标协议返回该工具会真实消费的响应，并保留方法、路径、字段、分片和结束语义。它能证明安装版工具的线协议，不自动证明真实云服务、账号策略或另一个隔离环境。

某个环境限制使“真实隔离启动”和“本地协议记录”不能同时运行时，可以建立两条正交证据：

```text
正式隔离启动 → 临时输入到达受限进程 → 结构化结果被项目消费者读取
准确安装版工具 → 实际上游请求被协议端点记录 → 工具消费响应并产生结构化结果
```

两条证据分别填入矩阵对应单元格，并明确各自绕过的边界。只有它们共享同一适配器合同、工具身份和结果语义，且没有未经证明的中间转换时，才共同支持这些分层结论；仍未由任何一条经过的层保持未验证或受阻，不能把两段拼写成一次实际运行过的端到端链。条件允许时仍应从正常入口运行完整链。

## 4. 兼容边界由一份适配器合同拥有

每个适配器由一份正式配置或类型化描述拥有：

- 工具身份、支持版本和实际执行 API；
- 能力、参数、权限和任务输入映射；
- 启动方式、隔离要求与临时输入通道；
- 上游协议选择、结果 schema 和生命周期语义；
- 不兼容条件和启动前拒绝规则。

### 启动参数由适配器完整拥有

调用者可以选择已经支持的适配器、经过核验的可执行文件，以及适配器公开的类型化业务选项；完整命令字符串和原始参数数组不属于用户配置。工作目录、隔离、权限、临时设置、结果通道、会话、模型和工具能力等约束参数由适配器按当前工具版本一次生成，配置加载器、设置界面、环境变量和调用者都不能在这份参数之后继续拼接自由文本。确实需要开放的模型、推理强度或其它选项要成为有允许值、冲突规则和正式消费者的类型化字段，不能借“高级参数”恢复第二个命令行真源。

外部工具存在重复参数、位置敏感参数、短长别名、配置文件再展开或最后一项生效等语义时，启动前按该工具当前合同计算最终有效值。只检查安全参数“曾经出现”不能证明它没有被后面的 `cwd`、目录扩展、沙箱、授权、输出、设置或工具参数覆盖。无法可靠计算或拒绝覆盖关系时，不启动进程，也不靠删除几个已知危险字符串维护黑名单。

迁移旧的自由命令配置时，一次覆盖默认值、配置模型、加载与保存、设置界面、运行时调用、文档、示例和测试；新链完整承载可保留选项后退出旧字段、字符串解析器、参数清洗器和兼容恢复。真实验收从正常入口取得最终解析的可执行文件与逐项参数，核对操作系统实际收到的参数顺序、工作目录和环境，再让对应隔离、结果与用户消费者成立；还要用重复或后置覆盖参数证明产品会在启动前拒绝，而不是让目标进程按最后一项悄悄改写边界。

### 权限模式和授权请求必须形成正式闭环

适配器能力目录同时拥有该工具实际支持的权限模式、稳定模式身份、面向用户的名称与即时解释，以及对应的启动参数或协议字段。设置界面只显示当前适配器真实支持的模式；选择、持久化、启动和运行时事件都传递同一稳定身份。界面出现三档不等于工具支持三档，命令行参数可用也不等于宿主已经接通运行中的逐次授权。

外部工具请求批准时，正式请求至少携带执行身份、任务身份、授权请求身份、工具调用身份、拟执行动作、规范化目标、风险或能力类别和适配器原始上下文。宿主把它提交给当前策略：交互模式投影为可操作界面并等待对应用户决定；自动允许或拒绝模式也经过同一策略入口，生成带相同请求身份的正式决定。决定再通过适配器规定的协议响应给仍在等待的准确进程或会话，并把请求、决定、响应结果和后续工具结果写入同一事件账本。

普通输出中的 `tool_use`、终端提示、日志文字、进程停住或模型自然语言不能替代正式授权请求；向标准输入发送一条无身份的 `yes` 也不能证明批准了准确动作。会隐藏以后请求的“始终允许”只有在外部工具提供可撤销、范围明确且可观察的正式授权合同，并且产品明确采用时才暴露。自动模式仍逐次核对能力和目标边界；工作目录、提示词提醒和自动回执属于协作约束，只有操作系统沙箱或等价强制边界才能声称进程无法越出工作区。

### 能力必须由可强制执行的边界支撑

适配器声明某项能力，不等于宿主已经能够约束它。Shell、任意命令、文件修改、网络、子进程或其它可扩大作用域的能力，只有在正式启动边界能够强制实施对应隔离时才允许开启；工作目录、提示词、授权回调、命令字符串扫描和参数中没有出现越界路径，都不能证明子进程无法在运行时计算另一目标。无法证明原生工作区隔离的适配器不得暴露 Shell，也不能把“模型应当只写授权目录”写成兼容能力。

能力在适配器合同、公共构造器、协议 helper 和测试入口中都默认关闭，只能由已经验证的具体适配器显式开启。迁移后按标识符边界搜索宽松默认值和旁路入口；依赖旧隐式默认的测试必须明确声明所需能力，不能为了保留旧夹具恢复产品的宽松默认。

文件型能力在每次实际操作处解析最终规范路径并核对允许根，目录符号链接、联接、大小写、别名和创建后重新指向都不能只按原始字符串判断。检查与写入之间仍可能发生路径身份变化时，使用能够在同一受限执行边界内解析和执行的机制，或者拒绝无法证明的操作；不能继续增加正则规则来猜测路径。

### 任务解释与工具选择由声明的执行者拥有

产品把某个外部 Agent 或 CLI 声明为任务执行者时，调用者向适配器提供业务任务，适配器把任务交给该执行者；执行者拥有任务解释、步骤规划和工具选择。宿主拥有能力开放、授权、隔离以及每次工具调用的执行边界，可以拒绝超出合同的操作，但不能只因自然语言中出现“删除文件”“移动目录”或其它看似确定的动作，就先把任务改判成宿主本地操作并绕过已经选择的适配器。这样的暗中改道改变了用户选择的执行者，也跳过了该适配器的决策、事件和结果合同。

“谁决定做什么”与“谁确认结果是真的”是两个边界。外部执行者选择删除、移动或写入，只证明它作出了行动决定；宿主允许某次工具调用，只证明该调用符合当前授权。业务任务是否完成仍由宿主在执行前建立的验收合同和执行后的真实状态决定。产品需要操作前确认时，由公开的授权合同决定确认对象、时点和用户选择，不能因为底层使用本地工具或外部 CLI 就临时改变确认语义。

宿主原生快速路径只有在产品合同事先明确把相应任务交给宿主，并向调用者公开执行路线、能力范围和结果语义时才成立；它必须拥有独立的验收合同和用户可见结果。它不能作为外部 Agent 路线内部不可见的优化，也不能在外部执行失败后没有正式回退合同就静默接管任务。

### 结构化结果是声明，宿主拥有验收事实

外部工具返回的成功状态、检查项和结构化结果只表达它的声明。宿主在执行前根据用户任务和正式消费者建立验收合同，记录相关对象的存在状态、内容身份或哈希，以及本轮必须成立的创建、修改、删除、内容、结构、测试或其它结果谓词；执行后由宿主读取真实产物和正式测试结果独立核验。工具不能自行生成验收项再为自己作证，退出码为零、路径存在、结果非空或声明“测试已运行”都不能替代宿主证据。

验收合同为每个必需谓词分配稳定身份、对象身份、谓词类型和证据来源。除非合同明确把若干谓词定义为可替代分支，全部必需谓词必须逐项求值并共同成立；验证器还要保留每项通过、失败或无法求值的结果。工具调用成功、已经出现一项通过、检查集合非空或代码提前返回，都不能跳过剩余必需谓词；任何必需谓词没有被求值时，结论只能是未验证或失败，不能是完成。

预期对象身份与结果谓词分开建模。任务或正式消费者点名的输出路径用于证明验收覆盖了正确对象，不自动把谓词解释为“路径必须存在”；创建和修改通常要求对象存在且属于本次变化，移动要求来源消失并核对目标身份，删除则要求准确对象不存在。验收对象被覆盖与该对象应存在还是应消失是两件事，不能用统一的 `path_exists` 检查替代动作语义。

执行前已经存在且本轮没有改变的目标不能满足“产生输出”或“完成修改”。写入任务核对最终内容或结构，移动任务同时核对来源消失、目标内容身份和必要哈希，删除任务核对准确对象不再存在；预期输出还要证明变化属于本次执行身份。宿主无法从任务合同确定可自动验证的谓词时，结果保持待确认或准确降级为只验证到的层级，不能把外部工具的自报升级成完成。

一次流式执行还要建立稳定的执行身份，并为每次工具调用分配稳定调用身份，把请求、授权或拒绝、工具结果、错误以及后续恢复关系保存在同一事件账本中。顶层退出码为零、最终消息声称成功或流正常结束，都不能抹去未配对、被拒绝或失败后仍未解决的工具调用。后续替代步骤确实恢复任务时，应明确关联被替代的失败尝试，并仍由宿主逐项验证全部必需结果谓词；较早失败继续作为过程证据保留，但在已经证明恢复后不单独强迫最终任务失败。

调用者只选择适配器和提供业务任务，不在提示词、界面、测试或启动脚本中再次判断协议、权限和结果语义。不兼容的模型、协议或版本应在外部进程启动前由唯一边界拒绝；不能启动后猜字段、尝试多个端点、解析自然语言错误或静默降级成另一适配器。

凭据和其它临时输入使用项目明确允许、并且在真实隔离边界内已经证明可达的单一通道。通道可以因平台和工具合同不同而变化，但其生命周期、唯一消费者和禁止落点必须明确；不能因为当前终端能读取某个环境变量，就推断受限子进程也能读取，也不能在原通道失败后把临时值移到长期配置、命令参数或日志来换取成功。

公共合同变化时，先更新权威生产者，再通过唯一同步边界迁移每个项目根的派生快照和正式消费者。新合同接通并完整承载原功能后，退出旧协议版本、旧 provider 选择、旧提示词兜底、旧结果解析、双读和兼容恢复路径；不同发布节奏确实要求外部过渡时，只在唯一边界外侧保留有期限和删除测试的适配器。

## 5. 真实验收

按适配器逐项覆盖：

1. 从正常用户入口选择适配器，记录正式入口最终解析的绝对可执行文件、版本和依赖或资源闭包。
2. 读取该工具实际给出的机器可读能力，并证明项目配置选择的操作、权限和执行模式在声明范围内；不兼容配置在启动前被拒绝。
3. 由正式启动器在目标隔离条件下启动工具，核对参数、目录、标准流、环境和权限，并让临时输入实际到达唯一消费者。
4. 使用准确安装版工具产生真实上游请求，核对方法、路径、字段、流式语义和响应消费；测试替身不得代替外部工具生产请求。
5. 让工具产生结构化业务结果、错误和至少一个生命周期分支，由项目正式消费者读取同一次执行身份。
6. 从用户入口观察最终结果；文本聊天、任务执行、取消或其它承诺分别按实际支持范围验收。
7. 检查参数、环境快照、配置、持久状态、日志和事件，只在合同允许的位置出现临时输入；测试值不能冒充真实凭据泄漏检查。
8. 对每个明确支持的适配器独立执行。未运行、被诊断开关绕过或只验证旧版本的单元格保持未验证，不能借其它适配器的成功关闭。
9. 原生产物与源码运行时不同，再从用户实际产物重复受影响的能力、协议、资源和结果链；源码测试不能替它背书。
10. 运行标识符边界明确的残留检查，确认活动代码、配置、文档、示例和测试不再声明已经退出或从未验证的兼容路径。
11. 用不能提供原生工作区隔离的真实或受控适配器请求 Shell，证明宿主在启动前拒绝；再让已验证适配器显式开启，检查正式启动参数和受限进程的实际边界。目录链接或联接指向允许根外时，文件操作同样被最终路径检查拒绝。
12. 让外部工具分别谎报错误内容已经写入、复用执行前已存在且未改变的输出、只声明测试通过，再由宿主验收合同逐项判失败；正常任务由同一宿主核验产物变化并交给正式消费者形成用户结果。
13. 为同一任务建立至少两个必需谓词，让前一项通过、后一项失败或无法求值，证明验证器仍记录全部结果并拒绝完成；再用删除任务证明预期对象已经覆盖、但正确谓词是对象不存在而不是统一要求路径存在。
14. 从正常入口选择外部 Agent 并提交一个看似确定的文件任务，证明宿主没有从任务文字预判动作或绕过适配器；外部执行者产生工具选择，宿主按公开授权合同处理调用，并由预先建立的验收合同确认最终状态。再选择正式声明的宿主原生路线，证明两条路线的身份、能力和结果不会静默互换。
15. 让一次流式执行先产生工具错误，再分别产生未恢复的顶层成功声明和经过明确替代步骤的恢复结果；前者必须因事件账本仍有未解决调用而拒绝完成，后者只有在全部宿主验收谓词成立后才能完成，并继续保留较早错误作为过程证据。
16. 对每个适配器从能力目录生成权限选项，核对界面解释、持久模式和实际启动或协议字段使用同一稳定身份；不支持的模式不出现为可选项。
17. 让真实或受控适配器发出两个交错授权请求，分别选择允许和拒绝，证明界面显示准确动作，决定按执行、任务、请求和工具调用身份返回准确等待者；再运行自动模式，证明它复用同一策略和事件账本，而不是向标准输入盲写确认文字。
18. 从产品正式配置或首次入口运行连接测试，再运行一项代表性正常操作，核对两者消费同一适配器、认证、端点、序列化、流式模式和响应解析；任一构成项不同就分别报告证据，不能用测试通过替正常操作背书。
19. 用一个会改变凭据要求、默认可用性、成本、隐私或正式能力的候选上游版本形成迁移计划，证明它在修改前被识别为产品合同变化并停止等待决定；再用不改变这些不变量的协议更新证明正常兼容迁移仍可继续。

## 6. 输出与停止

第一段直接给出兼容范围结论：哪些适配器完整兼容，哪些只通过了部分层，哪些未验证、受阻或不支持。随后交付适配器集合、分层证据矩阵、最早偏离边界、最终适配器合同、迁移与旧路径退出、各项目根状态以及用户链证据。

只要求检查时停在证据和缺口，不写项目。要求修复时按最早错误层一次迁移适配器真源、启动边界、上游协议、结构化结果和全部消费者；完成结论仍以每个适配器的新鲜矩阵为准，不用总测试数量替代缺失层。
