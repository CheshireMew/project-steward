# 运行时代次与热配置治理

用于配置、插件、provider、存储根或组合对象会在应用运行中重建共享服务，而前台回合、后台任务、事件消费者或桌面控制器可能同时访问这些服务的项目。目标是让一次操作始终消费同一代运行时，让配置文件、内存配置和活动服务图由同一个切换事务拥有，并让界面只在事务真正完成后报告结果。

普通字段修改如果不重建共享对象、不改变持久根、不会与在途操作并发，就继续使用项目既有配置入口，不增加代次协议。需要跨重启追踪用户操作、恢复产物或唯一终态时，持久操作方法仍拥有那条事务；本方法只拥有活动运行时从旧代切到候选代的边界。

## 1. 先冻结活动图和变更事实

热配置不能根据 patch 的字段名猜测影响范围。先从权威配置分别构造旧图描述与候选图描述，再比较真正会改变身份、生命周期、存储根或并发所有权的节点和边：

```text
当前配置身份与活动代次：
候选配置身份与候选代次：
旧图和候选图中的服务、存储、锁、调度器与消费者：
实际重建、复用、停用和新增的节点：
每个节点的创建者、活动使用者、释放者和失败语义：
本次切换允许热生效还是必须重启：
```

判断者必须消费最终服务图构造规则，不再维护另一份“哪些配置字段重要”的名单。一个字段即使名称不属于 provider 或服务分区，只要候选图因此重建服务、改变存储根或替换共享锁，就进入切换事务；反过来，字段变化但活动图身份完全不变时，不为形式完整停止无关工作。

服务图、内存配置快照和代次标识属于同一个权威运行时所有者。控制器、后台任务和测试不能分别缓存一份可独立变更的当前图，也不能在一次操作中反复查询“当前服务”并把前半段旧代与后半段新代拼在一起。

## 2. 一次操作只使用一代服务

每个会跨越两个以上服务调用、持久化边界或异步等待的操作，在进入时取得活动代次的租约或等价不可变上下文：

```text
进入正式操作
→ 从唯一运行时所有者取得代次与完整服务上下文
→ 在该上下文内完成读取、执行、写入和结果发布
→ 释放该代次租约
```

租约覆盖真实用户结果所需的整条链，不只覆盖一次字段读取。一次对话不能用旧 provider 生成结果、再用新角色解释并写入新存储；一次记忆操作不能在旧根读取、切换后写入新根；后台任务也不能执行旧 Agent 后把完成事件交给新代状态机。

切换协调器必须知道每一代仍有多少活动使用者，并能停止新使用者进入受影响的旧代。等待超时只说明旧代尚未排空，不能清除租约、线程或服务引用，也不能继续发布候选代来制造重叠所有权。

## 3. 热切换是一项有提交点的事务

标准顺序是：

```text
读取并固定旧配置、旧服务图和持久化原文
→ 构造候选配置、候选图与不对外服务的候选对象
→ 验证候选对象、路径、凭据和资源，不改变活动真源
→ 根据旧图与候选图的实际差异决定排空与重启集合
→ 进入唯一配置队列并阻止新的受影响操作取得旧代
→ 原子持久化候选配置；失败则旧服务完全不动
→ 请求受影响旧任务停止并等待租约排空
→ 停止不能与候选代并存的旧服务
→ 在一个内存提交点同时发布候选配置、服务图和代次
→ 允许新操作取得候选代，并释放已经退出的旧对象
→ 正式消费者读取新代，界面报告成功
```

候选构造若会启动线程、打开设备或产生其它副作用，这些对象从创建起就由切换事务拥有，失败时必须关闭并证明退出；更稳妥的候选对象保持未激活，直到旧代排空并到达提交点。

持久化成功后，如果旧任务不能停稳、旧服务不能释放或内存提交失败，切换事务必须恢复旧服务图和旧内存配置，并尝试原子恢复旧持久化内容。磁盘恢复再次失败时，仍先让运行时权威状态明确保持旧代，再把“磁盘候选内容与活动旧代不一致”作为独立、可操作的持久化错误上报；不能为了让文件和内存表面一致而谎称候选代已经活动，也不能静默保留半套新服务。

提交后的旧对象释放如果按合同允许延后，候选代已经是唯一新入口，旧对象只能服务提交前已经持有的明确租约；它们不得重新接收任务、发布当前状态或写入候选代存储。释放失败保持可观察并可继续等待，不能丢失引用后宣告完成。

## 4. 物理根变化默认是启动边界

数据根、工作区根、数据库位置、任务账本根或其它决定独立持久命名空间的配置，只有在以下集合已经完整枚举并能作为同一迁移提交时才允许热切换：

- 全部权威存储、任务历史、索引、缓存、恢复记录和后台调度器；
- 仍在使用旧根的活动代次及其排空方式；
- 新根准备、已有数据迁移、冲突、失败回滚和重启恢复；
- 每个正式消费者切换后的读取与写入证据。

任一消费者在运行时构造后固定持有旧根，或者迁移不能同时保持历史、身份和恢复语义时，就在唯一配置边界拒绝热修改并明确标为“重启后生效”或不支持。不能只移动显眼的主存储，让任务历史、缓存或恢复状态继续写入旧目录形成两个数据世界。

## 5. 桌面和交互入口只提交意图

GUI、事件循环或请求线程不得同步执行可能排空任务、停止 provider、写配置和重建服务的完整事务。交互层只提交类型化配置补丁和本次意图身份，由一个后台串行队列负责：

- 同一权威配置只允许一个活动提交者；连续编辑只能合并物理执行和最终补丁，不能重排具有不同语义的操作，也不能合并已经对调用者成立的完成责任。每个已受理意图保留稳定身份和自己的完成接收者，合并事务结束后分别取得且只取得一次完成、失败、被替代或取消终态；“被替代”必须是显式结果，不能靠移除队列项、丢弃回调或永久保留忙碌状态表达；
- 需要共同生效的字段进入同一个原子补丁，不能由两个保存入口分别制造中间配置；
- 界面显示可观察的等待、成功和失败状态；成功只在新代已经提交且正式消费者能够读取后发布；
- 失败保留用户仍未提交的脏字段和可重试意图，不能关闭向导、清空草稿或显示已经完成；
- 窗口关闭会先停止接收新修改，再排空全部已受理意图及其完成投递；不能清空待处理项、只等待合并后的最后一个接收者，或让逃逸任务在界面销毁后继续换代。

## 6. 真实验收

至少覆盖：

1. 一个字段名看似无关但实际重建服务的候选配置，由服务图差异正确进入切换；一个不改变图身份的字段不会无谓停止服务。
2. 用受控屏障让真实操作在旧代完成读取后暂停，再发起配置切换；切换等待旧租约，操作最终所有读取和写入都仍属于旧代，新操作只使用候选代。
3. 候选持久化失败时，旧任务、旧 provider 和旧服务图从未中断。
4. 旧任务停止或旧服务释放失败时，磁盘和运行时回到旧配置；再注入一次磁盘回滚失败，证明活动运行时仍明确保持旧代并报告持久化分歧。
5. 一个持久根消费者没有迁移时热修改被拒绝；只有存储、任务历史、缓存、恢复和后台调度全部进入同一迁移后才允许切换。
6. 从真实界面提交会重建服务的配置，事件循环仍能处理一次无关交互；界面只在后台事务完成后显示成功，失败时草稿和重试入口仍可用。
7. 切换后由正式消费者完成一次真实用户结果，并检查旧代不能接收新任务、旧入口和按字段猜测影响的 helper 已经退出。
8. 连续提交多个可合并意图，让它们共享一次物理提交但保留各自身份和完成接收者；正常完成、合并事务失败以及关闭时仍有排队项三种情况下，每个已受理意图都恰好取得一个可消费终态，忙碌计数也能归零。

测试不能在消费端手写两份服务图后只检查选择函数。候选图必须由正式配置和服务图生产者生成，操作必须经过实际租约或屏障，最终由当前消费者读取本次提交的代次和结果。

## 7. 输出与停止

第一段说明当前操作是否可能跨越两代服务、最早缺失的代次或提交边界，以及哪些配置只能重启生效。随后交付旧图与候选图差异、租约所有者、事务顺序、失败回滚、物理根决定、界面提交链、全部调用点迁移与真实验收证据。

只要求检查时停在证据和最终方案；要求实施时一次迁移服务访问、配置入口、后台任务、桌面消费者和测试，退出按字段猜测影响、重复当前图、同步 GUI 保存、半迁移数据根和旧换代 helper。
