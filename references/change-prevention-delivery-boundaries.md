# 改动前预防：公共边界与交付链

## 2. 找到真实边界

按当前改动建立一张最小影响图：

```text
输入或用户动作
  → 正式生产者
  → 唯一业务或平台边界
  → 传输 / 持久化 / 原生接口
  → 正式消费者
  → 最终可观察结果
```

### 工具动作按实际序列受权

授权按工具实际执行的中间动作判断，不按最终文件树或内容形状判断。删除后同路径新建仍包含删除与创建，移动后移回仍包含移动，覆盖后恢复仍包含覆盖；未取得准确动作和对象授权时只能原位更新，工具只能破坏性重建则在动作前停止并请求授权。

### 公共合同先核对身份

跨仓库、跨进程或跨工具消费公共协议、schema、清单或能力描述时，在比较字段前先核对：

```text
合同名称与版本：
权威生产者及其来源身份：
正式 schema 或规范化内容身份：
当前消费者快照的来源身份与内容身份：
机器可读的能力描述或操作发现入口：
```

合同名称与版本相同，只能说明标签相同。正式 schema、规范化内容身份或字段语义不同，就是合同身份碰撞，不能判定兼容，也不能让消费者猜测实际含义；停止普通接入，转入根因治理，由权威生产者建立新的明确版本并一次迁移生产者、同步边界和消费者。没有稳定内容身份时先建立可重复比较的规范化表示或来源哈希，不能用文件名、目录位置或手工复制时间代替。

HTTP 操作的精确身份是生产者与版本、方法，以及按顺序保留字面或参数种类和值的路径段；`/daily/news`、`/daily/article`、`/daily/{kind}` 是三项不同操作。消费者注册项只能一对一映射权威生产者的机器可读操作，不能把多个静态路由折叠成一个不存在的参数化模板。

当内容身份由目录或多个叶节点共同计算时，摘要构造本身也是公共合同。权威生产者必须冻结算法名称与版本、纳入和排除集合、相对路径正规化及分隔符与编码、明确的排序比较器、符号链接与空目录规则、叶载荷使用原始字节还是叶摘要，以及长度前缀或其它无歧义 framing。不同语言的生产者和消费者共享固定测试向量；“双方都使用 SHA-256”不能证明复合身份相同。单文件原始字节摘要不触发这套复合构造矩阵；一旦多个路径或叶节点参与，完整构造由交付边界唯一拥有，消费者不得自行定义。

### 复合交付包先证明合同与采用闭包

一个正式输入由顶层清单、伴随 schema、素材或资源账本、运行时接口、实际资源和采用引用共同决定行为时，兼容身份不是顶层协议名称、版本或单份 schema 哈希，而是这些节点及其引用关系形成的闭包。开始比较前，从权威生产者本轮实际入口递归取得全部正式引用，不根据消费者已有字段或样例反向猜测；为每个节点和边记录：

| 节点或引用边 | 唯一所有者 | 合同、版本与内容身份 | 声明、采用或执行职责 | 正式消费者 | 最终可观察贡献 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

复合包会被导入、登记、恢复或作为正式状态消费时，验证按五个职责层依次成立：**文件与传输层**核对允许路径、精确文件闭包、大小与字节哈希；**结构合同层**核对编码、格式、schema、版本、必需元数据和计数；**领域语义层**使用目标项目的唯一规范投影或领域构造器从实际内容重建对象与业务身份，再与清单声明和正式来源身份比较，不能信任清单自报的哈希、行数或身份替同一事实背书；**引用谱系层**递归核对父对象、原始证据、派生输入及引用边；**状态提交层**只在前四层完整通过后，以一个明确事务改变活动数据库、索引、登记或当前指针。任一层失败时，目标正式状态仍与验证前相同。

对抗测试要让每一层真正成为判别者，而不是让最外层提前拦截全部坏样例。验证领域语义层时，保持文件格式和必需元数据合法，修改会改变领域事实的内容，并重新计算全部外层文件哈希与传输清单；系统仍必须从实际内容重建出的业务身份拒绝它，并证明没有发生状态提交。其它层也分别使用已满足更早前置条件的输入。产物没有独立领域语义身份时停在它实际拥有的层，不为形式完整虚构第二套模型。

资源进入账本只证明它可被发现，不能证明已经被正式采用。可用性声明与正式采用关系必须分开：场景、配置、数据字段或其它权威入口要引用同一稳定资源身份，消费者再把这项采用编译成自己的执行计划，实际工作单元最后对可见、可听或可使用结果作出可辨认贡献。账本存在、解析器识别、执行计划非空、容器中碰巧存在某类轨道或最终文件能够打开各自只证明一层；任何中间采用边缺失时，对应能力仍未接通。

消费者自行迁移或手写的样例只证明消费者内部链路，不能代替真实生产者的互操作证据。跨项目时继续使用跨项目根共享合同与交付账本：长期回归消费带来源与内容身份的同步快照，跨根验收消费真实生产者本轮输出，并分别证明快照一致和实际互操作。生产者合同、任一闭包节点、采用边、适配器、消费者或执行环境发生相关变化时，只使依赖这些身份的证据失效；受影响边必须从新鲜生产输出重新验证，不能把变化前后的局部通过拼成一个完整兼容结论。

同步入口只有在来源记录、目标允许集合、逐文件原始字节身份和规范元数据同时相等时才能跳过；来源清单是待核对声明，不能替目标文件背书。Git 行尾或编码转换属于传输边界：合同要求字节相等时要在检出后重验，不能因来源哈希正确而忽略。MIME 等会随宿主注册表变化、又进入公共语义的值由合同真源固定；只有表示漂移时修复传输或规范化生产者，不升级协议，语义变化才按版本迁移。

### 产品升级先核对公开身份

产品升级、接替或更名改变用户名称，而包名、命令、协议、模块命名空间或安装目录可能保持时，修改前建立公开产品身份台账：

| 身份类别 | 唯一真源与当前值 | 允许出现的位置 | 必须迁移或保持的活动消费者 | 退出或兼容条件 |
| --- | --- | --- | --- | --- |
| 当前公开产品名称 | | 用户界面、标题、面向用户的 CLI 能力描述、Skill、活动文档与示例 | | |
| 稳定技术标识 | | 包名、命令名、协议、模块命名空间、安装或数据目录 | | |
| 旧公开名称 | | 已明确标为历史或迁移说明的非活动材料 | | |

公开名称由唯一活动真源拥有，全部面向用户的活动消费者只读或核对；稳定技术标识仅在外部合同、数据兼容或安装边界要求时迁移，不能为了让所有字符串相同而破坏兼容身份。实施后证明真实界面、公开 CLI 或其它正式入口显示当前名称，旧名称只留在历史范围。

仅修改内部包名、命令名、协议标识或其它技术标识，用户名称未升级、接替或更名时，不触发公开产品身份迁移；该改动继续按相应公共合同、协议或数据迁移边界治理。

### 可安装产物先冻结交付与升级身份

生成可分发产物时，首次昂贵构建前从项目真源冻结目标平台、构建 profile、包或应用稳定 ID、版本与构建号、产物形态与 ABI、安装消费者、签名证书指纹与覆盖升级关系、源码 / 配置 / 环境身份和输出集合。Debug、Release、试装与商店包不同；“正常包”不能代选。普通编译或只检查源码能否构建不触发这份合同。

私钥、密钥库与密码由环境或密钥服务拥有；项目只保存不泄密的签名身份。没有既有签名身份时，生成新密钥即建立长期升级身份；说明所有者、备份、轮换、失效和以后覆盖升级的后果并取得授权。不得静默生成、退回 Debug 或换证书签同一稳定包 ID；缺少决定则停在合同与环境预检，不启动打包器。

### 公共运行时与配置身份迁移

配置键、环境变量、端口、服务名、运行时 API 字段、进程角色或公共类型从旧架构身份迁移到新身份时，先建立身份迁移台账，避免把同名业务概念误删，也避免只改显示名称留下双路径：

| 旧身份 | 新身份与唯一真源 | 仍然有效的同名业务概念 | 生产者与传输或存储边界 | 全部正式消费者 | 旧身份退出证据 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

“仍然有效的同名业务概念”必须说明它的领域职责和正式边界。例如旧服务身份叫 `memory`，不表示记忆领域的路由、接口或提示文字也应删除；反过来，业务中仍存在记忆概念，也不能替旧端口键、服务别名或环境变量继续存活辩护。残留扫描先使用标识符边界覆盖配置、环境、schema、类型、运行时 API、IPC 或网络消息、启动器、脚本、测试、夹具、文档、示例、生成入口和维护工具，再逐项按职责人工分类；宽泛文本零匹配或把全部同名文字批量替换，都不能作为退出证据。

迁移顺序从唯一真源开始，让正式生产者只接受并产生新身份，再一次迁移传输或持久化表示、公共类型与导出、运行时消费者、启动与运维脚本、测试和夹具、文档与示例。内部迁移完成后不保留旧键回退、双读、双写、旧环境变量别名、旧类型、旧 helper、旧导出或由消费者猜测两种字段的兼容逻辑；只有外部独立发布节奏或用户明确迁移窗口进入最终合同时，才允许带所有者、截止条件和删除验证的兼容层。

结构搜索、配置解析、类型检查和定向单元测试只证明新身份能够被表达、旧结构可能已经退出。完成验收必须从正常启动或正式用户入口开始：权威配置生产者实际读取新键或环境变量，启动器和进程边界把新身份传出，运行时 API、IPC、网络消息或持久记录实际产生新字段，正式消费者从该边界读取，并在状态、连接、脚本输出、界面或其它用户结果中观察到新身份对应的行为。测试不能由消费端手写新字段，也不能 mock 掉正在验证的配置加载、启动、传输或消费边界；旧身份的拒绝或缺失还要由正式入口证明，不能只依赖源码搜索。

### 关系表重建先冻结数据与模式闭包

关系数据库迁移会重命名、复制、删除或重建表，或者改变主键、外键、所有权与基数时，在执行 DDL 前建立：

```text
来源数据库版本、表身份、事务或可恢复副本：
数据闭包：正常行、孤儿行、可保留异常行与明确不可迁移行：
关系闭包：父表、子表、连接表、级联语义与迁移顺序：
目标模式闭包：表、列、主键、外键、唯一、检查、默认值、索引、触发器、视图、生成对象与依赖查询：
旧到新稳定身份映射，以及每类排除行的处置证据：
目标对象重建、核对与旧临时对象退出顺序：
失败、回滚、重试、幂等与关闭重开合同：
```

先从旧表本身清点全部稳定行身份和模式对象，再执行破坏性 DDL；不能用新外键、内连接、`WHERE new_fk IS NOT NULL` 或当前消费者可见集合反推迁移输入。需要保留的孤儿行必须按产品合同进入可追溯的合成所有者、恢复或隔离状态；确实不支持时逐项形成明确失败，不能静默漏复制。模式闭包从权威迁移定义和运行时目录取得，表重建后按目标合同恢复约束、索引、触发器、视图、生成对象和依赖查询；只恢复行数和列，或只证明 `CREATE TABLE` 成功，都不能证明关系表已经迁移。

验收同时覆盖当前版本从零新建，以及“旧版本正式生产者 → 正式迁移器 → 当前消费者关闭并重开”。旧状态至少包含正常关系、孤儿关系和会触发一个目标约束的边界值；迁移后按稳定身份逐行对账，并用模式自省核对列、键、约束、索引、触发器、视图和依赖查询。复制、约束恢复或提交阶段的失败注入必须保留可恢复原状态；重试得到同一目标身份与对象集合，旧临时表和旧运行时读路径退出。只比较总行数、手写迁移后数据库或让测试直接调用消费查询都不能替代这条链。

### 跨项目根共享合同与交付账本

同一个用户结果会修改或验证两个以上准确项目根，或者公共合同的权威生产者、派生快照与正式消费者位于不同项目根时，在实施前建立一份跨根交付账本。项目根是职责和交付边界，不要求每个根都是 Git 仓库；每个根的 Git 能力只能由该根直接存在的仓库标记证明，不能从父目录、相邻目录或另一个参与项目继承。

| 准确项目根与身份 | 本轮职责 | 权威合同、派生快照或正式消费者 | 获准变化与停止位置 | 正式验证器及实际输入 | 本地完成与互操作证据 | Git、提交、推送与远端状态 |
| --- | --- | --- | --- | --- | --- | --- |
| | 生产者 / 同步边界 / 消费者 / 维护工具 | | | | | 非仓库 / 未提交 / 已提交 / 已推送 / 远端已验证 |

账本同时冻结权威合同所有者、合同名称与版本、规范化内容身份、唯一同步入口和单向同步方向。权威生产者拥有 schema、运行语义、默认值与正式案例；消费者仓库中的 schema、夹具、starter 或其它副本只能是带来源身份的派生快照，由唯一同步入口确定性更新。不能在消费者中手工修补快照，再让生产者反向迁就；也不能在两个根分别维护同一版本的可编辑真源。

共享合同变化按以下顺序完成：

```text
权威生产者更新合同、运行时与正式案例
→ 生产者正式验证器消费本轮结果
→ 唯一同步入口写入带来源身份的消费者快照
→ 消费者解析、状态、编辑、运行与导出链完成迁移
→ 消费者正式验证器消费同步后的准确输入
→ 从真实生产者经过同步边界到正式消费者的跨项目链形成可观察结果
→ 每个项目根分别记录本地与发布状态
```

消费者的正式回归不能默认读取开发机上相邻项目的绝对路径，也不能用“当前机器能找到生产者目录”代替可移植输入。需要长期、确定性运行的合同测试使用仓库内同步快照并核对来源身份；必须连接活动生产者工作区的测试明确标为跨项目集成测试，先取得外部根身份并在缺失时报告受阻，不能让普通干净克隆测试静默依赖它。同步快照通过不等于跨项目互操作通过，跨项目链通过也不等于每个根已经提交或发布。

完成结论分别回答本地实现、各根正式验证、跨项目互操作和每个根的远程发布。一个根是普通目录、存在未提交变化、没有远端或尚未完成正式验证时，准确报告该根状态；不能把另一个根已推送、共同链本机通过或最终产品可见，概括成“所有项目都已发布”。

### 跨项目接入分开实现、互操作、采用和运行绑定

一个能力需要跨项目、跨工具或跨 Skill 接入当前用户实例时，不能把本机测试中连续成功的步骤合并成一个“已经接通”。在写入目标实例配置前，分别建立以下交付状态；每一项都有自己的前置条件、获准写入、正式消费者和允许交付措辞：

```text
能力实现：生产者或公共边界已经具备目标能力
各根正式验证：每个参与根在自己的合同和正式入口下通过
隔离互操作：在已登记且满足双方不变量的新鲜实例中完成真实跨边界消费
当前实例正式采用：用户实际实例满足双方强制不变量，并从正式配置入口启用能力
稳定运行入口：跨会话消费者绑定到有明确所有者、生命周期和升级方式的运行产物
持久配置：配置写入已获授权，且只引用符合其承诺期限的实例与运行入口
发布状态：每个参与根的提交、推送、远端或部署状态分别成立
```

隔离互操作通过不等于当前实例已经正式采用。正式采用前从每个参与项目的活动真源读取当前实例必须满足的存储根、内容真源、版本、能力启用和生命周期不变量，并回读实例的真实状态；不能只从适配器能够运行或样例文件已经产生反推采用条件成立。当前实例违反任一参与系统的强制不变量时，能力实现和隔离互操作可以分别完成，但当前实例采用必须标为受阻：不得写入持久配置、不得静默把不变量降级成建议，也不得为了得到完成结论擅自移动数据。可以在独立合规实例中继续互操作验收，或在消费者支持时使用会话级覆盖；当前实例仍需要用户选择合规根、迁移、明确例外或退出采用。

持久配置引用外部可执行文件时，再读取 `user-environment-governance.md` 的稳定运行入口合同。构建输出、缓存、下载解压或临时目录中的文件即使当前存在并能报告版本，也只形成当前运行证据；它们不能自动成为跨会话绑定。安装、复制或建立稳定工具入口是独立动作，没有相应授权时使用会话级参数或环境覆盖完成隔离验收，并把稳定运行入口和持久配置保持为未完成或受阻。

最终报告按上面的状态逐项给出 **已验证 / 仅诊断 / 未验证 / 受阻**，并列出当前实例不变量、实际运行入口来源、已经写入的配置及其期限、仍需用户决定的动作。不能用能力实现、隔离实例的成功或当前进程能启动，替当前实例正式采用、稳定安装、持久配置或发布背书。

同时记录：

- 内容或状态的唯一真源；
- 所有创建、读取、更新、移动、删除或恢复调用点；
- 导出、复制、保存、下载、同步或最终化等持久操作的接受点，以及接受后 `pending → 输入重校验 → 正式生产者 → 物理结果或证据保全 → 唯一终态 → 正式消费者 → 可见确认` 的所有者；接受后的失败不能绕过账本成为无身份错误；
- 公共类型、命令、事件或扩展接口改变时，所有正式契约消费者，包括生产代码、测试夹具、schema、公共导出、文档、示例、SDK 片段、验证与发布脚本、真实用户链工具、生成物来源和维护工具；
- 运行时、桌面原生层、移动端、远程服务和缓存之间的责任；
- 跨进程生产者的业务结果、诊断日志、进程退出和传输收尾分别由哪个通道表达，哪个消费者可以据此改变任务状态；
- 回调、事件处理器或不返回 Promise 的命令若会派生异步工作，由谁登记这些工作，以及空闲、取消、关闭、重启和测试完成边界怎样等待它们；
- 失败、取消、重试、冲突和关闭时怎样收口；
- 现有测试究竟覆盖哪一层。

### 只读命令入口不得激活写入

项目 CLI、维护脚本、验证器或生成器提供 `--help`、`--version`、`describe`、`plan`、`dry-run` 或其它观察入口时，这些入口必须在创建目录、改写配置、刷新生成物、连接会改变状态的服务或启动正式生产者之前完成参数解析并退出。未知参数必须明确非零退出，不能被忽略后继续执行默认写入路径。帮助文本存在、脚本能导入或维护者认为某参数只读，都不能证明它没有副作用。

Agent 在只读审计、诊断或用法探测中，先从参数解析、公开合同或隔离预演确认观察入口和写入入口的边界；无法确认时读取源码或文档，不用 `--help` 试运行。验收记录运行前项目状态和全部登记输出根，让每个观察入口保持逐对象不变，再用一个未知参数证明正式入口在任何写入前拒绝。用户明确授权正式执行只允许调用对应生产动作，不会把探测命令的隐藏副作用变成正确合同。

### 新增写入能力先建立副作用激活图

新增或启用持久化、缓存、日志、恢复、窗口状态、自动创建目录或其它文件写入时，原本只负责构造对象的调用点也可能成为新的生产者。实施前枚举生产对象的全部构造与启动位置，包括正式入口、CLI、后台任务、桌面窗口、smoke、测试 fixture 和共享 helper，并逐项记录：

| 构造或启动位置 | 触发写入的条件 | 解析后的实际输出根 | 生命周期与清理所有者 | 测试隔离或用户保留合同 |
| --- | --- | --- | --- | --- |
| | | | | |

不能只检查新增保存函数的直接调用者。配置默认值、默认数据目录、初始化顺序或构造时副作用改变后，所有能够实例化该对象的路径都要重新进入影响图。共享 helper 和 fixture 除非合同明确说明，否则不得静默创建工作区、目录、文件、安装运行时、注入配置或替测试满足核心前置条件；需要这些动作时用明确参数或专用 fixture 表达，让“无副作用”“输入无效”“取消前未开始”等测试仍能建立真实前置状态。

在运行会写文件的验证前，记录准确项目状态和已登记输出根的存在状态与内容身份；运行后比较同一范围，把每个新增或改变的对象映射回正式生产者、消费者、保留期限和清理责任。不为此扫描整台机器，也不把用户已有未跟踪文件当成测试残留。新增对象来源不明、落在未登记根、清理失败或与“无副作用”承诺冲突时，该项验证不能宣告完整通过；用户没有允许删除时，按已同意的归档方式处理，未获归档授权则保留并准确报告。

改动会影响产品界面时，再补充一份轻量界面合同：当前用户任务、区域与滚动所有权、控件拓扑、关键状态、设计系统真源、目标视口和最终可见验收。结果需要被确认、标记已读或停止重放时，同时写明哪个活动窗口或表面负责展示，以及只有在内容真实出现、非离屏并具有非零几何后才允许确认；把文本写入隐藏控件、虚拟化容器或尚未呈现的树节点不算用户已经看见。纯后端、CLI 或库改动不增加这一步。

全局页面推进、章节内部演出、局部步进、媒体完成或导航恢复中有两个以上会共同改变连续体验时，轻量界面合同进一步冻结交互架构：列出硬保证、可调整目标、互相制约的要求、每个区域的唯一主架构、进入构图到再次进入的阶段、按输入来源与方向划分的所有权，以及自然反向、保持终态或明确重播的返回策略。多个跨页面症状在局部修正或测试通过后继续出现时，先重新打开这份合同并检查是否叠加了第二套滚动或状态所有者；不能继续增加阈值、冷却时间、追赶动画或恢复分支。

用户结果依赖首次渲染、加载、过场、滚动进入、异步资源到达、媒体播放或自动切换的先后关系时，再建立时间过程合同，而不是只写最终状态：

```text
触发动作与正式接受点：
必须依次出现的可观察里程碑：
每个里程碑的状态与资源所有者：
禁止闪现、空白、重叠、回跳或重放的中间状态：
中断、反向、离开再返回和完整重启怎样处理：
证明每个时刻而非只证明终点的验收证据：
```

最终画面正确不能证明启动过程、资源到达窗口或切换过程正确。时间过程里的每项状态仍必须落回同一生产者、边界、消费者和用户结果，不能为测试另建第二套时序解释。

### 代表性规模、消费者扩散与编辑状态

改动涉及列表、时间线、字幕、节点图、日志流、素材库或其它可能达到大量对象的界面时，在选择控件结构和状态通知前冻结代表性规模与用户操作：总对象数、首屏可见数、活动或选中对象数，以及打开、首个稳定画面、选择、编辑并持久化、首次进入可选面板和再次进入。规模来自产品合同或当前真实数据；没有可靠目标时明确标为待确认，不拿一个小夹具证明高基数路径。

随后建立消费者扩散图：

```text
一次正式数据变化
→ 实际实例化的界面对象数
→ 收到通知的消费者数
→ 重新计算、布局、序列化或跨边界传输的次数与范围
→ 尚未可见或尚未访问的面板、预览器和嵌入运行时
→ 用户看到首个结果与完成一次编辑的时间
```

隐藏、折叠或尚未访问的消费者除非承担首次成功路径，不应在启动时创建昂贵对象、启动嵌入运行时或消费全部通知。被动展示项可以按正式内容合同选择聚合绘制、虚拟化或按可见范围物化，交互对象可以限于当前活动或可见子集；这些是根据可访问性、命中、选择和编辑合同作出的候选，不是所有集合的固定实现。选择延迟创建或缓存时，必须同时定义首次访问的加载与错误反馈、再次访问的复用、状态保持、资源释放，以及快捷键、对话框和信号连接如何取得当前活动实例。

不可见不等于未实例化。界面合同要区分已实例化但隐藏、尚未物化或已经销毁；可见性只说明呈现状态，不能证明绑定、事件订阅、处理器或副作用不会运行。已经实例化的对象即使隐藏，绑定仍可能求值，因此表达式必须在空选择、空集合、对象被移除以及切换过程中都有明确结果，不能依赖控件不可见来避开空值。昂贵运行时或带生命周期副作用的消费者需要显式条件物化或等价的加载边界；普通轻量控件不为形式统一强制延迟创建。验收同时覆盖空集合到首项、首项到更多项、移除到空，以及显示、隐藏、再次显示和关闭，并把框架运行时错误、订阅和资源释放作为独立证据。

状态事件还要表达具体发生了什么、稳定对象身份和必要版本。无参数的“某处变化”通知不能授权所有消费者重建全部投影，也不能让无关选择变化覆盖本地草稿。编辑表面应把草稿绑定到正式对象身份与基线版本，只在对象真正切换、明确放弃或按冲突合同提交时重载；后台任务与表单可能同时更新同一设置时，表单只提交相对于当前权威状态的脏字段补丁，不能把加载时的完整旧快照写回并覆盖后台新值。

### 状态提交必须到达当前活动投影

同一聚合会被两个以上正式编辑命令、控制器、后台任务、导入器或回调修改，或者界面会在运行中动态增加、移除或重新分类集合对象时，在实现前建立一份活动投影合同：

```text
正式变更入口及各自允许改变的事实：
唯一提交边界、聚合身份与提交版本：
提交成功后发布的语义事件、对象身份、事实类别和版本：
打开中的编辑器、缓存聚合与派生视图怎样共享、协调、失效或重载：
界面绑定实际订阅的框架可观察属性、模型信号或事件：
本地草稿、并发提交和版本冲突怎样保留或拒绝：
无需关闭、重开或手工刷新即可观察的最终结果：
```

优先让所有变更经过同一个活动聚合所有者；入口必须独立提交时，由唯一提交边界发布带稳定身份和版本的完成事件，缓存消费者按合同协调、失效或重载，再允许后续编辑。不能让一个入口直接改存储，另一个入口继续持有无版本旧快照；也不能用无参数全局通知让全部表面盲目重建。存在本地草稿时，后台提交只使相关事实进入版本协调或冲突处理，不得静默覆盖草稿，也不得让草稿稍后把后台新值整份写回。

穿过事件、轮询、心跳、IPC 或网络的状态更新，必须由正式生产者声明它是覆盖其完整责任范围的快照，还是只改变已列字段的补丁，并携带稳定聚合身份、generation 或等价代次以及提交版本。完整快照只有包含该责任范围全部当前字段时才允许替换；补丁只改变明确出现的字段，字段省略表示保持当前值，显式清空必须使用合同内可区分的值或操作。消费者不得把补丁当快照、用语言默认值补齐省略字段，或从 payload 大小猜测更新类型。

快照和补丁都交给同一个活动聚合所有者按身份与版本合并。旧 generation、倒退版本或责任范围不匹配的更新在这里拒绝；高频补丁只有在不越过终态、错误或用户可见里程碑的情况下才能合并或丢弃旧值，不能由每个消费者各自决定保留什么。

异步加载的持久化历史、远端基线或初始快照可能与实时事件同时到达时，快照必须携带读取时的聚合身份、基线版本或等价顺序边界，并与基线之后的实时增量交给同一个 reducer 或活动聚合所有者。较晚返回的旧快照只能更新它负责的基线分区，再合并或重放所有更新版本的实时事件；不得用整表替换删除快照请求发出后已经进入界面的消息、任务或状态。无法提供稳定版本时，在加载期间由同一所有者无损缓存增量并在快照提交后重放，不能让快照生产者和事件消费者各自维护一份当前列表。

验收用受控屏障暂停正式快照生产者，让实时生产者经实际事件边界提交至少一项新状态，再释放快照；当前活动表面最终同时包含基线内容和实时增量，并立即允许一次依赖新状态的后续动作。只分别测试快照替换和事件追加，或者由测试直接调用 reducer 手写两边输入，不能证明真实并发链不会丢失结果。

更新类型合同再用另一条真实链验收：让正式生产者先发布包含多个字段的完整快照，再经实际边界发布只更新一个高频指标的补丁，证明其它字段仍然保留；随后发布显式清空，并交错一个旧 generation 或倒退版本的补丁，证明清空被正式消费者看见而过期更新被唯一所有者拒绝。消费端手写 payload 或直接调用 reducer，不能证明生产者声明、边界传递和当前消费者使用了同一更新语义。

响应式框架中的绑定必须依赖框架能够观察的属性、集合模型通知、计数信号或等价事件。模板或表达式调用一个能够查询最新数据的普通方法，只证明重新调用时返回正确，不证明底层状态改变会触发重新求值。动态集合至少明确空集合到首项、首项到更多项以及移除末项时，哪些可见性、数量、可用性、布局和命中投影更新；为修复一处界面而手工调用刷新函数，不能代替正式状态链。

没有活动缓存、动态投影或多个变更入口的普通单入口状态修改不增加这份合同。触发条件成立时，它补充消费者扩散与编辑状态，而不建立第二套事件总线、状态容器或界面模型。

名称相同不表示职责相同。两条路径只有在输入、责任、输出、消费者和停止位置都相同时才可合并。

文档和示例如果教用户或扩展作者调用公共接口，就是契约消费者，不是发布前再顺手更新的说明材料。验证脚本、发布前检查和真实用户链工具同样是公共接口的正式消费者；接口或生命周期状态迁移时必须与生产调用点一起迁移，不能等昂贵的最终链首次运行时才发现它仍调用旧入口、私有状态或已经退出的 helper。事件处理器本身被 `await` 也不代表生命周期已经收口：只要它在内部启动了未登记的异步工作，任务就可能在空闲、关闭或测试完成之后继续改变状态。

### 工作区存在其它写入者时

把前后结果解释为同一路径被外部改写前，先消费验证输入覆盖合同：从目录枚举、清单、正式事务或其它权威发现结果取得准确路径并直接复用，记录每次工具实际收到的字面路径、工作目录和解析后的稳定身份。身份不同的结果只能分别描述各自对象；“未找到”不能证明另一条近似路径对应的文件曾经存在或已经消失。只有同一身份在可比条件下确实变化，才进入外部写入者判断和后续等待，不能先把同步软件、生成器或其它进程当成已经成立的原因。

如果文件位于同步目录，项目运行着生成器、编辑器监视器或开发服务器，另一个 Agent、终端或进程也可能写入，或者状态在本轮没有执行对应动作时自行变化，就把这些来源作为并发生产者纳入影响图。开始写入前记录受影响路径的存在状态、内容身份和项目状态；只记录当前结果会消费的范围，不为此扫描整台机器。

在覆盖、恢复、格式化、批量改写、暂存或用旧验证继续下一步之前重新读取这些路径，并把变化分为：本轮动作直接产生、开始前已经存在、已确认的正式生产者产生、外部或来源未知。前两类按原范围处理；正式生产者需要进入生命周期与完成边界；外部或未知变化不得被恢复、覆盖、混入本轮修改或用作成功证据。只冻结与变化路径冲突的写入动作，安全的只读调查可以继续。

外部变化若确实是当前用户结果需要的新输入，先确认它的来源、产品含义和唯一所有者，再更新生产者、清单或存储边界、全部消费者与验收。文件刚好出现在运行目录、现有布局能够容纳或测试夹具已经支持，都不能代替完整迁移。外部变化与当前结果无关时保留原状并从本轮写入和验证中排除，不能为了得到干净状态使用恢复或删除。

把写任务委派给共享同一工作区的 Agent、线程或其它执行单元前，主任务先冻结委派合同：准确用户结果、允许修改的根与文件、禁止重叠的所有者、必须运行的验证，以及返回时必须交付的实际变更、证据、未验证承诺、仍在运行的进程和残留。多个写入者不得同时拥有同一文件或同一业务边界；必须并行改相邻消费者时，由主所有者明确合并顺序和最终迁移责任。

共享写入者结束、失联或中断后，只要它可能已经改变状态却没有完成上述交接，就把现有改动视为**未验证的部分交付**，不能根据任务状态、先前计划或文件时间推断完成。主所有者要从当前工作区重新清点实际变化和内容身份，把每项变化映射回生产者、边界、消费者与权限范围，检查是否留下半迁移、并行实现或未归属文件，再从这份最新状态取得受影响检查的新鲜退出证据。并发期间被观察到的中间状态不是产品失败证据；只有冻结后的交接状态或主所有者复核后的稳定状态才能进入缺陷与完成结论。
