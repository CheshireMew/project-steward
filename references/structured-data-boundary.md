# 结构化数据边界

用于外部输入、持久化文件、网络或进程消息、模型输出和维护脚本中的 JSON。目标是让同一份数据只经过一个可审计的结构化入口：原始字节怎样解码、允许消耗多少资源、什么数值和结构合法、怎样进入类型与 schema、失败怎样被消费者理解，都由同一个合同负责。

模型调用中的消息来源、角色、route、输出示例、实际线请求、运行时状态与呈现职责由 `model-mediated-operation-governance.md` 负责；本方法只拥有 JSON 的序列化、解析、schema、资源预算、逻辑消息从传输到完整提交的容量边界和稳定错误，不能用解析规则替代模型请求语义。

只读取代码内固定且受语言工具链控制的常量，或者已经接收该边界产出的类型化对象时，不增加一次重复解析。不同协议可以有各自的薄合同实例，但不能各自复制一套宽松解析、限制和错误解释。

## 1. 找到唯一结构化入口

当生产代码、CLI、迁移器、验证器或维护脚本中出现多个 `JSON.parse`、`json.loads` 或等价调用时，先建立：

```text
原始来源、内容身份与信任边界：
正式生产者及其输出编码：
唯一结构化入口及其合同版本：
字节、结构和数值预算：
类型、schema 与版本所有者：
正式消费者和用户可见结果：
稳定错误类别与展示所有者：
全部直接解析调用点和旧 helper：
```

唯一入口接收原始字节或明确编码的文本，只返回类型化结果或结构化错误。业务消费者不得再读取原文补字段、调用第二个解析器重试、用正则提取局部 JSON，或在解析失败后切换到更宽松的模式。序列化器是这条边界的正式生产者；它产出的真实字节同样要能被当前入口和 schema 消费。

## 2. 一份合同拥有全部限制

合同至少明确：

| 维度 | 唯一边界必须决定的事实 |
| --- | --- |
| 编码与总量 | 接受的字符编码、BOM 规则、按原始字节计算的最大输入、解码失败和尾随内容 |
| 结构预算 | 最大嵌套深度、对象成员数、数组元素数、节点总数、字符串和键长度；预算在完整物化前生效 |
| 对象语义 | 重复键在映射覆盖前直接拒绝；字段名规范、未知字段和字段省略由 schema 决定 |
| 数值 | 拒绝 `NaN`、正负无穷和其它非 JSON 数值；在通用数值转换前限制数字 token 长度、整数位数和指数，再按目标类型范围转换，溢出不得截断、取整或变成无穷 |
| 类型与版本 | 根类型、字段类型、必需字段、`null`、默认值、枚举、版本和迁移入口 |
| 输出与错误 | 类型化结果，或包含稳定类别、字段路径和安全位置的错误；原始解析器异常不直接成为产品提示 |
| 序列化 | 编码、非有限数值拒绝、字段省略、稳定版本和必要的规范化；不能由不同生产者各自猜测 |
| 逻辑消息与传输 | 最大合法逻辑记录、序列化后字节量、每一跳的帧或正文限制、重组预算、原子提交和重放游标；分片时的消息身份、顺序、完整性与确认 |

schema 还必须把字段缺失、显式 `null`、默认值和合同允许的空或假值分开。对适用字段至少列出缺失、`null`、空字符串、`0`、`false`、空数组和空对象中的合法与非法项；只测试该字段类型可能出现的值，不为形式完整强塞无关类型。校验器按字段是否存在、实际类型和字段约束判断，不能用真值判断把合法空值当成缺失，也不能用默认值覆盖调用者明确提供的合法空值。序列化、迁移和正式消费者必须保持同一组区别。

只限制文件大小不足以控制深层嵌套、超长数字或巨型集合；只做 schema 校验也可能发生在解析器已经消耗过量资源之后。先在最早能够拒绝的位置执行字节、token 和结构预算，再建立内存表示并进入类型与 schema。解析成功只证明语法成立，不证明数值可表示、版本受支持或业务对象有效。

错误至少区分编码、总量、结构预算、重复键、数值、语法、schema、版本、传输容量、重组不完整和内部边界故障。日志可以记录合同版本、来源身份、错误类别与安全位置，不默认记录完整外部内容、凭据或模型原文。消费者只把稳定错误映射成界面、CLI、恢复或重试结果，不能从异常文字判断类别。

### 身份确定后的结构化对象不能继续漂移

结构化对象进入内容哈希、缓存身份、签名、验证回执或不可变历史后，其身份覆盖的全部嵌套状态必须保持稳定。外层的 `frozen`、`readonly`、`const` 或禁止重新赋值只限制外壳，不能证明内部对象、数组、集合或缓冲区不会被原始调用方和后续消费者修改。先列出身份实际覆盖的字段、嵌套可变点、正式序列化器和全部消费者，再由同一边界选择一种真源：保存规范字节并在消费时从同一字节重建或复验，或者防御性复制后递归冻结身份覆盖的内存表示。不能先按可变对象计算身份，再把原引用继续交给调用方。

冻结是状态稳定策略，不得暗中改写公共数据合同。JSON array 不能仅为获得哈希能力就变成消费者看见的 tuple，object 也不能换成正式序列化器、相等比较、迭代或类型检查器不再接受的私有包装。必须使用不同内部表示时，由唯一结构化边界负责双向转换，公共 schema、数组与对象形状、字段顺序承诺、相等语义、序列化字节和类型合同继续按原决定成立；各消费者不得自行解冻或猜测包装类型。

验收先让正式生产者用可变输入建立身份对象，再修改原始输入并尝试修改对象内部的每一类嵌套容器，证明既有身份和正式序列化结果不变；随后让正式序列化器、schema 校验器、类型检查器和至少一个真实消费者读取同一对象，核对公共形状、比较和迭代行为。合同允许变化时创建新版本与新身份，不能原地修改后沿用旧哈希。只验证属性不能重新赋值、只比较哈希字符串或只让私有 helper 序列化成功，都不能证明深层稳定性和消费者兼容性同时成立。

### 逻辑消息容量必须穿过完整传输链

正式生产者可能生成大型结构化结果、事件或持久记录时，先从 schema 和代表性最大工作负载得到最大合法逻辑消息，再记录序列化后的实际字节量，以及生产者缓冲、持久日志、代理、HTTP 或 WebSocket 帧、进程管道、接收器、重组器和消费者各自允许的上限。解析入口能够接受该对象，不代表中间传输能够交付；只提高接收端解析预算，也不能修复发送帧、代理正文或持久重放仍然更小的链路。

逻辑消息必须原子提交时，每一跳都要在明确余量内承载最大合法消息。任一跳无法承载时，不能靠反复重连、缩小测试样例或让消费者猜测残缺结果继续；要么收紧权威合同的最大合法消息并让生产者在写入前拒绝，要么建立版本化分片协议。分片协议至少拥有稳定逻辑消息身份、协议版本、分片序号、总数或结束标记、整体长度或摘要、单片限制、重复与缺失处理、完整校验、一次提交和确认语义，不能把若干普通事件拼成没有共同身份的临时批次。

持久重放游标只在完整逻辑消息通过重组、结构预算、schema 和业务提交后前进。部分消息、容量拒绝、版本不支持或完整性失败必须形成可观察的稳定错误，并保持能够诊断或明确跳过的记录身份；不能让同一条永久不可交付记录把游标卡住，驱动客户端无界重连，同时让下游继续显示旧的进行中状态。重试必须复用同一逻辑消息身份和已定义的确认边界，不能把一次业务结果复制成多个终态。

验收由正式生产者分别生成接近上限和最大合法规模的真实消息，经过实际持久化与网络或进程边界，由正式消费者提交并形成用户结果；随后在传输中断后从真实游标重放同一消息，并证明没有丢失、重复或提前前移。若采用分片，再改变分片边界、重复一片、遗漏一片和破坏整体摘要；若采用原子帧，再验证超过权威上限的生产请求在进入持久队列前以稳定类别失败。消费端手写大对象、只测解析器或只证明数据库已有完成记录，都不能替代这条链。

## 3. 一次迁移全部调用点

修复分散解析时按以下顺序完成：

1. 枚举生产代码、桌面或服务入口、后台任务、迁移器、导入导出、验证与发布脚本、真实用户链工具和维护脚本中的全部 JSON 读取与写入。
2. 由权威 schema 和正式消费者冻结目标类型、版本、预算和错误合同；不能从当前宽松解析器碰巧接受的样例反推合同。
3. 建立唯一公共结构化入口，让正式生产者的真实输出先经过它，再迁移全部消费者。
4. 删除活动调用点中的原始解析、重复限制、第二套错误映射、宽松回退和旧 helper；内部重构不保留兼容层。
5. 用能够区分标识符与说明文字的残留搜索检查原始解析器和旧入口；逐项解释仍然存在的生成代码、依赖内部实现或受控常量。

维护脚本不能因为“只给开发者使用”而复制生产合同。它们处理同一种数据时调用同一公共入口；确实处理另一种格式时拥有明确的不同 schema 和停止位置，不能借脚本私有解析改变产品数据。

## 4. 真实验收

关键链必须是：

```text
正式生产者生成真实对象
→ 正式序列化器产生字节
→ 实际文件、网络或进程边界
→ 唯一结构化入口解码、限额、解析并校验
→ 正式消费者读取类型化结果
→ 用户得到可观察结果或可操作错误
```

正常样例由正式生产者产生，不能由消费端手写一份“等价 JSON”冒充。对抗输入可以直接送到外部边界，用来分别证明：错误编码与尾随内容、刚好低于和超过字节预算、深度与节点数超限、重复键、超长键或字符串、`NaN` 与无穷、超长整数、巨大指数、目标类型溢出、根类型错误、字段缺失、显式 `null`、合同允许的空字符串、`0`、`false` 或空集合、未知字段、版本不支持和迁移失败。合法空值必须由正式生产者经过同一边界到达消费者并保持原义；非法项在唯一入口得到稳定错误，消费者不得崩溃、挂起、改用宽松结果或把它静默替换成默认值。

生产和维护入口都要执行同一组合同案例。修复完成后，再让实际序列化产物经过存储或传输边界和正式消费者；解析库单元测试、schema 对手写对象通过或残留搜索零匹配，各自都不能替代这条链。

## 5. 输出与停止位置

第一段直接说明原始数据第一次进入系统的位置、当前分叉点和最终唯一入口。随后给出合同预算、schema 与版本、身份后的状态稳定策略、错误映射、全部生产者和消费者、迁移与旧路径退出、残留搜索以及真实链证据。用户只要求诊断时停在证据与最终修法；明确要求修复时才迁移调用点，并在旧解析路径已经不存在后结项。
