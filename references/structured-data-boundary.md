# 结构化数据边界

用于外部输入、持久化文件、网络或进程消息、模型输出和维护脚本中的 JSON。目标是让同一份数据只经过一个可审计的结构化入口：原始字节怎样解码、允许消耗多少资源、什么数值和结构合法、怎样进入类型与 schema、失败怎样被消费者理解，都由同一个合同负责。

模型调用中的消息来源、角色、route、输出示例、实际线请求、运行时状态与呈现职责由 `model-mediated-operation-governance.md` 负责；本方法只拥有 JSON 的序列化、解析、schema、资源预算和稳定错误，不能用解析规则替代模型请求语义。

只读取代码内固定且受语言工具链控制的常量，或者已经接收该边界产出的类型化对象时，不增加一次重复解析。不同协议可以有各自的薄合同实例，但不能各自复制一套宽松解析、限制和错误解释。

## 1. 找到唯一结构化入口

当生产代码、CLI、迁移器、验证器或维护脚本中出现多个 `JSON.parse`、`json.loads` 或等价调用时，先建立：

```text
原始来源、内容身份与信任边界：
正式生产者及其输出编码：
唯一结构化入口及其合同版本：
字节、结构和数值预算：
类型、schema 与版本所有者：
正式消费者和用户可见结果：
稳定错误类别与展示所有者：
全部直接解析调用点和旧 helper：
```

唯一入口接收原始字节或明确编码的文本，只返回类型化结果或结构化错误。业务消费者不得再读取原文补字段、调用第二个解析器重试、用正则提取局部 JSON，或在解析失败后切换到更宽松的模式。序列化器是这条边界的正式生产者；它产出的真实字节同样要能被当前入口和 schema 消费。

## 2. 一份合同拥有全部限制

合同至少明确：

| 维度 | 唯一边界必须决定的事实 |
| --- | --- |
| 编码与总量 | 接受的字符编码、BOM 规则、按原始字节计算的最大输入、解码失败和尾随内容 |
| 结构预算 | 最大嵌套深度、对象成员数、数组元素数、节点总数、字符串和键长度；预算在完整物化前生效 |
| 对象语义 | 重复键在映射覆盖前直接拒绝；字段名规范、未知字段和字段省略由 schema 决定 |
| 数值 | 拒绝 `NaN`、正负无穷和其它非 JSON 数值；在通用数值转换前限制数字 token 长度、整数位数和指数，再按目标类型范围转换，溢出不得截断、取整或变成无穷 |
| 类型与版本 | 根类型、字段类型、必需字段、`null`、默认值、枚举、版本和迁移入口 |
| 输出与错误 | 类型化结果，或包含稳定类别、字段路径和安全位置的错误；原始解析器异常不直接成为产品提示 |
| 序列化 | 编码、非有限数值拒绝、字段省略、稳定版本和必要的规范化；不能由不同生产者各自猜测 |

只限制文件大小不足以控制深层嵌套、超长数字或巨型集合；只做 schema 校验也可能发生在解析器已经消耗过量资源之后。先在最早能够拒绝的位置执行字节、token 和结构预算，再建立内存表示并进入类型与 schema。解析成功只证明语法成立，不证明数值可表示、版本受支持或业务对象有效。

错误至少区分编码、总量、结构预算、重复键、数值、语法、schema、版本和内部边界故障。日志可以记录合同版本、来源身份、错误类别与安全位置，不默认记录完整外部内容、凭据或模型原文。消费者只把稳定错误映射成界面、CLI、恢复或重试结果，不能从异常文字判断类别。

## 3. 一次迁移全部调用点

修复分散解析时按以下顺序完成：

1. 枚举生产代码、桌面或服务入口、后台任务、迁移器、导入导出、验证与发布脚本、真实用户链工具和维护脚本中的全部 JSON 读取与写入。
2. 由权威 schema 和正式消费者冻结目标类型、版本、预算和错误合同；不能从当前宽松解析器碰巧接受的样例反推合同。
3. 建立唯一公共结构化入口，让正式生产者的真实输出先经过它，再迁移全部消费者。
4. 删除活动调用点中的原始解析、重复限制、第二套错误映射、宽松回退和旧 helper；内部重构不保留兼容层。
5. 用能够区分标识符与说明文字的残留搜索检查原始解析器和旧入口；逐项解释仍然存在的生成代码、依赖内部实现或受控常量。

维护脚本不能因为“只给开发者使用”而复制生产合同。它们处理同一种数据时调用同一公共入口；确实处理另一种格式时拥有明确的不同 schema 和停止位置，不能借脚本私有解析改变产品数据。

## 4. 真实验收

关键链必须是：

```text
正式生产者生成真实对象
→ 正式序列化器产生字节
→ 实际文件、网络或进程边界
→ 唯一结构化入口解码、限额、解析并校验
→ 正式消费者读取类型化结果
→ 用户得到可观察结果或可操作错误
```

正常样例由正式生产者产生，不能由消费端手写一份“等价 JSON”冒充。对抗输入可以直接送到外部边界，用来分别证明：错误编码与尾随内容、刚好低于和超过字节预算、深度与节点数超限、重复键、超长键或字符串、`NaN` 与无穷、超长整数、巨大指数、目标类型溢出、根类型错误、字段缺失、显式 `null`、未知字段、版本不支持和迁移失败。每一项都要在唯一入口得到稳定错误，消费者不得崩溃、挂起或改用宽松结果。

生产和维护入口都要执行同一组合同案例。修复完成后，再让实际序列化产物经过存储或传输边界和正式消费者；解析库单元测试、schema 对手写对象通过或残留搜索零匹配，各自都不能替代这条链。

## 5. 输出与停止位置

第一段直接说明原始数据第一次进入系统的位置、当前分叉点和最终唯一入口。随后给出合同预算、schema 与版本、错误映射、全部生产者和消费者、迁移与旧路径退出、残留搜索以及真实链证据。用户只要求诊断时停在证据与最终修法；明确要求修复时才迁移调用点，并在旧解析路径已经不存在后结项。
