# 生产存储预防与审查

这份方法负责会持续生成大型媒体、缓存、测试证据、下载、模型或中间产物的生产项目。目标不是把“不要用系统盘”改写成另一个盘符，而是在任何大规模写入发生前，让项目自己的生产者拥有受控根、容量预算、复用身份、运行清单和可审查终态。Project Steward 负责建立与验收这条能力；项目运行时代码负责真正阻止越界写入。

## 1. 先把一次写盘当成生产合同

进入源码写入前，按正式生产者逐项冻结：

```text
生产者与公开入口：
项目事实的唯一所有者：
物理根由项目相对路径、运行配置还是用户环境策略解析：
将产生的真源、交付物、缓存、临时文件和验证证据：
本次预计新增量、同时存在的峰值及估算依据：
最大受管容量与最低剩余空间的配置来源：
重复输入的稳定身份、共享或复用方式：
成功、失败和中断各自保留什么：
清理授权、清理候选报告和实际执行者：
运行前闸门、运行后清单与用户可见入口：
直接覆盖这些承诺的确定性测试：
```

预计峰值未知、预算来源缺失、正式根不能唯一解析、清理权限不成立或消费者仍会自行拼接第二个根时，审查状态为阻塞。不能把当前磁盘空间很多、改用非系统盘、目录被 Git 忽略、文件属于缓存或以后可能清理当成通过依据。

项目和机器事实继续分层：项目源码与 `.project-steward/storage-contract.json` 记录生产者、类别、实现入口和稳定治理决定；盘符、绝对路径、具体容量与本机保留偏好由运行配置或用户环境档案提供。项目合同不得写入用户目录、盘符或某台机器的剩余空间。

## 2. 事先预防必须发生在首个大文件之前

运行时预检由真正写文件的生产者调用，至少同时核对：

- 目标路径解析后位于登记根内，不能从当前目录、驱动器根、测试根的祖先或无关仓库推导临时目录；
- 当前受管用量加预计新增量不超过配置预算；完成本轮预计写入后仍满足最低剩余空间；
- 单个大文件和整轮峰值都有可复核算法，压缩结果未知时使用保守上界或明确停止；
- 相同输入与参数能够按内容身份复用时，不为新的任务 id、测试 id 或重试复制同一大对象；
- 生产者在写入前已经建立运行身份与所有权清单，失败和中断不会留下无法归属的目录。

预检失败必须在创建大文件、启动下载、解码全量帧、展开依赖或并行启动 worker 之前停止，并返回准确根、当前用量、预计新增量、容量上限、剩余空间要求和清理候选入口。不得静默换盘、降低质量、缩小测试范围或继续写到阈值之外。

长任务在阶段边界重新核对本轮实际用量。实际增长超过本轮预算时停止后续阶段并封存当前清单，不能因为前一阶段已经花费时间就继续扩大残留。

## 3. 获准实施时必须写进生产项目

用户授权修复或治理目标项目后，Project Steward 不停在建议、外部包装脚本或自己的 reference。按同一依赖闭包完成：

1. 用 `scripts/project_templates.py` 为目标项目采用或升级显式的 `managed-runtime-artifacts` 模板，使 `.project-steward/project.json` 固定本项目的治理决定。
2. 在目标项目写入 `.project-steward/storage-contract.json`，列出真实生产者、运行根来源、产物类别、预算与估算入口、复用身份、终态清单和直接测试；再用 `scripts/production_storage_review.py <项目根>` 审查。
3. 修改目标项目的实际生产者、配置读取器、缓存或任务生命周期代码，让预检和终态清单位于首个大文件之前与最后一个生产者释放之后。不能让 Project Steward 的脚本成为运行时代理。
4. 更新目标项目现有唯一说明和公开配置示例。项目已有同类运行清单或缓存管理器时原位增强，不新增平行框架。
5. 添加确定性测试，证明普通根和配置根都保持在项目或环境登记范围；相同大输入只生成一份共享对象；超过预算和最低剩余空间时零大文件写入；成功、失败和中断都能列出实际残留；未知、活动或无所有权对象不进入清理候选。

Project Steward 只在目标项目获得写入授权时执行上述写入。只读审查停在合同缺口和影响图，不用生成 `.project-steward` 文件伪装成项目已经采用。

## 4. 终态清单与删除边界

每次运行的终态清单至少记录运行身份、生产者、状态、登记根、实际新增和复用对象、各类别字节数、峰值、失败或中断残留以及清理候选。真源、交付物、可重建缓存、纯临时文件和验证证据必须分开，不能用一个 `working` 标签永久保留全部内容。

清理候选只包含由清单证明属于当前工具、已经终止且不再被消费者使用的对象。用户或项目要求删除逐次授权时，运行时代码只报告准确候选和可回收字节，不自动删除；达到预算时停止新生产并等待处置。若项目已有用户明确启用的保留策略，自动轮换也只能处理该策略登记、可重建且不活动的对象，并把失败写回清单。

移动到归档不是释放容量的默认替代。只有归档根、容量、保留期和消费者已经明确，且移动本身得到授权时才执行；否则保持原位并报告。

## 5. 验收从生产者到磁盘结果闭环

先运行 `scripts/production_storage_review.py <项目根>`，确认生产合同、活动源码和测试入口一致。随后从项目真实公开入口执行至少四条链：首次生产、同输入复用、预算拒绝、失败或中断恢复。验收读取真实文件系统结果和运行清单，核对目标根、实际字节、对象数量与用户可见报告；不能只断言一个估算函数、手写缓存文件或 mock 掉真实写入边界。

任务结束后重新盘点所有登记根，并与运行前基线比较。只有没有新增未登记根、没有重复大对象、预算拒绝发生在首个大文件之前、终态清单覆盖全部实际残留，而且正式消费者仍能读取复用对象和最终结果，才能关闭这项治理。旧目录退出仍遵守用户的移动、归档和删除授权；本次能力完成不以清理历史文件为前提。
