# 运行时消息传输与消费者就绪治理

用于 IPC、MessagePort、worker、线程消息或等价运行时通道新增、替换或改变数据表示、传输所有权、首条与终态投递、ACK、背压或懒加载监听的任务。目标是让正式生产者创建的同一条消息经过目标运行时真实支持的发送 API，按明确的线表示和所有权到达已经就绪的消费者，再形成业务结果或稳定错误。

本方法只拥有运行时消息的线表示、可传输对象、投递就绪、确认和通道收口。JSON 编码、schema、逻辑分片与重放游标归 `structured-data-boundary.md`；session、generation 与 callable 状态归 `change-prevention-state-and-capability.md`；任务终态归 `durable-operation-governance.md`；进程、窗口和设备所有权归对应桌面与根因方法。普通进程内函数调用、没有消息边界的纯计算优化和只读取已经类型化对象的消费者不进入本方法。

## 1. 冻结实际运行时传输合同

写入前记录：

```text
用户结果与改变消息通道的原因：
目标平台、运行时、框架及准确版本：
正式生产者、发送对象与消息身份：
实际发送 API、允许的数据与 transfer list：
结构化克隆、复制、移动或共享后的所有权：
接收事件及 event.data 的真实形态：
跨 realm 或语言边界的规范化入口：
监听器注册、传输可用与领域消费者就绪里程碑：
首条、普通、终态消息的投递与保留策略：
sequence、generation、ACK 与业务提交的所有者：

正式消费者与最终用户结果：
```

发送端能够创建 `ArrayBuffer`、typed array、Blob、端口或原生句柄，不表示当前发送 API 允许把它放入正文或 transfer list。根据目标运行时实际类型、版本和正式入口冻结允许集合，并区分结构化克隆、复制、所有权转移和共享；传输后发送端还能否读取、底层内存是否仍有第二份、失败时谁释放，都进入同一合同。不能从浏览器同名 API、另一 Electron 进程类型、语言声明的宽泛联合类型或开发者记忆推断当前宿主行为。

接收边界先验证外层事件、正文存在性、消息版本和稳定身份，再读取 sequence 或业务字段。`null`、`undefined`、空载荷、错误类型、已分离缓冲区、版本不支持和不允许的可传输对象分别形成稳定传输错误；不得让属性读取异常成为协议结果，也不得用默认对象、空数组或上一条消息补齐。跨 realm、preload、sandbox 或语言边界的二进制值在唯一适配器按可观察结构和运行时支持的转换规范化，不能只用当前 realm 的 `instanceof` 判断真实性。

逻辑正文是 JSON 时继续经过结构化数据唯一入口；二进制和元数据组成一条业务消息时，共享同一消息身份、顺序、长度或摘要与提交边界，不能让控制帧成功掩盖正文缺失，也不能让消费端手写元数据重新关联未知二进制对象。

## 2. 把通道存在与消费者就绪分开

端口创建、连接打开、模块开始加载、监听器注册和领域消费者能够处理消息是不同里程碑。任何首条、关闭、取消、失败或其它一次性事件可能早于消费者就绪时，只能选择并冻结一种完整机制：在生产者启动前同步注册必要监听器；由消费者提交 ready 握手后生产者才可发送；或者由通道所有者按稳定消息身份和顺序做有界缓冲并在 ready 后原样排空。固定等待、通常足够快的 import、发送失败后重试和消费者自行读取“当前状态”不能代替投递合同。

缓冲合同说明容量、溢出、重复、顺序和终态。不可丢终态不得与可合并遥测共用覆盖槽；模块加载失败、页面或窗口关闭、取消和宿主退出时，已接收未消费、仍在途和尚未产生的消息分别进入准确终态。旧 generation 的迟到 ready、ACK 或完成事件只能收口旧尝试，不能释放当前队列或改写新消费者。

验收至少制造一次真实竞争：让正式生产者在懒加载消费者注册前产生首条或关闭事件，再证明合同选择的注册、握手或缓冲机制让匹配消费者只消费一次；随后让加载失败或关闭发生在排空期间，证明终态没有丢失、重复或投递给已经销毁的消费者。直接等待模块加载完成后才手工触发事件，不能覆盖这项风险。

## 3. ACK、背压与释放必须表达真实事实

ACK 必须声明它确认的是传输层收到、边界校验通过、消费者接受，还是业务结果已经提交。上游只有在合同允许的里程碑后才能释放、复用或覆盖源缓冲；收到端口事件不能替代正式消费者提交。每条需要关联的消息携带稳定身份与 sequence，重复、缺失、乱序、迟到和未知 ACK 在一个边界处理，不由发送端、接收端和界面分别猜测。

逐层记录生产速率、消费速率、最大在途消息、单条和累计字节、运行时或原生缓冲、满载策略和解除压力后的恢复。JavaScript 队列有界不能证明编解码器、原生端口或下游消费者没有继续积压；帧率或最终输出正常也不能掩盖未确认消息持续占用内存。背压必须在最早拥有消费者容量事实的边界阻止新生产、等待、合并可丢遥测或按产品合同降级，不能先生产完整大对象再在末端丢弃。

关闭顺序为“停止新生产 → 处理或拒绝在途消息 → 提交不可丢终态 → 等待匹配 ACK 或明确失败 → 释放消息和通道 → 销毁消费者”。超时只说明仍有未知所有权；不能把缓冲当成已释放，也不能关闭旧通道后由迟到回调重新创建生产者。

## 4. 用目标运行时证明真实往返

正式验收按以下顺序执行：

1. 从项目锁定运行时、类型声明和实际调用点取得发送 API、正文与 transfer 规则；只保留会改变当前合同的官方或运行证据。
2. 用最小真实消息从正式生产者经过目标平台和运行时的实际通道，让正式消费者提交可观察结果，同时记录发送前、发送后、接收、校验、ACK 和释放身份。
3. 覆盖合法消息，以及 `null` 或空载荷、错误类型、不允许传输、重复或乱序、首条早于 ready、终态与关闭竞争、过载和解除压力；只选择项目真实存在的维度。
4. 先证明正确性、终态和释放，再测复制次数、在途字节、内存、延迟和吞吐。正确性链失败后的性能数字只用于定位，不能成为采用新通道的理由。

浏览器 MessageChannel 不能替代 Electron MessagePortMain，当前线程的 worker mock 不能替代实际 worker，直接调用接收 handler 也不能证明发送、克隆、转移、监听器注册和关闭成立。确实无法启动目标运行时时，停在静态合同或诊断证据，明确把真实往返、资源和用户结果标为未验证。

## 5. 修复与输出

已经出现 `event.data` 为空、属性读取崩溃、sequence 或 ACK 不前进、首次操作无响应、关闭超时或懒加载后偶发丢事件时，先保留经过真实通道的失败证据，定位第一次改变表示、越过未就绪消费者或丢失所有权的边界。空值保护只能成为稳定错误入口；重试只有在消息身份、幂等、旧尝试收口和容量成立时才可加入。最终修复一次迁移生产者、适配器、发送与 transfer 调用、监听器就绪、ACK、背压、消费者和关闭链，并退出旧通道、双发、猜类型和固定等待。
