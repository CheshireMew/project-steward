# 高频界面问题模式

## 用法与边界

只在界面问题反复出现、跨区域扩散、明显来自共享边界，或存在稳定的媒体与平台跨层边界信号时使用。先用实际项目证据匹配模式，再回到当前项目确定唯一真源和迁移范围；不要把本文件当成所有界面每次都要逐项执行的检查表。

模式只记录稳定因果关系。组件名称、库 API、像素尺寸、颜色值和一次性修补留在当前项目。

每张模式卡都回答：何时适用、用户能看到什么、常见根因边界、最早预防点、目标结果、确定性证据、真实可见证据和版本范围。

## 1. 区域或窗口外壳所有权泄漏

- **适用**：标题栏、侧栏、内容头部、边框、滚动层或临时表面互相侵入。
- **症状**：原生白条与应用外壳割裂；内容分隔线伸入侧栏；最大化、主题或缩放后边界错位。
- **常见根因**：外壳策略未决定，或多个容器同时拥有同一边界、拖动区和窗口控件。
- **最早预防**：实现布局前为窗口外壳、标题栏、导航、内容头、边框和滚动分别指定唯一所有者。
- **目标结果**：每条边界只由一个区域绘制，原生与自绘外壳只有一种活动策略。
- **确定性证据**：配置、布局容器、控制调用和权限与选定策略一致；无第二套活动入口。
- **真实证据**：真实窗口在普通、最大化、恢复、深浅主题和目标缩放下仍是一体，边界不越区。
- **版本范围**：通用模式；原生窗口调用与权限必须按当前框架版本另行核对。

## 2. 层级缩进与空间预算失控

- **适用**：树、列表、嵌套导航、侧栏或低宽度区域显得空、挤或层级漂移。
- **症状**：子项离左边过远；内容宽度被多层 padding 重复消耗；展开后文字、图标和操作拥挤。
- **常见根因**：层级深度、展开控件、图标和内容各自重复增加间距，没有集合级空间预算。
- **最早预防**：先定义每一级只由一个缩进来源负责，并按最窄目标视口计算完整行的图标、文本和操作预算。
- **目标结果**：层级清楚但不过度消耗内容宽度，同级元素对齐，深层仍可读可操作。
- **确定性证据**：缩进由单一深度规则产生，局部组件没有叠加同义外边距。
- **真实证据**：用真实长文件名和最大支持深度在窄宽度、缩放和展开状态检查。
- **版本范围**：通用模式，不保存具体间距数值。

## 3. 控件拓扑与交互语义不一致

- **适用**：一个动作被实现成错误数量或错误类型的控件，图标与状态含义混乱。
- **症状**：用户要求一个循环按钮却出现多个按钮；图标表示“当前状态”还是“下一步动作”不清楚；菜单、单选和切换器可见关系错误。
- **常见根因**：把控件当视觉样式选择，没有先定义对象、状态集合、顺序和每次输入结果。
- **最早预防**：在组件选择前写明同一时刻可见控件数、状态机、输入后的结果和反馈位置。
- **目标结果**：控件形态与任务语义一致，用户能预测操作结果。
- **确定性证据**：单一状态源驱动全部消费者，所有转换和禁用条件可枚举。
- **真实证据**：从自然入口逐次操作完整状态序列，观察每一步可见反馈和恢复。
- **版本范围**：通用模式。

## 4. 主题、状态与临时表面不成族

- **适用**：深浅主题、悬停、焦点、选中、禁用、错误、弹层或通知中只有部分画面正确。
- **症状**：主题切换后某些文字或边界不可读；弹层仍使用另一套颜色；错误只在某一状态出现。
- **常见根因**：只修默认状态或局部 CSS，没有把共享颜色角色和组件状态作为最终可见组合治理。
- **最早预防**：定义主题角色、组件状态和临时表面的完整消费矩阵，由一个设计系统真源提供。
- **目标结果**：每个可达主题与状态组合都保持层级、可读性、焦点和操作反馈。
- **确定性证据**：所有消费者读取同一语义 token 或正式组件状态，没有活动硬编码旁路。
- **真实证据**：在真实内容上遍历主题、焦点、选中、禁用、失败和临时表面。
- **版本范围**：通用模式；平台强制色与系统主题行为按当前平台验证。

## 5. 响应式、低高度、缩放与输入方式割裂

- **适用**：页面只在默认桌面尺寸或鼠标输入下成立。
- **症状**：低高度看不到主要动作；缩放后重叠；触控命中过小；键盘无法进入或退出临时表面。
- **常见根因**：按单张截图布局，没有定义内容优先级、滚动所有者、断点行为和替代输入。
- **最早预防**：用实际可视区域和用户任务定义宽度、高度、缩放、键盘、鼠标与触控合同。
- **目标结果**：主要任务在承诺范围内可达，降级方式明确且不丢能力。
- **确定性证据**：布局和滚动所有权唯一，关键动作不存在仅靠一种输入触发的活动路径。
- **真实证据**：在承诺的最小宽高、缩放、系统字号和主要输入方式完成任务。
- **版本范围**：通用模式；具体平台输入规范以当前官方合同为准。

## 6. 设计系统漂移与多重视觉真源

- **适用**：同义组件、颜色、间距或状态在项目中出现多个实现。
- **症状**：修一处后其它页面仍旧；新增页面看起来像另一个产品；局部覆盖越来越多。
- **常见根因**：设计规范、token、共享组件、平台主题和页面样式都能独立决定同一视觉事实。
- **最早预防**：为语义角色和组件状态指定唯一规范真源、生成或适配边界及正式消费者。
- **目标结果**：共享变化从一个来源到达全部活动消费者，项目偏离有明确理由。
- **确定性证据**：同义旧变量、组件和覆盖退出活动路径；依赖关系可追踪。
- **真实证据**：抽查不同入口、状态和平台表面，确认共享变化一致且局部职责仍保留。
- **版本范围**：通用模式；第三方组件库适配应限定版本。

## 7. 只验证源码，没有验证用户画面

- **适用**：修改声称完成，但证据只有测试、属性值、组件树或单张静态预览。
- **症状**：代码正确却看不到结果；测试数据绕过正式生产者；修复后真实入口仍读旧状态。
- **常见根因**：把生产者、边界、消费者和最终画面拆成互不相连的验证。
- **最早预防**：在实施前写出真实入口到最终可见结果的链，并规定核心边界不得被 mock。
- **目标结果**：正式生产者产生结果，跨过真实边界，被活动消费者读取，用户在目标环境可见可用。
- **确定性证据**：核心链测试由正式生产者建立数据，并能证明消费者读取的是同一结果。
- **真实证据**：从自然入口完成主要任务，检查最终画面、操作结果、失败恢复和重启后的状态。
- **版本范围**：通用模式。

## 8. 媒体内容、渲染表面与布局容器混为一层

- **适用**：预览看起来只显示了部分内容、边缘被切掉、上下或左右留白异常，或者外壳压缩后媒体构图随之失衡。
- **症状**：用户无法判断正式内容是否完整；调整容器后裁切消失但留白变大；默认视口正常而缩放、调整窗口或切换显示器后再次失效。
- **常见根因**：源媒体范围、正式输出比例、原生渲染表面的物理像素、界面逻辑尺寸和布局容器由不同层决定，却被一个宽高或缩放选项代替；外壳空间改变后下游仍沿用旧几何。
- **最早预防**：在选择缩放和布局前，为源内容、输出契约、逻辑尺寸到物理像素的转换边界、布局容器分别指定所有者，并定义完整展示或允许裁切的明确合同。
- **目标结果**：生产内容缺失、渲染裁切和比例留白能够被分别证明；正式输出比例驱动容器，显示缩放和尺寸变化通过唯一边界更新原生表面，外壳调整后下游重新构图。
- **确定性证据**：正式媒体探测结果与输出契约一致；逻辑尺寸、组合缩放和物理表面转换可追踪；没有第二份无来源比例或只在一个视口成立的旧尺寸路径。
- **真实证据**：同一正式媒体从真实入口进入活动预览引擎，完整范围和内容矩形可见，播放或定位实际推进；改变窗口、显示缩放或外壳占位后重新记录几何与画面。
- **版本范围**：模式通用；交换链、纹理、视频视图和组合缩放 API 按当前桌面、移动或网页运行时核对。

## 9. 透明媒体的低 Alpha 画布噪点与派生产物分叉

- **适用**：透明图片或视频在页面合成后出现矩形薄雾、整幅画布噪点、主体暗边或 poster 与播放画面切换不一致，即使文件元数据声明存在 Alpha。
- **症状**：透明区域在某些背景上显出完整文件边界；角落和主体外部仍有微弱颜色；主体边缘出现黑色或脏色半透明像素；静态首帧正常但播放后出现方框，或相反。
- **常见根因**：透明母版在主体外保留了大面积低 Alpha RGB，抠图边缘的颜色与 Alpha 被错误预乘或污染，有损编码放大了这些残留，poster 和媒体变体来自不同处理阶段，或者活动消费者仍选择旧派生产物。仅有 Alpha 通道、`alpha_mode` 或文件可播放不能证明透明区域在最终合成中干净。
- **最早预防**：在母版进入有损编码前建立 `透明母版 → Alpha 清理或边缘修复 → 各交付编码与 poster → 正式清单 → 活动消费者` 的唯一派生链；先用实际 Alpha 的数值与空间分布区分整幅低 Alpha 噪点、主体边缘污染和编码伪影，再选择只影响已证明噪点范围的处理。固定阈值不能脱离素材证据成为默认值。
- **目标结果**：主体需要的半透明边缘、光效和材质仍被保留，主体外画布透明且不泄漏矩形边界；所有编码变体、poster 和静态回退来自同一已确认母版状态，正式消费者不再读取旧产物。
- **确定性证据**：分别记录源母版与交付产物的尺寸、帧数、时长、Alpha 分布、画面外圈和角落、主体边缘及显著半透明区域；清理后这些正式内容合同保持成立，低 Alpha 噪点下降且有意义的半透明内容没有被误删。每个派生产物能够回到同一处理身份，旧资源引用退出活动清单。
- **真实证据**：把 poster、首帧和实际播放连续合成到至少一明一暗且与缺陷有反差的背景上，检查文件边界、暗边和切换；从自然入口核对活动媒体节点的 `currentSrc`、真实加载与播放，并覆盖合同中的桌面、移动、减少动态效果和静态回退。浏览器能播放、请求成功或单张透明网格预览都不能单独通过。
- **版本范围**：因果模式通用；Alpha 表示、编码器、像素格式、poster 生成与浏览器支持按当前交付链核对。

## 记录新模式的门槛

只有当新问题的根因跨独立项目重复、用户明确指定为高频默认、存在严重稳定因果链，或来自正式平台合同时才增加模式卡。新增卡必须能在不保存项目名、报错、补丁和具体数值的情况下写清上述八个字段，并且主流程会按条件读取它；否则留在项目复盘或局部决定中。
