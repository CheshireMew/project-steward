# 改动前预防：状态与能力合同

## 可编辑设置必须连到真实能力和运行结果

设置页、首次运行向导、托盘菜单或命令行只要允许用户填写、选择或切换一个值，就先为该设置建立效用账本：

| 稳定设置身份 | 所属决策阶段与精确效果 | 能力、设备或 provider 真源 | 允许值与适用条件 | 界面入口 | 持久化边界 | 当前运行时应用或重建 | 重启恢复 | 用户可观察结果 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | | |

能力真源负责说明某个 provider 支持哪些声音、参数和执行模式，操作系统或驱动枚举负责设备身份，产品配置只保存已经通过该真源校验的稳定值。显示名称只用于呈现；设备重名、顺序变化或重新枚举时仍使用稳定身份。provider 专属字段只在当前能力适用时可编辑，枚举失败、能力不支持或没有真实消费者时，界面应显示准确的不可用状态、只读说明或退出该字段，不能保留一个看似可改但会被忽略的控件。

保存成功必须同时说明值进入哪个配置提交边界、是否立即应用、需要重建哪个运行时对象，以及失败时当前活动值是否保持。首次运行向导与正式设置页消费同一能力目录、校验器、连接或设备测试和配置提交入口；向导完成标记还要绑定向导版本与必需能力，不能因开发模式、窗口重建或一次未改变配置的启动反复出现，也不能用另一套默认值让首次配置与日常设置产生分歧。

用户询问“这个设置是否有效”、报告修改后结果没有变化，或者一个宽泛设置名称实际横跨分类、门控、聚合、解码、过滤等多个阶段时，先建立阶段效用图：

```text
用户实际反馈的现象与输入条件：
从正式输入到最终结果的决策阶段顺序：
每个阶段实际读取的参数、默认值或硬编码值：
现有设置准确控制哪个阶段，哪些相邻阶段仍会主导或改写结果：
配置提交后活动实例取得新值的时点，以及是否需要重建或重启：
最终消费者能够观察的变化与仍未覆盖的现象：
```

结论必须区分三个逐级增加的层次：**已经接通**只表示稳定设置身份经过配置边界到达正式运行时消费者；**活动运行时已经应用**还要求当前实例实际读取新值，或者准确说明需要重建或重启；**对用户所说的结果有效**则要求该阶段确实能改变目标现象，并且没有更早的门控主导输入，也没有更后的阶段重新产生或覆盖同一结果。接口返回成功、状态端点回显、对象属性变化或代码中出现读取点，各自不能把前一层升级成后一层。回答设置是否“有用”时要报告实际证明到哪一层，不能把局部接通说成已经控制整条链。

同一用户结果受多个阶段共同决定时，界面名称、方向说明和帮助文字必须对应准确阶段及其取舍，不能用“灵敏度”“质量”或“强度”等宽泛名称替一个局部比例、窗口或后处理参数承担整条链。隐藏的默认值或硬编码参数只有在环境差异会稳定改变用户结果、取值范围和取舍可解释、正式运行时能够校验并回读当前值时，才成为用户可调能力；随后以一个稳定身份一次迁移能力描述、配置模型、提交接口、持久化、活动实例、状态回读、界面与测试。条件不成立时它继续由内部能力真源拥有，界面不得暗示现有控件能够调节它。针对最终文本、标签或输出增加关键词过滤等下游补偿，只有存在独立产品合同并验证误杀与漏放时才可保留，不能充当上游设置修复或根因退出证据。

一次设置动作还要从用户点名的稳定设置身份推导准确目标集合，并在提交前记录未选中的同级路由、provider 或设备设置基线。请求对象没有携带目标身份时，不能通过遍历全部同级项来猜测修改范围；目标只属于一个路由时，兄弟路由必须保持逐字段不变。全部目标值先完成能力和业务校验，再通过一个配置事务或一次持久提交同时发布；不能在循环中逐项保存，也不能先改活动运行时再依赖补偿回滚。任一校验、应用或持久化步骤失败时，旧的持久状态和活动状态都保持可用，不能留下部分新值。

验收从正常设置入口读取真实能力列表，修改一个会改变行为的值，经过正式配置服务和活动运行时，再观察目标 provider、设备、角色、背景、模型或其它消费者的结果；多阶段链路还要让同一份由正式生产者取得或按正式输入合同记录的受控输入，在变更前后经过真实决策阶段和最终消费者，证明差异来自该设置负责的阶段。测试不能手写已经分类、识别或过滤完成的下游结果来绕过正在验证的阶段。随后关闭并重启正式入口，确认相同稳定值恢复且仍被消费。测试直接改配置文件、手写下拉选项、只断言控件文字变化或只证明序列化成功，都不能替代这条链。没有办法证明最终消费者使用该值时，该字段仍属于未接通，而不是“已实现设置”；只证明接通或活动应用时，也不能宣称它已解决目标现象。

## 语义记录修改与连续决策批次使用已提交状态

记录除了展示内容，还携带会决定资格、可信度、归属、关系或派生结果的来源、证据、权威性等事实时，或者同一批处理中后一步决定会受前一步提交影响时，在实现前建立：

```text
稳定记录身份与当前版本：
用户或生产者允许修改的事实：
必须随修改一起更新或重新计算的来源、证据、权威性、资格和关系：
唯一提交边界与原子提交范围：
读取这些事实的正式资格、筛选、关系或派生消费者：
批次语义：固定计划批次 / 连续决策批次
每一步读取的已提交版本，以及状态怎样推进：
最终持久状态、派生结果和用户可观察结果：
```

界面允许编辑哪些字段不等于完整修改合同。正式修改入口必须把可编辑事实和受它影响的语义事实作为同一次原子提交更新，或者由同一边界在提交前重新计算；不能只保存正文，却保留与新事实矛盾的旧来源、旧证据或旧资格。记录仍存在于真源、但正式筛选器或派生消费者不再接受它，属于修改链失败，不能用界面刚显示过新正文证明成功。

固定计划批次中的全部动作由同一个变更前版本决定，提交前重新核对该版本，再整体提交或整体拒绝；不能让前一项的中间状态重新解释已冻结的后续动作。连续决策批次则相反：每次动作都会改变下一次选择的候选、资格或关系，后一步必须消费提交边界返回的新版本与正式结果，或者重新读取权威状态；不能在整个循环中反复使用同一份初始快照。只有能够证明本地状态推进与正式提交返回完全同义时才允许复用本地投影，不能在批处理器中复制一套资格或关系规则。

验收从正式修改或批处理入口产生记录，让它经过真实持久化边界，再由资格、筛选、关系或派生消费者读取。连续决策批次至少包含两个互相影响的动作，使第二步在使用初始快照时会稳定产生重复对象、错误关系或错误资格；测试必须从第一步的正式提交结果取得第二步状态，不能由消费端手写更新后的来源、证据或关系。

## 计划范围与实际变更事实分离

命令可能触及多个对象或集合、允许无变化成功、产生合同内副作用，或者提交后的版本、事件、历史、撤销、缓存和界面通知需要说明“实际发生了什么”时，在实现前分开四类集合：

```text
用户意图与授权范围：调用者允许请求改变什么
冲突集合：执行前哪些身份与版本必须保持稳定
观察集合：提交前后必须读取哪些权威事实，包含全部合同内副作用
实际变更集：提交后真实创建、更新或退出的稳定身份、事实类别、前后版本或内容身份
消费实际变更集的版本、事件、历史、撤销、缓存和活动投影：
```

前三类是执行输入，不能直接成为已经发生的事实。实际变更集只能由权威提交结果，或同一提交边界内对观察集合的前后状态比较产生；命令声明、目标参数、冲突锁集合和调用者预计会影响的对象都不能冒充它。操作合法但没有改变权威事实时，实际变更集为空，不增加内容版本，不发布“已改变”事件，也不制造撤销项或缓存失效；产品确实需要记录尝试行为时，使用与状态变更分开的操作审计事实。

观察集合必须对合同内副作用闭合。移动、拆分、合并、重排或删除一个对象会同时改变关系、容器、索引或相邻对象时，局部读取必须覆盖这些正式副作用；无法证明闭合时扩大到相应权威聚合，或者让唯一提交边界直接返回完整实际变更集，不能为追求性能漏掉事实。冲突集合可以比实际变更集更大，实际变更集也可以包含由正式规则产生、但未在用户参数中逐项列出的副作用；两者拥有不同语义，不能共用一个笼统的 `affected` 列表。

闭合也不表示读取越多越正确。观察集合应是能够证明覆盖全部合同内副作用的最小稳定身份集合；把整个项目、序列、文档或其它上层聚合长期作为默认观察范围，会让一次局部操作重复读取、序列化、比较并通知无关对象，形成隐藏的性能耦合。为候选范围记录正式副作用、实际读取身份、前后比较次数和下游重算范围；只有无法从较窄身份集合证明闭合，或权威提交边界本来只提供聚合级事实时，才扩大到上层聚合。全聚合观察可以作为诊断基线，不能代替最终范围设计。

代表性规模下的操作超过性能门槛时，先沿规划、权威读取、提交、实际变更计算、事件或历史以及活动投影分段测量，再判断观察范围是否过宽。缩小范围必须继续覆盖关联创建、删除、重排和失效等正式副作用，并让实际变更集与最终消费者结果保持一致；不能靠漏观察、跳过事件或放宽门槛换取速度。修复后用同一正式事务同时证明最小闭合范围、正确持久化、下游消费和代表性耗时。

版本、语义事件、历史记录、撤销、缓存失效和活动投影只消费实际变更集及其提交版本。冲突检测只消费冲突集合；授权检查只消费用户意图与授权范围。验收至少覆盖一次带关联副作用的真实修改、一次合法无变化操作和一次提交前冲突拒绝：从正式命令经过权威提交取得实际变更身份，再让事件、版本、历史、缓存和最终消费者读取同一结果。测试不能根据命令参数手写预期变更集，也不能用消费者收到一条看似合理的事件代替提交事实。

## 适配器先绑定显式参数，再注入默认值

同一个操作可以由位置参数、命名参数、请求正文、配置覆盖或其它公共输入表达，而适配器最终要生成一份规范命令时，在实现前建立：

```text
稳定字段身份及其全部显式输入来源：
各来源的正式优先级、等价规则与冲突处理：
字段省略、显式空值和有效空集合分别表示什么：
显式输入完成绑定后的规范命令：
只对仍缺失字段生效的默认值及注入位置：
消费规范命令的规划器、提交边界和最终结果：
```

适配器先收集并规范化全部显式输入，再按合同合并；两个来源同时提供不等价值时在适配器边界明确拒绝，不能靠处理顺序让后一个静默覆盖前一个。占位值、空字符串、空集合或默认对象在显式输入绑定完成前不得写入规范字段，否则它们会伪装成调用者选择并遮住位置参数或请求正文中的真实值。只有 schema 明确把空值定义为有效显式输入时才保留它；省略与显式空值不能由消费者事后猜测。

全部显式来源绑定完成后，默认值只补充仍然缺失的字段，并由一个边界产生一次规范命令；规划器、授权、冲突、持久化和界面投影都消费这份结果，不再各自重放参数优先级。验收至少从正式入口覆盖仅位置参数、仅命名或正文参数、合法显式空值、完全省略后使用默认值，以及两个来源冲突；让实际适配器产生规范命令并经过规划、提交与消费者。直接构造已经正确的命令对象只能证明下游，不能证明绑定与默认值顺序成立。

## 为用户可见承诺建立证据覆盖表

行为合同中每一项用户会据此判断“已经完成”的承诺，都要单独建立证据覆盖；启动服务、自动打开网页、保存文件、完成迁移和恢复状态是不同承诺，不能因为它们出现在同一个入口里就合并成一个通过项：

| 用户可见承诺 | 正常触发或入口 | 必须经过的实际分支 | 正式生产者、边界和消费者 | 最终证据 | 当前状态和允许交付措辞 |
| --- | --- | --- | --- | --- | --- |
| | | | | | 已验证 / 仅诊断 / 未验证 / 受阻 |

环境变量、测试开关、手工注入状态、直接移除遮罩、手工复制产物、跳过正式构建任务或其它诊断动作绕过某个承诺时，只能证明未被绕过的部分。例如关闭“自动打开浏览器”后验证服务可访问，只证明启动和服务链成立，不能证明默认启动器确实打开了网页；手工把生产物交给下游消费者，也不能证明正常入口负责的传递步骤成立。实施和验证可以分批进行，但最终报告必须保留逐项状态，不能把一条成功链概括成全部承诺完成。阻塞正常入口的外部条件后来改变时，重新运行同一个正常入口并取得目标分支、正式消费者和本轮产物证据；不能把较早替代分支的产物拼接成正常入口通过。

## 先证明验收门槛适用

项目规则、模板、发布流程或专项方法列出了一项检查，不表示它在每次相邻改动中都自动成为完成门槛。列入验证计划前先建立：

| 验收项 | 规则来源与精确触发条件 | 本次改动怎样命中条件 | 验证器实际覆盖的输入、分支与承诺 | 前置条件、成本与副作用 | 分类 | 对完成的影响 |
| --- | --- | --- | --- | --- | --- | --- |
| | | | | | 适用且必需 / 辅助 / 范围外 / 用户取消 | 阻塞 / 补充证据 / 不参与结论 / 更新完成合同 |

产品完成检查、就绪门槛或引导清单还要从用户结果和正式能力合同生成，不能把首选内部表示、处理阶段或控件形态当成唯一合格事实。存在多个正式支持的实现或表示路径时，逐条记录它们的生产者、能力证明和共同消费者；任一路径满足同一必需结果就通过，只有共同能力缺失才阻塞。验收至少包含首选路径、另一条正式支持路径和一个确实不满足共同能力的反例；不能要求合法对象先转换成某种内部形态，只为让检查器读取统一字段。

规则写着“修改 X 时运行 Y”，必须先用变化事实证明本次确实触及 X；同一个仓库、相邻模块、相似主题或任务规模较大都不能代替触发证据。公共接口变化时，验证器、发布脚本和真实用户链工具仍是正式消费者，必须迁移它们对旧接口的调用；但“验证器必须完成迁移”不等于它承载的每个高层场景都自动成为阻塞项。只有场景实际经过本次改变的边界，或它独占一项必须交付的承诺时，才列为适用且必需。

适用且必需的门槛缺少凭据、运行时、目标平台或其它前置条件时，结论是受阻；辅助或范围外检查的缺口只影响其自身证据，不能借高成本或失败状态扩大完成合同。用户明确取消一项验收时，保留已经发生的失败、未运行原因和覆盖缺口，更新本次完成合同，并追踪哪些承诺只依赖该验收：这些承诺继续标为未验证；没有剩余承诺单独依赖它时，该验收不再阻塞其它已经成立的结果。后续改动若重新命中触发条件，必须重新分类，不能沿用较早的范围外或取消结论。

## 已有对象使用一份关系变更合同

当前结果会连续修改已有页面、路由、章节、链接、控件、媒体、文件或其它稳定对象时，先为每个受影响对象建立同一份关系变更表，再进入布局或实现：

| 稳定对象身份 | 当前所有者与位置 | 本轮动作 | 目标所有者、相邻锚点与顺序 | 内容或真实行为是否改变 | 必须保持的兄弟对象 | 最终可观察结果 |
| --- | --- | --- | --- | --- | --- | --- |
| | | 保留 / 新增 / 移动 / 换序 / 改名 / 替换 / 合并 / 退出 | | | | |

“新增”只创建点名对象，不隐含替换、隐藏或删除现有对象；“移动”只改变所属关系或位置，不隐含改写内容和行为；“改名”只改变显示身份，不自动改变职责；“退出”才表示对象不再出现在活动结果中，实体文件是否删除仍由独立权限决定。位置要求优先表达为稳定所有者、相邻锚点、前后关系和正式顺序，不把参考截图中的临时像素坐标当成产品真源。

后续纠正只更新用户明确改变的字段，其余已经确认的关系继续保持。多个对象同时移动时，目标位置仍按同一个变更前快照解释，再由正式最终顺序派生序号、选择、预热和其它消费者；不能按请求书写顺序逐项修改后让中间状态重新解释下一项。

## 把已接受差异从阻塞项中分开

在实现和验收前同时记录：

```text
必须通过的结果：
用户已经看见并明确接受、不得阻塞本轮交付的现有差异：
不在本轮范围内的行为：
哪些新证据会使已接受差异重新成为问题：
```

用户接受的现有差异继续作为目标合同的一部分，后续通用质量检查不能擅自把它恢复成阻塞项。接受不会授权本轮改动扩大该差异、把它传播到其它对象或引入新的回归；它开始妨碍主要任务、正式消费者或用户点名结果时，先展示新证据并重新确定范围。

## 技术迁移与呈现变化分开授权

React、Vue、原生框架、播放器、状态架构、构建工具或其它实现迁移会经过可见产品表面时，不能把“迁移后更容易维护”和“迁移后应该换一种设计”合并成一个结果。实施前建立两份相互关联但独立授权的合同：

```text
实现迁移合同：本次替换什么技术责任，最终唯一所有者、接口、状态和旧路径退出条件是什么
呈现保护合同：加载、首个稳定页面、目标视口、真实内容、媒体时刻、控件与互动中哪些必须保持
获准呈现变化：用户明确允许改变哪些区域、状态和关系
等价证据：迁移前后用哪些相同入口、内容、视口、时序里程碑和操作比较
设计改造入口：保护项等价成立后，哪些获准区域才进入视觉或体验改造
```

框架、组件库和动画工具按状态复杂度、生命周期、渲染能力、平台集成、性能和维护责任选择；它们本身不能证明画面更有设计感。一个请求同时要求迁移和局部改版时，可以在同一实施中完成，但仍先固定两份合同并分别验收：保护区不能借改版被替换，改版区也不能因追求等价而停留在旧结构。若根因修复确实必须改变保护项，先展示冲突、影响和新的可观察目标，取得授权后更新呈现合同，不能在实现层静默改变。

## 核心路径与可选能力

产品存在同步、版本管理、插件、账号、云服务或其它高级能力时，先写清：

```text
主要用户和核心对象：
不启用高级能力时的第一条成功路径：
高级能力的启用条件：
启用前后增加的状态、命令和界面：
能力不存在、关闭或失败时核心路径怎样继续：
```

被定义为可选的能力不能成为创建、打开、读取或完成主要任务的隐含前提。正式模型应让核心对象独立成立，再用非空能力描述高级路径；不能用一个“没有能力时跳过报错”的分支掩盖核心类型仍由高级能力命名和拥有。

## 实现机制先按能力来源收敛

新增依赖、抽象或自建机制前，按“项目已有责任所有者 → 语言、运行时、数据库、浏览器或操作系统原生能力 → 已安装依赖 → 新依赖或自建实现”逐层核对。先冻结最终用户结果，以及输入输出、失败语义、生命周期、正式平台和消费者；某一层只有完整覆盖这份最终合同才停止查找并复用，不能因代码更短、名称相近或常见场景能跑就提前结束。覆盖不足时写清唯一缺口再进入下一层，也不为迁就现有实现削弱已经确认的合同。

采用记录至少包含：各层候选与证据、未覆盖的准确缺口、最终所有者与正式消费者、被拒绝方案，以及新依赖或自建机制增加的安装、版本、更新、运行和退出成本。已有实现本身错误或制造第二真源时仍应沿根因修正。验证同时放入一个较低层能力足以闭合合同的正例，以及一个表面相邻但缺少必要失败语义、生命周期或平台保证的反例；前者阻止平行机制，后者阻止把“优先复用”机械执行成不完整方案。

## 自动化协议入口先证明消费需求

项目已经通过 CLI、API 或机器可读能力描述公开同一组业务语义时，新增 MCP、RPC 服务、daemon、插件桥接或其它协议表面之前先建立：

```text
现有唯一公共应用边界及其机器可读能力真源：
已经确定的消费者及其正式调用入口：
现有 CLI 或 API 已经满足和仍未满足的需求：
新增表面必须补充的传输、工具发现、会话、流式结果或取消能力：
协议请求、结果、错误和生命周期到现有边界的映射：
新增进程、连接、配置、部署与恢复成本：
不允许进入适配层的业务任务、领域状态、持久化、恢复和参数语义：
采用 / 暂不采用的目标侧证据：
```

仅靠“以后可能有用”、参考项目提供了同名入口或某个客户端理论上支持该协议，不能建立第二个自动化表面。没有已经确定的消费者，或者结构化 CLI、公共 API 与能力发现已经满足该消费者时，停在暂不采用；不能先实现服务、状态和配套工作流，再等待未来需求为它补理由。

确有消费者只能通过新协议满足传输、发现、会话、流式结果或取消需求时，新表面只作为唯一公共应用边界外侧的薄适配器。它可以转换协议消息并协调协议生命周期，但不得复制业务任务、领域状态、持久化、恢复、参数语义或错误解释，也不得让 CLI 与新适配器分别维护命令集合。机器可读能力描述继续是实际操作与参数的真源；适配器和说明文档都是消费者。验收用同一业务请求分别经过原入口和新适配器，证明它们到达同一应用边界、产生同一领域结果与失败语义，并在连接、取消和关闭时只收口各自增加的传输生命周期。

## 实时连接先建立权威身份与可调用状态

WebSocket、事件流、IPC 或其它长连接会在握手前排队请求，或者把 session、generation、sequence 与运行端点暴露给客户端时，先冻结以下合同：

```text
会话身份与 generation 的唯一运行时所有者：
传输已经连接与领域已经就绪的不同里程碑：
权威身份握手及允许释放排队请求的准确条件：
首次连接、重新连接与显式 reset 各自保留或创建什么身份：
旧 generation、迟到分片和过期完成事件的唯一拒绝边界：
configured、process online、endpoint reachable、callable 四种能力事实的生产者：
可以公开调用 URL、流式 URL 或控制入口的准确条件：
```

传输通道打开不等于领域已经就绪。session 或 generation 由一个服务端或运行时所有者签发，并在客户端释放排队消息前通过正式握手到达；客户端默认值、`0`、缓存身份或待发送消息不能反向创建权威会话。重新连接按产品合同重新取得当前权威身份，不得暗中等同于 reset；显式 reset 必须由同一所有者创建新 generation，并让旧 generation 的请求、分片和终态在一个边界被确定性拒绝。队列清空只能消费已确认的当前身份，不能用 socket `open`、固定延时或乐观本地状态猜测准备完成。

能力快照把“已经配置”“进程在线”“准确端点可达”和“当前可调用”分成不同事实。静态配置可以描述预期目标，进程存活可以描述宿主状态，但只有精确路由、所有者和依赖在当前 generation 中已经就绪时，快照才允许发布可调用 URL、流式 URL 或控制入口；离线、启动中、旧 generation 或路由不匹配时应返回不可调用状态并隐藏这些活动入口。验收至少覆盖握手前已有一条排队请求的首次连接、不断开产品语义的重新连接、显式 reset 后的第一条请求、旧 generation 迟到消息，以及离线到在线过程中能力快照与正式消费者实际调用的一致性。

## 外部参考实现与性能方案

用户指出另一个项目、引擎或已有实现，希望当前项目“也这样做”、直接接入或借鉴时，先把参考实现从目标架构中拆开。当前项目的用户结果、唯一真源、正式生产者、持久化边界、消费者和停止位置仍由当前项目事实决定；参考实现只提供待验证候选，不能因为名称、协议或表面结构相似就成为新的运行依赖。

上层已经形成来源能力台账时，先核对它对应的研究根、版本、完整范围和未知项，再消费其中的独立行为、运行假设与授权边界；不能把过期台账或只覆盖 README 的介绍当成完整来源。实施目标要求吸收能力而来源证据仍不足时，先补齐来源研究，不在目标 schema、目录或代码中猜测参考项目的真实职责。

解释参考项目时，先用用户能够执行和观察的语言说明实际动作、操作中的连续反馈、最终结果，以及它减少了什么理解或操作成本；随后才映射到字段、接口和内部模块。只列参数名、类型或实现组件，不能证明已经理解参考能力，也不能作为当前项目采用它的理由。

先建立：

```text
参考项目中用户实际执行的动作：
操作过程中连续看到的反馈：
最终可见结果和减少的理解或操作成本：

可独立迁移的机制：

当前项目已经具备、不能重复建立的职责：

```

候选能力会改变可见产品的对象分类、主导航、主要按钮、工作区或设置层级时，先消费体验路径已经形成的目标对象与入口层级判断，再建立采用位置合同：

```text
目标用户任务、发生频率与当前阻碍的证据：
候选职责：核心对象 / 现有对象操作 / 获取渠道 / 视图或筛选 / 状态反馈 / 可选集成

目标入口：现有统一入口 / 对象内行动 / 次级入口 / 独立工作区 / 不采用
若要成为主入口，现有路径不能承载的目标侧证据：
因此退出或不得新增的平行入口、状态、设置和恢复分支：

```

参考项目的导航结构、显眼程度、功能数量、供应商数量和实现复杂度都不能证明目标项目需要同级入口。结果进入目标项目后若与现有对象共享同一生命周期和主要行动，采用合同默认复用现有对象路径，把差异留给类型、元数据、筛选或上下文控制。只有独立且反复发生的用户结果、不同的关键决定或持续生命周期，以及现有路径无法自然承载的目标侧证据同时成立时，才允许把候选能力提升为主导航、主要按钮或独立工作区。关键证据仍未知而实施会改变核心信息架构时，停止在可选择的入口方案，不先写界面和配套后台再等待用户纠正。

局部吸收或目标原生重写还要建立能力采用合同：

```text
来源规范真源、手工来源和派生视图：
按可观察行为和执行合同识别的独立能力：

由目标规范确定性生成的目录、索引、预览或运行投影：

公开发现、选择、采用或物化入口：

```

名称与别名只负责发现；同一可观察行为和执行合同只算一项能力。目标项目使用一份目标规范记录表达语义意图、可执行合同和机器会消费的条件，再让目录、搜索索引、预览和其它投影由它确定性生成；不能把参考项目的并行数据文件、展示名称或手工目录复制成目标项目的第二真源。会改变宿主尺寸、资源到达、时间、生命周期、输入所有权或失败收口的要求必须进入可校验合同，说明文字只解释，不能独自承担运行条件。

可扩展字段由生产者的机器可读描述拥有稳定字段身份、默认值、范围、单位、建议控件和是否可动画等语义。消费者只把建议控件映射到自己的界面组件，并通过现有公共编辑边界读写值；不得再维护一份字段清单、默认值表或参数语义。工具已经提供可执行的能力描述、操作发现或参数 schema 时，以该机器可读边界为真源；说明文档是契约消费者，只负责解释和示例，不能复制维护另一份实际操作集合。

能力被找到不等于已经进入产品。完整采用链至少是 `发现或选择 → 公开采用或物化入口 → 目标产物或存储边界 → 正式消费者 → 最终可观察结果`；演示页、样例或画廊只证明预览，不能代替正式采用入口。公开文档中的选择示例必须对当前生成索引实际执行；面向用户的语义搜索存在多种语言或叫法时，由同一规范元数据生成别名和检索投影，不另建手工同义词真源。

先决定它是制作期能力还是共享契约。若生产者只需在制作阶段选择能力并把结果物化进现有自包含产物，正式消费者仍能完整读取既有协议，就保持共享契约不变；若消费者必须识别、编辑或依赖能力身份、参数或语义，则升级产品无关的共享契约并一次迁移所有生产者、存储、消费者、示例和验证器，不能把消费者需要的状态藏在入口代码或私有文件中。

复制、改写或再分发参考代码、配方、素材或生成包时，来源身份、内容哈希和适用授权说明必须随正式产物跨过存储或分发边界；权利或通知义务无法确认时，不把相应内容进入活动产物。确定性格式化和整体重写只用于工具拥有的生成文件；修改源码以及用户拥有的清单、配置或文档时，只改变本次获准的路径和语义范围，保留无关内容、顺序和表达。格式化器、行尾转换或批量改写运行前记录范围与基线，运行后检查实际差异；若工具因格式版本、行尾或全文件重排扩大了改动，就缩小工具范围或从最新基线重新应用本轮修改，不能把机械噪声当成顺带整理，也不能为了生成哈希稳定而重排整个用户文件。

随后使用会触发不同路径的最小代表性工作负载矩阵。只选择本次真实存在的维度，例如简单与复杂内容、标准与快速生产者、新旧持久状态、纯内容与混合媒体、单执行单元与并行执行；不为形式完整穷举组合。参考项目自己的基准只能说明它在自身条件下成立，当前项目必须在同一输入、输出合同和正式消费者上测量。整体依赖只有在它能接管完整责任且不会建立第二套状态、时间轴、缓存或恢复边界时采用；否则逐项吸收已经证明有价值的机制，并明确拒绝不匹配部分。

性能目标同时冻结正确性与速度。先定义标准路径的正式结果、允许精确相等还是具备业务依据的差异阈值、需要保护的工作负载类别和最终消费者；再测量速度。简单夹具通过不能代表复杂内容，单一新项目不能代表旧状态，某个快速后端通过不能代表每个 worker、GPU、浏览器或并发实例都具备同一能力。新增替代生产者、并行执行、缓存捷径或快速后端时，按主路由进入高成本、难复现问题方法的“受验证的高速路径与原子回退”维度。
