# 本地文件工作区治理

用于把用户可见的普通文件夹作为核心工作区的项目。它适用于 Markdown、文本、素材或其它以磁盘文件为内容真源的工作台；版本管理、同步和远程能力都只能作为可选能力进入。

## 1. 文件夹先于版本管理

工作区身份由用户或平台实际选择的根目录决定。根目录内的受支持磁盘文件是内容唯一真源；应用状态可以保存最近路径、标签、选择、界面状态、恢复副本和能力引用，但不能镜像一份仍可独立编辑的活动内容。

版本管理只在工作区根自身精确满足能力条件时启用。不能向父目录发现仓库，也不能因为父目录或子目录存在版本管理元数据就改变当前工作区身份。嵌套仓库在父工作区中是普通目录内容，其内部元数据从内容树排除；需要版本管理时单独打开该根。

没有版本管理的普通文件夹必须完成同一条核心路径。主界面不显示分支、同步、变化数量或其它无效状态；启用入口属于高级能力，失败也不能阻止文件工作流。

## 2. 工作区与目录树模型

工作区描述应当包含真实根、显示身份和可选能力，不能继续由“仓库”类型代替。目录模型同时表达文件和目录，并使用工作区相对路径；按需要提供条目类型、文件类型、大小、修改时间和可选能力状态。

内容树默认排除应用内部目录、版本管理元数据、废纸篓和明确忽略的生成目录。排除只影响展示、搜索或能力扫描，不能创造第二份内容。

### 一套路径身份，多项内容策略

路径先在原生工作区边界转换成有根约束的工作区相对身份，消解分隔符、`.`、`..`、大小写和符号链接时遵循目标文件系统的真实语义。随后由一个内容策略分别回答：是否在树中可见、是否进入搜索或索引、是否允许普通内容命令修改、是否进入版本变化、是否必须被监听和通知。`hidden` 不能同时代替这五项决定；界面中看不见也不表示原生命令有权读取或修改。

目录树、搜索、监听器、可选版本管理、基线扫描、新建、保存、移动、删除和恢复都消费同一个路径身份与策略，不得各自维护顶层名称、大小写或字符串前缀特判。内部目录无论嵌套深度和大小写变化都按路径段分类；正常内容命令在原生边界拒绝内部路径，不能依赖前端没有展示入口来保护边界。

应用控制文件可以在内容树中隐藏，同时被版本化、监听或用于恢复。能够改变自身观察、解析或修复行为的控制文件，先按稳定路径身份识别并发出变化事实，再解析其内容；内容损坏、版本不兼容或字段无效不能让该文件从观察链中消失。文件监听器、IPC 或平台 API 提供绝对路径、规范路径或大小写不同的路径时，在其正式适配边界转换成上述身份；测试必须经过同一生产者形态，不能用方便的字符串直接调用内部分类器冒充真实监听链。

层级缩进只由语义深度产生。展开控件、图标槽、行容器和子列表不能重复增加同义左边距；侧栏和内容区的分隔线各由一个区域拥有。最终用真实长文件名、展开深度、窄侧栏和目标缩放检查，而不是保存某个项目的像素值。

## 3. 文件操作是状态事务

新建、重命名、移动、删除、恢复和用系统程序打开都从工作区边界进入。原生边界校验相对路径、工作区逃逸、符号链接、目标存在和覆盖语义；界面不能自行拼接路径绕过它。

移动或删除前先协调活动文档：

```text
受影响标签与选择
→ 脏内容保存
→ 外部修改与冲突判断
→ 原生文件操作
→ 标签、最近文件和当前选择迁移
→ 文件树、搜索和可选能力状态刷新
```

保存或冲突未解决时阻止破坏性操作。目录移动展开到受影响文件集合；成功后旧路径不能继续留在标签、最近记录、恢复状态或能力变更清单中。

## 4. 删除默认可恢复

删除前明确对象和影响，并要求用户确认。桌面优先使用系统回收机制；受限平台使用应用拥有的废纸篓并提供恢复。清空废纸篓是第二个独立确认动作。“从最近工作区移除”只删除应用记录，永远不删除磁盘内容。

平台实现可以不同，但用户语义一致：普通删除可恢复、永久删除明确、恢复后由正式目录消费者重新读取。

## 5. 源文件保真

打开和保存不应在没有用户语义修改时重写源文件。受支持格式与编码必须明确；对需要保真的文本至少验证：

1. 从真实磁盘文件读取。
2. 不修改内容直接保存。
3. 比较保存前后字节。
4. 修改后只产生预期内容变化。
5. 外部修改通过正式冲突链处理。

预览、索引、恢复副本和编辑器内部状态不能反向覆盖更新的磁盘事实。

## 6. 可选版本管理

如果产品提供“启用版本管理”，它是显式用户动作。启用前扫描当前可见且未忽略的内容，展示数量、大小与忽略摘要；用户确认后再建立本地基线，不自动配置远端。

后续自动历史或同步只纳入应用已经成功创建、编辑、移动或删除的精确路径。外部程序产生的无关改动不能因一次全量暂存被自动提交。移动同时记录旧路径退出和新路径写入；目录移动展开为精确文件集合。

版本管理状态、冲突、提交、分支和同步从非空能力进入。高级面板可以提供完整工具，核心文件界面只显示与普通用户当前任务直接有关的简短状态。

## 7. 真实验收链

至少选择适用链执行：

1. **普通文件夹**：在没有版本管理元数据的真实临时目录中打开、展开、搜索、编辑、保存、新建、重命名、移动、删除和恢复；证明没有调用版本管理，也没有生成其变更清单。
2. **嵌套仓库**：普通父目录包含多个子仓库时仍按文件夹打开；子目录内容可见、内部元数据隐藏、主界面无版本管理状态。单独打开子仓库后能力才出现。
3. **文件状态迁移**：制造脏标签、外部修改和路径操作，证明保存、冲突阻止、原生操作、标签迁移和刷新使用同一真实路径。
4. **源文件保真**：用真实受支持编码文件完成未修改保存的字节比较。
5. **层级与边界**：在真实界面展开多层目录，用长名称、窄宽度、主题和缩放检查缩进、命中、截断与分隔线所有权。
6. **可选版本管理**：只有产品支持时，使用真实仓库和独立远端验证基线、精确应用变更、同步及第二个消费者；外部无关改动不得被纳入。
7. **统一内容策略**：从真实目录枚举、监听事件和原生命令输入产生路径，覆盖嵌套内部目录、大小写与分隔符变化、工作区逃逸和损坏控制文件；证明树、搜索、监听、版本变化和修改权限消费同一分类结果，同时允许控制文件在不可解析时仍被观察和修复。

函数返回、手写树数据、消费端伪造变更清单或单张静态截图都不能单独证明这些链成立。
