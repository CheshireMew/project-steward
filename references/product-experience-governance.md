# 产品体验与界面治理

## 目的

把产品目标、用户证据、核心任务、真实内容和获准使用的参考界面转成可执行、可保护、可验收的体验合同。体验不仅要让任务能够完成，还要让界面看起来一体、操作顺手、使用舒服，并适合当前任务、平台和风险。它服务网页、桌面软件、移动 App 和响应式数字产品，但不把界面设计强加给没有产品界面的项目。

默认不修改代码、不生成图片、不保存设计文档。用户只要求讨论、比较、审查或方案时停在判断；用户明确要求实施时，才在授权范围内修改并验收真实结果。

## 1. 先确定交付和停止位置

| 请求 | 默认交付 | 停止位置 |
| --- | --- | --- |
| 定义产品体验 | 用户、情境、核心结果、旅程、信息架构、任务流 | 不自动进入视觉细节 |
| 研究参考产品 | 当前来源、可迁移关系、代价和适用条件 | 不照抄外观 |
| 讨论页面或流程目的 | 对象职责、上下游、事实和取舍 | 不展开完整规格 |
| 诊断为什么不好 | 体验根因、用户影响、目标状态、证据缺口 | 不自动修复 |
| 比较方向 | 二到三个结构性方向和推荐 | 等用户选择 |
| 详细方案 | 旅程、结构、内容、状态、界面、互动、平台、验收 | 不自动实施 |
| 设计系统治理 | 真源、漂移根因、消费者和迁移范围 | 不自动迁移 |
| 综合体验审计 | 核心任务、相关表面与状态、根因、优先级 | 不自动修改 |
| 实际体验审查 | 真实入口、任务完成、理解、恢复和可见问题 | 不自动修复 |
| 界面使用感与打磨 | 目标使用感、连续任务摩擦、共同根因和可观察通过结果 | 不自动扩大为整体改版 |
| 实施产品设计 | 唯一真源修改、完整迁移、真实可见验收 | 达到已确认结果 |
| 忠实重建 | 真实页面证据、组件合同、实现和同视口对照 | 达到约定保真度 |

“先看看”“你觉得怎样”“先给方案”不授权写文件或启动大范围改造。

## 2. 建立证据和保护合同

先消费主路由已经建立的目标行为基线，区分目标意图、当前实现和历史原因，不在产品体验路径另建一套来源真源。在来源适用范围已经确定后，产品与界面判断按以下职责取证：

1. 用户当前明确要求、纠正和选择；
2. 当前项目中的产品与设计真源；
3. 正式入口、真实内容、状态、组件和运行结果；
4. 当前平台规范与获准参考；
5. Agent 明确标注的假设。

这里的顺序服务当前产品判断，不抹掉来源的时间和适用状态。用户当前明确纠正决定目标行为；现有实现说明对应状态下怎样工作，不自动成为正确答案；旧提交和旧截图用于解释历史，不自动恢复成当前设计基线。用户身份不自动推导偏好、能力或场景。分析数据说明发生了什么，不自动说明原因。

盘点已有对象时标为保留、新增、移动、替换、合并、改名、退出或待确认。设计中的退出不等于获准删除文件。局部任务中，未授权文案、功能、数据身份、路由和范围外界面是保护区。

已有界面发生连续修改时，直接消费改动前预防中的对象关系变更表，不在界面层重新猜测“新增、移动、换序、改名或退出”的含义。界面路径只补充区域所有者、相邻锚点、视觉顺序、命中与滚动关系；没有被本轮动作改变的对象、内容、真实链接和交互继续留在保护区。用户用截图标出位置时，把标注转换成活动区域、稳定邻接关系和正式顺序，不能把截图像素坐标保存为第二套布局真源。

用户用“例如”“比如”“不止这些”等表达列出对象时，点名对象是查找同类问题的入口，不是完整范围；只有“只检查这些”“只改这些”等明确限制才把它们视为封闭集合。反过来，“其余不要改”“其它保持不变”等表达会立即把未点名对象纳入保护区。开始前分别写清检查范围、获准改变的范围和保护区；全面检查不等于全面修改。

## 3. 先定义用户结果，再选择界面

在颜色、风格、组件和动效前回答：

```text
主要用户和使用情境：
什么触发用户开始：
用户最终要得到什么：
当前怎样完成、在哪里受阻：
哪些约束会改变设计：
怎样从用户角度判断成功：
```

界面会被连续使用时，再把抽象目标转换成目标使用感：当前任务应该偏向快速、安静、紧凑、引导还是审慎；这对入口、密度、反馈、等待、恢复和高低频行动分别意味着什么。目标使用感必须来自任务频率、平台、输入方式和错误代价，不能用“舒服、自然、有质感”几个形容词代替设计决定。

页面、功能、文案、装饰和控件必须承担用户结果、信息、状态、选择、操作、信任或恢复职责。不能用“高级、沉浸、有设计感”替代体验目标，也不用没有职责的内容填空间。

多页面展示、作品集、媒体叙事和长滚动体验在选择卡片、素材与动效前，先建立正式页面与状态顺序：每项的稳定身份、相对顺序、允许入口、稳定可见状态、离开条件、下一状态和输入所有者由同一信息架构真源负责；页面注册、组件或文档顺序、菜单与导航、锚点与吸附、进度指示、前后项、历史与深链、响应式顺序、预热和过场完成回调都消费它。随后逐章建立内容价值合同：用户经过后新增什么理解、哪份真实内容承担证明、怎样延续前后页面的产品或角色主张、开始 / 中段 / 结束分别出现什么、需要多少有效滚动距离，以及哪些元素移除后不损失信息、结构或操作。首屏建立的独特主张不能在后续页面退化成任意项目都能使用的模板区；作品页面中的角色、媒体和视觉层只能组织或解释真实项目，不能替代名称、说明、过程、结果与有效入口。

同一连续体验还要在动效规格之前建立体验保证与取舍合同：原生连续手感、离散完整落位、相邻内容何时允许可见、舞台是否必须完整后才演出、局部状态按哪些方向推进、第一下反向输入怎样反馈、离开后保持还是重演，分别是硬保证、可调整目标还是明确不要求。普通文档流不能同时硬性保证完全原生的连续手感和换场任意时刻都不出现相邻页面；存在这类制约时先说明优先级、代价和需要用户决定的部分，再选择实现关系。不能用吸附、固定舞台、额外滚动跑道和局部输入拦截层层叠加来假装所有保证已经兼得。

长滚动、全屏媒体、视差、固定层或连续动效在实施前建立滚动性能责任合同：主要输入的优先级、允许同时运行的动效、必须稳定的布局关系、媒体承担的内容职责、离屏停止、减少动态效果和低能力设备策略，以及目标设备与视口都要明确。性能判断先区分输入与脚本执行、样式与布局、绘制、合成、媒体解码与上传、资源加载与并发，不预设视频或动效中的某一类必然是主要成本。

新增素材进入方案前分别说明它服务内容、身份、结构还是交互，与相邻内容有什么可见关系，移除后用户会失去什么。说不清职责、关系和移除后果的素材不生成、不拆分、不进入页面；已经存在于生成批次中也不自动获得用途。留白可以承担聚焦、分组、节奏、动作方向和安全区，不因缺少装饰而判定为未完成。

多张来源图片、角色形态、作品截图或其它素材将被批量转换时，每项输入分别建立素材证据合同，不能用批次共享主题代替逐项判断：

```text
稳定素材身份与正式来源：
源内容实际可见的主体、服装、姿态、道具、环境和主题：
必须保持的身份与内容事实：
允许改变的材质、结构、表现和构图：
本项可以使用的特效、辅助物与来源依据：
没有证据、不得从其它素材迁入的称号、符号、道具和设定：
目标消费者、输出比例、静态或时序用途：
用户最终怎样识别它仍是同一对象：
```

每项素材只继承用户明确声明的批次共同合同；动作、道具、象征和角色解释仍由自己的来源证明。同批其它素材或生成批次中偶然出现的元素不能充当证据。用户要求逐项成品时，每项交付必须能够独立使用，不能依赖“同上”、隐藏前缀或让用户自行拼接缺失约束。

### 共享视觉锚点与派生素材的依赖顺序

多个页面状态、角色形态、图片、视频或转场共同依赖同一主体时，在批量生产前建立一份依赖合同：

```text
稳定身份事实与正式来源：
全批次共享的视觉与构图变量：
只属于单项状态的动作、场景和特效变量：
共享视觉锚点、当前版本与确认状态：
直接依赖它的图片、视频、转场和界面消费者：
哪些选择需要在派生生产前确认，以及确认的可观察依据：
锚点或共享变量改变后必须失效、重做或重新验收的派生物：
```

共享锚点负责统一身份和已接受的视觉关系，不要求所有状态复制同一姿势或场景。探索稿可以在确认前比较，但不能被标为正式基线，也不能让高成本派生物在关键身份、构图或视觉方向仍待确认时成批展开。用户要求先判断共同锚点、再决定是否调整依赖状态时，必须在锚点评审处停止；不能把未确认结果继续传入后续生产。确认依据来自用户实际看到并接受的输出，不来自提示词、生成任务成功或文件名。

锚点或共享变量发生变化时，沿依赖关系把受影响派生物标为过期，重新生产或重新验收后才能进入正式消费者；不受该变量影响的单项状态保持有效。不能静默混用旧锚点与新派生物，也不能为了保留已经投入的生成成本，把后来否定的视觉关系继续当成批次真源。

### 外部媒体生产能力与派生链

页面结果依赖图片、视频、三维或其它外部生产工具时，在决定提示词、批次数量和文件格式前，先记录当前实际能力。能力只由用户当前确认、工具当前界面或文档，以及本轮真实生成结果证明；过去经验和文件名不能补造不存在的选项。

```text
工具、版本或取得时间：
允许的参考输入、数量与组合方式：
支持的比例、分辨率、时长和首帧 / 尾帧方式：
是否直接输出透明背景、分层或可编辑结构：
已经由真实结果证明稳定的身份、构图、动作和材质能力：
已经由真实结果证明不稳定或不可用的条件：
这些能力变化会使哪些素材计划和验收失效：
```

随后按最终消费者选择正式素材生产者，不反复要求已经证明不适合的工具完成同一任务：

| 生产策略 | 适用结果 | 正式来源与派生关系 |
| --- | --- | --- |
| 直接静态 | 稳定识别、细节展示、排版构图或局部放大 | 已确认静态母版直接产生网页或应用交付版本 |
| 时序来源再取帧 | 自然动作、表情过程、视线或运动张力决定画面质量 | 合格视频是动作真源，静态图记录准确视频身份和取帧时刻 |
| 可抠像源再合成 | 工具不能直接提供可靠透明背景，但页面需要独立主体 | 纯色或可分离源经过抠像和边缘处理形成透明母版，再派生编码、poster 和静态回退 |
| 批次源再拆分 | 多个角色视图、细节或项目元素需要共享一次生成条件且在页面独立排版 | 批次源先为每个目标保留完整轮廓、隔离区和稳定身份，再分别产生有来源记录的独立素材 |

策略选择来自真实结果，不是固定偏好。静态工具已经稳定得到所需姿态时不为形式先做视频；时序变化本身没有内容价值时不增加视频。批次图只是一项中间生产物，不能因为整体画面好看就跳过独立元素的完整性、遮挡、边缘和最终布局检查。

为每个活动素材维护同一份生产与消费记录：

```text
稳定素材身份与页面职责：
正式生产者和准确源身份：
中间处理、取帧时刻或拆分区域：
透明母版、编码、poster、静态回退或其它派生物：
最终页面、组件、媒体清单或其它消费者：
当前状态：可直接使用 / 只使用已指明部分 / 需要重新生产 / 不进入项目
可观察验收和使旧结果失效的条件：
```

已经生成但不满足原要求的素材可以在明确指出可用部分和新职责后进入“只使用已指明部分”，不能含糊地当成正式成品，也不能为了避免浪费给它补造页面用途。需要交给其它生成或提示词能力时，本合同只传递真实工具能力、每项独立输入、正式用途和输出条件；精确创作提示由相应生产能力负责。完整提示必须能独立提交，但完整不等于堆叠同义形容词，每项约束都应改变构图、动作、身份、背景、输出或排除结果。

参考产品研究围绕具体任务，记录当前来源、它降低的成本、代价、适用条件和本产品应采用、调整或拒绝的关系。产品名和截图不自动成为证据。视觉参考还要拆开结构、互动机制、运动关系、构图、内容密度与视觉皮肤，逐项标明采用、调整或拒绝；只点名轮播、弹出或其它机制时，不自动复制参考的配色、材质、容器、品牌元素和文案。当前产品已经接受的相邻表面、设计系统和品牌资料继续负责视觉皮肤，除非用户明确授权视觉重做。

## 4. 建立完整界面合同

界面合同至少覆盖：

```text
产品表面与每个区域的职责：
布局、边界、滚动和层级所有权：
连续体验的硬保证、现实取舍与所选交互架构：
多章节内容证据、可见状态与有效滚动成本：
正式页面与状态顺序、下一状态规则及全部顺序消费者：
共享视觉锚点、派生素材依赖、确认门槛与失效规则：
滚动性能责任合同、目标设备与视口及成本分类：
核心对象、自然入口和最短成功路径：
控件数量、拓扑、状态集合和每次输入结果：
内容、空、加载、成功、失败、冲突和恢复：
首次渲染、加载、过场、资源到达和进入内容的时间过程及禁止中间状态：
主要与次要行动及反馈位置：
共享 token、组件和平台外壳的唯一真源：
目标视口、缩放、主题、输入方式和无障碍：
目标使用感，以及顺手、舒服、合适、一体和可控怎样在连续任务中表现：
用户不看说明也能观察到的通过结果：
```

下拉菜单、并列选项、循环按钮和独立按钮是不同的操作语义，不是可互换的外观。主题状态必须按最终可见组合验收，而不是只检查变量值。局部新增视图或控件时重新计算整个区域的空间预算。

设计方向从项目身份、内容、用户任务、平台表达和已有设计系统产生。项目没有既定视觉方向时可以提出结构性候选，但不要为了形式制造多个近似版本；用户已选择或接受的方向成为当前合同，被否定方向退出活动方案。

## 5. 实施只改获准结果

实施前确认目标产物、正式入口、唯一真源、保护区、迁移范围和验收方式。技术或框架迁移触及可见表面时，直接消费改动前预防中的实现迁移与呈现保护合同，不在界面层把可维护性重新解释成视觉改版授权。问题来自任务模型、信息架构、共享主题、token、组件、平台外壳或状态投影时，在最早失效来源修复并迁移全部消费者；不要用局部覆盖掩盖共享根因。

同一对象的多视图共享对象身份、排序、筛选、选择、行动和持久化状态，只改变呈现密度与信息层级。移入次级入口的动作仍必须连接原业务行为。

素材批次进入实现时只消费已确认的共享锚点和仍然有效的派生物。锚点或共享变量修改后，先沿依赖关系退出过期结果并更新全部消费者，再验收新的正式组合；不能让页面以加载成功为由继续混用相互矛盾的批次。

多页面或多状态体验实施后，从自然入口、直接入口、导航、返回和恢复等本轮适用路径核对实际稳定身份与顺序，证明全部顺序消费者读取同一真源，过场结束只通过正式状态边界进入当时的下一状态。长滚动或动效性能使用同一真实内容、视口和输入建立可比较记录，分别观察脚本执行、样式与布局、绘制、合成、媒体解码与上传、资源加载与并发；临时隔离一类成本只用于定位，最终结论必须恢复完整内容和正常用户路径。

实施不自动授权安装依赖、生成无关素材、删除、打包、部署或发布。

## 6. 验收真实体验

先验证用户能否理解并完成目标任务，再沿真实链：

```text
自然入口或操作
→ 正式内容、状态或素材生产者
→ 存储、传输或平台边界
→ 当前可见组件
→ 目标视口中的最终画面与可用结果
```

至少先看第一眼的整体关系，再连续完成主要任务，并检查重复使用、失败恢复、关键状态、主题、目标视口、缩放和输入方式。记录用户是否需要无职责地寻找、往返、记忆、等待或切换模式，以及反馈、密度和视觉重心是否符合当前任务。消费端手写数据、直接改组件状态、静态属性、函数返回和组件存在只能作为中间证据。影响可见结果的代码变化会使旧截图和旧验收失效。

多章节或滚动演出还要从自然入口用真实滚轮、触控板或触摸经过开始、中段、结束和反向状态，记录实际内容视口、有效滚动屏数、相邻内容首次出现的位置和每段距离带来的信息或构图变化。真实作品证据与入口必须在最终页面可见可用；素材加载成功、动画函数运行或单张稳定截图不能单独证明章节体验成立。

交付时明确区分设计判断、规格可执行、代码已实现、真实入口已运行、最终画面已验收和连续使用质感已检查。
