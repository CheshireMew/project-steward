# 互动、动效与生命周期

用于定义输入反馈、命中范围、动效状态与生命周期、连续滚动、离散滚轮手势、导航恢复和媒体预热。

## 1. 先定义互动结果

| 输入 | 生效区域 | 操作对象 | 反馈位置 | 可见结果 | 是否可打断 | 替代输入 |
| --- | --- | --- | --- | --- | --- | --- |
| | | | | | | |

输入位置、取样位置、反馈位置和命中范围可以不同，但坐标映射、边界和离开状态必须明确。同一输入只产生一个主要回应；点击明确控件不附带触发背景反馈。

集合项先按稳定对象身份分开已提交选择、人工临时预览和系统临时预览，不能把悬停、自动轮动与用户锁定压进一个“当前选择”：

```text
稳定对象与顺序：正式内容中的身份和排序来源
已提交选择：由点击、回车、确认式触摸或正式业务动作写入
人工临时预览：由悬停、可见键盘焦点或其它明确的人类浏览意图写入
系统临时预览：仅由自动演示或轮动写入
当前显示投影：人工临时预览 ?? 系统临时预览 ?? 已提交选择
持久行动、恢复状态和可访问性选中语义分别读取哪一层：
```

前移、强调和临时读数等即时反馈读取当前显示投影；`aria-pressed`、需要锁定的行动目标和返回后的恢复状态读取已提交选择。人工预览优先于系统预览，人工预览结束后才允许系统按恢复合同继续；系统轮动不能改写已提交选择。没有自动演示的集合省略系统临时预览，不为统一形式制造额外状态。不同设备可以改变反馈形式，但共享同一对象身份、正式顺序和已提交选择。

上层集合合同同时定义内容全集、本轮样本和当前项时，系统临时预览只从本轮样本取得推进顺序；点击、按钮、键盘、手势、目录和深链按合同选择遍历全集还是样本，但都通过同一个稳定对象身份更新当前项和已提交选择。系统轮动不能把本轮样本回写成新的内容全集，也不能让样本外对象失去原有入口。

## 2. 离散模式使用一个状态转换合同

切换、分段选择、循环模式和展开选择先写清：

```text
状态唯一真源与允许值：
当前状态怎样显示：
每种输入从哪个状态进入哪个状态：
能否随机跳转，还是只能按稳定顺序前进：
快速重复输入、重开界面和恢复时读取什么状态：
图标、文字和辅助说明表示当前状态还是下一步动作：
```

同一个可见控件承载多个状态时，每次输入只推进合同规定的一步，控件数量保持不变，图标、说明和内容视图在同一次状态提交后更新。互斥选项允许直接跳转时，所有入口仍写入同一状态源。视图变化不能重建对象身份、筛选结果、选择或行动目标；需要记忆时明确持久化范围和恢复时机。

## 3. 连续直接操作使用临时预览与单次提交

拖动时间位置、区间手柄、曲线控制点、画布对象或其它连续控件时，持久状态和拖动中的画面是两层投影，不把每次指针移动都写成一次正式编辑：

1. 按下时从正式生产者读取并冻结本次操作的持久基线，同时建立只属于这次拖动的操作身份。
2. 移动时通过项目已有的权威坐标、时间或数值映射和吸附策略计算临时预览；当前正式消费者直接渲染这份预览，让画面、读数和命中结果连续反馈，但不逐次写入持久化、历史或撤销栈。
3. 释放时把最终值通过既有公共编辑边界提交一次，再清除临时预览；取消、失去捕获或目标失效时恢复按下时的持久基线并清除本次操作，过期回调不得提交。

连续预览不得建立第二套时钟、坐标映射、状态机或恢复逻辑。验证要用真实指针取得至少一个中间画面，证明正式消费者读取预览；再分别证明释放只产生一次持久提交，取消后正式值与画面都回到基线。

直接操作开始前把选择集合、持久关联、本次操作集合和操作入口作为四个不同事实冻结：

```text
选择集合：用户当前明确选中的稳定对象身份
持久关联：哪些对象按正式业务关系共同变化，以及关联是否仍有效
本次操作集合：本次按下后实际参与预览与提交的对象
操作入口：指针、键盘或触摸从哪个成员、手柄或表面开始
目标映射：本次操作集合怎样共同映射到目标容器、位置或数值
退出路径：空白或无目标区域、平台取消键、明确清除、模式切换和失去捕获分别怎样处理
```

选择本身不能让已解除的关联继续进入本次操作，持久关联也不能把未获合同允许的全部选择自动并入操作。本次操作集合由按下时的稳定关系、显式多选语义和操作入口共同解析；合同规定关联对象整体操作时，从任一等价成员发起都必须得到同一对象集合和成对目标映射。不同入口如果确实承担不同动作，要在表中明确区分，不能让实现顺序偶然决定。

操作身份、本次操作集合、每个成员的持久基线、入口、坐标映射和目标计划必须由同一操作所有者一次原子发布，然后可见性、命中、拖影和读数才开始消费。不能先发布“正在拖动”，再让绑定看到空集合、旧入口或部分目标并隐藏、取消或转移当前操作。取消、失去捕获或目标失效同样由该所有者一次撤回全部临时状态，不改变持久关联。

临时选择或模式必须有可到达的退出合同。空白或无目标区域点击、平台约定的取消键、明确清除动作和模式切换只在项目适用时启用，但每项必须说明是否清除选择、取消当前操作、保留持久关联以及焦点落点；不能只提供进入方式而让用户依赖重新打开界面退出。

验收按等价入口逐项使用真实指针、键盘或触摸完成按下、中间移动、释放和取消，并让父级滚动或手势容器实际参与命中竞争，证明输入没有被错误窃取。本次操作集合含多个成员时，从每个合同内等价成员至少各发起一次；解除关联、单选、多选和目标映射的实际分支分别取得最终状态。直接调用控制器、拖动 helper 或提交函数只能证明内部计算，不能代替真实输入取得捕获并穿过父级容器的链路。

从素材库、文件系统、组件面板或其它正式来源拖入目标并创建新对象时，并不存在可恢复的对象持久基线。开始拖动时冻结来源对象身份和目标权威状态版本；所有预览与提交共同调用唯一放置决策边界，按固定顺序生成一份放置方案：

```text
原始指针与拖拽热点
→ 对象锚点
→ 上下文放置不变量（命中即锁定，例如空目标首项必须落在原点或中心）
→ 未锁定时的邻近吸附
→ 冲突与兼容性解析
→ 预期位置、目标容器、决策原因和目标状态版本
```

临时拖影、落点指示、读数和提示文字只消费这份放置方案。不能显示原始指针位置却提交另一位置，不能在界面和提交层分别实现一套放置规则。界面把上下文规则与邻近吸附作为不同原因展示，避免把强制位置误称为吸附。

释放时通过同一公共放置边界重新核对来源身份和当前权威目标状态。目标状态版本未变时提交已经验证的方案一次；状态已经变化时由该边界重新计算或拒绝并给出明确反馈，界面不得拿旧预览静默提交。

验证拖入创建要使用真实来源对象和真实指针，在远离普通吸附阈值但会触发上下文规则的位置取得至少一个中间预览，证明拖影、落点、读数和原因已经指向最终计划位置；释放后再证明正式消费者得到同一位置且只提交一次。还要覆盖目标非空或上下文规则不成立的分支，证明原有自由放置与邻近吸附行为仍成立。

## 4. 分开稳定布局、运动和命中

含位移、缩放、悬浮、跟随或弹层的效果分别定义：

```text
最终布局锚点：动画结束后相对谁定位
动画起点与路径：从哪里来，改变哪些属性
运动属性的唯一所有者：
命中阶段：动画前、中、后哪些区域接收操作或拦截底层
```

最终布局先独立成立，运动层只控制表现，命中层只控制交互。布局规则、CSS transition 和动画工具不能同时写同一个最终变换。运动方向正确不能代替终点正确；透明但仍可点击的旧层属于失败。

### 层级可视对象变换合同

DOM、SVG、Canvas、场景图或 3D 对象存在父子层级、挂载点、骨骼、插槽或组合变换时，先冻结：

```text
稳定对象身份：
父级或挂载点及其坐标空间：
枢轴、锚点、局部坐标系与轴向：
基础位置、旋转与缩放：
姿态或状态覆盖：
动画增量及唯一所有者：
关键摄像机或观察方向：
必须退出的旧世界坐标、局部坐标与动画写入者：
```

最终世界变换只由这条父级到子级的变换链推导，不另存一份并行结果。对象需要随父级移动时，子对象以父级或挂载点为基准保存局部基础变换，不能同时保留世界坐标硬编码；位置、旋转和缩放在每个状态下各自只能有一个最终所有者。姿态和状态从基础变换派生，动画只施加已声明的动画增量，并在结束或取消后回到同一基础值，不能用硬编码终值覆盖基础旋转或缩放。内部转子、光效或装饰层只拥有自己的内部变化，不能顺带改写外层对象。

修复层级对象的错位、歪斜、尺寸漂移或跟随错误时，先列出模型构造、父级姿态、状态切换、动画循环、响应式适配和相机逻辑中的全部写入者，再把每个变换分量一次迁移到上述唯一所有者并退出旧写入。只改一组坐标或在动画后补一次复位，不能证明根因已经收口。

## 5. 复杂动效必须有生命周期所有者

滚动关联、多阶段编排、指针跟随、媒体联动和页面过场分别建立生命周期合同：

```text
目标与作用域：哪些对象由哪个组件、页面或窗口负责
创建条件：目标、最终布局和必要内容何时已经就绪
进度或事件来源：谁推动当前效果
更新与重建条件：哪些视口、内容、字体、媒体或偏好变化会使旧几何失效
中断、重叠与反向：新输入怎样接管正在运行的效果
清理条件与所有者：离开、替换或失效时谁停止效果并移除临时状态
清理后的稳定结果：布局、可见性、命中和状态最终由谁继续负责
```

作用域使用能够同时拥有目标和稳定状态的最小边界。动效只在目标与所需几何可用后创建；响应式和减少动态效果的不同版本由同一条件边界创建与撤销，切换时不能留下并行实例。页面、组件或窗口退出后，旧效果、事件订阅、临时样式和命中层必须一起退出，不能继续作用于已分离对象。

内容数量、字体、媒体尺寸、窗口或容器几何变化会改变起止位置时，旧测量立即失效并由同一所有者重建。简单悬停或按压可以继承组件本身的生命周期，不为了填写合同制造独立系统。

开场、揭幕、提交或导航过场需要完整结束才能保证结果时，建立一个排他操作窗口。窗口从请求通过目标、权限和当前状态检查并被正式接受时开始，覆盖资源等待、动画或媒体播放、完成事件、目标导航以及滚动或布局落位，直到后一稳定状态已经可见、可命中并可继续操作才释放。鼠标、触摸、滚轮、键盘、自动推进和旧延迟回调都经过同一个操作所有者；逐项规定期间是忽略、排队还是允许中断。只给动画元素加播放标记、却允许其它入口改写同一对象或导航目标，不算建立了排他所有权。失败与超时只负责进入合同中的可恢复终态，不能猜测成功目标或提前解除后让旧回调继续提交。

自动演示、自动轮动或模仿悬停的效果还要由同一生命周期所有者定义：

```text
系统推进来源与稳定顺序：
开始条件与活动作用域：
人工接管信号和立即结果：
人工预览或提交结束后的空闲恢复条件：
粗指针、触摸和减少动态效果边界：
离开作用域、隐藏、卸载或内容变化时的清理：
```

真实指针、键盘或触摸意图出现时，系统预览立即让位并暂停推进；指针离开单项只清除对应人工预览，不表示用户已经空闲。键盘可见焦点仍在集合内时保持人工接管，不能在焦点下方悄悄恢复轮动。只有集合仍处于活动作用域、目标可用且达到合同定义的空闲条件后，系统才从正式稳定顺序恢复。装饰性的自动预览在粗指针、纯触摸和减少动态效果模式下默认关闭，保留静态内容、人工选择与已提交状态。计时器、事件订阅和系统临时状态随所有者一起创建、重建和清理，不能在离开页面后继续推进，也不能由多个计时器争夺显示投影。

### 异步切换使用操作身份和原子提交

图片、视频、平台视图或其它异步内容在同一舞台复用、替换或分层切换时，每次切换都建立不可复用的操作身份，并同时捕获目标对象身份、目标资源、传入节点或图层，以及切换开始时的传出节点或图层。加载、解码、播放、`ended`、错误和清理回调在改变状态前，必须重新核对操作身份、对象身份、实际节点和当前资源仍属于本次操作。

旧操作的清理只能处理它捕获的旧节点，并且只有该节点仍处于旧角色时才能暂停、复位、隐藏或释放；不能通过随后已经指向新对象的可变 `current` 引用清理。过期回调直接失效，不能重播当前媒体、推进当前选择、覆盖说明文字或改变当前可见层。

传入内容在达到本次合同规定的可用状态前保持不可见且不接管命中。资源身份、当前对象、可见层、说明内容和交互目标由同一个切换所有者一次提交；稳定画面最多有一个主视觉对象。两个对象同时可见只允许发生在合同明确的有界过渡区间，并由同一序列所有者决定透明度、层级、结束条件与中断结果，不能由两个独立回调偶然叠加。

## 6. 动效服务可理解结果

先按职责区分动效，再选择位移、视差、透明度、颜色、模糊或镜头变化。不能用“统一删除位移和视差，只保留透明度与颜色”处理所有场景：

| 动效职责 | 负责什么 | 可采用的表现 | 通过条件 |
| --- | --- | --- | --- |
| 自主表现 | 角色生命感、环境状态或持续系统活动 | 克制循环、呼吸、局部运动或状态变化 | 用户不操作时仍有明确内容意义，不妨碍任务 |
| 滚动驱动 | 揭示信息、改变构图、解释空间或推进章节 | 位移、尺度、镜头、遮挡、视差、清晰度与层级变化 | 进度对应新的内容或状态；停止立即稳定，反向按区域返回策略改变可见进度或交还页面 |
| 媒体转场 | 连接真实素材首尾差异或共享锚点 | 短淡化、失焦、遮挡、颜色变化或中性状态 | 覆盖真实切点，不出现黑帧、重影或身份跳变 |
| 即时反馈 | 确认悬停、按下、选择、焦点、成功或错误 | 短暂透明度、颜色、形状、位置或触觉变化 | 输入后立即发生，不阻塞下一步 |
| 低频媒体门 | 等待不可随意截断的真实媒体或任务状态完成 | 完整媒体、进度与明确锁定状态 | 只接管本次推进所需输入，以真实完成事件释放 |

同一种表现放在不同职责中可能得到不同判断。滚动章节中的明显位移、镜头和视差可以成立，因为它们承担内容推进；独立饰品长期漂浮如果没有内容或状态职责，就不因风格一致而获得同等价值。

动效只用于即时确认输入、解释空间关系、连接状态变化、表达真实时间过程或呈现内容自身运动。规格定义起始、目标、触发、结束、中断、快速重复、反向和减少动态效果。

把时间拆成启动延迟、运动时长与缓动、阶段重叠与间隔、媒体播放速度。用户只要求某一段略快或略慢时，修改负责该感知区间的唯一时间源，保留已确认的位移、终点、内容停留和其它阶段。

多个对象共同完成一个状态变化时，由一个序列所有者定义命名时刻、先后和相对重叠；不让各组件通过互不知情的延时拼出顺序。运行中被中断或自然反向时从当前可见状态继续，不能先跳回旧起点；合同明确把再次进入或重新选择定义为重播时，它是从稳定状态开始的新操作。

实际实现与审查中，相同可见结果优先使用不会持续触发布局重算的大范围运动方式。高频输入只保留一个更新通道，离屏、隐藏或失去活动身份的效果停止工作；性能通过目标设备上的响应和画面判断，不用固定帧率口号代替可见证据。

### Web 动效实现服从现有系统

网页中的简单悬停、按下、展开、图标切换或状态反馈先核对项目已经采用的样式系统、动效依赖和相邻组件做法，在同一系统中表达；不能为了一个细节引入第二套样式写法或新的运行时动效依赖。项目已有动效库时沿用实际安装包和当前导入边界；没有时，能够由 CSS 完成的短状态过渡继续使用 CSS，不把示例库名变成项目依赖。

交互状态变化必须能从当前可见值响应新的用户意图。CSS transition 常适合悬停、按下、开关和其它可反向状态，固定时间线适合明确的一次性序列；这只是实现选择信号，真正合同仍是中断、快速重复、反向和最终状态，不能因为使用某种 API 就推定已经满足。

CSS 过渡只声明实际变化的属性，不使用 `transition: all` 让无关布局、颜色或边界偶然参与。`will-change` 只在当前目标设备已经观察到首次合成抖动，并且变化属性能够由合成器受益时有界使用；不能预先铺到所有动效元素，也不能写成 `all`。按压比例、模糊、位移、时长和缓动从当前任务频率、设计系统、减少动态效果和真实画面确定，不把示例数值升级成跨项目默认。

### 滚动性能先区分成本

滚动卡顿先在同一真实内容、视口和输入下建立可比较记录，再区分六类责任：输入与主线程中的监听、脚本和时间线；样式计算与布局；绘制以及滤镜、遮罩、混合和阴影；合成器、大面积固定或粘滞层与图层数量；媒体解码、纹理上传、分辨率、透明通道和并行媒体流；资源加载与并发竞争。性能记录、filmstrip、浏览器或平台时间线和最终画面共同说明哪一层先失去响应或画面连续性。

一次只临时隔离一个成本类别用于定位，并保持内容、视口和输入不变；隔离结果不能直接充当最终方案。正式实现优先保持布局关系稳定、使用适合合成的变化、让高频输入只经过一个更新所有者，并在对象离屏、隐藏或失去活动身份时停止工作。最终验收恢复完整内容、正式媒体和正常用户路径，在目标设备上证明输入响应和画面连续性。

减少动态效果按职责保留选择、状态、内容顺序、主要操作和因果关系。自主装饰循环可以停止；滚动驱动的内容变化改为直接状态、较短路径或静态顺序；媒体转场保留最短可理解连接；即时反馈仍应清楚。不能只按属性名称删除全部位移或视差，否则可能同时删除章节结构和必要空间关系。

## 7. 多层滚动先选唯一主架构

全局页面推进、章节内部演出、局部步进、媒体完成或导航恢复中有两个以上共同控制一段连续体验，或者多个页面反复出现提前播放、相邻页面露出、输入迟钝、反向空滚或回访重放时，先停止调整局部阈值、时长、`scrub` 和冷却时间。先按用户结果为每个区域选择一个主要架构：

| 主架构 | 主要进度与输入所有者 | 适用结果 | 必须接受的代价或边界 |
| --- | --- | --- | --- |
| 原生内容流 | 浏览器或平台滚动 | 阅读、连续浏览和普通内容 | 页面交界按真实几何自然出现 |
| 连续驻留舞台 | 页面滚动位置与一个固定关系所有者 | 完整构图内连续揭示多段信息 | 需要有信息增量的有限跑道、明确释放边界和反向状态 |
| 固定全屏换场 | 一个全屏舞台把连续位置映射成页面或镜头状态 | 不采用离散落页但又不允许普通页面交界进入表演画面 | 状态、深链、可访问性和内容高度管理更复杂 |
| 分页落页 | 平台分页或唯一落页控制器 | 用户明确把内容理解为一组离散屏幕 | 会改变触控板、触摸和快速反向的原生手感 |
| 有限局部步进 | 完整就位后的局部组件 | 逐项查看形态、步骤、轮播或镜头 | 只在合同指定的方向与阶段消费输入，到边界后必须交还页面 |
| 低频媒体门 | 当前排他操作与真实完成事件 | 不可随意截断的揭幕、教程或关键叙事 | 只接管本次推进所需输入，等待本身必须有内容价值 |

一个区域只有一个主要架构。有限局部步进或媒体门可以作为有界子阶段嵌入页面，但不能再让分页吸附、连续 sticky 跑道、全局滚轮累计和另一套落页动画共同决定页面位置。普通内容流可以优先保留原生手感，却不能同时承诺换场任意时刻都看不到相邻页面；无页面交界是硬保证时，明确选择固定全屏换场或用户接受的分页落页，并承担相应代价。

选定架构后为每个有内部演出的区域写完整生命周期：

| 阶段 | 用户可见结果 | 内部进度 | 相邻内容 | 输入所有者与允许离开条件 |
| --- | --- | --- | --- | --- |
| 进入构图 | 区域正在进入，关键主体、标题或操作尚未全部到达合同位置 | 需要完整舞台时保持为零 | 按主架构自然出现或保持在舞台外 | 页面或浏览器拥有，直到完整就位 |
| 完整就位 | 必要内容完整、无遮挡、可读且可操作 | 仍为零 | 需要完整演出时不得进入表演视口 | 合同确认几何与资源已经稳定 |
| 内部演出 | 每一步都新增信息、构图关系或明确状态 | 连续推进或按有限步骤变化 | 按所选保证保持不可见或不干扰 | 只有唯一进度或步骤所有者可以消费对应输入 |
| 终态释放 | 必须出现的内容和操作稳定成立 | 固定为终态或最终步骤 | 此时才按主架构允许进入 | 输入交还页面，用户可以立即离开 |
| 再次进入 | 从相邻页面、导航、深链或局部选择返回 | 读取本区域的返回策略 | 不破坏当前定位与页面顺序 | 仍使用同一状态与输入所有者 |

返回策略按内容目的逐区域选择，不能由动画库或全站默认决定：

- **自然反向**：空间关系或连续数值本身可逆，第一下反向输入立即改变可见进度；
- **保持终态**：首次揭示已经完成，返回时直接显示稳定结果，并移除已经没有信息变化的反向跑道；
- **明确重播**：返回、重新选择或其它合同条件本身有内容意义，重新从起点播放。

普通规则和明确例外同时进入同一合同。不能为了统一“只前进”删除有意义的回访动作，也不能因为一个区域允许重播就让所有章节返回时重新演出。

局部组件接管输入前再填写：

| 输入来源 | 方向或动作 | 当前阶段 | 所有者 | 状态转换与可见反馈 | 交还页面的条件 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

滚轮、触摸、按钮和键盘如果选择同一对象，必须更新同一个稳定对象身份、正式顺序与选择边界；它们可以按行动语义拥有不同转换许可。例如按钮可以主动查看上一项，而反向滚轮可以直接交还页面。任何被消费的输入都必须立即产生合同内的可见状态变化或明确锁定反馈；既不改变局部状态也不移动页面的输入属于失败。

## 8. 连续滚动进度按几何合同处理

选择连续进度架构后，滚动叙事、视差、固定舞台或随滚动连续变化的效果定义：

| 滚动来源 | 触发对象 | 开始边界 | 结束边界 | 进度模型 | 固定层与占位所有者 | 几何失效来源 | 退出结果 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | |

开始和结束使用触发对象与实际滚动容器之间的几何关系，不复制其它页面的像素距离。每个效果选择连续进度或离散进入/离开中的一种主要模型；两者不能同时控制同一状态或运动属性。

每个演出区域同时记录：

```text
有效滚动屏数 = 该章实际消费的滚动距离 ÷ 浏览器或应用真实内容视口高度
开始状态：用户新看到或理解什么
中段状态：用户新看到或理解什么
结束状态：用户新看到或理解什么
有意停留：为何需要，以及它提供什么内容价值
```

除非合同明确记录有意停留及其内容价值，连续约一屏没有新的信息、构图关系或状态，视为需要压缩的空滚。先合并重复状态、缩短跑道或减少不必要的追赶滞后，不增加漂浮物、循环运动或全局滚轮倍率填补结构问题。

进入构图和舞台完整就位后的内部推进使用独立进度边界。内部进度在需要完整构图时保持为零，舞台就位后才开始，终态成立后才释放相邻内容。缩短章节高度或调整 `scrub`、惯性和持续时间后，重新映射两条边界并用真实输入检查，不能只改容器高度后沿用旧时间线。

首屏开门、揭幕或关键教程等低频媒体门以真实媒体或任务完成事件释放本次输入锁；固定计时只可作为失败超时。门控结束后，后续普通章节恢复浏览器或平台的原生滚动所有权，不把 `preventDefault()`、滚轮累计或输入倍率传播到整页。

固定关系与被推动的视觉内容分开：固定层负责稳定位置和文档占位，内部运动层负责表现。视口、容器、内容数量、字体或媒体加载改变几何后，由生命周期所有者重新测量；不能继续使用旧边界。正向、反向、快速越过、直接进入中段、低高度视口和返回页面都必须得到确定状态。

减少动态效果时保留内容顺序、导航和主要操作，连续位移、视差或固定时长可以缩短、离散化或取消。用户离开当前对象后释放滚动接管和临时占位，页面恢复正常滚动边界。

## 9. 离散滚轮按手势会话处理

轮播、逐项选择或离散镜头不能按单个 `wheel` 事件切换：

```text
连续事件
→ 按设备和 deltaMode 归一化
→ 当前会话累积有效位移
→ 越过阈值后最多推进合同数量
→ 吸收同一手势的惯性尾段
→ 输入安静后结束会话
```

阈值识别意图，空闲间隔区分手势，不能用一个固定冷却值替代。首末项的惯性尾段是否继续由组件吸收、同方向下一手势何时交还页面、快速反向是选择上一项还是立即退出，都来自本区域的输入所有权合同；不能默认前进与后退对称，也不能在已经无局部转换时继续累计输入。第一下有效反向输入必须立即改变局部可见状态或移动页面。
