# 根因治理

用于已经出现缺陷、重复回归、半迁移、架构漂移或跨层链路失效的项目。目标是找到错误第一次产生的边界并完成最终迁移，不在每个症状旁增加特判。

## 1. 区分现象、根因和放大点

建立证据表：

| 项目 | 要回答的问题 |
| --- | --- |
| 现象 | 用户真实看到什么，怎样稳定复现 |
| 行为基线 | 用户现在要什么、当前实现是什么、历史来源只证明哪个时点；冲突与未知项在哪里 |
| 首次错误 | 哪个生产者或边界第一次产生错误事实 |
| 放大点 | 哪些缓存、恢复、状态同步或消费者让影响扩大 |
| 旧架构 | 哪些类型、helper、入口、数据源或兼容路径仍在活动 |
| 影响 | 哪些用户结果、平台、数据或恢复能力失效 |
| 目标边界 | 修复后由哪个唯一真源和接口负责 |
| 证据缺口 | 哪些结论仍只是推断 |

每条诊断判断在进度说明和最终报告中都保留明确的证据状态：观察到的事实、待验证假设或已确认根因。观察到的事实只能描述当前证据直接证明的内容；待验证假设必须给出竞争解释和下一项判别证据；只有权威生产者、持久化边界、正式消费者或同等直接证据已经定位第一处偏离并排除关键竞争解释时，才称为已确认根因。新证据推翻原假设时明确更新状态，不能把较早的猜测继续写成已知事实。

错误最后显示在界面，不表示根因在 CSS；原生命令报权限错误，不表示只需加一项权限；保存失败发生在关闭时，不表示关闭按钮本身是唯一问题。

旧提交、旧截图和旧测试只能按它们的适用状态参与诊断。它们可以解释回归从何处引入，但不能自动决定修复后的目标行为；目标由用户当前明确要求、接受结果和项目活动真源共同确定。当前运行结果与目标冲突时，前者是失败证据，不是把目标改回现状的理由。目标仍不可靠时先交付待确认的行为合同，不进入修复。

普通对象反复进入版本管理、登录、同步或其它高级能力的错误路径时，先检查产品模型是否把可选能力错当成了核心对象的拥有者或前提。若是，应迁移核心类型、命令、状态、持久化和界面层级；给“能力不存在”增加特判只会保留错误定位。

界面症状跨区域、主题、状态或视口重复时，把它作为共享边界问题检查：布局与外壳所有权、控件拓扑、完整状态族、设计系统真源和真实可见验证。只有证据匹配时才使用高频模式，不逐项套用整库。

桌面应用或本地应用出现“点击没反应”“语音没反应”“发送后没反应”等反馈时，先把它当作用户可观察链路断裂，而不是单个按钮、接口或子服务失败。沿真实入口建立证据链：用户点击或快捷键事件、前端控制台、IPC 或本地 HTTP/WebSocket、主进程与子进程、业务生产者、传输边界、消费者，以及最终界面、声音、文件或对话结果。任何单层成功只能证明该层可用；例如子服务识别到文本、接口返回 200、进程存在或模型加载成功，都不能单独宣告用户结果成立。修复完成前必须让正式生产者产生结果，结果经过真实边界，被正式消费者读取，并形成用户能看见或使用的结果；否则按证据缺口报告。

### 桌面客户端远程配置获取失败

桌面客户端导入、更新或拉取远程配置时，`TLS`、`request failed` 或“导入失败”只是表面现象。先在**发生失败的那台机器**建立四层证据：精确配置端点实际返回的是可消费配置还是授权页、过期页或其它 HTML；当前运行的客户端二进制、版本、代理模式、回环端口和内核进程怎样形成真实请求链；该机器自己的时间、证书、解析和网络状态；正式消费者最终是否成功加载配置并让用户使用。源机浏览器、另一个设备的 `curl` 或只访问同域首页的成功，只能证明各自经过的层，不能替故障机上的完整端点和客户端路径背书。

配置 URL 含令牌、账号或临时授权时，诊断只保留脱敏后的主机、状态码、内容类型、长度和可核对的内容身份；不把完整 URL、响应正文或令牌带入日志、命令输出和对话。若必须由用户在故障机执行精确端点探测，输出也只回传这些投影。

本地端口是请求链中的一个边界：同时核对配置值、监听地址、监听进程身份和目标客户端实际连接的端口。改成另一端口后成功，只证明旧端口或其配置路径是直接触发条件；没有观测到旧端口的占用者、绑定冲突或错误配置前，不能把“端口冲突”写成已确认根因。系统时间异常、首页 TLS 成功、配置文件已经复制或核心进程存在也按同一原则分别记录，不让其中任何一项替代完整链路。

迁移程序与配置时，源机文件哈希只证明快照内容；运行中的锁定文件、动态缓存和未复制的会话状态必须单列。迁移成功还要在目标机从实际启动入口确认程序加载了预期配置，并完成远程配置获取或用户明确接受的替代路径，最后形成可观察结果。

### 连接已经打开但交互尚未就绪

只有首次连接、重新连接或 reset 后的第一条消息丢失、使用错误 session，或者旧回复进入新会话时，先分别取得传输连接、权威身份握手、队列释放、当前 generation 和过期消息拒绝的时间与身份。socket 已经 `open` 只能证明传输可用；客户端先发默认 session、握手前清空队列、把重新连接当成 reset，或者让多个边界各自增加 generation，都会制造看似随机的首轮故障。最终修复消费 `change-prevention.md` 的“实时连接先建立权威身份与可调用状态”合同，一次迁移会话所有者、握手、队列、reset、重新连接和旧消息拒绝，不在发送端、接收端与界面分别补重试或身份回退。

能力页显示在线或发布了 URL，但正式消费者仍然不可调用时，沿 configured、process online、endpoint reachable、callable 四个事实寻找第一次错误提升；进程存在、静态 URL 已配置或健康检查访问了相邻路由都不能证明准确能力成立。能力快照与真实调用继续由上述预防合同治理，根因路径只负责定位哪个生产者提前发布了更强状态。

媒体预览看起来少了一部分、被裁切或出现大块比例留白时，不能从最终截图直接断言正式内容已经缺失，也不能先用一种缩放模式覆盖症状。先分别取得源媒体或正式素材、输出尺寸与比例契约、渲染表面的逻辑尺寸与物理像素、布局容器与外壳空间预算；从第一处偏离契约的边界判断是生产内容缺失、渲染表面错误还是布局构图错误。外壳或固定区域改变后，下游渲染容器和最终媒体构图必须重新验收。

### 路径过长先检查工程根所有权

工程创建、渲染、缓存、恢复或导出被路径保护拒绝时，先取得调用者传入路径、解析 `SUBST`、PowerShell 驱动器、符号链接和目录联接后的规范化真实路径、正式消费者的最窄限制，以及工程内最长合法后缀。当前路径确实超过预算是直接原因；保护规则在共同消费者不能保证更长路径时是合法边界；如果消费系统的工程状态被创建在生产者的深层内容输出目录下，最早架构根因是工程根所有权错误。别名映射未被清理、等待超时或临时副本只属于放大点和残留，不能取代这三个层次。

修复把短工程根的选择权迁移给实际生成工程状态的系统：公开创建入口接受逻辑名称与必要业务选项，返回规范化真实工程路径；全部调用者消费返回值，源素材继续留在原位置并通过正式引用边界进入工程。缓存、恢复、代理、临时文件和导出中间物随工程状态进入该系统自己的根。移除调用者注入物理根、深层项目内嵌、临时复制与回写同步、路径别名回退和其它旧恢复逻辑，再让正常入口从真实根生成最深合法后缀并由正式消费者读取。不能只提高阈值、启用系统长路径或放宽保护，除非共同链中的每个原生消费者都已经证明支持新的预算。

别名残留需要单独核对环境事实：先证明它是文件系统映射而不是磁盘分区，取得准确别名、目标、创建者、生命周期和持久性；只有映射与待清理对象完全一致且用户允许时才解除别名，并验证别名消失、真实目标仍存在。这个清理只收口失败替代路径，不能作为长路径根因已经修复的证据。

### 仓库反复出现本机值先检查项目配置所有权

绝对路径、工具安装目录、用户名、主机名、端口、服务地址或相邻项目根同时出现在源码、README、脚本、测试和示例中时，不把它诊断成若干独立字符串错误。先沿正常启动入口找到第一次选择这些值的生产者，区分项目不变量或可移植默认、用户机器事实、部署事实、凭据和单次运行覆盖；若调用点各自解释、拼接或回退到维护者机器值，最早根因是项目运行配置没有唯一所有者和消费边界。

修复直接消费 `change-prevention.md` 的“机器和部署事实先进入项目运行配置边界”：复用项目已有配置系统，让源码、CLI、桌面入口、后台任务、脚本、测试和 README 示例一次迁移到同一加载器、schema、优先级和规范化结果，并退出本机 fallback、旧环境变量别名、双读和调用点路径拼接。残留扫描覆盖活动源码、配置、脚本、测试、文档和示例；随后用不含开发机状态的干净检出和不同合法配置经过正常启动与正式消费者。只把路径移进 `.env`、在 README 隐去字符串、给测试注入正确对象，或保留本机默认作为兜底，都不能证明根因已经退出。

### 权威状态正确但活动界面仍旧

用户只有关闭重开、切换页面或手工刷新后才能看到正确状态时，先保持原表面打开，分别读取同一聚合在权威提交边界、语义事件、活动编辑器或缓存聚合、界面模型和最终可见投影中的稳定身份与版本：

```text
正式变更入口
→ 权威提交、聚合身份与版本
→ 语义事件的对象身份、事实类别与版本
→ 活动状态共享、协调、失效或重载
→ 框架可观察属性、模型信号或事件
→ 当前界面的可见性、数量、布局、命中与后续编辑
```

提交版本正确而没有事件，根因在提交到通知边界；事件正确但活动缓存仍是旧版本，根因在状态协调；缓存已经更新但界面只在其它动作后变化，检查绑定是否真正订阅可观察依赖，不能因为普通查询方法此刻能返回新值就判定响应链成立。修复应让全部正式变更入口汇入同一个提交与活动投影合同，并迁移缓存、事件和界面消费者；全局刷新、关闭重开、切换页面、固定延时或每个调用点各自调用刷新函数，只能作为诊断信号，不能成为最终架构。

### 事件或版本前进但权威事实没有对应变化

事件、版本、历史、撤销或缓存声明某些对象已经改变，但权威状态、关联对象或最终表面没有对应事实时，分别取得命令的用户意图与授权范围、冲突集合、观察集合、提交前后权威状态、提交返回的实际变更集，以及各下游消费者读取的身份和版本。计划目标或冲突集合直接被写成事件事实，最早错误在提交到实际变更事实的边界；观察集合遗漏移动、拆分、重排等合同内副作用，最早错误在观察闭包；实际变更集正确而消费者仍重建错误对象，才继续检查投影边界。

最终修复消费 `change-prevention.md` 的“计划范围与实际变更事实分离”合同，由那里唯一规定四类集合、无变化操作和真实验收。本路径只定位第一次混淆发生的位置，不另建变更集、事件或版本规则，也不通过扩大所有命令的全量读取永久掩盖观察范围不完整。

### 错误作用范围必须由生产者保留

单次请求、连接、配置提交、后台任务或关闭失败被界面显示成启动失败、全局故障或另一个操作的错误时，先沿同一操作身份检查错误作用范围在哪里丢失。正式错误至少保留发生阶段、作用范围、稳定操作身份、错误类别、原始原因、可恢复性和允许的后续动作；应用启动、活动连接、会话、回合、任务、一次操作和关闭等范围由项目合同定义，不能由异常文字、出现位置或消费者当前页面反向猜测。

全局致命或启动错误只描述核心运行时确实没有建立、已经失效或无法继续服务的事实。局部失败由对应生产者提交带身份的类型化事件，只改变自己的回合、任务、连接或操作投影；状态栏、横幅、行内消息、重试入口、日志和通知分别订阅合同允许的范围。一个局部超时、供应商错误或取消不能覆盖已经成立的启动成功，也不能让无关操作失去继续能力。

修复时枚举全部错误生产者、事件类型、状态存储、订阅者、界面映射、重试与恢复入口，把作用范围和操作身份迁移到唯一结构化边界；新链完整承载后退出被多种范围共用的通用错误事件、按文字分流、消费者补范围和旧兜底。验收从正常入口先建立成功的上层状态，再让真实局部生产者失败，证明只有匹配消费者显示错误、上层健康状态不被改写且后续允许动作仍能继续；随后由真实启动或全局生产者产生另一项失败，证明它到达自己的全局投影。测试直接调用界面 handler 或手写已经带正确范围的事件只能证明消费者，不能证明完整错误链。

### 记录仍存在但派生消费者将其排除

用户已经修改记录，真源中也能看到新正文，但搜索、筛选、编译、推荐、关系计算或其它派生消费者不再返回它时，沿同一稳定记录身份检查：正式修改入口实际提交了哪些字段；来源、证据、权威性、资格和关系是否仍与新事实一致；持久化记录是什么版本；正式派生消费者用哪些事实决定纳入。若修改边界只写了展示内容，却留下会使下游拒绝记录的旧语义事实，第一处错误就在修改生产者与原子提交边界，不在最后一个筛选器。

批处理出现重复对象、过期关系或错误资格时，再判断它是固定计划批次还是连续决策批次。固定计划被中间状态重新解释，错误在计划版本边界；后一步本应依赖前一步提交、却始终读取同一份初始快照，错误在批处理器的状态推进边界。最终修复使用 `change-prevention.md` 的“语义记录修改与连续决策批次使用已提交状态”合同，一次迁移正式修改入口、持久化字段、批处理器和派生消费者；验收必须让正式生产者修改或连续生成记录，再由真实存储和派生消费者读取，不能手写一份语义已经对齐的对象绕过错误边界。

### 设置或维护工具越过唯一写入边界

修改一个设置却同时改变多个同级路由、保存失败后留下部分新值，或者检查器中的写入能绕过正式服务时，先比较用户动作选择的稳定目标身份、实际写集合、提交次数和派生状态更新。设置范围与单次配置提交由 `change-prevention.md` 的“可编辑设置必须连到真实能力和运行结果”唯一拥有；长期记忆的首轮召回、检查器和维护写入则由 `log-audit-standard.md` 的“召回触发与维护写入边界”唯一拥有。根因修复迁移全部调用点到各自正式命令边界，并让没有领域命令的维护入口退回只读；不能在这里再定义一套保存循环、driver 写入或失败回滚规则。

设置能够保存、状态端点也能回显，但用户报告目标结果没有变化时，仍消费上述唯一设置合同的阶段效用图，分别判断已经接通、活动运行时已经应用和对目标结果有效，沿全部决策阶段定位最早主导结果的参数、默认值或硬编码值。不能只继续调整现有控件，或在最终输出增加后置特判来换取表面改善；后置补偿只有形成独立产品合同和验收时才作为次级结果处理。

## 2. 诊断路径

用户只要诊断时：

1. 复现真实现象，或说明当前无法复现的准确条件。
2. 从用户动作反向追到消费者、边界和生产者，再从生产者正向验证。
3. 用代码、配置、运行输出或真实文件证明最早错误位置。
4. 缺陷与启动、加载、过场、滚动、资源到达或媒体切换有关时，沿时间顺序找到第一个错误里程碑，并区分最终状态正确但中间过程失败的情形。
5. 列出完整影响范围、最终架构和迁移顺序。
6. 说明修复后怎样证明旧路径退出。

交付诊断后停止，不借“验证根因”实施修复。

命令找不到、版本错位、包安装位置、缓存、SDK、终端差异或长任务超时参与现象时，先把根因归入项目源码或配置、用户与机器环境、命令执行器、外部服务四个边界之一，不能用“环境问题”混写。已有用户环境档案只提供当前事实候选，仍要由绝对可执行文件、版本、目录或真实进程核验；档案缺失不等于项目有缺陷。只有检测确认、未来任务会复用且用户允许写入的机器事实才更新档案，项目依赖和一次报错仍留在项目或本轮。

外层等待超时不能直接归类为构建失败。先确认实际阶段、原进程与子进程、日志和产物是否继续变化、命令是否已退出，以及正式消费者能否读取结果。原任务仍有进展时继续观察，不启动可能争用锁、缓存、端口或输出目录的重复任务；只有成功退出且产物可消费、明确失败退出、进程消失且没有产物、连续观察没有进展并形成诊断证据，或达到用户明确时间与成本边界时才停止。

## 3. 修复路径

用户要求修复时：

1. 先保留一个能证明缺陷的失败测试、复现实验或可观察证据。
2. 定义最终真源、类型、命令或接口，以及生产者和消费者各自职责。
3. 一次性迁移所有调用点、状态、持久化字段、事件、导出、平台适配，以及会教用户或扩展作者使用该契约的文档、示例、schema、SDK 片段、验证与发布脚本、真实用户链工具和生成物来源。
4. 在新链已经接通且原功能完整迁移后，退出旧类型、旧 helper、旧命令、旧恢复路径和仅为半迁移存在的兼容层。
5. 用户未允许删除时，把必须保留的历史材料移到已同意的归档位置；不能继续从归档运行。迁移前建立准确的“源文件 → 归档文件”清单，归档后逐项核对字节数与哈希或直接逐字节比较。先重命名再继续修改同一文件不等于保存了原内容；只有归档副本与动作前来源一致，且活动入口不再读取归档，才算完成保留。
6. 运行标识符边界明确的残留搜索并检查每项命中，证明活动源码、测试、配置、文档、示例、生成物来源和公共导出只剩最终身份；归档、生成结果和自然语言误报要明确排除，不能靠忽略全部命中宣称完成。

### 补丁和写入载荷必须来自完整真源

文件、差异或生成内容经过终端、工具响应、聊天上下文或其它有界展示后，只是可观察投影，不再自动等于完整真源。输出带有截断、省略、下一页游标、未读区间、输出预算耗尽或起止边界无法核对时，不得把它复制、拼接或转交给补丁和写入工具；先固定源内容身份，再从实际文件、正式生成器或稳定的行、字节、页和游标区间读取到明确末尾，重新构造写入载荷。生成步骤可以提供补丁候选，但不能把展示层回显的候选文本当作源文件绕一圈写回。

应用补丁前固定准确目标路径、预期旧内容、作用范围和唯一命中依据。相同字面量出现多次时，使用能够唯一定位职责或结构的上下文，或拆成可分别核对的小补丁；不能因工具报告“应用成功”就假定改中了预期位置。应用后从磁盘重新读取实际差异和受影响文件，核对预期命中数、完整边界、意外截断或省略标记，再运行对应解析、编译或正式消费者验证。目标、载荷或实际差异任一项仍不完整时停止写入链并补齐证据，不能让后续测试的偶然成功替错误补丁背书。

修复请求明确指向本任务此前诊断或审计的“全部问题”或“上述问题”时，原诊断结论成为本轮结项合同。开始实施前为每项发现保留稳定身份、原证据、目标边界和完成条件；新证据可以合并同根因发现或拆分迁移范围，但必须保留原发现到最终结论的对应关系，不能让一项发现因为后续方案换了名称而静默消失。

每项发现最终只能标为 **已解决 / 经新证据重新分类 / 经用户明确同意退出范围 / 受阻**。已解决需要最后一次相关修改后的正式生产、边界、消费或结构退出证据；重新分类需要说明原判断的哪项构成条件已被新证据推翻；退出范围只能来自用户明确决定，不能由实现者自行缩小“全部问题”；受阻要记录缺少的权限、产品决定或外部条件。仍然开放或证据未知的发现不得借完整测试、真实用户链或其它发现的成功被关闭；用户结果仍是“全部问题”时，不得宣告“全部问题已经解决”。

公共协议、schema、清单或能力描述出现同名同版本、实际结构或语义不同的情况时，把它定性为合同身份碰撞，而不是普通兼容缺口。由权威生产者分配新的协议版本并确定最终合同，通过唯一同步入口单向更新快照，再一次迁移正式生产者、存储或传输边界、全部消费者、文档、示例和测试；原来发生碰撞的活动版本退出。不能原地改写同一版本的多份副本、继续手工同步，或增加猜字段、按来源降级和双读回退来掩盖碰撞。

工具存在机器可读的操作发现、能力描述或参数 schema 时，它是实际可执行能力的真源，说明文档只是消费者。迁移同时让文档、示例和验证器读取或核对实际操作集合与参数 schema；发现漂移时修正文档消费者或正式能力边界，不能让运行时代码迎合过期说明，也不能在文档中长期复制维护第二套命令定义。

### 产品升级后的公开身份漂移

产品升级版已经成为当前入口，但界面、CLI 能力描述、Skill、活动文档、示例或当前配置档案仍显示旧公开名称时，把它定性为公开身份迁移不完整。先建立“当前公开产品名称 / 稳定技术标识 / 旧公开名称”台账，确认唯一产品身份真源，再迁移全部活动消费者；旧名称只允许留在明确标为历史的非活动材料。包名、命令名、协议标识、模块命名空间、安装目录和数据目录属于技术合同，除非目标合同明确要求，否则保持稳定，不能把公开更名扩大成破坏兼容性的全面字符串替换。

完成证据同时包含边界扫描和真实入口：活动源码、UI 文案、CLI 描述、Skill、文档、示例和当前配置只剩当前公开名称；历史材料中的旧名称已经与活动消费者隔离；至少一个真实界面、CLI 或公开能力入口显示当前名称。只修改常量、README 或搜索结果为零，不能单独证明用户实际使用的产品身份已经迁移。

外部协议需要过渡时，把兼容适配器放在唯一边界外侧，记录版本、拥有者、最后期限和删除测试。项目内部不能继续读写两套真源。

## 4. 同源变体收口

找到第一个最早错误边界后，在同一事实和同一受影响链内派生变体，再冻结迁移范围：

- **权限归属**：创建、读取、改变、取消和恢复是否由同一正式身份约束，连接、会话、客户端、进程和持久化所有者是否会错位；
- **状态生命周期**：持久化失败、等待、断开、重新调度、取消、终态、重启恢复和关闭是否遗漏转移或清理；
- **数据表示**：原文、序列化或转义文本、结构化字段、流式分片、参数、环境、请求头、日志、事件和持久化记录是否仍会产生同一错误；正式序列化器的实际输出是否通过 schema、存储或线协议校验，字段省略与显式 `null` 是否符合合同；改变 chunk 边界和最终 flush 后是否等价；
- **边界转向**：重定向、代理、重试、回调、并发、中止和关闭是否把目标、顺序、所有者或失败收口带离最终合同；
- **实际运行入口**：源码、生成文件、包装脚本、解释器和原生产物中，用户入口实际选择的是否仍是旧实现或过期产物，以及其子进程是否解析到同一执行计划中的工作目录、包导出、相邻依赖和资源，允许集合与实际集合是否完全相等。

这不是扩大成项目综合审计。只对已经证明受同一事实或边界影响的维度建立失败证据、迁移调用点和验收。主要测试通过后才连续发现同源问题，说明迁移范围的生成方法仍缺维度；更新范围并一起收口，不能修一个、重跑一次、再等下一个偶然暴露。

## 5. 持久化和临时状态迁移

涉及持久化状态时同时处理：

- 新 schema 和单向迁移；
- 当前版本新建状态、由旧版本正式生产或保存的真实历史状态，以及各自的准确版本与内容身份；
- 旧字段何时读取、何时立即重写；
- 不可用路径、未完成操作和恢复副本怎样保留；
- 失败或中断后能否安全重试；
- 新运行时是否已经停止读取旧字段。

迁移验收使用同一份状态矩阵：当前版本从零新建；真实旧状态进入正式迁移器；迁移后的实际文件、记录或消息通过当前 schema、存储或线协议校验器；当前消费者读取、关闭并重新打开；失败注入后原版本、原内容和原身份保持可恢复，失败产物不会取代正式状态。真实旧状态应来自旧版本生产者、旧版保存路径或可核对的历史制品，不能由测试直接手写迁移后对象或凭当前模型猜一份旧对象。一次迁移完成后立即重写并由当前消费者只读新合同，运行时不保留长期双读。

关系表经重命名、复制或重建后出现行消失、孤儿关系丢失，或者索引、约束、触发器、视图和依赖查询退出时，直接消费 `change-prevention.md` 的“关系表重建先冻结数据与模式闭包”唯一合同。根因路径只定位第一次遗漏发生在旧表数据清点、关系映射还是模式对象恢复，不在这里再定义一套迁移字段或验收清单。

临时状态不能只验证“没有落库”。按创建、持久化失败、等待、断开、重试或重新调度、取消、终态、重启恢复和关闭逐项确认所有者、保留条件与清理条件。恢复链需要知道临时依赖已经丢失时，持久化记录只保存不含该数据的需求或所有权标记，并进入明确等待或失败；不能静默换用另一个依赖，也不能把临时值转存到参数、环境、日志或事件。

用户动作已经被接受、随后仍可能失败或留下外部结果时，`pending` 必须在易失败的输入重校验前持久化。发布成功、失败保全和无产物失败只能描述已经完成的物理事实：先完成正式目标或恢复副本的写入、移动、刷盘与必要校验，再记录唯一终态。释放生产者、文件句柄、设备或远程会话失败时，事务保持未决，不能因为等待超时就提前宣告完成。

## 6. 平台与生命周期

桌面窗口、Android、后台任务、远程同步和关闭刷盘属于生命周期链。修复时核对：

```text
启动 → 恢复 → 正常操作 → 外部变化 → 保存 → 关闭请求 → 刷盘 → 退出 → 再次启动
```

每个平台使用自己的真实边界。共享业务语义可以统一，原生权限、文件系统和生命周期实现不能用一个平台的假接口代替。

回调、事件处理器或 `void` 风格命令如果能启动异步操作，生命周期所有者必须登记派生工作，并让空闲、取消、关闭、重启和测试完成边界等待或收口。每个线程、任务、读取器和订阅分发器都要有唯一创建者、可等待完成信号、取消后的排空路径和唯一释放者；超时只表示等待未完成，不表示工作已经结束。只等待事件处理器返回、却让它启动的 Promise 继续运行，仍然是生命周期链失效。

权威状态转换、终止原因和致命错误使用无损通道；高频进度、帧率或其它遥测才可以有界、合并或丢弃旧值。不能为了避免慢消费者阻塞而丢掉操作终态，也不能让逃逸任务在事务已经宣告完成后继续写状态。

跨进程生产者同时输出业务结果和诊断内容时，先确定唯一结构化结果通道并让正式消费者只从该通道改变业务终态；结果帧至多一次，缺失、重复或版本不兼容都形成明确失败。stdout、stderr、日志尾部、退出码和 EOF 分别保留文本、进程与传输语义，不能从自然语言或最后一行猜测结果。完整日志写入和结果帧消费都必须在关闭宣告前完成；有界摘要只能是可追溯到完整记录的投影。

验证有状态服务重启或恢复时，通过权威端点、端点到进程的映射、锁文件或服务管理器确定确切实例，先处理正在运行的工作并保存重启前的正式消费投影；只停止该实例并重启后，再由同一个消费者读取。按进程名称批量终止，或只证明数据库文件仍在，都不能证明服务恢复和消费结果成立。
