# 外部 Agent CLI 治理

用于项目需要让 Codex、Claude Code 等外部 Agent 通过本机 CLI 调用已有业务能力时，设计、实施或验收稳定、可脚本化、机器可读的入口。它拥有项目首次公开 Agent CLI 时的入口选择、命令合同、机器发现和 CLI 边界验收，不把 Agent、模型调用、聊天界面或 Agent 编排层内置进产品。

JSON 的编码、解析、schema、容量和稳定结构错误继续由 `structured-data-boundary.md` 拥有；租约、幂等、等待、恢复和唯一终态由 `durable-operation-governance.md` 拥有；项目调用第三方 CLI、SDK 或外部服务的兼容关系由 `external-tool-compatibility.md` 拥有。本文只把这些合同投影成外部 Agent 可以可靠调用和判断结果的项目入口。

## 1. 先冻结外部消费者和入口边界

“让 Agent 做”默认指项目外的 Agent 使用公开入口，不是给产品增加 Agent。开始前建立：

```text
外部 Agent 要完成的用户结果与第一条成功路径：
准确平台、项目根，以及只在本机还是需要远程调用：
现有界面、API、应用服务、组合根和业务真源：
数据库、worker、队列、外部服务与认证的实际边界：
需要公开和明确不公开的业务能力：
调用者怎样发现能力、提供输入、判断完成并恢复失败：
本轮允许修改、运行和验收到哪一层：
```

当前结果只服务拥有项目文件与本地数据库权限的同机 Agent 时，CLI 可以直接消费项目的公共应用服务和组合根，不要求先启动 HTTP 服务或复制网页登录认证。结果要求跨机器、跨账号或复用远程授权边界时，先建立公共 API 或其它真实远程合同，不能把本地 CLI 描述成远程能力。

CLI 是应用边界外侧的薄适配器。它负责参数绑定、输入模型校验、调用调度、结果投影和进程退出，不直接实例化 repository、不复制业务规则、不建立第二套事务、租约、队列、幂等、恢复或配置语义。项目已有责任所有者能够闭合合同时直接复用；缺口才进入原应用边界修复，不能在 CLI handler 中补一份更方便的实现。

## 2. 一份命令合同拥有全部公开语义

实施前为每个命令建立同一份账本：

| 合同项 | 必须决定的事实 |
| --- | --- |
| 稳定身份 | 不随帮助文案变化的命令 ID，以及正式调用路径和用途 |
| 应用所有者 | handler 最终调用的公共服务、命令或阶段所有者 |
| 输入 | 位置与命名参数、结构化输入模型、默认值、字段权威性和冲突处理 |
| 输出 | 正常结果的具体 JSON Schema、终态语义和正式消费者 |
| 前置 | 数据库状态、worker、外部服务、凭据或其它真实依赖 |
| 副作用 | 只读、普通写入、高影响写入、文件输出或外部发送 |
| 保护 | 是否要求显式确认，以及拒绝发生在任何修改之前的边界 |
| 持久语义 | 调用者提供的幂等身份、租约、排队、等待、超时、取消、重试和恢复 |
| 进程结果 | 成功、输入错误、不存在、冲突、依赖未就绪、未完整完成、超时和中断的稳定退出码与错误类型 |
| 消费者 | 能力发现、包装脚本、文档、示例、测试和已知外部 Agent |

命令行路径中的对象 ID、slug 或其它资源身份是权威输入时，结构化正文出现同一字段必须相等；冲突在进入 service 前拒绝。结构化输入复用应用已有的请求模型和校验器，不能由 CLI 维护较宽或较窄的第二套字段语义。一个操作需要跨次重试保持幂等时，调用者必须能够提供并复用稳定身份；CLI 不为每次调用自动生成一个无法在下次重试中复现的替代值。

高影响操作的确认是命令合同，不是交互提示。非交互 Agent 必须显式给出项目规定的确认参数，解析器在加载生产者或改变状态前拒绝缺失确认。数据库创建、迁移、维护、外部发送、不可逆删除和整周期工作流分别按项目事实分类；不能因为 CLI 运行在本机就把全部写入都标成普通操作，也不能把普通可恢复修改全部升级成危险动作。

## 3. 注册表和能力发现是可执行真源

稳定命令注册表一次拥有命令 ID、路径、handler、参数、输入模型、输出 Schema、依赖和保护标记。解析器、`capabilities` 或等价机器发现、帮助和文档从它投影，或者由启动检查证明集合和稳定身份完全相等；不能让命令代码、能力清单和说明文档分别维护子集。

能力发现必须在数据库、worker、网络和可选模型运行时加载前可用，并为每个命令返回足以构造调用和判断结果的具体合同。通用 `{type: object, additionalProperties: true}`、空对象或同一份宽 schema 只有在业务输出确实不受约束时才成立；不能作为尚未完成输出建模的占位。每个公开命令都有 handler 和输出 Schema，每个应公开的 handler 都进入注册表；内部 helper 不为追求数量暴露成命令。

机器发现中的 Schema 不是说明性装饰。至少让每类代表性正式 handler 产生真实结果，再用其公开 Schema 校验；只断言 Schema 字典非空、有 `properties` 或命令数量正确，不能证明 Agent 会收到符合声明的数据。序列化器只处理合同明确支持的 JSON 值和类型适配，不能用通用 `str(value)` 或等价兜底把未知对象静默改成字符串后继续声称符合 Schema。

环境选择、版本和能力发现先解析，再延迟导入配置、组合根和可选运行时。导入 CLI、查看版本或读取能力目录不得提前加载模型 SDK、浏览器、爬虫或其它昂贵依赖；这项性能与副作用边界由真实导入集合和状态前后证据证明，不由模块文件较小推断。

## 4. 机器结果与诊断通道分离

JSON 模式的 stdout 一次调用只包含一个版本化结果文档。稳定 envelope 至少区分成功、命令身份、业务数据、消息、结构化错误和运行元数据；字段省略、`null`、空集合与失败数据按同一合同表达。业务日志、进度、调试堆栈和第三方库的 `print` 进入 stderr 或正式日志边界，不能污染机器结果，也不能从最后一行自然语言反推业务成功。

退出码和 JSON 错误描述同一失败类别，但各自保留进程与业务语义。项目必须公开一张稳定映射，并让参数错误、资源不存在、业务冲突、依赖未就绪、需要人工处理、等待超时和用户中断各自经过真实拒绝或失败入口。未知异常只能进入项目声明的内部错误，不得被宽泛捕获后返回成功；调试堆栈只在调用者显式启用时写入 stderr。

文本输出可以是同一 envelope 的人工投影，不能另行调用业务服务或解释终态。Windows、Shell 或其它包装脚本先选择项目已经核验的解释器，原样转发参数、标准流和退出码；包装器成功启动解释器不等于底层命令成功。

## 5. 只读、写入和长操作分别成立

`version`、能力发现、帮助、状态和其它观察入口在创建目录、打开会隐式创建文件的数据库连接、迁移 schema、初始化运行状态或启动生产者之前返回。普通命令发现数据库缺失或过期时给出稳定未就绪结果和显式初始化入口，不偷偷创建或迁移；只有项目点名的初始化命令拥有这项状态改变。

业务命令在项目正式事务或 repository session 中调用公共应用服务。需要 worker 的操作继续经过正式队列，不能为 CLI 增加进程内捷径。`run --wait`、`wait` 或等价入口等待业务任务或实际生产进入项目定义的终态，而不是只等队列命令被接受；超时只结束本次等待并返回准确状态，不把仍运行的任务改写成失败或完成。

外部发送、交付和其它可能先产生物理结果再失去确认的操作消费持久操作合同，保留调用者提供的幂等身份、租约冲突、`needs_attention` 或等价人工处理终态。文件导出明确输出路径、覆盖政策、部分失败处理、流式或容量边界和内容身份；返回路径、条数、字节数或摘要时由正式文件事实计算，不能从计划值或内存计数猜测。

## 6. 用确认计划逐项验收 CLI 边界

实施计划或用户确认的命令面必须转换成完成账本：

```text
计划承诺与稳定发现 ID
→ 命令 ID 和注册表合同
→ handler 与公共应用所有者
→ 能力发现中的输入和输出 Schema
→ CLI 边界测试的实际唯一身份
→ 包装脚本或正式进程入口
→ 当前状态：已验证 / 仅诊断 / 未验证 / 受阻
```

最低代表矩阵按本次真实命令面选择，不为形式完整虚构功能：

1. 在无数据库状态运行帮助、版本、能力发现和状态，逐项证明没有创建文件或运行状态；普通业务命令明确拒绝，显式初始化才改变状态。
2. 让参数、JSON、schema、资源身份冲突和缺少确认分别在修改前失败，并核对每个公开退出类别都只产生一个 JSON 文档。
3. 从正式 handler 取得代表性读取、写入、删除或恢复、文件导出和列表分页结果，让实际输出通过对应公开 Schema。
4. 在 CLI 边界验证 worker 缺失、租约冲突、调用者幂等身份复用、人工处理终态、实际任务等待和超时；service 单元测试只证明下层，不能替这些入口语义。
5. 把 Telegram、AI、真实网络和其它不可控外部依赖替换在正式边界外侧，仍让同一次 CLI 调用经过请求模型、应用服务、结果映射和退出码；替身通过不能写成真实服务已经可用。
6. 从当前平台正式运行 `python -m ...` 或项目等价入口和包装脚本，核对参数、解释器、工作目录、stdout、stderr 与退出码；再证明导入和观察命令没有加载项目声明的可选重型运行时。
7. 从原确认计划逐项映射测试框架实际收集的唯一身份。总测试数、完整套件名称或相邻 service 测试通过，不能关闭没有 CLI 边界证据的承诺。

只有每项计划承诺都有合法终态，才能回答“都做完了”。主体代码存在但 Schema 仍是占位、关键命令只测了下层 service、包装器或真实进程未运行、外部依赖只使用替身时，分别报告已经实现、当前验证层和仍未验证边界；不能把 Ruff、编译和完整后端测试的总通过概括成 Agent CLI 全部验收。

## 7. 输出与停止位置

第一段直接说明外部 Agent 的第一条成功路径、选择本机 CLI 的理由和明确不内置 Agent。随后交付命令合同账本、注册与能力真源、结构化输入输出、依赖和副作用、持久操作与等待、包装入口、完成账本及未验证边界。

只要求设计或计划时停在合同和验收矩阵；明确要求实施时才修改项目，并在每项承诺由真实 CLI 入口取得对应证据后结项。项目自己的命令、路径、退出码和业务规则留在项目真源，不写入本方法成为跨项目默认。
