# 日志审计标准

在审计字段、LLM 交互、长期记忆、TTS、任务链路或日志观看体验时使用。输入是当前项目的代码、配置、真实日志和可复现操作；输出是证据充分的诊断或已验证改造。

## 0. 先区分残留与噪音

用户把一段启动输出、日志文件或查看器结果称为“上个版本残留”时，先按真实来源分型，不能仅凭旧名称、重复内容或时间观感下结论：

| 类型 | 识别证据 | 治理位置 |
| --- | --- | --- |
| 当前运行日志 | 时间、进程、启动身份或关联 ID 属于本轮实例 | 评估级别、事件价值和默认可见性 |
| 历史持久记录 | 文件、数据库、缓存或查看器游标确实读取了旧实例范围 | 在存储保留、轮转、查询范围或查看器边界收口 |
| 旧架构命名残留 | 当前生产者仍把活动组件、配置、端口、服务或事件写成已经退出的身份 | 转入身份迁移，更新真源和全部消费者，不能靠隐藏文本掩盖 |
| 高频低价值运行噪音 | 内容真实但不改变生命周期、故障、性能或用户结果判断，例如健康探测、静态资源成功访问和重复注册成功 | 在最靠近生产者的 logger、访问日志或事件级别收口 |

审计一次真实启动或用户动作时，分别定位业务生产者、日志框架、子进程 stdout/stderr 转发、持久化或缓冲边界和最终查看器。重复前缀、多行内容失去组件身份、同一事件被宿主与子进程各记一次，通常来自转发或格式化边界；逐请求访问记录、初始化步骤成功和能力注册成功通常来自生产者级别。修复应落在首次产生无效语义或错误级别的位置，不能只在最终查看器增加字符串过滤。

降噪必须保留错误、警告、启动与关闭里程碑、服务不可用、重试耗尽、降级、恢复结果和能够解释用户等待的性能异常。正常成功细节可以降为调试级别或默认关闭，但仍要有按需启用入口；不得通过整体提高阈值让关键组件失去可诊断性。发现旧架构身份时，把“减少可见噪音”和“公共身份迁移”拆成两个结果：前者按本标准治理，后者按 `change-prevention.md` 的公共运行时与配置身份迁移完成全调用点退出和真实链验收。

## 1. 字段有效性分级

| 分类 | 判定标准 | 处理方式 |
| --- | --- | --- |
| 必要且有效 | 真实产生并贯穿所需链路；缺少后无法定位、关联或复盘 | 默认保留并保证可筛选 |
| 有效但按场景需要 | 真实生效，只在并发、性能、重试等特定场景改变判断 | 结构化保留，默认可隐藏 |
| 已输出但冗余 | 内容真实，但可从同条日志稳定推导或从未参与诊断 | 合并、折叠或移除 |
| 已声明但未生效 | 配置、模型或格式里存在，运行时未产生、未传播或被覆盖 | 修复传播或移除声明 |
| 必要但缺失 | 缺少后无法区分关键运行路径或还原结果 | 在最靠近真源的位置补充 |

不要根据字段或配置名称判断有效性。逐项核对定义、真实取值、传播、格式化、写入和展示；声明存在但没有改变真实输出的配置归为“已声明但未生效”。

## 2. 通用字段

### 默认必要

- 时间：带时区并保留足够精度，能够还原事件顺序。
- 级别：语义一致，错误不能伪装成普通信息。
- 组件或 logger：能定位责任边界。
- 事件或操作：使用稳定名称，不依赖自由文本猜测行为。
- 结果：成功、失败、取消、跳过或降级。
- 关联 ID：至少有一个能够串起当前操作的稳定标识。
- 正文或结构化详情：保留足以复盘的真实输入、输出与异常。

### 按场景需要

- `session_id`：跨多个回合或连接的会话。
- `turn_id`：对话回合及其 LLM、记忆、TTS 下游事件。
- `task_id`：Agent、队列或后台任务。
- `trace_id` / `parent_trace_id`：跨组件或父子操作链。
- `request_id`：远程请求、重试和供应商响应。
- `thread` / `process`：存在多线程或多进程竞争时。
- `duration_ms`：远程调用、磁盘操作或性能边界。
- `attempt`：存在重试时。
- `file` / `line`：开发调试有用，普通用户视图默认隐藏。

项目不存在对应边界时，不为字段齐全制造无意义 ID。

## 3. LLM 交互

必须能够还原：

1. 实际调用的 provider、model 和端点类别。
2. 真正发送的完整 messages 或 prompt，包括 system、user、assistant 历史和注入上下文。
3. 实际发送的工具定义、工具选择和影响结果的参数。
4. 完整回复正文、接口提供且允许记录的 reasoning 摘要、工具调用和结束原因。
5. 错误类别、供应商错误正文、取消、超时、重试次数和最终结果。
6. 请求、回复与所属 session、turn、task、trace 的稳定关系。

流式回复保留分片诊断能力，并在结束时记录可直接阅读的完整重建结果。不能只打印本地准备的 prompt，也不能只保存截断后的返回值。

认证 header、API Key 和访问令牌不属于交互内容，单独排除；用户文本、模型回复和注入上下文仍然完整可查看。

验收问题：

- 能否从日志准确复制一次真实请求并说明它属于哪个回合？
- 能否看到模型真实回复，而不是 UI 二次加工后的文本？
- 能否区分模型产生重复、流式合并重复和界面重复渲染？
- 失败后能否知道请求是否已发出、收到多少内容、是否重试？

### 日志落点是用户可见合同

用户要求把记录打印到控制台、写入文件、显示在日志查看器或包含在诊断导出时，每个落点都是独立的正式消费者。开始前记录该落点由哪个运行入口创建，消费 stdout、stderr、结构化日志还是持久记录，格式化、过滤、缓冲和 flush 由谁负责，开发运行、后台启动、服务宿主和原生产物分别是否实际提供这个落点，以及用户从哪里读取、复制或导出完整内容。

logger 已经调用、handler 已经注册或单元测试捕获到一条示例，不能证明指定落点可用。控制台承诺要从受支持的正常启动入口捕获真实进程输出；文件与查看器要读取同一关联身份的实际落盘记录；诊断导出要从正式完整记录生成。GUI 或后台产物没有控制台时，开发命令中的 stdout 通过不能替它背书；为补证据而改变窗口类型、打包方式、服务宿主或用户启动体验属于新的产品与生成动作，没有授权时停在“当前入口已验证、其它产物未验证”。

### 诊断读取先投影再输出

读取设置、结构化运行报告、环境档案、缓存元数据或诊断制品时，先读取文件身份、schema 和字段名，不在发现结构的步骤输出字段值。根据当前判断建立允许字段清单，只输出当前判断需要的允许字段、稳定身份、状态和必要摘要；禁止递归输出未知结构化文件、任意目录中的全部 JSON，或为了找一个字段把整份对象送进控制台和对话。

投影前同时按 schema 语义和字段名识别 API Key、访问令牌、认证 header、cookie、密码、私钥及同等凭据，包括嵌套对象、数组和动态键。凭据必须在进入控制台、工具输出、对话、日志或诊断导出前完成脱敏，不能先输出再依赖下游界面遮盖。结构发现只需要字段名和类型；需要证明值相同或发生变化时优先使用类型化状态、长度或受控摘要，不能保留可反推出原凭据的前后缀。

原始证据继续留在正式所有者和原受控位置，诊断流程只持有有界投影或内容身份。只有正式安全消费者的合同明确要求完整原文并定义访问、传输、保留和清理边界时，才允许在该边界内读取；本地桌面应用也不把方便诊断解释成向工具输出或对话公开凭据的授权。

LLM 日志验收从正式用户动作开始，让真实请求构造和 provider serializer 生成最终线请求，再让实际响应经过正式解析与完整重建后进入日志系统和指定落点。可以用记录线协议的受控本地端点代替不稳定远端服务，但不能替换正在验证的 serializer、响应入口、日志配置或落点；mock 网络返回、直接调用 formatter 或手写已经正确的日志事件只能证明局部格式。每个承诺落点都要在同一次关联链中看见完整请求、完整回复或准确失败、稳定身份和结束结果，同时确认认证信息没有进入记录。

## 4. 长期记忆质量

沿以下链路核对：

```text
对话事实 → 记忆候选 → 质量判断 → 去重或合并 → 持久化 → 检索 → 上下文注入
```

关键证据：

- 候选来源的 session、turn 和原始内容。
- 为什么写入、拒绝、合并或替换。
- 写入前后内容、稳定 ID 或内容摘要哈希。
- 检索条件、命中项和最终注入给 LLM 的内容。
- 人工编辑、自动整理和恢复操作的审计记录。

长期记忆写入前还要按记忆类别建立证据资格，而不是把同一会话里的所有文字视为同等事实：

| 记忆类别 | 可作为权威证据的来源 | 只能作为上下文或派生材料的来源 | 正式消费者 |
| --- | --- | --- | --- |
| 用户事实、偏好与经历 | 用户明确陈述、用户确认的人工记录 | 模型回复、任务报告、猜测和未确认摘要 | 召回与对话上下文 |
| 角色自身特质与习惯 | 角色在多个独立情境中的重复选择和表达 | 用户希望角色成为什么、单次迎合、系统提示词和任务状态话术 | 角色派生画像与对话上下文 |
| 关系变化 | 双方实际互动、纠正、冲突、和解与共同经历 | 单方标签、预设亲密度和没有互动证据的结论 | 关系派生视图与对话上下文 |
| 任务与项目事实 | 运行时已提交事件、真实产物和正式验收 | 面向用户的润色台词、执行者自报和未完成计划 | 任务恢复、项目记忆与结果说明 |

每条原子记忆保留来源角色、来源类型、session、turn、原文定位、写入理由、当前状态和被哪次纠正取代。角色回复可以证明角色当时怎样表达或选择，不能据此新增用户事实；用户评价可以成为关系事件，不能直接改写角色特质。任务接收、进度和完成话术属于运行时表达，不进入角色特质学习。证据不足时保留为候选或不写入，不用模型“说得像真的”提高权威性。

用户画像、角色画像和关系画像是从仍有效的原子记忆确定性派生的视图，不是第二份可独立编辑的事实真源。纠正、删除、过期或证据失效时，先提交原子记录状态，再重建派生视图和检索索引；画像中的结论必须能追到当前有效证据。角色特质的形成可以参考多个不同情境，但阈值由产品合同和真实评测决定，不能把固定回合数或固定特质数量写成通用真理。

### 召回触发与维护写入边界

长期记忆召回由当前用户输入、记忆能力是否启用、检索资格和当前权威身份共同决定，不能以短期对话历史非空作为前置条件。短期历史为空只说明当前上下文没有已保留回合，不表示长期记忆不存在；除非产品合同明确要求遗忘，reset 清理短期会话也不能顺带关闭或删除长期记忆。验收分别覆盖应用首次连接后的第一轮、显式 reset 后的第一轮、重新连接后的第一轮和普通连续回合，让正式检索器产生命中并让上下文组装器实际消费；消费端手写召回项或只在已有短期历史时测试，不能证明首轮召回成立。

记忆查看器、检查器、调试页面、维护脚本和迁移工具都是同一领域边界的消费者，不是第二个写入者。它们需要创建、更新、合并、归档、删除或恢复记忆时，必须提交与正常整理器相同的类型化领域命令，经过唯一记忆服务完成证据资格、身份、版本、持久化、索引和派生画像的一致更新，并产生可审计操作记录；不能直接调用存储 driver、写表、改索引或在界面层复制校验。领域层尚未提供对应命令时，维护表面保持只读，不能因为入口只供本地调试或管理员使用就绕过正式写入边界。

### 记忆整理批次与恢复

对话写入和记忆整理是两个提交边界。正式回合先完整进入对话历史，整理器再从尚未处理的已提交回合产生记忆操作；不能为了省一次存储让整理器同时拥有原始对话，也不能把整理失败解释成对话没有发生。用户明确发出的“记住”或“忘记”命令可以拥有确定性入口，其它需要跨轮判断稳定性、更正关系或长期价值的内容，关键词命中不能代替跨轮语义判断。任务状态、CLI 输出、测试日志和系统诊断继续保留自己的正式消费者，不能因为整理器能读到就自动进入陪伴关系或用户画像。

产品选择用模型整理时，同时读取 `model-mediated-operation-governance.md` 和 `structured-data-boundary.md`。模型只提出引用真实 session、turn 或事件身份的创建、更新、归档、合并或拒绝操作；宿主在唯一结构化入口验证证据存在、来源资格、目标记忆身份、类别和操作 schema，再通过唯一记忆写入边界提交。模型输出自然、理由充分或与旧内容相似都不能绕过这些检查。

批量策略把成本触发、输入预算和恢复分别定义。正常调度根据已经提交的回合数、事件数或其它稳定业务工作单元决定何时形成完整批次；字符数和 token 上限只负责输入预算、裁剪或拒绝，除非产品明确把内容体积本身定义为触发合同，否则不能暗中改变调用频率。具体门槛属于项目配置和真实成本评测，不写成通用常数。

需要跨重启补处理时，同时读取 `durable-operation-governance.md`。正常调度只接收达到业务批量门槛的完整批次；启动恢复必须检查持久游标后的全部积压，并按同一顺序处理最后一个不足正常门槛的尾批。每批使用由真实输入身份确定的稳定批次身份。先原子提交全部记忆变更与必要索引，再推进最后处理游标；模型失败、解析失败、证据失效、部分写入或关闭中断都不能推进游标。重试消费同一批次身份并检查已经提交的操作，不能重复创建记忆。前台对话和后台整理共享 provider、锁或可热替换服务时，再读取 `hard-to-reproduce-diagnostics.md` 与 `runtime-generation-governance.md`，明确前台优先级、取消、释放、代次切换和重新调度。

验收从正式对话入口连续产生未整理回合，让真实请求构造与 provider serializer 生成模型请求，响应经过正式解析、记忆写入、索引和游标，再关闭并重新启动同一个应用，由正式检索与记忆界面读取结果。分别证明正常门槛之前不调用、达到门槛后只提交一次、启动能处理尾批、失败不推进游标、重试不重复，以及不合格的任务或诊断内容不会进入个人记忆。测试可以使用记录线协议的本地端点代替不稳定远端模型，但直接替换 provider、手写整理结果或只检查存储文件不能证明完整链路。

判断污染时先找首次错误写入，再检查错误内容是否被检索、再次总结或反复写回。只看到最终回复重复，不能直接断言长期记忆已经污染。

## 5. TTS 内容资格、清理与重复放大

沿以下链路核对：

```text
正式消息生产 → 来源、语义阶段与受众资格 → 语音投影 → 文本清理 → 分段 → 入队 → 去重 → provider 调用 → 播放
```

消费资格必须先于文本清理。角色回复、系统消息、运行时状态、CLI 或工具原文、路径、按钮标签和诊断内容即使都表现为字符串，也继续保留不同来源和语义阶段；只有产品合同明确允许朗读的消息才能产生语音投影。清理 Markdown、动作标记或其它符号不能把原本不合格的消息变成角色语音，也不能让系统事件因文字像一句自然回复就进入 TTS。

屏幕正文和语音不必逐字符相同，但必须从同一份已定稿语义结果派生。屏幕可以保留 emoji、Markdown、链接、文件路径和视觉动作，语音投影按产品合同移除不应发声的非语言内容并保持剩余自然语言；这不是第二套消息真源，也不能由另一个 helper 重新判断任务结果。emoji 清理要覆盖变体选择符、肤色、零宽连接组合、旗帜和键帽等完整字素序列，不能删掉一半后把残余符号或名称交给 provider 朗读。

按需记录：

- 来源 `turn_id`、消息身份、语义阶段、回复版本和内容哈希。
- 消费资格、拒绝原因与语音投影身份。
- 清理前后文本及分段序号。
- 入队、跳过、替换、取消和重试决定。
- provider 调用次数、播放开始和完成。

先比较正式消息是否在流式合并、结果提交或界面投影之前已经重复，再判断语音投影、分段重叠、重复入队、重试误判或播放器重复。同一语义结果的流式增量和最终帧使用稳定消息身份与版本收口，不能各自变成一次完整朗读；重试只有在原分段尚未播放且 provider 合同允许时才能替换，不会把已播放内容再入队。完整文本在详情中查看；列表用哈希、长度和片段摘要避免长文刷屏。

验收从正式消息生产者分别产生可朗读角色回复、不可朗读系统或运行时事件，以及包含组合 emoji、Markdown、链接或路径的正文。让这些消息经过真实资格 gate、语音投影、分段与队列，到达记录实际请求的 TTS provider 边界，再核对：系统和工具内容没有 provider 调用；屏幕仍保留合同要求的视觉内容；provider 只收到清理后的自然语言；流式增量、最终帧和重试没有造成重复播放。直接调用清理函数、手写已经合格的队列项或 mock 掉资格与队列边界，只能证明局部字符串处理。

## 6. 日志观看体验

### 双层展示

- 摘要层：时间、级别、组件、事件、结果、关联 ID 和短摘要。
- 详情层：完整多行正文、结构化字段、堆栈、LLM 原文和相关事件入口。

摘要不能替代原文。长内容默认折叠，但必须能完整展开、复制和导出。

完整记录和有界投影是两个不同合同。持久层保存生产者实际产生的全部 stdout、stderr、事件、请求、回复和生命周期记录，并用稳定序号或游标恢复顺序；列表、状态对象和通知可以只携带长度、哈希、截断标记和短摘要，但必须能沿同一关联身份读取完整记录。不能先截断再持久化，也不能让摘要字段成为重启后的唯一日志真源。

### 必要交互

- 组合筛选：级别、组件、事件、时间段和关联 ID。
- 全文搜索：同时搜索可见正文与结构化详情。
- 链路查看：一键查看同一 session、turn、task 或 trace。
- 顺序稳定：相同时间戳下仍能按事件序号还原先后。
- 清晰区分：请求、回复、错误、重试、记忆、TTS 和用户操作使用稳定标签。
- 诊断导出：包含日志、环境、有效配置差异和必要审计记录，并说明时间范围。

### 控制视觉噪声

- 普通列表默认隐藏文件行号、进程号和大段 JSON，详情保留。
- 相同异常连续出现时显示次数与时间范围，原始记录仍可访问。
- 多行 LLM 内容保持原始换行和角色边界。
- 颜色只辅助级别和状态，不作为唯一识别方式。

## 7. 终止、取消与跨进程日志

存在辅助进程、事件流或异步关闭时，日志分别记录发起者、终止原因、结果状态、传输收尾、退出码和清理结果。客户端请求关闭、后台声明的安全中断和真实故障是原因；`stopped`、`ready` 或 `failed` 是结果；EOF、断管和取消 I/O 是传输或清理现象。后出现的通用结果不能覆盖先确定的结构化原因，传输结束也不能凭自身升级成故障。

进程还提交业务结果时，结构化结果帧是业务状态的唯一来源，日志只记录和解释它，不能用最后一行、自然语言、关键词、退出码或 EOF 反推。结果帧与日志分别落入可关联的无损通道；摘要消费者不得重新实现结果解析。

主动停止产生的取消只有在日志能够证明停止所有者、发生阶段和精确取消结果时才按正常收尾记录。超时强制终止、非零退出、订阅者未排空和未交付的终止事件仍是失败。跨进程文本同时记录生产者声明的编码和消费者实际解码方式；原文出现替换字符或乱码时，从字节生产边界修复，不能只在查看器里替换显示。

流式脱敏、解析和编码转换还要验证分片不变量与最终 flush：同一字节序列在任意 chunk 划分下得到相同结果，跨分片的凭据、字符或结构化帧不会泄漏、丢失、重复或破坏周围普通文本。

一次通过的真实运行还要反向扫描同一关联链：成功结果附近是否出现矛盾的 failure marker、乱码、未结束进程、恢复残留或重复终止原因。扫描结果只有在扫描命令成功、时间范围和关联 ID 准确时才成立；发现矛盾时，较早的“通过”结论退回待解释状态。

## 8. 证据矩阵

每个诊断问题至少记录：

| 项目 | 内容 |
| --- | --- |
| 现象 | 用户实际看到或复现到什么 |
| 代码路径 | 哪个真源产生、传播或消费它 |
| 运行证据 | 哪条日志、测试或实验支持结论 |
| 根因 | 错误第一次产生在哪里 |
| 放大点 | 哪些后续环节让影响扩大 |
| 影响 | 哪种诊断、交互或恢复能力失效 |
| 修复边界 | 应在哪个唯一边界收口 |
| 验证 | 怎样证明修复完成且旧路径退出 |

完成字段、链路和观看体验判断后，把观察返回已选日志子类型；本方法不自行切换到改造。
