# 参考界面忠实重建

用于用户明确要求还原、重建、复刻或像素级匹配一个有权使用的网站或数字界面。用户最终得到的是在约定范围、视口和状态下与参考一致的可运行实现，不是受参考启发的新设计。

## 一、先锁定重建合同

开始检查前写清：

```text
目标 URL、页面或路由集合：
用户拥有或获准使用的内容与资产：
目标项目、技术栈和正式入口：
保真度：结构关系、视觉接近、像素级或用户另行定义
需要覆盖的视口、输入方式和状态：
允许的定制与必须保持不变的内容：
后台、身份、数据、SEO、分析和发布是否在范围内：
用户怎样判断完成：
```

默认只重建用户点名页面当前可观察的前端内容、布局、视觉、互动和响应式行为。真实后台、数据库、身份、实时服务、隐藏管理功能和未展示业务规则不因前端出现对应入口而自动进入范围。用户没有授权定制时先做忠实基线，不边检查边加入个人审美或“现代化”调整。

目标站点只在该分支中承担表现真源。产品目标、合法使用范围、目标技术栈、交付位置和未展示业务事实仍由用户与当前项目决定。目标不可访问、依赖登录或按账号动态变化时，先说明能稳定观察的范围；未获登录或访问授权时停在公开状态。

## 二、先检查页面，再设计实现

忠实重建依赖真实浏览器。只有截图不能证明互动、状态和响应式；只有 DOM 或 CSS 不能证明最终构图、素材层和像素结果。检查按以下顺序进行。

### 1. 建立主参考

在合同约定的每个目标视口保存完整页面和关键区域截图。至少覆盖能改变布局的宽视口与窄视口；存在独立平板布局、深浅主题或系统外观分支时再增加对应状态。截图记录 URL、视口、缩放、主题、登录状态和取得时间，后续实现与验收必须使用同一条件。

### 2. 建立页面拓扑

从自然入口向下记录页面区域顺序、流式内容、固定或粘性层、覆盖关系、滚动容器、导航与返回关系，以及跨区域共享的头部、背景、媒体和状态。为每个区域明确主要职责和互动模型：静态、点击驱动、悬停或焦点驱动、滚动驱动、时间驱动，或它们的明确组合。

### 3. 先识别互动模型

不要先点击看起来像标签的对象。先缓慢滚动并观察内容是否随视口自动切换、吸附、固定或推进；再检查悬停、焦点和点击；最后检查自动播放和时间变化。对每个变化记录：

```text
输入或进度来源：
生效区域和目标对象：
触发阈值或状态条件：
变化前状态：
变化后状态：
改变的属性、内容与素材：
持续时间、缓动和中断方式：
反向、重复输入和减少动态效果时的结果：
```

滚动驱动与点击切换、视频与 HTML 模拟、原生吸附与脚本动画属于不同实现合同。没有确认互动模型前不写组件代码。

### 4. 提取全部状态和真实内容

逐一打开标签、菜单、折叠项、弹层、轮播和其它可见状态，记录每个状态的真实文字、图片、图标、顺序、选择、禁用、加载、空、错误和结束结果。滚动触发对象至少记录触发前后；悬停和焦点同时检查鼠标、键盘及触摸替代。不能只实现首次加载状态，再用占位内容代替未检查状态。

### 5. 提取设计基础、几何和素材层

先从生产页面的计算结果提取字体家族与实际字重、颜色、间距、圆角、边框、阴影、层级、断点、全局滚动和动效，再映射到目标项目的唯一 token 与共享基础。每个区域记录真实边界、对齐、最大宽度、网格或弹性关系、裁切、对象适配、重叠和安全区。

枚举所有图片、视频、poster、背景图、内联 SVG、字体、favicon 和社交预览资源。看起来像一张图的区域继续检查是否由背景、前景、遮罩、覆盖图标或视频共同组成；不能用一张近似截图替代可观察的分层关系。只有用户有权使用的资源才下载到项目；不能复制时保留尺寸、职责和替代要求，并使用用户提供或获准素材。

### 6. 检查响应式变化

在每个合同视口重复检查页面顺序、网格、可见项、导航、媒体裁切、互动入口、固定关系和状态。断点来自布局实际发生变化的位置，不因目标项目使用某套 CSS 框架就套用默认断点。移动端不是桌面简单缩放；消失、改序、折叠或更换互动模型都必须进入规格。

## 三、形成可审计规格

在实现任何区域前，先建立页面级检查结果和组件合同。已有项目有研究目录约定时沿用；没有时可以在项目的设计研究目录中保存：

- 主参考截图与对应条件；
- 页面拓扑和全局互动清单；
- 字体、颜色、空间、形状、层级和动效基础；
- 资产清单、来源、许可状态和本地路径；
- 每个待实现区域或组件的规格文件。

上层主路径会为每个组件提供统一的组件规格模板；复制后填写实际证据。规格是检查与实现之间的合同：目标文件、结构、计算样式、真实内容、全部状态、互动模型、素材和响应式必须完整，使实现者不必凭经验猜颜色、间距、触发方式或内容。

组件规模由独立职责、状态和实现复杂度决定。一个规格同时包含多个不同互动模型、多个独立子组件或已经难以让实现者完整核对时，拆成更小合同；不要为了并行或文件数量机械拆分。共享基础、跨区域状态和页面级滚动关系由共同所有者负责，不能复制到多个组件后各自实现。

## 四、按依赖顺序实施

### 1. 先建立基础

先迁移当前项目实际需要的字体、全局 token、页面容器、共享类型、图标与获准资产，并验证正式入口仍能构建。基础层是后续组件共同读取的唯一来源，不能让各组件复制近似色值、字重、断点和全局动画。

### 2. 再逐组件实施

每个组件只按自己的规格实现结构、内容、状态、素材和响应式。规格缺少会改变结果的信息时回到浏览器补查并更新规格，不由实现者猜测。每完成一个组件先运行项目已有的类型、静态检查或构建命令，再装配下一个；具体框架、组件库和样式方案由目标项目决定，不强制迁移参考站点或来源模板的技术栈。

### 3. 最后装配页面关系

组件通过后再连接页面拓扑、导航、固定层、滚动容器、跨区域主题变化和全局互动。页面级所有者负责共享进度与状态；组件内部效果不能分别监听同一输入并竞争最终位置。

是否使用并行 Agent 由当前环境、用户授权和仓库规则决定，不属于忠实重建能力的默认要求。无论谁实施，每个任务都必须读取同一规格与正式基础，合并后重新检查共同入口。

## 五、同条件视觉与互动验收

完成不能由“构建通过”证明。按主参考的 URL 状态、视口、缩放和主题条件打开参考与实现，逐区域比较：

- 内容、字体、颜色、间距、尺寸、对齐、裁切、层级和素材是否一致；
- 固定、滚动、点击、悬停、焦点、时间变化和全部状态是否使用相同互动模型；
- 宽窄视口是否在相同关系上变化，没有只匹配一个截图；
- 实际内容和资源是否由正式消费者读取，没有用测试状态或手写假数据冒充；
- 键盘、焦点、语义和减少动态效果没有因视觉复刻而退化。

发现差异时先判断来源：检查证据错误就重新观察并更新规格；规格正确而实现错误就修正式组件；共同 token、资产或页面关系错误就修唯一基础并迁移所有消费者。不能在组件旁增加只对一个截图有效的补丁。

结束前重新运行目标项目的正式检查与构建，从最终实现取得同视口截图，并实际走过所有合同互动与状态。交付时说明覆盖的页面、视口、状态、组件与资产，构建和视觉互动验收结果，以及任何因不可访问、权限、动态个性化或范围决定留下的明确差异。

## 六、停止边界

达到合同保真度、正式入口可用、约定视口和状态通过对照后停止。不要自动继续到后台实现、品牌改造、SEO、部署、发布或未点名页面。用户要求在忠实基线上继续定制时，把定制作为新的设计分支，保护已经通过的结构、内容与互动关系。
